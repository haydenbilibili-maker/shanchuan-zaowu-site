# 祈福墙 · 玩法弹层（2026-09-27）

> 产品口径：「今天的玩法」六个模块（今日一签 / 拆签饼 / 星座签 / MBTI 贴士 / 节气签 / 铜钱签）
> 做成**祈福墙页内弹层**，玩法全程在墙上完成，入口不再跳新页面。

## 1. 组件落点

| 位置 | 作用 |
|------|------|
| `subpackages/plays/components/PlaySheet/` | 弹层外壳：遮罩、把手（下拉 ≥88px 收起）、「收起」键、进出场动画；只挂当前玩法的本体 |
| `subpackages/plays/components/PlayBody/<id>/` | 玩法本体（六个）：`index.wxml` 一行 `include` 独立页 WXML，`index.wxss` `@import` 独立页 WXSS + `body.wxss`（只改最小高度与底部安全区），`index.js` = `Component(createRitualPlayBody(id))` |
| `subpackages/plays/utils/ritualPlayPage.js` | 同一个工厂：`createRitualPlayPage`（独立页）与 `createRitualPlayBody`（弹层本体）共用全部方法 |
| `subpackages/feature/wish-wall/index.{json,wxml,js}` | 墙页挂点：`<play-sheet wx:if="{{playSheetId}}">`；入口 `onPlayTap` → `openPlaySheet` |

**为什么组件在 plays 分包而不是 feature**：feature 分包实测 2037 KiB，距 2 MB 上限只剩 ~10 KiB；
主包也只剩 ~11 KiB。所以墙页通过**分包异步化**引用 plays 的组件：
`usingComponents` + 同名 `componentPlaceholder: { "play-sheet": "view" }`，并在 `app.json` 的
`preloadRule` 里让进祈福墙时预下载 plays 分包（首开弹层不等下载）。
`check:asset-refs` / `check:subpackage-refs` 已按「同名登记占位才放行」识别这条官方通道（各配自检）。

**为什么本体是六个小组件而不是一个**：六份玩法样式里有同名类（如 `.rp-paper`）各自不同，
合进一个组件会互相覆盖；每个玩法一个组件 = 样式天然隔离，且皮与行为都与独立页**同一份源**（不复制）。

## 2. 状态机

墙页（`playSheetId`）：

```
''（未开） --点入口 / 深链 play=<id>--> '<id>'（弹层挂载）
'<id>' --收起（遮罩/收起键/把手下拉）--> ''  + refreshPlayStates（入口立刻变「今天已…」）
'<id>' --本体「写成心愿」--> wish（出场开始即抛）→ applyPlayHandoff；出场结束 close → ''
'<id>' --挂签条「挂上墙」--> post（出场开始即抛）→ onPlaySheetPost → submitWish；出场结束 close → ''
```

弹层本体（与独立页相同）：`idle → pending（spinMs）→ result`；缺资料 `need`；星座/MBTI 可「换一个」。
本体宿主差异只有三处（`this._embedded`）：不改导航栏标题；「写成心愿」写交接后抛 `wish` 事件、不跳页；
「分享这份结果」抛 `share`（detail.title = `result.share`），墙页 `onShareAppMessage` 读到即清、只用这一次。
挂签台、弹幕、签廊不受弹层开关影响（弹层 `wx:if` 挂在 `.ww-page` 直接子节点，层级 9970）。

## 3. 独立页兼容策略

- `play-*` 六个独立页**保留不动**（`app.json` 仍注册）：旧消息链接（`utils/messageHelper` 的路径映射）
  与任何外链仍能打开完整的独立页，行为不变（写成心愿仍 `navigateBack`/`reLaunch` 回墙）。
- 墙页新增深链 `play=<id>`：门禁放行后自动开对应弹层（只消费一次）。需要时可把独立页改成
  「`redirectTo` 墙页并带 `play=<id>`」—— 属产品点名项，本次未做。
- 分享路径一直是祈福墙（独立页与弹层都分享墙页路径），不存在指向 `play-*` 的分享卡。

## 4. 全链路提速（2026-09-27 第二轮：玩法 → 写签 → 发布）

| 环节 | 改前 | 改后 |
|------|------|------|
| 结果 → 挂上墙 | 写成心愿 → 弹层沉完（220ms）→ 滚到挂签台（260ms）→ 键盘弹起（300ms 后）→ 点「挂上墙」 | 结果下方**挂签条**（`play-shared/post.wxml`，只在 `embedded` 时渲染）已预填心愿词，可就地改一句 → 点「挂上墙」一步完成；想细改仍可点「到挂签台慢慢写 ›」走旧路 |
| 弹层出场与墙页动作 | 两段式：出场结束才抛事件 | 一段式：`wish` / `post` 在出场**开始**时抛，墙页滚动/预填/落愿与面板下沉同时进行，出场结束再抛 `close` 卸载 |
| 发布实现 | — | 挂签条只抛 `post { text }`；墙页 `onPlaySheetPost` 先把这句放进挂签台（被门禁拦 / 失败时草稿留着），滚到墙面，再走**唯一的** `submitWish`（门禁、额度、云函数入参出参不变） |
| 落地时机 | 等云函数返回才插墙 | **先落地后确认**：点下即插墙首 + 弹幕落签 + 清空输入；成功换服务端 `_id`（弹幕行只换 id 不换 key，不重播）；失败 `unlandWish` 撤回、额度还原、草稿还给挂签台 |
| 反馈 | 原生 toast「心愿已挂上墙」+ 挂签台「成」+ 回声 + 弹幕落签 叠在一起 | 去掉原生 toast（它盖住正在落签的墙面）；挂签台「成」/ 震动 / 回声只在确认后给；挂签条路径不再先回一声「我摇了…」 |
| 连点 | `posting` 要等门禁读完会话才置真，其间连点可发两次 post | `_submitting` 锁住整次提交 |
| 列表对齐失败 | 落愿成功后 `refresh()` 抛错会被当成「发布失败」toast，续发漏斗记失败 | 已挂上后列表对齐失败只记日志，仍返回成功 |
| 弹层首开 | 面板上滑 + 本体整页淡入 520ms 叠加，内容晚半拍 | 本体关掉整页淡入（`body.wxss`），只留面板进场 |
