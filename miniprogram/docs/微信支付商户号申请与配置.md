代码行为摘要（当前仓库逻辑）：

```
payOrder:
  有 WX_PAY_SUB_MCH_ID → cloud.cloudPay.unifiedOrder({ subMchId, envId, functionName: 'payCallback', ... })
                        → 返回 payment → 前端 wx.requestPayment

  微信异步通知 → 写 wxTransactionId / wxPayMode:'wechat' → fulfillOrder

  微信实付（wxPayMode=wechat 或有 wxTransactionId）→ 必须 cloud.cloudPay.refund；失败不改库
```

### ⚠️ 回调鉴权红线（2026-09-15 事故复盘，务必遵守）

`payCallback` 是**平台回调**，不是 C 端可调用的业务函数。加固时只能依据 **`wxContext.SOURCE`** 判定调用来源：

```js
// ✅ 正确：只拒绝小程序端 / 开发者工具直调
const source = String(cloud.getWXContext().SOURCE || '')
if (source === 'wx_client' || source === 'wx_devtools') return { errcode: 0, errmsg: 'IGNORED' }

// ⛔ 错误示范（曾造成线上事故，已回退）：
// if (isClientSource(source) || wxContext.OPENID) { ... }
```

**为什么不能用 OPENID 判定**：`cloud.cloudPay.unifiedOrder` 是**带付款人 openid 下单**的，平台回调同样会携带该 OPENID。用它当"伪造特征"会把**全部真实回调**判为伪造；而伪造判定返回的是 `errcode: 0 / SUCCESS`，微信认为回调已送达、**不再重试**，于是：

- 商品订单：支付成功但订单一直停在 `pending_pay`（页面继续显示「待支付 / 立即支付」）；
- 钱包充值：`stored_value_recharge_orders` 停在 `pending`，余额不到账。

事故期间已实扣的订单/充值不会自动补：用下面两个补单入口人工恢复（都要求超管、幂等）。

| 场景 | 入口 | 说明 |
|------|------|------|
| 钱包充值未到账 | ERP → 我的钱包 → **补单入账**；或 小程序超管台 → 钱包配置 → **补单入账** | 填充值单 ID 或 `SV…` 单号，可选微信交易号；服务端 `manageStoredValue.reconcileRecharge`（仅超管 `staffGuard`） |
| 商品订单已付款未履约 | ERP → 全渠道订单 → **补履约**；或 小程序超管台 → 订单管理 → **待支付** 页签 → **补履约** | ERP 走 `confirmPayment.adminFulfill`（`ADMIN_OPS_KEY`）；小程序走 `managerShipOrder.fulfillPaidOrder`（超管）→ 内部转发同一个 `adminFulfill` |

回调排查：每次回调都会打印 `payCallback context: { source, hasOpenid, outTradeNo }`——若看到 `source=wx_client` 才是真的客户端伪造。

验收失败时优先查：AppID 是否绑定、云控制台是否授权 1800008281、JSAPI 是否授权、环境变量是否打到**当前**云函数版本、类目是否触发云调用限制。

## 5. FAQ

**Q1：我们是普通商户还是服务商子商户？**  
A：你们申请并持有的是**普通商户号**。使用云开发 cloudPay 时，技术上以「云开发服务商 + 你们作为子商户参数」代调用，所以代码字段叫 `subMchId`，并不等于你们要自己注册成服务商。

**Q2：`WX_PAY_SUB_MCH_ID` 填服务商号还是自己的商户号？**  
A：填**你们自己的 mchid**（在云控制台添加的那个）。服务商侧由微信云开发托管。

**Q3：要不要配置 APIv3 密钥和证书？**  
A：走 cloudPay 云调用则**一般不需要**自行管证书。若改用 CloudBase 集成中心 / 自建统一下单，才需要密钥与证书（本仓库当前未走该路径）。

**Q4：生产能否开 `ALLOW_MOCK_PAY=1`？**  
A：**不能。** 开启后可不经微信支付直接 `mockPay` 并履约，等于 0 元出货。

**Q5：`confirmPayment` 是否等于支付成功？**  
A：主路径应以 `payCallback` 写入的微信交易号为准。当前 `confirmPayment` 在已配置商户号时，仍可能在回调到达前做短时确认；上线后应对账，后续可再加固查单（见上线清单 P2）。

**Q6：审核要多久？**  
A：官方小程序接入页写明资料审核约 **1–2 个工作日**，通过后签约；主体不一致的 AppID 绑定额外约 **1–3 个工作日**。以页面与商家助手通知为准。

**Q7：个人能申请吗？**  
A：普通商户支持个体工商户、企业等；**不支持**未认证的个人小程序收款。无执照的「个人」通常无法按普通商户入驻。

**Q8：绑定 AppID 后还要在公众平台做什么？**  
A：必须在公众平台**确认**商户号关联；仅商户平台发起不够。

**Q9：能否用 CLI / 脚本自动写入商户号到云端？**  
A：**不能**（开发者工具 CLI 无此能力）。请控制台手动配置；本地仅可用 `pay.env.local` 备忘（gitignore）。
