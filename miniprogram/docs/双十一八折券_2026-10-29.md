## 2. 规则改动（本次落地）

### 2.1 `receiveCoupon`（已部署，部署前线上 = origin/main，部署后复比一致）

- **新增可选字段 `fixedExpireTime`**：有它 → 用户券到期 = `min(fixedExpireTime, 领取时刻 + expireDays 天)`（`expireDays` 为 0 时只看固定到期）。
  没有它 → **与改前逐字同口径**（`expireDays` 天 / 模板 `expireTime` / 默认 30 天），老券不受影响。
- 固定到期已过 → 「优惠券已过期」；字段写坏 → 「优惠券配置异常，请稍后再试」（不会发出一张到期时间错误的券）。
- 时间一律按**绝对时刻**存 Date（模板以 `+08:00` 写入），云函数跑 UTC 也不偏 8 小时。
- **限领计数纳入 `locked`**（下单锁定中的券）：改前锁定期间可再领一张，属行为修正。
- **活动券（有固定到期 + 每人限 1 张）用确定性 `_id = cw_<模板id>_<openid>`**：连点两次只会成功一次（数据库主键兜底）。
- **渠道**：写入 `user_coupons.channel = normalizeCouponChannel(模板.channel)`；模板为 `online` 时领取结果也是 `online`。

### 2.2 ERP 礼券表单（`admin/src/components/Marketing.vue`，随 main 部署）

- 新增「领取时间」（开始 / 截止）、「到期方式」（领取后 N 天 / 统一到期）+「统一到期」时间；表格加「领取时间 / 有效期」两列。
- 时间按**北京时间**输入，存为带 `+08:00` 的绝对时刻（`admin/src/utils/couponWindow.js`）。
- **顺带修复**：`coupons` 集合安全规则 `write:false`，ERP 礼券表单原先直写被拒（新建 / 编辑 / 上下架都失败）。

  集合权限与 `COLLECTIONS` 未改。
- `channel=online` 时表格 / 表单展示「仅线上 / 仅线上商城」（既有 `channelLabel`，无需另改）。

## 3. 场景行为（2026-10-30 起）

| 场景 | 能否用 | 怎么算 / 怎么用 |
|---|---|---|
| 线上普通单 | ✅ | 券夹 / 结算页选用；`makeOrder` 要求 `couponChannelAllows(..., 'online')` |
| 礼赠单 | ✅ | 与普通单同一计价 + 同一锁券流程（`makeOrder` 礼赠分支不屏蔽礼券） |
| 门店核销 | ❌ | `verifyStoreCoupon`：`couponChannelAllows(..., 'store')` 为 false → 拒「该券仅限线上商城使用，请在小程序下单抵扣」 |

- **到账方式**：10-30 00:00 起自动发到注册会员券夹（§6）。**备用领取入口**：商品详情页的礼券抽屉 / 券夹「可领取」。
- 退款 / 取消 / 支付超时：锁定或已用的券按原流程退回为「未使用」（到期仍是 11-15 23:59:59）；退回后仍是 `channel=online`，门店仍不可核销。

- **到期后**：什么都不做也安全 —— 11-15 23:59:59 之后抽屉不再展示、领取被拒、已领券全部过期。

  已领的券仍可用到 11-15（**仅线上**）；如需作废已领券，要改 `user_coupons`，**需产品负责人点名**。
- **代码回滚**：revert 相关提交并按需 `bash miniprogram/scripts/deploy-drifted.sh …`。
  旧版 `receiveCoupon` 不认识 `fixedExpireTime`，会按 `expireDays=0` → 回落模板 `expireTime` / 默认 30 天，
  **回滚前务必先下架模板**，否则新领的券有效期会变成 30 天。

## 6. 自动发放（产品负责人 2026-10-29 改口）

| 项 | 口径 |
|---|---|
| 云函数 | `issueCampaignCoupon`（旁路，**新增**；不改 upsertUserProfile / receiveCoupon / getUserCoupons / makeOrder） |
| 触发器 | `issueCampaignCouponRun`，cron `0 */10 * * * * *`（每 10 分钟整点），已在线上查得（`Enable=1`） |
| 时区 | 云开发 cron 按 **UTC+8** 解析。每 10 分钟的表达式与时区无关；**是否发放只看函数内绝对时刻** |
| 窗口 | 活动常量 `2026-10-30T00:00:00+08:00` ~ `2026-11-15T23:59:59+08:00` **∩** 模板 `active` / `startTime` / `endTime` / `fixedExpireTime`；窗口外空转 |
| 对象 | 注册会员 = `users` 有文档且 `status != 'cancelled'`，**含员工 / 店长 / 超管账号** |
| 文档 | 与 `receiveCoupon` 写入的 user_coupons **字段与顺序完全一致**；`channel: normalizeCouponChannel(coupon.channel)` **读模板、不写死**；模板为 `online` 时新发券带 `online` |
| 幂等 | `_id = cw_<模板id>_<openid>`；先排除已持有该券的人（任何状态），并发 / 重跑由主键兜底 |
| 批量 | 每批 20 并发、单次执行 45s 预算；日志只记计数，不含 openid / 手机号 |
| 新会员 | 注册后**最迟约 10 分钟**到账（下一个整 10 分） |
| dryRun | `{ action: 'dryRun' }` 只返回将发人数；仅超管或 `ADMIN_OPS_KEY` |
