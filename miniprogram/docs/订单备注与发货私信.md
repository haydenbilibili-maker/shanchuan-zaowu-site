# 订单管理：会员/私信全入口 + 订单备注 + 发货私信去重

**落地日期**：2026-09-14  
**涉及**：`subpackages/manager/manager/`（店长台 · 订单管理）、`cloudfunctions/managerShipOrder/`、`utils/messageHelper.js`

---

## 1. 会员信息与私信：四个入口一致

订单管理四个子 Tab（待发货 / 已发货 / 已完成 / 售后）现在都展示「下单会员」卡片：
头像 + 昵称 + 脱敏手机号，并带「私信」按钮直达山海有信（预填收件人）。

- 数据：`managerShipOrder.action=listManagerOrders` 对四个 Tab 统一 `attachBuyerBriefs`（分页与搜索两条路径都富集），前端 `enrichManagerOrderCard` 统一映射 `buyer`。
- 权限：「私信」按钮同样受 `menu.support` 与工作台权限（Tab 11 有信）双重门控，与待发货一致。

## 2. 订单备注（店长录入 → 随发货私信发出）

**位置**：订单管理 · 待发货卡片底部「订单备注」输入框 + 保存。

| 环节 | 行为 |
|------|------|
| 输入 | 待发货卡片输入框，上限 100 字（前端 `ORDER_NOTE_MAX` 与云函数 `NOTE_MAX` 一致） |
| 保存 | `managerShipOrder { action: 'saveNote' }` → 写入 `orders.managerNote` / `managerNoteAt` / `managerNoteBy` |
| 发货 | 发货时以输入框当前值为准（未保存也会写入）；未填写则沿用已保存备注 |
| 私信 | 发货私信正文追加一行 `馆员留言：<备注>`，无备注时不产生空行 |

**字段约定**：`orders.managerNote` 为店长备注；买家下单备注仍是 `orders.remark`（两者不要混用）。

**展示**：山海有信信封页把 `馆员留言：` 整行识别为 `note` run（`utils/messageHelper.js` 的 `LETTER_TOKEN_SPECS`），以铜色加重 + 浅底纹高亮，避免备注淹没在订单号/运单号里。

## 3. 发货私信去重（修复「两条相似私信」）

**问题**：礼赠订单发货时，历史上同时发出 `order_shipped`（标题「藏品已发出」）与 `gift_shipped`（标题「标本已启程」），会员在山海有信收到两条内容近似的私信。

**规则（现状）**：

| 订单类型 | 收货人 | 发出事件 | 标题 |
|----------|--------|----------|------|
| 普通订单 | 买家 | `order_shipped` | 藏品已发出 |
| 礼赠订单 | 赠予者（买家） | `gift_shipped` | 标本已启程 |
| 礼赠订单 | 受赠人（地址不同） | `gift_shipped` | 标本已启程 |

即：**每人每次发货只收一条**。同时 `dispatchMessage` 侧仍保留 24h `dedupeKey`（`eventType:relatedId:openid`）作为兜底。

> 若产品希望礼赠订单对赠予者保留「藏品已发出」文案，只需把 `cloudfunctions/managerShipOrder/index.js` 里
> `shipEventType` 的礼赠分支改回 `order_shipped`，并把 `gift_shipped` 只发给受赠人。

## 4. 部署与验证

1. **必须重新部署云函数** `managerShipOrder`（备注保存、发货去重、私信带备注都在这里）。
2. 小程序侧改动随上传生效（订单卡片布局 / 备注输入框 / 信封高亮样式）。
3. 冒烟：待发货选一单 → 填备注并保存 → 确认发货 → 山海有信应只收到**一条**私信，且正文含高亮的「馆员留言」。
