## 第 1 轮（2026-10-01）· 交易主链：订单列表 / 订单详情 / 购物车礼券 / 确认下单

### 问题清单（用户感知 × 改动风险 排序）

| # | 页面 | 现象（取证） | 感知 | 风险 |
|---|---|---|---|---|
| 1 | 订单详情 | 「已付定金抵扣」行用了 `price-row` 类，**该页 wxss 里没有这个类** → 这一行不走 flex、没有字号，标签和金额挤在一起 | 高（钱） | 低 |
| 2 | 订单详情 | 会员折扣写成 `{{order.discountRate * 10}}折`：0.7 × 10 = `7.000000000000001折`；括号前还多一个空格「会员折扣 （」 | 高（钱） | 低 |
| 3 | 订单列表 / 详情 | 「立即支付」没有防重入：拉起支付前连点两下会发起两次 `payForOrder`，按钮也没有任何「处理中」反馈 | 高 | 低 |
| 4 | 订单列表 | 多件订单只显示第一件，看不出「还有几件」；缺图时是空白方块；学名缺失时显示占位英文 `Specimen`（E11 占位当内容） | 中 | 低 |
| 5 | 订单列表 | 6 个 tab 共用一句空态「暂无相关记录 / 下单后档案会出现在这里」；`已签收` 印章灰 `#666` 在深底上几乎看不见；`已取消 / 退款未通过 / 待自取` 没有印章色（落成白色） | 中 | 低 |
| 6 | 订单列表 / 物流 / 售后 / 小票认领 / 详情「重新确认支付」 | 失败提示把微信原文透给顾客：`跳转失败： navigateTo:fail …`、`cloud.callFunction:fail …`、物流页副标题直接放 `errMsg` | 中 | 低 |
| 7 | 购物车（主包） | 礼券弹层：无门槛券显示「满 0 可用」；没有券时只剩一行「不使用礼券」，像没加载出来；门槛说明用 `--color-text-muted`（深底实测 2.7–3.1，低于 4.5） | 中 | 低 |
| 8 | 购物车（主包） | 侧滑「移除」云调用失败时没有任何反馈（未捕获的 Promise） | 低 | 低 |
| 9 | 确认下单 | 藏品图缺失时整块空白；「尾款将通过微信支付」「运费规则」「礼券门槛」等关键说明用 `#6B6560`（低于 4.5） | 中 | 低 |

### 改动

1. **订单详情 · 定金抵扣行**：改用该页既有的 `f-row highlight`，与上面几行同排版、同金额格式（`- ¥ 200.00`）。
2. **订单详情 · 折扣文案**：新增纯展示字段 `order.discountText = formatDiscount(rate)`（复用 `utils/profileHelper` 已有函数，确认下单页同款）→「会员折扣（7折）」。`discountRate` 本身与金额计算不动。
3. **支付防重入 + 反馈**：订单列表 `payingId`、订单详情 `paying`；进行中按钮半透明并改字「支付中… / 正在拉起支付…」，`finally` 复位。`payForOrder` 调用、`msg` 分支（「已取消支付」「暂不可用」弹窗）原样保留。
4. **订单列表卡片**：缩略图包一层 `prod-img-wrap`，缺图走 `box.png` 占位；多件订单右下角「共 N 件」；学名有才显示（礼券兑换单不显示）；数量改为 `× N`。
5. **订单列表空态与印章**：每个 tab 一句对应的空态（如「没有待付款的订单 / 下单后未完成支付的会停在这里」）；`已签收` 改 `#A09A90`；补 `已取消 / 退款未通过`（灰）与 `待自取 / 支付确认中`（金）印章色；空态说明抬到 `#A09A90`。
6. **失败文案大白话**：订单列表跳转失败「暂时打不开订单详情，请稍后再试」；物流「暂未同步到物流」+ 原兜底说明；售后提交 / 小票认领：本地「图片上传失败 / 开箱视频上传失败」保留并补「，请重试」，其余一律「提交没成功，请检查网络后再试」；详情「重新确认支付结果」异常「暂未确认到结果，请稍后再试」。原文只进 `console`。
7. **购物车礼券弹层**：门槛「满 ¥X 可用 / 无门槛」；无券时显示「暂无可用礼券」；门槛色改 `--color-text-secondary`；提示 toast 补「¥」。
8. **购物车移除失败**：捕获并以 AppToast 提示「没能移除，请稍后再试」（不新增原生 toast，`check:dialog-ratchet` 不涨）。
9. **确认下单**：缺图占位；`shipping-tip / summary-foot-hint / c-min / custom-label / coupon-hint.muted` 由 `#6B6560` 抬到 `#A09A90`；礼券门槛同第 7 条口径。

### 「审核中」根因（生产只读实测，`.tmp/probe-comments-status.mjs` / `.tmp/probe-comments-orders.mjs`）

- `comments` 共 12 条，`status` 只有两种取值：`"approved"` 11 条、`"pending"` 1 条；无 `rejected`，**也没有任何驳回原因字段**（字段全集：`_id targetType targetId userId rating content images likes replies status createdAt updatedAt`，另有少量 `isPinned / merchantReply / merchantReplyAt / likedBy / orderId / productTitle`）。
- 带 `orderId`（即走订单评价链路）的 3 条，按 `submitComment.orderStatus` 同一逻辑本地重算：
  - 「蒲公英标本」「印尼金锹」两单：`status = approved` → 页面显示「这件藏品已评价过」，**不会**显示「审核中」；

### 内容安全判定（`submitComment` 提交路径）

先读清的现状：`contentSecurity.js`（`submitCommunityPost` 的同步副本，本次**未改**）里文本走 `msgSecCheck` v2（同步，返回 `result.suggest`），图片走 `imgSecCheck`（**同步**接口：先 `downloadFile` 再提交缓冲区，返回 `errCode`）；`mediaCheckAsync` 是异步接口，评价**不用**它。原 `checkImageBuffer` 把「不是 87014 的任何返回」都当 `ok`（包括没有 `errCode`），所以判「明确通过」不能直接用它的 `ok`，改在 `submitComment` 内逐张判。

| 情况 | 结果 |
|---|---|
| 文本 `suggest === 'pass'`，且每张图 `imgSecCheck` 返回 `errCode === 0`（无图也可） | **自动展示**：写 `status: 'approved'`、`autoApproved: true` |
| 文本 `suggest === 'review'` | `pending`（原因 `text_suggest_review`） |
| 文本无 `suggest` / 其他值（结果不确定） | `pending`（`text_result_unknown`） |
| 文本检测报错 / openapi 权限缺失 | `pending`（`text_check_error` / `text_check_openapi_unavailable`） |
| 图片返回无 `errCode` 或非 0 非 87014 | `pending`（`image_result_unknown`） |
| 图片报错 / 下载失败 / 超过 1MB 同步上限 / 非云存储地址 | `pending`（`image_check_*`） |
| 文本或任一张图违规（87014 / risky） | **拒绝提交**，不写库（与原逻辑一致；现逐张检查，多图里后面的违规图也能拦住） |
| 活动 / 课程评价改写一条**已被隐藏**的评价 | `pending`（`previously_hidden`），不因改写自动重新展示 |

- `pending` 时把原因写进新增字段 `reviewReasons`，ERP 人工审核时可参考；`approved` 时 `reviewReasons: []`。
- ERP「评价审核」照常可用：`moderateComment` 未改，自动通过的评价在「已通过」「全部」页签里，**仍可隐藏**（隐藏后用户评价页显示「未展示」，订单列表不再给「写下感受」）。注意 ERP 默认停在「待审核」页签，自动通过的不会出现在那里。
- 出参：`success / msg / commentId / status` 四个键不变；`status` 如实回 `approved` 或 `pending`；`msg` 文案改为「已展示在藏品页，谢谢分享」/「已收到，内容检测后会展示在藏品页」。
- 评价页：「审核中」说明改为「正在检测内容，稍后展示在藏品页。」；提交成功提示按出参 `status` 区分：`approved` →「评价已展示」（成功图标），`pending` →「已提交，正在检测内容，稍后展示」。
