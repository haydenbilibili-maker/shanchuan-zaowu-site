# 我的成就 · 馆志重设计（2026-10-17）

> 产品负责人：「继续重新设计与规划我的成就模块，大开大阖重新设计」。
> 范围：`subpackages/extra/user/achievements`。**不动**：云函数 `getUserAchievements` 出入参与点亮规则、积分发放、「我的」页成就角标（`markAchievementsSeen`）、山海拾遗彩蛋逻辑、分享文案与路径、`focus=relics` 深链。

## 1. 改前诊断

| 问题 | 证据 |
|---|---|
| 分档徽章被拆成互不相干的卡 | 25 枚里 21 枚是分档（浏览 10 / 50 / 100、收藏 5 / 10 / 50、消费 首单 / ¥500 / ¥2000 / ¥1 万…），页面却是 25 张各带进度条的卡，同一件事的进度重复画三遍 |
| 层级重 | 总览卡（三个统计 + 进度条 + 积分）+「全部 / 已点亮 / 未点亮」筛选 + 每类「已点亮 / 未点亮」分区头 |
| 下一步不明显 | 想知道「最快能点亮哪一枚」要在 25 张卡里自己找 |
| **定位缺陷** | 从「博物笔记」带 `focus=relics` 进来要滚到山海拾遗，但内容在 `scroll-view` 里，`wx.pageScrollTo` 滚不动 —— 定位从未生效 |

## 2. 新结构：馆志

1. **卷首**：眉标「ACHIEVEMENTS · 馆志」+ 宋体大标题 +「8 / 25 枚已点亮」大数字 + **每枚一格的刻度**（顺序 = 下面成长线的顺序）+ 一行累计积分；「分享 ›」只在有点亮时出现。
2. **下一枚**：离点亮最近的三枚（进度高者优先，全为 0 时门槛小者优先），每行：名称 / 百分比 / 细进度线 / 条件 / 还差多少。
3. **五章 × 成长线**：探索 / 收藏 / 社交 / 消费 / 学习五章；同一件事的分档收成一条线 ——
   铭牌节点（点亮 = 浅纸 + 铜圈 + 墨色罗马数字；未点亮 = 发丝空环），节点下是门槛标签（10 / 50 / 100、首单 / ¥500…、第一页 / 霜降…）；
   **通往下一枚的那段连线按进度部分填色**；行头一句「下一枚『探索家』· 还差 32 次」或「已全部点亮」。
4. **山海拾遗**：两列纸签（已偶遇 = 浅纸，未偶遇 = 虚线空签），常驻页底。
5. **详情 / 点亮弹层**：一枚纸面铭牌 + 条件 + 进度 / 奖励两栏行；主按钮「分享这枚徽章」。

筛选 Tab 退场（成长线本身同时表达已点亮与未点亮）。成长线分组只在前端（`TRACK_DEFS`）；云端将来新增未登记的徽章按 id 前缀自动成线，不会丢。

## 3. 顺手修的缺陷

`focus=relics` 定位：内容改回**页面滚动**（去掉 `scroll-view`，开启原生下拉刷新 `onPullDownRefresh`），`wx.pageScrollTo({ selector: '.relics-card' })` 才真正生效。

## 4. 守卫

`check:achievement-tracks`（home 域，170 → 171）：真跑页面 `_applyAchievementData` —— 云函数配置里每枚都进成长线且已登记、未登记的兜底成线不丢、连线按进度填、下一枚为最近三枚、刻度一枚一格、内容不在 scroll-view 且开了下拉刷新；7 个内存注入，不写盘。
离线预览场景 `achievements` 改为由真页面逻辑现算数据（不手抄）。

## 5. 真机验证点

- 五枚节点（山海图鉴线）在 320 宽屏是否放得下（固定格宽 128rpx × 5 = 640rpx）；
- 从「博物笔记」进来是否滚到山海拾遗；
- 下拉刷新与点亮弹层（新点亮时 500ms 后弹出）。
