## 1. 高风险口径（唯一真源）

| 层 | 位置 | 值 |
|---|---|---|
| 商品著录字段 | `products.protectionType` | `none` / `sanyou` / `protected_plant` / `protected_animal` |
| 云函数筛选 | `manageProducts` 的 `PROTECTED_TYPES` | `['sanyou','protected_plant','protected_animal']` |
| 客户端打标 | `managerPageConfig.js` 的 `PROTECTED_TYPE_LABELS` | 三有 / 保护植物 / 保护动物 |

### 1.1 中等风险（产品负责人 2026-10-13 追加）= **动物类**

| 口径 | 判定 |
|---|---|
| 中等风险 | **动物类藏品**，且**不含保护类**（`protectionType ∉ {sanyou, protected_plant, protected_animal}`） |
| 动物类信号（并集，两级） | ① 商品自己的 `taxonomy.kingdom` ∈ `{动物界, Animalia}`（落库时经 `toChineseTaxonomy` 归一）；② **所属分类**（`categoryId` / `rootCategoryId`）指向动物界分类 —— 兜底 taxonomy 为空的历史商品（云函数只读查 `categories.taxonomy.kingdom`）；③ `protectionType === 'protected_animal'`（保护动物必然动物） |
| 与高风险的关系 | **互斥**：保护类一律归高风险。否则同一件会同时落进两个「一键上下线」—— 计数重复、两次操作互相打架 |

> 互斥是**按「两个独立存在、方便分别操作」推定的口径**。若产品负责人的本意是「中等风险 ⊇ 所有动物（含保护动物）」，
> 改一处即可（`manageProducts` 的 medium 分支去掉 `_.nin(PROTECTED_TYPES)` 那半边），代价是两个入口的件数会重叠。

守卫 `check:product-lib-risk` A1 钉住**三方同源且都不含 `none`**（把 `none` 算成高风险 = 全库都成高风险，这是最容易犯的错）。
编辑表单里它叫「三有/保护物种」（原有字段，`protectionTypeValues` 四选一），保护类商品本来就强制上传收藏证书。

## 2. 一键上下线（新增能力）

- **位置**：藏品库 → 藏品明细 顶部新增**两条独立工具条**（仅非标本师视角），**各自**两个动作（下架 / 上架），互不影响：
  - 「**高风险 N 件** · 三有 / 保护类标本」—— 红底纹，下架键危险红实底 + 上架键金描边；
  - 「**中等风险 N 件** · 动物类标本（保护类已归入高风险）」—— 琥珀底纹，下架键琥珀实底 + 上架键金描边。
  - 进行中只压暗**正在跑的那一组**（`bulkRiskRunning` 记 `'high' | 'medium'`），另一组仍可点；某一条为 0 件时该条不出现。
- **作用域 = 全库该口径的筛选结果**，不是当前页：`_scanProductIds({ riskFilter: risk })`（`risk` 取 `high` / `medium`）分页扫描（每页 100、只认服务端 `total`、最多 50 页兜底）。
- **先确认再执行**：`openAppModal` 显示件数与方向后果（上架提醒合法来源与许可齐备；下架说明顾客不可见、数据不受影响）。
- **执行**：8 件一块并发调用 `manageApprovals.submitProductShelf`，`wx.showLoading` 报进度；结束后汇总
  「下架成功 N 件 · 待超管审核 N 件 · 失败 N 件」，并**静默刷新**（不弹遮罩、不回顶）。
- 标本师（非店长 / 超管）调「一键上架」时，服务端按既有规则**逐件生成上架审批单**（结果里单列「待超管审核」）——这是既有流程，未改。

### 稳定期报备

- 云函数 `manageProducts` 的 `list` action **新增两个可选参数** `riskFilter`（`all|high|**medium**|normal`）与 `shelfFilter`（`all|on|off|pending|rejected`）；
  `medium` 分支会**只读**查一次 `categories`（动物界分类 id，≤200 条；失败退化为只认商品 taxonomy）：
  **不传 = `all` = 与改前逐字一致**（既有调用方零影响）。已部署并复比一致。
- 未改任何写接口、集合结构、权限规则、审批状态机。`products` 集合的 `protectionType` 早就在 `ALLOWED_FIELDS` 白名单里。

## 3. 停留当前页（效率修复）

**病根**：`toggleShelf` / 编辑保存 / 搜索 / 切排序 / 切筛选 完成后都调无参 `loadProducts()` ——
它做三件伤效率的事：① `wx.showLoading('加载藏品…')` 全屏遮罩（像整页刷新）；② `productPage` 重置为 1（**已加载的第 2、3 页全丢**）；③ 列表整体替换（滚动位置随内容高度跳）。

**改法**：
- 抽出 `mapProductRow()`（利润 / 销量展示 / 水印 / 风险标记 / 工艺标签）与 `withThumbImages()`，成为**唯一一套**行派生；
  列表加载与「就地更新一行」都走它 —— 这样就地更新后的结果与重新加载**逐字段一致**（不会出现第三种口径）。
- 新增 `_patchProductRow(id, mutate)` / `_patchShelfRow(id, patch)`：只 `setData('products[i]')` 命中那一行；
  行不在当前列表时（新建 / 被筛掉）才退化为**静默重载**。
- `toggleShelf`：成功就地改 `isOffShelf` / `shelfApprovalStatus`；**失败也要换一次对象引用**把开关拨回真实状态
  （数据没变时 `setData` 同值不触发重渲染，这是开关类交互的经典坑）。
- 编辑保存：用编辑弹窗里的表单值就地合并那一行；新建才静默重载。
- `loadProducts({ silent: true })`：搜索（防抖 500ms）/ 切排序 / 在档·促销·上架态·风险筛选 / 清过期秒杀 / 一键上下线收尾 —— **一律不弹全屏遮罩**。

## 4. 筛选与分类优化

- **筛选条拆两行**，按「问题」分组而不是混在一起：
  - 第一行 = **上架态**：全部 / 在架 / 已下架 / 待审 / 已驳回 —— 后两颗**按需出现**（计数为 0 时不占位），并**带计数**；
  - 第二行 = **性质与活动**：在档 / 孤品 / **高风险** / 秒杀中 / 秒杀过期 / 拼团。
- 计数来自服务端 `shelfCounts`（与筛选条件**同一套优先级** on → pending → rejected → off，避免「筛选结果条数」与卡片计数打架）。
- 「全部」改走 `resetProductFilters()`：一次清空四个筛选维度（原来只清两类，残留条件会让人以为列表坏了）。
- 卡片新增警示标签：**高风险 · 三有 / 保护植物 / 保护动物**（排在标签行首位）。
### 分类管理（Tab 3）展示层优化

原有：一棵长树只有「一级名 + 二级名 + N 件」，分类一多就得一路往下翻，且**一级没有合计**、不知道哪个一级是空的。

现在：
- **检索**：一个输入框覆盖「一级中文名 / 一级英文名 / 二级中文名 / 二级英文名 / **拉丁名**」（防抖 200ms），并显示「匹配 N 个一级 · M 个二级」；
- **排序**：默认（服务端 sortOrder）/ **按合计数量降序** / **按名称**（`localeCompare(..., 'zh-Hans-CN')`，一级二级两层都排，避免两段顺序不一致）；
- **只看空分类 N**：一键筛出 0 件的二级分类（清理候选），chip 上带全库空分类数；
- **一级合计件数**「共 N 件」= 二级之和 + 直接挂一级上的（历史数据）；
- 被条件隐藏的二级会提示「另有 N 个二级被当前条件隐藏」，**不会让人以为分类丢了**；筛选后的空态文案与「暂无分类」区分开。

⚠️ **派生视图与源树严格分离**：页面 `data` 里新增 `catTreeView` 只作为渲染用，**绝不写回 `categoryManageTree`** ——
因为「新增二级分类」要按 `tree[newCatParentIndex]` 取所属一级、关联弹层按 `_id` 取，一旦把过滤后的树写回源，
下标就会错位（会把分类加到错误的一级下）。守卫 E1 同时钉住「派生不写回源」与「submitCategory 仍读源树」两条。

## 5. 水印可辨识度

原来：只有「已上架 / 审核中 / 已驳回」三种，**下架商品完全没有水印**；样式是 22rpx 斜字 + 半透明（`approved` 只有 `.55`），在 120rpx 实拍缩略图上几乎看不见。

现在：**左上实底角带**（不透明底 + 反色字 + 细描边 + 投影），四态齐全且配色分明：

| 态 | 文案 | 底色 |
|---|---|---|
| 在架 | 已上架 | 品牌金实底 |
| 下架 | **已下架**（新增） | 墨底浅字（与金色形成明确对立） |
| 待审 | 审核中 | 暖米实底 |
| 驳回 | 已驳回 | 警示红实底 |

判定优先级保持原样（`isOffShelf === false` → 已上架优先于审核态），只**追加**了「已下架」分支 —— 不改既有语义。

## 7. 真机核对点

1. 藏品库顶部出现「**高风险 N 件**」与「**中等风险 N 件**」**两条独立**工具条（各自为 0 时该条不出现）；分别点「一键下架」→ 确认框的标题与文案各带自己的口径与件数 → 执行时只有那一组变灰、另一组仍可点 → 完成后列表**停在原位置**，卡片出现「已下架」角标。
1b. 筛选条「高风险 N / 中等风险 N」两颗 chip 的口径与工具条件数一致；**同一件藏品不会同时出现在两个口径里**（保护动物只算高风险）。
2. 同一商品单独拨开关：**不再整页刷新、不回顶**、加载更多过的页数不丢；开关失败时会**自己弹回**原位。
3. 搜索框输入：列表刷新**没有全屏「加载藏品…」遮罩**，输入框不失焦、页面不跳。
4. 切排序 / 切筛选：同样无遮罩；「全部」点一下清空所有筛选。
5. 藏品卡封面：四态角标在实拍图上清晰可辨（尤其「已下架」在深色实拍上）。
6. 标本师视角（匠人端）：不出现高风险工具条与上下架开关（沿用 `artisanEmbed` 既有判定）。
7. 分类管理（Tab 3）：输入「蝶」→ 只剩含蝶的一级/二级并显示匹配计数；点「按数量」→ 一级与二级都按件数降序；点「只看空分类」→ 只剩 0 件的二级，chip 上的数字与之一致；「新增分类」里选「所属馆」→ 一级下拉仍是**完整**列表（不被筛选影响）。
8. 分类管理：一级行右侧显示「共 N 件」，与它下面二级件数之和一致；被筛选隐藏的二级有「另有 N 个被隐藏」提示。

## 6.6 视觉一致性返工（产品负责人 2026-10-13 真机截图）

真机截图指出「分类管理上方区域的交互与排版要视觉一致」。核对后确认是我上一轮引入的**语言混用**：

| 问题 | 原本 | 现在 |
|---|---|---|
| 检索框与筛选 chip 借了别的页的语言 | `.cat-search` 用 `rgba(38,35,32,.8)` 边（暗底上**几乎看不见**）+ 72rpx/26rpx；chips 直接复用「藏品明细」页的 `.pf-chip`（近黑边 + 22rpx） | 统一到**本页语言**：发丝金边 `rgba(196,167,108,.24)` + `rgba(196,167,108,.06)` 底 + 64rpx/24rpx / pill；选中 = 铜铸渐变（与分区页签同源） |
| 占位文字没样式 | `placeholder-class="ph"` 在本页**不存在** → 用默认灰 | 新增 `.cat-search-ph`（secondary 色 / 24rpx） |
| 两排 pill 分不出层级 | 页面页签（分段控件）与分区页签（pill 行）都是 pill，叠在一起重复 | 分区页签改**轻量分段控件**（`flex:1` 等分 / 22rpx，容器更轻）；且**只有多个分区时才渲染**（非超管单分区不再出现一整条金实底） |
| 「只看空分类」用红 | 红色在本页只表示「删除」这类危险动作，筛选用红会误读 | 与其它 chip 同语言（金）；数字用 `.cat-tool-count`（等宽、降一档） |
| 「清空」也是第四颗 pill | 四颗 pill 争主次 | 收成**文字链**（`.cat-tool-clear`） |
| 顺序：操作 → 说明 → 工具 | 阅读与操作交错 | **说明（读）→ 主操作（做）→ 工具条（找）→ 分区标题（`.form-section-label`）→ 分类树（看）** |

证据：`r10-lib-category`（筛选态）+ `r10-lib-category-default`（默认态 / 单分区）两张离线图；
`<switch>` / `picker` / `radio` 是原生组件、离线不画，真机核对点见 §7。
