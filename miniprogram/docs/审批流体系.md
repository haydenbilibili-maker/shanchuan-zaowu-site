# 审批流体系

## 模型

集合 `staff_approvals`：

| 字段 | 说明 |
|------|------|
| applicantOpenid / applicantRole / applicantWorkspaceRole | 申请人 |
| actionType | 见下表 |
| payload | 业务快照 |
| status | pending / approved / rejected |
| approverRole | store_manager \| super_admin（下一审） |
| finalApproverRole | 终审角色 |
| relatedId / relatedType | 关联业务单 |
| title / summary | 队列展示 |
| rejectReason / decidedBy / decidedAt | 结论 |
| createTimeMs / lastNudgeAtMs / nudgeCount | SLA 与催办 |

### 通用规则

1. 店员操作 → 店长审  
2. 店长操作 → 超管审  
3. 超管本人操作 → 直通（不自审）

### 特例

1. **积分族**（`pointsFamily`）终审**仅店长**，不上报超管；店长窗口内赠分/撤销直通  
2. **逾期积分撤销**：超窗口后店长改为提交 **超管** 审批  
3. **商品上架**店长 → 超管；下架直通；**新建商品默认下架**  
4. **敏感发货**：改运单 / 实付≥¥2000 / 孤品·镇店·唯一 → 超管审；普通首发直通  
5. **买家退款申请**走 `refundOrder.action=request`；执行退款店长→超管；Admin `adminOpsKey` 直通  
6. **运费 / 内容开关 / 门店装修**：仅超管直写（权限点已挡店长）  
7. **积分规则变更**：店长保存 → 超管审  

### SLA

- 默认 **48 小时**未审标记 `overdue`  
- 「我发起的」可催办（满 4h，间隔 12h）

## actionType 清单

| actionType | 审批人 | 轮次 |
|------------|--------|------|
| `points_store_grant` / `points_receipt_claim` / `points_platform_bind` | 店长 | 1 |
| `product_shelf_on` | 超管 | 1 |
| `order_refund` / `order_ship_sensitive` / `invoice_issue` / `booking_verify_reverse` | 超管（冲正按角色链） | 2 |
| `points_store_revoke` | 店长；逾期→超管 | 2 |
| `store_point_rules` | 超管 | **3** |

## 第 3 轮完成项

1. 积分规则变更审批（`store_point_rules`）  
2. 审批页「待我审批 / 我发起的」+ 催办 + SLA 高亮  
3. 封绕过：商品保存不再写 `isOffShelf`；新建默认下架（小程序 + Admin）；买家退款走云函数；Admin 单条上下架/执行退款走闸门  
4. 运费 / 内容开关 / 门店装修：权限点仅超管直写（店长触达会被拒）  
5. `scripts/sync-staff-guard.sh` 同步 `staffGuard` / `approvalRules` / `approvalBridge` 副本（跳过同源自拷）

```bash
./scripts/tcb-fn-deploy.exp getStorePointRules
./scripts/tcb-fn-deploy.exp refundOrder
# Admin: npm run build && npm run pages:deploy
```

`products`/`orders` 安全规则已用 API 落库为集合级仅云函数可写（`database-rules/` + `scripts/configure-products-orders-security-rules.cjs`）。字段级 `request.data` 在本环境静默不落库，详见 `docs/database-security-rules.md`。
