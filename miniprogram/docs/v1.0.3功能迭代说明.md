# 山海造物微信小程序 · v1.0.3 功能迭代说明

> 基线：上一正式版 **v1.0.2**（导航调整、门店积分基础说明、C 端开票入口、地址/票根等体验项；详见 `docs/v1.0.2审核说明.md`）  
> 版本号：上传体验版 / 提审时在微信公众平台填写 **1.0.3**（仓库无独立业务 version 字段；`project.config.json` 的 `libVersion` 为基础库，勿与业务版本混淆）  
> 用途：产品 / 运营可读的功能迭代说明；可摘录改写入「版本更新说明」  
> 关联仓库：小程序 `shanchuanspecimens`；Admin `shanchuanzaowu`  
> 生成日期：2026-09-05  
> **说明**：优惠券领取与核销能力延续 v1.0.1 / v1.0.2，本版不作为新功能宣传。

## 一、版本概述

v1.0.3 在 1.0.2 导航与开票入口基础上，重点补齐**会员成长体系（含 Lv6）**、**门店积分规则收紧与风控**、**生日礼券自动发放**，以及 **C 端开票 ↔ 店长 / Admin 开票台**、**多平台订单绑定审核**的闭环。同步收敛「我的」页重复入口，并修复物流轨迹、知识卡、鉴定结果页与若干稳定性问题。整体偏「规则可运营 + 审核可追溯」，而非大范围改版视觉。

## 二、C 端功能迭代

### 2.1 导航与个人中心入口整理

- **底部 Tab**（延续 1.0.2）：探索 / 馆藏 / **标本工坊**（居中）/ 购物车 / 我的；购物车等 Tab 图标沿用新套图标。
- **「这有店」**：不在 Tab，由「我的 → 这有店」进入（与 1.0.2 一致）。
- **「我的」菜单精简**：去掉与 Tab / 专员页重复的「标本工坊」「标本师招募」入口；标本师招募统一走「联系专员 → 标本师招募」。
- 馆藏服务区保留：地址管理、山海有信、图鉴、成就、养护、AI 鉴定、社区、联系专员、反馈、门店与品牌等（员工后台入口仅员工可见）。

### 2.2 开票（半自动）

- **申请路径**：登录后「我的 → 联系专员 → 发票开具」→ 开票申请页；选择已支付订单，填写个人/企业抬头与联系方式后提交。
- **处理方式**：申请落库 `invoice_requests`，由店长或 Admin 开票台人工开具后回传状态；**非即时自动开票**。用户可通过站内信获知开具 / 驳回结果。

### 2.3 多平台订单绑定（积分侧）

- 积分页在模块开启时可提交外部平台订单绑定申请（如抖音/抖店、淘宝/天猫、小红书、京东等，以页面配置为准）。
- 申请写入 `platform_order_binds`，经店长 / Admin 审核通过后按门店积分规则入账；驳回可见状态说明。

### 2.4 其它 C 端可见优化

- **商品知识卡**：分享文案精简（约 36 字内），减少溢出与冗长卖点。
- **AI 鉴定结果页**：关联操作按钮去重，避免卡片内外重复 CTA。
- **收货地址手动填写**：输入框显示与裁切继续对齐，姓名/手机/详细地址完整可见。
- **预约票根**：票务展示质感延续优化（纸纹 / 光泽等视觉细节）。

## 三、会员与积分

### 3.1 会员等级

| 项 | 说明 |
|----|------|
| 最高成长档 | 新增 **Lv6 星耀·博物官**（默认成长门槛 50000；藏品 8 折等权益以云库 / 页面为准） |
| 荣誉档 | 荣誉馆长仍为独立档位（非成长门槛递进） |
| 配置源 | 优先读云库 `member_levels`；缺档、占位名（如「等级6」「琥珀·博物官」）由代码默认补齐 / 映射为正式名 |
| 会员卡视觉 | 六档皮肤、标本元素 emoji、材质递进与微动效（Museum Mode） |
| 成长里程 | 「我的」会员卡区域展示距下一档缺口与权益差提示 |
| 商品折扣开关 | 商品可设 `memberDiscountEnabled`；关闭后该行不参与会员折扣（结算仍可叠优惠券等既有能力） |

### 3.2 门店积分规则（相对 1.0.2 文案变更）

| 项 | 1.0.2 口径 | **1.0.3 默认口径** |
|----|------------|-------------------|
| 门店消费赠分 | 满 ¥1 赠 1 分 | **每满 ¥10 赠 1 分**（例：消费 ¥1800 → 180 分） |
| 兑券说明 | 100 分 → ¥10 线上代金券 | 不变（具体档位以 `rewards` 上架为准） |
| 成长值 | 门店分不计入成长 | 不变 |

- 规则以云函数 + 集合 `store_point_rules` 为 SSOT；前端文案兜底与云端一致。
- **模块开关**：门店消费赠分、分享、评价、签到、浏览、外部订单绑定等可按模块启停（Admin / 店长规则页）。
- **积分兑换代金券**：兑换前增加二次确认（扣分即时、券进券包、提示有效期与门槛）。
- 门店消费仍只加 `bonusPoints`，**不计入会员成长值与等级**。

### 3.3 生日礼券

| 项 | 规则 |
|----|------|
| 触发 | 生日当天（Asia/Shanghai；2/29 非闰年按 2/28）；需登录且已填生日 |
| 积分 | **200 分**，`excludeGrowth=true`，**不计成长值** |
| 优惠券 | **¥100 × 3 张**，满 ¥300 可用；有效期至**生日本月最后一天** |
| 防重 | 同一自然年只发一次 |
| 体验 | 「我的」弹出生日卡；站内信「山海有信」生日快乐私信；可从生日卡进入券包 |

主路径：进入「我的」触发 `claimBirthdayGift`；辅路径：云函数定时批处理扫当日生日用户。

## 四、店长 / Admin

### 4.1 店员与店长（小程序）

- **现场赠分**：店员录入门店消费后进入 `pending_approval`，**须店长审核通过才入账**；店长 / 超管可直接入账。
- **门店积分台**：流水筛选、待审赠分、撤销（选原因）、规则查看；外部订单绑定待审列表。
- **发票管理**：店长后台「发票管理」处理 C 端开票申请（核对 → 线下开具 → 标记已开 / 驳回）。
- 权限依赖 `MESSAGE_ADMIN_OPENIDS` / `staff_members` 等配置；普通用户不可见。

### 4.2 Admin（`shanchuanzaowu`）

- **发版对齐**：会员等级、门店积分规则等与小程序云库同源，避免双端口径漂移。
- **开票申请台**：处理 `invoice_requests`（与店长端同一业务集合）。
- **订单绑定审核台**：审核 `platform_order_binds`。
- **门店积分规则**：读写 `store_point_rules`（默认每满 ¥10 赠 1 分；含模块开关）；勿再依赖已废弃的旧 `points_rules` 口径。
- **会员等级配置**：可维护 `member_levels`；缺 Lv6 时保存后与小程序默认档对齐。

### 4.3 物流履约

- **占位单号拦截**：形如全相同数字等测试/占位运单号不再请求微信轨迹接口，前端明确提示需填真实运单号。
- **轨迹补同步**：真实单号在订单详情侧可触发补同步；避免失败状态被永久锁死导致无法重试。

## 五、体验与稳定性修复

- 分包 **preload** 规则调整（首页 / 馆藏 / 购物车预加载 `feature`；门店 / 我的预加载 `business`），降低预加载相关异常（如 **80058**）引发的白屏 / 黑屏风险。
- 启动与云能力基础库提示、云健康检查等稳定性链路延续加固（工具链参考 `libVersion` 3.11.2；业务最低基础库以公众平台设置为准）。
- 鉴定同图重复识别提示、知识卡生成失败提示等边界体验完善。
- 优惠券包与结算选用为既有能力，本版仅生日礼券与积分兑券确认流程有新增触达点。

## 六、配置 / 运维注意（简短）

1. **提审版本号**：公众平台填写 **1.0.3**；同步上传对应体验版代码包。  
2. **积分规则升级**：若云库 `store_point_rules` 仍为旧文档（如 ¥1=1），会覆盖代码 v3 默认；须在 Admin「门店积分规则」或店长规则页改为 **threshold=10 / pointsPerThreshold=1**，或停用旧文档。  
3. **必配环境变量**：涉及店员/店长能力的云函数需配置 `MESSAGE_ADMIN_OPENIDS`（详见 `docs/门店积分上线操作清单.md`）；未配置可能导致后台入口或赠分接口拒绝。  
4. **新云函数 / 集合**：确认已部署 `claimBirthdayGift`、`bindPlatformOrder`、`submitInvoiceRequest`、`manageInvoiceRequests`、`exchangeCoupon`、`grantStorePoints`、`getStorePointRules` 等；集合含 `platform_order_binds`、`invoice_requests`、`store_point_rules`、`member_levels`，及相应幂等索引。  
5. **兑券商品**：运营在 `rewards` 配置至少一档 `type=coupon`、成本 100 分、面值 ¥10，与对外文案一致。  
6. **生日礼券**：确认 `claimBirthdayGift` 已部署且定时触发器生效；测试时注意清本年防重字段后再验。  
7. **开票**：一期半自动，需有人值守开票台；审核说明中勿写「自动开具电子发票」。  
8. **优惠券**：勿在版本说明中宣称「全新上线优惠券」——主链路为 1.0.1/1.0.2 既有能力。
