# 博物君 · 山海造物标本馆的 AI 馆员 —— 蓝图（2026-11-23）

> 产品负责人点名：「在『我的 · 馆藏与内容』新增功能模块『博物君』，定位是山海造物标本博物馆的 AI Agent，全面了解山海造物的品牌，身负自然博物情怀和动物植物科学百科知识，全面规划这个功能并开始实现。」

## 1. 定位

博物君是馆里一位**会说话的馆员**：

- **懂品牌**：山海造物是谁、在做什么（标本与自然博物）、品牌语（把山海带回家 / Bring Nature Home）、1% 承诺与山海造物公益基金、馆里的各项功能（山海图鉴 / 我的成就 / AI 标本鉴定 / 标本养护 / 预约参观 / 心愿签 / 礼赠）。
- **懂自然史**：动物、植物、昆虫、矿物与化石的科普与分类学常识；会讲物种的形态、习性、分布、保护现状，带一点博物学的温度。
- **守边界**：不编造馆方没公布的事实（门店地址、价格、库存、活动、捐赠对象）→ 指向对应页面；不做医疗 / 法律 / 投资建议；涉及野生动植物买卖时提醒合法来源与保护法规；只聊与自然、标本、品牌相关的话题，其它话题礼貌拉回。

不是客服替代品：订单、退款、物流等**个人业务**一律指向「山海有信」「我的订单」与人工客服，博物君不查也不改任何业务数据。

## 2. 用户旅程（一期）

1. 「我的 → 馆藏与内容」宫格新增「博物君」（角标 `AI`）。
2. 进入后：卷首（眉标 `MUSEUM GUIDE · 博物君` + 一句自我介绍）→ 欢迎语 → 五个开场问题。
3. 提问 → 「博物君正在翻书…」→ 回答（纸面气泡）+ 最多 3 个追问 + 最多 2 个**站内去处**（白名单：山海图鉴 / AI 鉴定 / 标本养护 / 预约参观 / 我的捐赠 / 我的成就 / 馆藏）。
4. 底部输入条：今日剩余次数、发送；页脚：AI 生成，仅供参考。
5. 对话只存在**本机**（最近 40 条），可「清空对话」。

## 3. 架构

| 层 | 内容 |
|---|---|
| 小程序页 | `subpackages/feature/museum-guide/index`（feature 分包，主包只加一个宫格入口） |
| 纯函数 | `subpackages/feature/museum-guide/guideChat.js`：历史裁剪、请求组装、回复解析、去处白名单、错误文案 |
| 云函数 | `askMuseumGuide`：入参校验 → 输入内容安全（msgSecCheck）→ 每日额度 → 大模型（百炼 DashScope，与 AI 鉴定同一密钥）→ 输出内容安全 → 出参 |
| 知识 | `askMuseumGuide/knowledge.js`：品牌事实（口径与「我的捐赠」页同源）+ 馆内功能地图 + 山海图鉴 80 种（中名 / 学名 / 章节，由 `manageAtlas/catalog.js` 生成，守卫比对不漂移） |
| 人设 | `askMuseumGuide/persona.js`：系统提示（人设 / 边界 / 输出 JSON 格式） |
| 集合 | `museum_guide_usage`：只记「谁哪天问了几次」（`_id = openid_YYYYMMDD`），**不存对话内容**；仅云函数可读写 |

### 云函数出入参

入参 `{ question: string(1–300), history: [{ role: 'user'|'assistant', content }] (≤ 6 条，每条 ≤ 600 字) }`

出参：
- 成功 `{ success: true, answer, followUps: string[≤3], actions: string[≤2], quota: { left, cap } }`
- 失败 `{ success: false, error_type, msg, quota? }`，`error_type ∈ invalid | risky | quota | ai_service`

### 额度与成本

- 每人每天 30 问（云函数环境变量 `MUSEUM_GUIDE_DAILY_LIMIT` 可改）；按北京时间切日。
- 模型链 `qwen-plus → qwen-flash`（环境变量 `MUSEUM_GUIDE_MODELS` 可覆盖，逗号分隔，排在默认前）。
- 每次只带最近 6 条历史，回答约束在 300 字以内。

### 安全与隐私

- 问题先过 `msgSecCheck`：risky → 拒答；检测服务报错 → 拒答（不 fail-open，与全站口径一致）。
- 回答再过一次 `msgSecCheck`：risky → 换成固定的安全回复。
- 服务端**不落对话内容**，只记次数；本机历史可一键清空。
- 密钥只从云函数环境变量 `DASHSCOPE_API_KEY` 读；未配置时出参 `ai_service`，页面提示「博物君暂时不在馆里」。

## 6. 超管工作台「博物君」：开关 / 每日额度 / 使用监测（2026-11-23，产品负责人点名）

**入口**：超管工作台「系统监测」分区磁贴「博物君 · 开关·监测」（菜单键 `museumGuideMonitor`，只在超管菜单）；页面 `subpackages/manager/museum-guide-monitor/`（超管分包）；页内 `guardStaffPage('super_admin')`，云函数 `museumGuideMonitor` 再判 `requireSuperAdmin`。

**开关**：开馆 / 闭馆，**两步确认**（第一下只亮出「再点一次确认」，3 秒内再点才改；不弹原生框）。闭馆后：
- 「我的」宫格入口隐藏（`getContentDisplayFlags` 只读带出 `museumGuideOpen`，小程序端缺省开启）；
- 博物君页进页即显示「闭馆整理中」，开场问题与输入条收起，本机旧对话仍可回看；
- 云函数 `askMuseumGuide` 对提问返回 `error_type: 'off'`（不过内容安全、不调模型、不计次）。

**开关为什么不放进「内容开关」**：内容开关由 ERP 与店长端整份保存，保存方若不认识新字段会把它重置为默认（开启）——同类事故在 `getContentDisplayFlags` 注释里记过两次。所以开关存在博物君自己的配置（`museum_guide_config/main`），**唯一写入方是本页**；内容开关只在读取时带出 `museumGuideOpen`，它的保存不写这个值。字段刻意不叫 `showXxx`（不属于 `check:hook-registration` 管的展示开关一族），端到端由 `test:museum-guide-monitor` M5 钉住。

**每日额度**：10 / 20 / 30 / 50 / 100 问（云函数只认 5–200 的整数）；未设置时用云函数环境变量 `MUSEUM_GUIDE_DAILY_LIMIT`，再缺省 30。

**监测**（近 7 / 30 天，北京时间按日）：今日提问 / 今日人数 / 成功率（分母只算问到模型那一步的：不含额度满、闭馆、入参不合法）/ 平均耗时 / 九成不超过 / 单人今日最多（接近额度 → 额度偏紧或有人刷，**不出身份**）；按日条形；没答上的原因；大家在问的图鉴物种；博物君推荐的去处；从哪里进来提问；实际回答的模型。没有数据写「—」，不编 0。

**数据**：`askMuseumGuide` 每次提问写一条 `museum_guide_logs`（字段白名单 `buildLog`：状态 / 耗时 / 模型 / 命中物种 / 去处 / 问题与回答字数 / 历史条数 / 入口，**没有问答原文**；1.5 秒上限、写失败不影响回答；`status` 动作不写）。页面会把入口来源（我的 / 图鉴页 / AI 鉴定结果 / 分享）随提问带上。

**审计**：改开关与额度先写 `admin_operation_logs`（`module: 'config'`, `action: 'museum_guide_config'`, 带改前值与改动），审计写失败即拒绝、不写配置。

**新集合**（三处同步 + `serverOnly`）：`museum_guide_logs`、`museum_guide_config`。

**上线步骤（追加）**：部署 `museumGuideMonitor`、重新部署 `askMuseumGuide` 与 `getContentDisplayFlags`；控制台建集合 `museum_guide_logs`、`museum_guide_config`（均仅云函数读写）。不建 `museum_guide_config` 也能用（读不到 = 开馆 + 默认额度），第一次在工作台改设置时会自动写入。


## 7. 回答反馈与满意度（2026-11-23）

- 超管「博物君」报表加一行「满意度 x%（有帮助 a · 没帮助 b）」：只算已回答的票；没人投票写「—」。票数少时满意度不稳，所以票数一起写出来。

## 11. 修：回答气泡露出 follow_ups / actions 字段行（2026-11-23，产品负责人真机截图）

- **现象**：回答正文下面原样出现 `follow_ups: ["…", "…"]` 与 `actions: ["atlas", "identify"]`，「接着问」与去处按钮没出来；同一段里还夹了英文单词（selectively）。
- **根因**：模型偶尔不按「只输出 JSON」回，而是正文 + 另起几行写字段；`parseReply` 对非 JSON 一律整段当回答。
- **修**：
  1. 云函数 `salvageFields`：非 JSON 时摘掉正文里的字段行（follow_ups / followUps / 追问 / actions / 去处，引号与全半角冒号都认，数组可跨行），条目捞回，去处仍过白名单；
  2. 页面兜底 `guideChat.stripFieldLines / salvagedFields`：旧版云函数的回答与本机旧记录也清掉字段行，追问 / 去处还原成按钮；
  3. 提示词：除拉丁学名外不要夹带英文单词。
