# 全站图片质感 · 多轮施工（2026-11-23 起）

> 产品负责人：「图片是整个小程序非常重要的一个要素，它的展示决定了小程序整体的质感，接下来进行一个多轮优化，主要解决全局图片展示，样式，交互，清晰度等问题。」

## 0. 取证（第 1 轮开工前，源码实扫）

| 项 | 数 | 说明 |
|---|---|---|
| 全部 `<image>` | 416 | 含图标、静态资源 |
| 远程图（src 绑定数据） | ≈200 | |
| 远程图**没有 binderror** | 163 | 加载失败 = 空洞或系统破图 |
| 列表里的远程图没懒加载 | 47 | 首屏之外也一起下载 |
| 没写 mode（默认拉伸变形） | 1 | 基本没有变形问题 |
| 用了 `utils/imageUrl` 缩略图链路的 JS 文件 | 21–23 | 其余远程图直接加载原图（清晰度够、但大，首屏慢） |

**加载中**：多数图片外框底色 = 页面底（#1A1814），图没到时是一块看不出来的空洞，到了「啪」地跳出来。
**全局占位样式疑似从未生效**：`app.wxss` 的 `image[lazy-load] {…}`、`image[error] {…}` 用的是**属性选择器**，WXSS 官方支持的选择器里没有属性选择器 → 真机上大概率整段不生效。静态分析 ≠ 事实：列为**真机核对项**，确认后再删或替换（本轮不动）。
**缩略图链路本身是好的**（`utils/imageUrl.js`，稳定期共享件，**不改**）：按设备物理像素算宽度（详情大图 `clamp(窗口宽 × DPR, 750, 1600)`）、quality 90、不支持时整会话回落原图。问题在于**很多页面没接它**。

## 1. 方案：一个组件统一「加载中 / 加载完 / 失败」

`components/ShanImage`（`<shan-img>`，主包，约 2 KB）：
- 加载中：暖深底 `#24211D`（比页面亮一档）+ 淡「山海」方印；
- 加载完：0.32 s 淡入；系统开「减少动态效果」时直接出；
- 失败：不出破图（收起 `<image>`，留底与方印），并调用 `imageUrl.onImageError()`（与各页原 binderror 同一调用）；
- 换图（同一实例 src 变）：回到加载中；
- 用法同 `<image>`：尺寸 / 圆角 / 滤镜写在页面 class 上，`ext-class` 落到外框；`load / error` 事件透传；
- 只用于**定框**模式（aspectFill / aspectFit 等）；`widthFix / heightFix` 仍用原生 `<image>`（守卫 I3 拦）。
- **每个用到的页面 / 组件 json 要本地声明**（`lazyCodeLoading: requiredComponents` 下全局声明不保证注入 —— `check:asset-refs` 第 1 轮当场拦下）。
