## 2. 社保扣缴标准（数据驱动）

真源：`miniprogram/cloudfunctions/manageStaffWorkspace/socialInsurance.js`（ERP 副本 `admin/src/utils/socialInsurance.js`，ESM，守卫逐项比对）。
标准 `si-2026-09`：来源 2026-09-03 三方协议缴费记录（两人合计），均摊人数 2。

| 品目 | 合计·个人 | 合计·单位 | 每人·从工资扣 | 每人·公司缴纳 | 所属期 |
|---|---:|---:|---:|---:|---|
| 养老保险 | 702.92 | 1054.36 | 351.46 | 527.18 | 缴费当月（2026-09） |
| 医疗保险 | 175.72 | 676.56 | 87.86 | 338.28 | 缴费次月（2026-10） |
| 大额医疗互助 | 200.00 | — | 100.00（全年一次） | — | 全年 |
| 失业保险 | 26.36 | 61.50 | 13.18 | 30.75 | 缴费当月 |
| 工伤保险 | 0（个人不扣） | 28.12 | 0 | 14.06 | 缴费当月 |
| **每人合计** | | | **月度 452.50；含全年一次 552.50** | **910.27** | |

复核：个人 702.92 + 175.72 + 200 + 26.36 = 1105.00 ÷ 2 = 552.50；单位 1054.36 + 676.56 + 61.50 + 28.12 = 1820.54 ÷ 2 = 910.27。

规则：每人金额 = 合计 ÷ 均摊人数（按分取整）；工伤必须标「仅公司缴纳」、个人部分必须为 0（标准自检拦截）；
公司缴纳只存进工资条快照做展示，不进扣款、不影响实发；大额医疗互助同一年度只扣一次（再扣会被拒）。
**调整金额 / 人数 / 新年度**：在 `SI_STANDARDS` 追加一条（`effectiveFrom` 递增），不要改已用过的条目；ERP 副本同步改，守卫会比对。

## 3. 改了什么

- **云函数 `manageStaffWorkspace`**（新增旁路，旧入参结果逐字不变）：
  - `payslipUpsert` 可选入参 `socialInsurance: { standardId, paidMonth?, includeAnnual? }`：
    保存社保快照 `socialInsurance`（个人 / 公司分项、所属期、合计）、`otherDeduction`（其他扣款），
    `deduction = 其他扣款 + 个人社保`，`net = 应发 − deduction`；不传则与改造前完全一致。
  - 新 action `payslipSiPreview`（仅超管）：返回默认标准、默认缴费月（工资月上一月）和预览快照，与保存时同算法。
- **小程序 超管「工资维护」**：编辑弹层新增「套用社保扣缴标准」开关、社保缴费月、「含大额医疗互助（全年一次）」开关，
  实时预览个人扣款逐项、个人合计、公司缴纳合计（写明不扣工资）、预计实发；套用时「扣款」栏改叫「其他扣款（考勤等，不含社保）」。
  编辑旧工资条时提示「原扣款可能已含社保，避免重复扣」。
- **小程序「工资条明细」**：有快照的工资条在扣款区逐项列出 养老 / 医疗 / 大额医疗互助 / 失业（带所属期），
  另起一张「公司为你缴纳（不从工资里扣）」卡片，注明「工伤保险按政策由公司全额缴纳，个人不扣」「按缴费记录 2 人合计 ÷ 2 计入本人」。
  没有快照的旧工资条照原样显示。
- **ERP 员工薪酬管理**：「全局配置」新增社保扣缴标准表 + 「参保员工」多选；生成 / 重算薪酬时参保员工按同一标准扣个人社保
  （实发 = 应发 − 个人社保），薪酬明细与导出新增「社保个人扣」「公司缴纳(不扣)」两列。ERP 这边仍是本地数据，不会写到员工的小程序工资条。
- **守卫** `npm run test:payslip-social-insurance`（manager 域，79 项；`--selftest` 16 个内存注入）。
