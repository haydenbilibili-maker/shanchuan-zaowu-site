## 一、项目概览

### 1.1 项目类型

- **类型**：微信小程序（含云开发）
- **技术栈**：小程序原生（WXML/WXSS/JS）、云函数、自定义 TabBar、分包
- **仓库**：miniprogram-2（WeChatProjects）

### 1.2 功能域概览

| 域         | 说明 |
|------------|------|
| 首页/配置  | 首页、首页配置、推荐、热门搜索 |
| 内容       | 文章、视频、社区、百科/详情、评论 |
| 预约/预订  | 预约、我的预约、预约提醒、候补 |
| 电商/订单  | 分类、购物车、订单、订单详情、优惠券、秒杀、拼团 |
| 用户/成长  | 个人中心、成就、消息、证书、收藏 |
| 营销/运营  | 分享卡片、积分、优惠券领取/转赠、行为追踪 |
| 其他       | 搜索、AR、关于、证书、画框等（部分在分包） |

### 2.6 文件夹整理建议

- **去重与统一**：合并或明确区分 `detail/wiki-detail` 与 `detail/detail/wiki-detail`、`user/achievements` 与 `user/user/achievements`、主包与分包的 certificate，避免重复页面与路由混淆。

- **文档同步**：新增/删除页面或云函数时，同步更新 app.json 与本文档「文件夹结构」和「开发现状」。

## 三、开发现状梳理

### 3.1 已具备能力

- 主包页面较完整：首页、文章/视频/社区、预约、购物车/订单/优惠券、秒杀/拼团、用户中心/成就/消息等。
- 云函数覆盖：登录、预约、内容与评论、收藏、优惠券与订单、拼团、行为追踪、分享卡片、错误日志等。
- 自定义 TabBar、分包（business）已存在，利于首包体积控制。
- 有 Calendar、CommentList 等可复用组件。
- 有 PRD 与 BUG 复盘文档，便于规划与排错。

### 3.2 需关注的问题

1. **路径与页面重复**
   - `detail/wiki-detail` 与 `detail/detail/wiki-detail` 并存，易混淆且不利于维护，建议统一为单一路径并在 app.json 中只配置一处。
   - `user/achievements` 与 `user/user/achievements`、主包 `certificate` 与分包 `business/certificate` 等，需确认是同一功能多入口还是不同功能，并统一命名与路由。

2. **样式与资源**
   - 存在「样式文件重写」相关 BUG 复盘，建议：样式改动前确认作用域（页面/组件/全局），避免全局样式误覆盖；重要改动前备份或小步提交。
   - 有 icon 优化清单，可按清单逐步替换为统一风格的图标资源。

3. **文档与配置**
   - 云函数数量较多（约 40+），建议为每个云函数保留简短说明（如 README 或 config 内注释），并统一命名与目录规范。
   - 分包的具体 root 与 pages 列表以 app.json 为准，建议在本文档或单独「分包说明」中维护一份与 app.json 一致的清单。

4. **代码与质量**
   - 部分页面/云函数为未跟踪（??）或已修改（M）状态，上线前需做回归与必要的单元/集成测试。
   - 建议对核心链路（如登录、下单、预约、支付）做错误监控与日志（可结合现有 logError 云函数）。

## 四、后续开发优化计划

### 4.1 短期（优先）

1. **路径与结构**
   - 统一百科详情页路径（只保留一个 wiki-detail 路径），并更新所有跳转与 app.json。
   - 明确 user/achievements 与 user/user/achievements、主包与分包 certificate 的职责，合并或区分后更新文档与路由。

2. **样式与 BUG**
   - 按《BUG复盘-样式文件重写问题》落实规范：避免全局样式污染、组件样式隔离、关键改动前检查影响范围。
   - 按《icon优化清单》完成图标替换与命名统一。

3. **配置与文档**
   - 核对 app.json 中 pages、subpackages、tabBar 与当前目录一致，并更新本文档「文件夹结构」一节。
   - 为 cloudfunctions 补充简要说明（用途、入参、权限），便于协作与排查。

### 4.2 中期（按 PRD 排期）

1. **功能**
   - 严格按 `PRD_二期优化.md` 逐项开发与验收。
   - 将 `PRD_三期规划.md` 拆解为可执行任务与迭代，并标注依赖关系与优先级。

2. **体验与性能**
   - 分包与主包体积监控，必要时将更多页面/静态资源迁入分包。
   - 首屏与关键接口耗时监控，对慢接口做优化或缓存策略。

3. **稳定性**
   - 核心云函数增加入参校验与错误码规范，前端统一错误提示与降级。
   - 利用现有 logError 或扩展日志，对支付、下单、预约等关键操作做追踪与告警。

### 4.3 长期（持续）

1. **架构**
   - 公共逻辑（请求封装、登录态、错误处理）抽离为统一模块或 mixin，减少页面重复代码。
   - 组件化：将重复的列表、表单、空状态等抽象为组件，便于复用与 UI 统一。

2. **质量与规范**
   - 制定并遵守命名规范（页面、组件、云函数、样式类名）。
   - 关键流程补充自动化测试或关键路径用例，避免回归。

3. **文档与协作**
   - 本文档随目录与 app.json 变更及时更新。
   - 每个迭代结束后同步更新「开发现状」与「后续计划」，便于复盘与排期。
