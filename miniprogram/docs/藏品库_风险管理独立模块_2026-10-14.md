## 1. 核查结论：**旧口径（动物界）下 216 属实**（附量具可信性证明）

> ⚠️ 本节记录的是**第一轮核查时**的口径（动物界）与数字。产品负责人当天第二轮把口径收窄为「动物馆」后，
> 现行数字是 **11 / 43 / 201** —— 见 **§1.5**。本节保留，是为了留住「216 是怎么来的、为什么它不是 bug」这段证据。

### 1.1 两把量具，两侧逐项一致

| 量具 | 做法 | 结果 |
|---|---|---|
| 只读探针（`@cloudbase/node-sdk`，与云函数同一个 SDK） | 直接分页读 `products` + `categories`，在本地按云函数的表达式重算 | `high 11 / medium 216 / normal 28`，相加 `255 == 全库 255` |
| **部署后直接 invoke 线上云函数**（`riskOverview`，走 `ADMIN_OPS_KEY` 运维鉴权分支） | `manager-node` 的 `functions.invokeFunction('manageProducts', {action:'riskOverview'})` | 回包与探针**逐项相同** |

### 1.3 那 15 件"只靠分类兜底"的，是过宽吗

不宽。逐件看过之后，它们分两类：

| 类型 | 样本 | 判断 |
|---|---|---|
| 真动物（只是 `taxonomy.kingdom` 忘了填） | 巨扁竹节虫、双叉犀金龟幼虫、贵妇鸽、鬃狮蜥标本、蜜袋鼬、西瓜招潮蟹、侏儒兔标本、日本拟人面蟹、蝎子螺 | **必须纳入** —— 没有分类兜底这 9 件会漏掉 |
| 动物源文创 / 标本框 | 玫瑰俏眼蝶闹钟、海洋小集·贝壳相框、贝壳杯垫、银光螺酒杯、植物与蝴蝶组合相框、自然小集·植物与蝴蝶组合框 | **建议纳入** —— 蝶翅画用真蝶翅、相框内是真标本，恰恰是"三有/保护物种"规则最该巡查的对象 |

结论：**不动口径**。上一轮定的"动物类 = 学名 ∪ 所属分类"是对的，收窄反而会把最该巡查的动物源文创放走。
真正需要人工判定的是极少数**不含动物实体**的（如"巴普洛夫菊石装饰框"是化石、"石英与水晶"1 件疑似分类错位），已在 §1.4 单列。

## 1.5 口径收窄（产品负责人第二轮指令）：动物界 → **动物馆**

> 「中等风险藏品**仅限于分类中为动物馆**中的藏品，而非动物界；缩小覆盖面」

改动本体只有一句：判据从「`taxonomy.kingdom ∈ 动物界` ∨ 所属分类指向**任一**动物界分类」
改成「所属分类 ∈ **动物馆子树**」，并且**不再读 `taxonomy.kingdom`**。

| | 旧（动物界） | 现行（动物馆） |
|---|---|---|
| 高风险 | 11 | **11**（不变） |
| **中等风险** | 216 | **43** |
| 普通 | 28 | **201** |
| 相加 = 全库 | 255 ✓ | 255 ✓ |
| 中等风险 在架 / 已下架 | 204 / 12 | **37 / 6** |
| 中等风险 构成 | 学名属动物界 201 · 按分类兜底 15 | **爬行纲 20 · 哺乳纲 12 · 鸟纲 7 · 两栖纲 2 · 辐鳍鱼纲 1 · 头足类 1** |
| 中等风险 缺收藏证书 | 216 | **43** |

**缩掉的 173 件按一级分类**：昆虫馆 121 · 海洋馆 28 · 首饰馆 18 · 矿石馆 3 · 衍生品 2 · 植物馆 1。
典型样本（这些现在都归「普通」）：大蓝闪蝶标本框、巨扁竹节虫、日本拟人面蟹、水母浸液标本、
大蓝闪蝶项链/手链、蝶翅画、贝壳相框、巴普洛夫菊石装饰框。

两点必须记下来的后果（不是 bug，是这次选择的语义）：

1. **昆虫馆 / 海洋馆的无脊椎动物不再算中等风险**（蝴蝶、甲虫、蟹虾、贝壳、水母…）。
   如果后续想覆盖它们，应当**另开一层**（例如「无脊椎动物」），**不要**把动物界口径偷偷加回来 ——
   那会让覆盖面一次性跳回 216，且与「仅限动物馆」这句话自相矛盾。
2. **服务端不再因为查不到分类而退化放大**：`loadAnimalHallCategoryIds()` 返回空时，
   `where` 会追加一个**命中零条的哨兵条件**（中等风险这一层为空），而不是「不追加条件」
   （那等于全库都算中等风险）。宁可这一层暂时是 0（概览上能看出异常），也不能把范围偷偷放大。

## 2. 为什么把风险能力**移出**「藏品明细」

| | 之前 | 现在 |
|---|---|---|
| 位置 | 「藏品明细」搜索框**上方**两条大色块（红 + 琥珀），每次进藏品库先看到它们 | 独立的第 2 个顶部 tab「**风险管理**」 |
| 明细页职责 | 既要"找一件藏品改它"，又要承担合规巡查的入口 | 只放**找藏品**要用的（清过期秒杀 / 搜索 / 排序 / 上架态 / 在档·孤品·促销） |
| 风险筛选 | 「高风险 N / 中等风险 N」两颗 chip 长在明细的筛选行里 | 迁到风险管理页的「按风险分层」一行（4 颗：全部 / 高风险 / 中等风险 / 普通） |
| 计数来源 | 进藏品库时各打一次 `count()`（2 次云函数往返） | `riskOverview` 一次调用给全部；明细页不再打这两次 |
| 口径漂移风险 | 工具条、chip、明细列表**三处**各有一套风险口径 | 一个能力一个入口；页面上的数**全部**来自服务端回包，客户端一个数都不重算 |

守卫 `check:product-lib-risk` 的 A9 直接钉住这件事：**「藏品明细」块内不许再出现 `bulkToggleRisk` / `setProductRiskFilter`**（抽走了还留着 = 两处计数迟早打架）。

## 3. 口径定稿（**现行**；一处修正）

三层 **互斥 + 穷尽**，相加 = 全库：

```
高风险   = protectionType ∈ {sanyou, protected_plant, protected_animal}
中等风险 = (categoryId ∈ 动物馆子树  ∨  rootCategoryId ∈ 动物馆子树)   ← 2026-10-14 收窄：只认分类
            ∧ protectionType ∉ 保护类
普通     = 既不是高风险也不是中等风险
```

- **「动物馆」子树 = 一级 `动物馆` + 它的 6 个二级**（哺乳纲 / 爬行纲 / 鸟纲 / 两栖纲 / 辐鳍鱼纲 / 头足类）。
  分类 id **每次现查不写死**（`loadAnimalHallCategoryIds()` 先按名字取一级、再取 `parentId` 指向它的二级），改分类树不用改代码。
- **不再读 `taxonomy.kingdom`**：学名属于哪一界不参与「算不算中等风险」的判定（见 §1.5）。

**修正（`riskFilter='normal'`）**：原实现是「`protectionType === 'none'` 或缺失」= **244 件**，而中等风险那批里绝大多数的 `protectionType` 恰好就是 `none` —— 于是「普通」把中等风险**又包了一遍**，三层相加 ≠ 全库 255。分层计数加不回总数，产品负责人一眼就会问。现改为**真补集**：`_.nin(PROTECTED_TYPES)` ∧ 分类 `_.nin(动物馆子树)`。

> `riskFilter='normal'` 在改前**没有任何界面在用**（明细页只放了高风险 / 中等风险两颗 chip），所以这处修正不影响任何既有交互；它只影响本轮「普通」分层 chip。

## 6. 模块有哪些能力（产品负责人第 3 问）

1. **分层概览**（一次调用）：全库 / 风险藏品 / 普通三颗数字 + 每层一张条（等级 · 件数 · 凭什么算 · 在架与已下架）。
2. **保护类细分**：三有 / 保护植物 / 保护动物（当前 0 / 1 / 10）。
3. **中等风险构成**：动物馆下二级分类的件数（当前 爬行纲 20 · 哺乳纲 12 · 鸟纲 7 · 两栖纲 2 · 辐鳍鱼纲 1 · 头足类 1）——
   口径收窄成「只看分类」之后，「凭什么算」已经不言自明，更有信息量的是**这一层由什么构成**
   （原来的「命中原因」会恒等于一个值，成了废字段，已换成构成）。
4. **合规提醒（分两档，只报真数）**：先问「保护类缺不缺证书」，缺了才是真警报；不缺才退成静默提示。
   线上实测：**高风险 11 件一件不缺**，其余 **244** 件为空（中等风险 43 · 普通 201）。
   > 早先我按"字段全为空"写成 255/255 —— 直接 invoke 线上云函数才发现 11 件保护类是有证书的。**分档是为了不把做到位的部分也说成没做。**
5. **两条独立一键上下线**（口径、确认框、进度、全量作用域与改前逐字相同，只换了页）。
6. **按风险分层筛选**：全部 / 高风险 / 中等风险 / 普通（4 颗，数字取自服务端）。
7. **按上架态筛选**：计数**随所选分层变**（选"高风险"显示 0 / 11，不是全库 231 / 24）。
8. **逐件命中原因**：清单每行标出风险等级 + 命中原因 + 分类。
9. **复制风险清单**：把**当前筛选的全量**（不是"已加载的那 50 件"）整理成纯文本进剪贴板 —— 提审 / 平台问询时给法务或平台，手机上一页页截图没法用。含件数、口径说明、导出时间、逐件的分类 / 风险等级 / 命中原因 / 上下架态。
