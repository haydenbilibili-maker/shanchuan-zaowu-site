# AI 能力与审核口径（2026-11-26）

> 背景：小程序连续被拒，理由为「提供文本深度合成技术（如 AI 问答），请补充选择 深度合成-AI问答 类目，
> 并在 AI 生成页面增加显著说明」。产品负责人问：是不是主包代码里有 AI 能力，命中了代码审核？

## 1. 核查结论（按发布包 = 主包 + 全部子包）

| 检查项 | 主包（pages / components / utils / app.*） | 子包 |
|---|---|---|
| 模型密钥 / 直接调用大模型（wx.request 到 dashscope 等） | **0 处**（唯一的 `wx.request*` 命中是 `requestSubscribeMessage`，订阅消息，不是 AI） | 0 处 |
| 提示词 / persona / 模型链 | **0 处** | `feature/museum-guide`（persona、guideChat）、`ai/ai-center`（roles.js 人设）、`ai/ai-debate` |
| AI 页面 | 无（只有入口与文案） | **15 个 js**：`subpackages/ai/ai-center`、`subpackages/ai/ai-debate`、`subpackages/feature/museum-guide`（含 quiz）、`subpackages/feature/identify` 及 `result` |
| AI 文案 / 入口 | 14 个文件（分类页「AI 鉴定」、我的「博物君」、首页口播、埋点 schema 等） | 同上 |

**结论：主包没有"模型能力"，但发布包（含子包）确实携带完整的 AI 问答与文本生成页面与提示词。**
微信代码审核判的是「这个包是否提供该能力」，**内容开关只控制展示，不改变包内容**，所以关掉开关也仍然需要按深度合成类目申报。

审核意见本身就是两条要求：
1. 补选 **深度合成 - AI问答** 类目（平台设置里操作，需主体资质）；
2. AI 生成页面加显著说明（已做：识图结果页顶部声明条、博物君逐条「AI 生成」签）。

## 2. 两条可行路径

### A. 保留 AI 能力 → 补类目（产品当前选择）
- 微信公众平台 → 设置 → 基本设置 → 服务类目 → 增加「深度合成 > AI 问答/文本生成」；
- 按平台要求提交主体资质（深度合成服务算法备案 / 安全评估等）；
- 提审说明里写清：AI 入口受「内容开关」控制，关闭时服务端拒答（askMuseumGuide / identifySpecimen 已加闸）；
- 页面标注已满足第 2 条。

### B. 暂不申报 → 发布包彻底移除 AI 能力
只把开关关掉**不够**，必须让上传包里没有 AI 页面与提示词：
1. `app.json` 移除 `subpackages/ai` 分包；
2. `subpackages/feature/museum-guide`、`feature/identify`（含 result）从发布包移除，相关入口一并删除；
3. 主包里的 AI 文案/口播（`pages/index/guideBroadcast.js`、分类页「AI 鉴定」按钮、我的「博物君」）删除；
4. 云函数保留（不上传小程序包，不影响审核），但 C 端入口为零。
代价：AI 鉴定 / 博物君 / AI 中心 三个能力对顾客与员工都不可用，需产品负责人点名确认。

## 3. 自查清单（提交前）

- [ ] 内容开关里 AI 鉴定 / 博物君 均关闭；
- [ ] 我的 / 首页 / 分类页 / 搜索页 / 图鉴详情 / 识别结果 均无 AI 入口（fail-closed 已改，未确认一律不显示）；
- [ ] 历史分享链接进博物君 → 只看到闭馆提示（服务端已加闸）；
- [ ] 识图结果页顶部有「AI 生成」声明；博物君每条回答有「AI 生成」签；
- [ ] 若走 A：类目已补；若走 B：发布包内已无 AI 页面（`node -e` 检查 app.json 与目录）。
