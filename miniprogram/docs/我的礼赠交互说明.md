# 我的礼赠（人情账本）交互说明

> 页面：`subpackages/feature/gift/my-gifts/index`（往来 / 对象 / 日子 三栏）
> 需求来源：业务方 33 条需求 **#31【P1】优化我的礼赠整体交互与设计，重点「我送出的」展示逻辑，
> 已退款与已取消订单折叠展示**
> 守卫：`npm run test:gift-mygifts`（含 `--selftest`，10 个回归注入）
> 服务端：`cloudfunctions/manageGift` 的 `listMine` / `classifyMineProgress` / `buildMineActions`

---

## 1. 本轮修掉的真问题

### 1.1 模板作用域：`{{flowTab}}` 永远解析不出来（**用户可见**）

WXML `<template>` 的作用域是**隔离**的：只能读到 `data="{{...}}"` 传进去的值，读不到页面 data。
卡片模板里写了 `{{flowTab}}`（页面 data），于是：

| 位置 | 后果 |
|------|------|
| `class="role-chip {{flowTab}}"` | 角标永远拿不到 `sent` / `received` 类 → 「收到」侧本该是绿的，一直是金色 |
| `wx:elif="{{item.recipientName && flowTab === 'sent'}}"` | **「致 XX」这一行从不显示**，被顶到 `storeName` / `deliveryLabel` |

WXML 对未定义标识符**不报错、不警告**，所以这个 bug 不会以任何形式浮出来。

**证据（仓内）**：`feature/components/mp-html` 是本仓最老练的第三方组件，它连组件自己的
`opts` / `ctrl` 都要显式写进 `data`（`data="{{n:n1,i:...,opts:opts,ctrl:ctrl}}"`），
正是「模板作用域隔离」这条规则的实证。

**修法**：`flowTab` 随 item 一起进模板（`decorateFlowItem` 落 `flowTab` 字段），模板改用
`{{item.flowTab}}` —— 这样**不依赖**作用域语义，隔离与否都正确。

**顺带修掉的第二层问题**：原来「致 XX」是 `cardSnippet` 的 `wx:elif`，所以**只要写了礼笺，
受赠人就不显示**。而写礼笺恰恰是礼赠流程的常态 —— 等于「我送出的」最该看到的信息被摘句顶掉。
现在「致 XX」是独立一行，放在摘句之前；摘句有就多显示一行（同一段内高度差仅一行）。

### 1.2 失效口径（折叠谁）

折叠 = **终态**：`progressKey ∈ {cancelled, refunded}` 或 `progressSteps.mode === 'terminal'`。
云端 `buildMineProgressSteps` **只对 refunded / cancelled 返回 `mode: 'terminal'`**，所以两条口径等价，
「已完成」「待付款」「履约中」「待启封」「待填址」都不会被折进去（守卫逐 key 断言）。
`expired_refunding`（过期退款中）云端也映射成 `refunded` → 归入折叠，卡片自带正确状态名。

### 1.3 折叠计数不能说谎

折叠计数只统计**已加载页**里的失效笔数。分页未到底时它不是总数，所以：

- 还有更早的 → `已加载 N 笔`
- 已到最早 → `共 N 笔`

（与钱包账单流水 `ledgerCapText` 同一口径；两处都由守卫钉住。）

### 1.4 失效卡没有任何出口

云端 `buildMineActions` 对 `refunded` / `cancelled` **不派发任何动作**，折叠区里的卡片
一个按钮都没有，只能靠「点整卡」这条隐晦路径。现在客户端兜底补一个
**「订单详情」**（与云端 `done` 态同词、指向本单 `deepLink`），
且**仅在云端确实没给动作时**补，不覆盖服务端口径。

## 2. 折叠件（与礼券夹同一套券包语言）

- 结构：`.pouch` > `.pouch-head`（可点，`aria-role` / `aria-expanded` / `aria-label`）+
  `.pouch-body`（`wx:if` 惰性渲染）。
- 堆叠示意：`.pouch-stack` 内 **3 张错位迷你券**（+7° / −4° / 正放），最前一张提亮并在券面打 3 个孔。
- 箭头：CSS 折角（`border-right/bottom` + `rotate(45deg)` ↔ `rotate(-135deg)`），不是字符箭头。
- 动画：`pouch-in .26s`；`softVibrate('light')` 软震动。
- 展开区尾部说明：「已结束的往来仅作记录 · 可点开查看订单」。
- **位置**：折叠件在 `.list` **内部**（与在途列表一起受下拉刷新 dim 影响，页脚顺序也不乱）。
- **重置**：换分栏 / 换段位 / 清筛选三处共用 `foldedResetPatch()` 收回折叠态，避免只改一处漏另一处。

## 3. 往来面板的分层

- 同屏**既有在途又有失效**时，在在途列表前起小标题「在途礼赠 N 笔」+ 细铜线。
  （只有失效时不出现，避免平白多一行；这也解释了下面为什么有券包。）
- **在途清空、只剩失效**时给一条说明：「在途礼赠已清空 / 已退款与已取消的往来收在下方，可展开回看」，
  不留「空白 + 券包」的困惑。

## 3b. 主路径清晰度（2026-09-26 体验升 · 稳定期只动 UI）

- **页头待办焦点条**：`listMine` 返回的 `todoCount + attentionCount > 0` 且当前在「全部」段位、无对象筛选时，
  从现有 `segmentCounts` 挑优先格（待启封 → 待填址 → 履约/待收货），点「去处理」落到该段位。
  **不改**云函数入参/出参，只读已有字段。
- **对象 → 往来**：`viewContactGifts` 与换段位同口径，调用 `foldedResetPatch()`，避免带着上一次折叠展开态跳转。
- **空态文案**：送出/收到/对象/日子空态补一句主路径引导；送出空态次 CTA 可进「对象」栏。
- **未开放/校验中**：标本纸空标 + 回工坊出口（关礼赠开关时更诚实）。
- **选礼 Hub**（`gift/hub`）：与人情账本同一套纸面语言；从账本带入称呼时显示「正在为 XX 选礼」；
  柜中加载骨架 / 失败空态与账本对齐。

## 4. 刻意没动的部分

- **云端契约 / 状态机 / `buildMineActions` / 段位口径**：稳定期不动。云端仍把 `refunded` / `cancelled`
  归到 `segment: 'done'`，「已完成」chip 计数含失效笔数——折叠件已在视觉上分开，拆开须产品点名。
- **「对象」页筛选**：`recipientName` 筛选走服务端（`listMine` 的 `recipientName` 参数），保持不变。
- **页面正式名**：界面仍称「我的礼赠」（用户口中的「我的礼遇」即此模块，未改入口文案以免与生日礼遇混淆）。

## 5. 验收方式

1. `npm run test:gift-mygifts` —— 加载**真源码**跑失效口径 / 折叠计数 / 失效卡兜底 / 折叠态重置 /
   待办焦点条 / 对象跳往来复位，
   并用真 `loadList` + 打桩云函数跑两页分页（含「list 本体保持全量」的分页契约）。
   **外加一条全仓守卫**：扫描 `miniprogram/**` 所有非组件 WXML 的 `<template name>` 块，
   禁止模板体引用未通过 `data` 传入的标识符 —— 这类 bug 不会报错，只能靠静态守卫拦。
   `--selftest` 注入回归必须全部被检出。
2. `npm run check:quick -- gift-print`（或含 `test:gift-mygifts` 的 cross）。
3. 开发者工具：我的 → 我的礼赠 → 有待办时页头焦点条 → 点「去处理」落到段位；对象「往来」后折叠收回；
   底栏「选一份山海」进 Hub 可见纸面页头与（若有称呼）「正在为 XX 选礼」。
