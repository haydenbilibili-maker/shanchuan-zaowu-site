# 超管工作台 · 功能归并与分类优化（2026-11-25）

> 现状：**7 个分区 / 52 个一级入口**（`subpackages/manager/manager/hubNav.js` 的 `HUB_ENTRIES`）。
> 产品负责人：「超管功能已经超过 52 个，看看有哪些是可以合并同类项的，大幅度优化功能分类与数量」。

**问题不在数量本身，而在「同一件事被拆成多个一级入口」**：
- 会员的「权益 / 调级」、「新人礼包 / 生日礼包」各自占一格，但都是「等级与礼遇」一件事；
- 工作室的「供应商 / 采购 / 库存 / SKU 维护」是一条第 1 段到第 4 段的同一价值链；
- 门店的「员工 / 权限 / 工资维护 / 我的工资条」是同一份人事数据；
- 系统的「运费 / 预约 / 客服 / 微信通知」全是**一条一条的规则设置**；
- 商品的「装修 / 开关 / 审核」是同一个「上线前的店铺状态」。

## 1. 归并原则（三条）

1. **同一份数据 / 同一条动线，只留一个入口**，内部用分档（子 Tab）复用它已有的页面能力；
2. **一级入口=任务**（我要干什么），**二级=对象**（给谁、哪一类）——不按系统模块名建入口；
3. 归并后**每个入口的权限键保持不变**（`keys` 只增不减地映射到原菜单键），不做权限收紧或放宽。

- `check:hub-entries`：磁贴 ↔ 清单逐枚一致、每枚有 16 字内说明、无重复入口；
