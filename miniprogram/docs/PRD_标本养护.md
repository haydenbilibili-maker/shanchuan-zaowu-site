## 2. 背景与机会

### 2.1 业务诉求

标本不是「买完即结束」的标准消费品。用户在签收后最常问的三类问题是：

1. **怎么摆、怎么擦、能不能晒** — 品类差异大（昆虫框画 vs 矿物 vs 湿标本），通用 FAQ 不够用；
2. **我这件具体要注意什么** — 与订单 / 框型 / 工艺绑定的提醒缺失；
3. **出了问题找谁** — 轻微落灰 vs 需要返店护理，缺少分级引导。

线下门店店员会在交付时口头交代养护要点，但**线上购买用户签收后链路断裂**：当前仅提供「确认归档 → 收藏证书」，没有结构化的养护承接。

### 2.2 现状诊断（基于代码）

| 维度 | 现状 | 缺口 |
|---|---|---|
| 签收后 | `order-detail` 确认收货 → 状态 `received` → 「查看收藏证书」 | 无养护入口、无品类提示 |
| 支付成功 | `confirm-order` Toast「支付成功」后返回 | 无购后教育动线 |
| 站内信 | `order_received` 模板已预留，跳转订单详情 | 未引导至养护内容 |
| 商品 | `products.category` 含 INSECTA / PLANTAE / MARINE / MINERALS | 未映射养护指南 |
| 定制单 | `orders.customMeta` 含框型、包装、标本师 | 未生成「装裱养护」补充说明 |
| 内容 | 馆藏 `cms_wikis` 偏物种知识 | 与「持有后怎么养」场景未分离 |
| 专员 | `pages/user/support` 支持 `topic` 参数 | 无 `specimen_care` 预设话题 **【待确认】** |

**结论**：在**不改动交易主链路**的前提下，新增轻量「标本养护」内容模块，并在**签收 / 证书 / 我的**三个高意图节点接入跳转，把线下交付话术产品化。

### 2.3 模块命名 **【待确认 C1】**

| 方案 | 对外文案 | 说明 |
|---|---|---|
| **A（推荐）** | **标本养护** | 与博物馆「藏品维护」语感一致，偏预防性 |
| B | 标本保养 | 偏周期性维护，略像汽车保养 |

## 3. 产品定位

### 3.1 一句话定位

> **标本养护 = 把标本师交到你手里的那句话，留成随时可查的养护手册**——让藏品在家里也能被好好安放。

### 3.2 与相邻模块关系

| 模块 | 关系 |
|---|---|
| **订单 / 签收** | 签收成功后首要导流节点（与收藏证书并列） |
| **收藏证书** | 证书证明「归属」，养护页承接「责任与方法」；可互相链接 |
| **馆藏 / 百科** | 馆藏讲「物种是什么」，养护讲「到家后怎么办」；内容不混排 |
| **商详** | 可购前预览「此类标本养护概要」建立信任 **【P2】** |
| **标本工坊** | 定制单额外展示框型 / 包装相关养护（如木框防潮） |
| **伴宠记忆** | 独立子指南「纪念标本长期安放」**【P2，见宠物 PRD 联动】** |
| **山海有信** | 季节养护提醒、签收后 7 日养护摘要 **【P2】** |
| **联系专员** | 异常处理 escalation（变色、虫蛀、框体开胶等） |
| **预约到店** | 深度护理 / 换框 / 除尘服务导流 **【P3】** |

### 3.3 北极星指标（建议）

| 指标 | 说明 |
|---|---|
| 签收后养护页到达率 | 确认收货 UV 中打开养护页 UV |
| 养护页完读率 | 滚动至底部或停留 > 30s 占比 |
| 品类指南覆盖率 | 有对应 `care_guides` 的已售 SKU 品类占比 |
| 养护相关专员咨询率 | 作为服务质量信号（过高可能说明内容不清） |
| 复购 / NPS 相关性 | 长期观测签收后 30 日回访 **【待埋点】** |

## 4. 设计原则

1. **Curator, Not Manual** — 像博物馆说明牌，不是家电说明书；短句、具体、可执行。
2. **Category First** — 养护建议按**标本品类 + 装裱形态**组织，而非按 SKU 堆砌。
3. **Calm Urgency** — 提示风险（阳光、湿度）但不用恐吓式文案；禁止「损坏自负」类冷硬表述。
4. **Post-Purchase Native** — 购后场景优先；未购用户仅看通用公开指南 **【待确认 C2】**。
5. **Escalation Path** — 每条指南末尾固定「仍有问题 → 联系专员 / 预约到店」。
6. **Museum Visual** — 暗底、黄铜标注、品类色仅用于标签；禁止 emoji 作图标。

## 5. 目标用户与核心场景

| 用户 | 场景 | 期望路径 |
|---|---|---|
| 首次购买者 | 刚签收蝴蝶框画，不知如何清洁 | 确认收货弹层 → 养护指南 → 昆虫类「除尘与避光」 |
| 送礼接收者 | 朋友代买，本人无购买 App 习惯 | 分享卡片 / 证书二维码 → 公开品类养护页 **【P2】** |
| 藏家复购 | 多件不同品类，想统一查看 | 我的 → 标本养护 → 我的藏品列表 **【P1】** |
| 定制客户 | 木框 + 礼盒，担心南方梅雨季 | 订单详情 → 定制养护卡（框型 + 品类） |
| 问题用户 | 发现翅面粉化 | 养护页「异常信号」→ 联系专员（带订单号） |

### 6.2 养护内容结构（单篇指南）

每篇 `care_guides` 文档建议固定模块，便于 CMS 与前端渲染：

| 模块 | 说明 | 示例（昆虫框画） |
|---|---|---|
| **Overline + 标题** | 品类英文名 + 中文名 | INSECTA · 神奇昆虫 |
| **一句话摘要** | 20 字内核心原则 | 少碰、避晒、干处安放 |
| **适宜环境** | 温度、湿度、光照 | 18–26℃，相对湿度 45–60%，避免直射 |
| **日常安放** | 摆放位置、倾斜、堆叠 | 宜挂墙或平置柜面，不与重物叠压 |
| **清洁与除尘** | 频率、工具、禁止事项 | 软毛刷单向轻扫，禁止湿布与酒精 |
| **运输与搬家** | 短途 / 长途 | 原盒+缓冲，框面朝上 |
| **异常信号** | 何时该联系门店 | 翅面起雾、框内返潮、异味 |
| **相关物种** | 链馆藏内容 **【P2】** | 跳转 `cms_wikis` |
| **Escalation** | 专员 + 预约 | 固定底栏 |

## 7. 购后链路设计（重点）

### 7.1 触发节点与跳转

| 节点 | 当前行为 | 建议增强 | 优先级 |
|---|---|---|---|
| **支付成功** | Toast + 返回 | 可选轻提示条：「制作完成后我们将提醒您；签收后可查看养护指南」 | P2 |
| **订单发货** | 站内信 `order_shipped` **【待接入】** | 消息摘要 + 链接「运输与签收注意事项」 | P2 |
| **确认签收** | Modal「确认归档 + 证书」 | Modal 增加第三按钮或签收成功页：**「查看养护指南」**（主 CTA 之一） | **P0** |
| **已签收订单详情** | 底部「查看收藏证书」 | 并列按钮：**「标本养护」**；清单每项可加「养护」小入口 | **P0** |
| **order_received 站内信** | 跳转订单详情 | 增加 secondary actionUrl 模板变量 **【P2】** |
| **收藏证书页** | 展示证书 | 底部链接「如何养护这件藏品」 | P1 |
| **我的 → 馆藏服务** | 无 | 新增菜单「标本养护」 | **P0** |

## 15. 风险与边界

| 风险 | 缓解 |
|---|---|
| 养护建议不当导致藏品损伤 | 标本师审核；异常场景引导联系专员而非 DIY 修复 |
| 内容与 SKU 不匹配 | 以品类为粒度；单品特殊说明走专员 |
| 签收弹层按钮过多 | 采用 ActionSheet 分步，证书与养护并列 |
| 伴宠 / 浸液等特殊工艺 | 独立 guide，不与标品昆虫 guide 混用 **【P2】** |
| 法律免责 | 指南页脚统一温和声明 **【待法务】** |
