# 站内信功能说明

## 📋 功能概述

在小程序"我的"页面添加了站内信入口，实现了红点提示策略，并与web管理后台的通知消息配置打通。

## ✅ 已完成功能

### v1.1 升级（山海有信）

- **分类筛选**：全部 / 预约 / 订单 / 活动 / 系统，与服务端 `category` 字段联动
- **深链跳转**：消息含 `actionUrl` 时，详情页展示 CTA 按钮（查看订单、查看预约等）
- **分页加载**：每页 20 条，滚动触底加载更多
- **长按删除**：列表项长按可删除消息
- **VI 对齐**：Museum Mode 暗底 + 黄铜未读点，去掉红色高亮
- **统一发送**：`sendInAppMessage` 云函数，订单/预约链路自动写入站内信

**触达场景**：
| 场景 | type | 触发点 |
|------|------|--------|
| 订单待支付 | order_created | makeOrder |
| 支付成功 | order_paid | payCallback / confirmPayment |
| 订单取消 | order_cancelled | cancelOrder |
| 退款完成 | order_refunded | refundOrder |
| 预约提醒 | booking_* | sendBookingReminder（与订阅消息双通道） |

### 1. 站内信入口（pages/user/index）

- **位置**：在"馆藏服务"菜单列表中，位于"我的成就"之后
- **样式**：与其他菜单项一致，使用消息图标
- **红点提示**：
  - 显示未读消息数量（最多99+）
  - 红色圆形徽章，带脉冲动画效果
  - 实时更新未读数量

### 2. 站内信页面（pages/user/messages）

**页面功能**：
- 消息列表展示（按时间倒序）
- 消息详情查看
- 标记单条消息为已读
- 标记全部消息为已读
- 删除消息
- 下拉刷新
- 空状态提示

**消息展示**：
- 未读消息：红色圆点标记，特殊背景色
- 消息图标、标题、内容、时间、分类
- 支持点击查看详情

**消息分类**：
- 预约相关（booking）
- 订单相关（order）
- 活动相关（activity）
- 系统通知（system）
- 其他（other）

### 3. 云函数（cloudfunctions/getUserMessages）

**支持的操作**：
- `getMessages`：获取消息列表（支持 `category`、`page`、`pageSize`）
- `getUnreadCount`：获取未读消息数量（支持按 `category` 筛选）
- `markRead`：标记单条消息为已读
- `markAllRead`：标记全部消息为已读（支持按 `category` 筛选）
- `deleteMessage`：删除消息

### 3b. 云函数（cloudfunctions/sendInAppMessage）

统一写入 `user_messages` + `notification_logs`，供订单、预约及其他业务调用。

**数据来源**：
- 主要从 `user_messages` 集合读取
- 兼容 `notification_logs` 集合（如果user_messages不存在）

### 4. 与Web后台打通

**数据同步机制**：
- Web后台发送通知时，会写入 `user_messages` 集合
- 同时记录到 `notification_logs` 集合（用于后台查询）
- 小程序站内信从 `user_messages` 集合读取

**字段映射**：
```
user_messages:
  - _openid: 用户openid
  - title: 消息标题
  - content: 消息内容
  - category: 分类（booking/order/activity/system/other）
  - type: 消息类型（order_paid、booking_reminder 等）
  - relatedId: 关联业务 ID（订单/预约等）
  - actionUrl: 小程序内跳转路径
  - read: 是否已读（boolean）
  - createTime: 创建时间
  - _createTime: 创建时间（云数据库标准字段）
```

## 🔄 数据流程

### 发送消息流程：
1. Web后台配置消息模板（NotificationConfig组件）
2. 触发发送操作（如预约提醒、订单通知等）
3. 调用云函数或直接写入数据库
4. 消息写入 `user_messages` 集合
5. 同时记录到 `notification_logs` 集合

### 接收消息流程：
1. 小程序"我的"页面加载时调用 `loadUnreadMessageCount()`
2. 调用 `getUserMessages` 云函数的 `getUnreadCount` 操作
3. 显示未读数量红点
4. 用户点击站内信入口
5. 跳转到站内信页面，加载消息列表
6. 用户查看消息时自动标记为已读

## 📱 页面路径

- 站内信入口：`pages/user/index` （"我的"页面）
- 站内信列表：`pages/user/messages/index`

## 🎨 样式特点

- **黑金主题**：与小程序整体风格一致
- **红点动画**：脉冲动画效果，吸引注意
- **未读高亮**：未读消息有特殊背景色和红色圆点
- **流畅交互**：点击反馈、下拉刷新、详情弹窗

### 数据库集合：
- `user_messages`：用户站内信主表
- `notification_logs`：通知发送记录（web后台查看）

## 🚀 使用说明

### 用户端：
1. 在"我的"页面查看站内信入口
2. 未读消息会显示红色数字徽章
3. 点击进入站内信列表
4. 查看消息详情
5. 消息查看后自动标记为已读

### 后台端：
1. 在Web管理后台配置消息模板
2. 设置发送规则
3. 系统自动发送消息到用户站内信
4. 可在"发送记录"中查看发送历史

## ⚠️ 注意事项

1. **数据库权限**：确保 `user_messages` 集合允许小程序用户读写
2. **云函数部署**：需要部署 `getUserMessages`、`sendInAppMessage`；订单/预约相关云函数更新后需重新部署
3. **消息图标**：确保 `/assets/icons/message.png` 图标文件存在
4. **兼容性**：云函数兼容 `notification_logs` 集合，确保向后兼容
