## 2. 背景与目标

### 2.1 为何做礼赠

标本天然适合送礼：

- **可叙事**：物种中文名 + 拉丁学名 + 产地，铜牌本身就是「礼物说明书」；
- **可仪式**：封装工艺、证书、礼盒，交付感强于普通电商 SKU；
- **可延续**：签收后进入收藏证书 / 养护 / 山海有信，礼物不会「拆完即无」。

当前痛点：

| 痛点 | 现状 | 代价 |
|---|---|---|
| 送礼必须先要到地址 | 只能代下单或备注里写「礼物」 | 破坏惊喜；向 TA 索要地址尴尬；易暴露价格 |
| 无仪式感触点 | 无贺卡、无专用领取卡 | 与市面廉价「送礼按钮」同质 |
| 门店现场购赠断层 | 这有店可购可核销，但无「代赠 / 代领」闭环 | 线下导购话术无法产品化 |
| 触达不闭环 | 无礼赠角色分流与催填 | 分享后无人填址 → 库存空挂、客服扯皮 |

**一句话定位**：

> **礼赠 = 把一件标本从「商品」变成「郑重的交付」——送礼人先备妥并支付，再邀请 TA 开启礼笺、留下去处；复用订单内核，体验层对齐淘宝送礼 / 星礼送的「先付后填址」，气质对齐博物柜。**

### 2.2 北极星与成功指标

**北极星**：礼赠订单 GMV 占同期零售 GMV 比例（目标：上线 90 日内 ≥ 8% **【待确认基线】**）。

| 目标 | 指标 | 基线 | 目标（90 日） | 测量窗口 |
|------|------|------|---------------|----------|
| 转化 | 礼赠入口曝光 → 支付成功 | 无 | ≥ 4% | 滚动 30/90 日 |
| 主路径健康 | **先付后填址**单：支付后 7 日内填址率 | 无 | ≥ 65% | 支付成功后 7 日 |
| 催填有效 | 催填触达后 48h 内填址率 | 无 | ≥ 40% | 按催填批次 |
| 过期可控 | 超时未填址自动退款率（占该交付方式） | — | 观测；目标 < 25% | 90 日 |
| 客单 | 礼赠客单价 vs 普通 | 普通客单 | ≥ +15% | 同品类 |
| 分享 | 分享卡点击 → 领取页 UV / 分享次数 | 无 | ≥ 35% | 每笔 |
| 复购 | 送礼人 60 日再礼赠或自购 | 普通复购 | ≥ +5pp | cohort |
| 门店 | 自提代赠核销成功率 | 无 | ≥ 95% | 按门店 |
| 隐私 | 隐价开启率 | — | 观测 | 迭代用 |
| 客服 | 礼赠售后工单 / 礼赠单 | — | < 8% | 90 日 |

### 2.3 设计原则

1. **Pay First, Address Later（主路径）** — 默认不要求送礼人填写 TA 的收货地址；支付后分享领取卡，由收礼人确认并填址后再履约发货。对标淘宝送礼 / 星礼送。
2. **Ceremony Over Coupon** — 卖仪式与体面，禁止「限时秒杀」话术。
3. **Reuse Kernel, Redesign Skin** — 支付、库存、履约、退款走现有订单；页面与文案全新。
4. **Privacy by Choice** — 默认对收礼人隐藏价格；手机号等仅履约所需，界面脱敏（不露全号）。
5. **Two Audiences** — 送礼人看进度与催填；收礼人看礼笺与填址，互不串戏。
6. **Museum Voice** — 朋友式、克制；禁止浮夸直播话术与 emoji 开头。
7. **Brass & Specimen Paper** — 礼笺标本纸 + 黄铜语义，拒绝蓝紫科技卡。
8. **Store Continuity** — 门店自提代赠与线上下单同一状态机族。

## 3. 用户与场景

### 3.1 角色

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| **送礼人 Giver** | 已注册会员 | 不必先要地址；体面礼笺；可催填；可知是否收下 |
| **收礼人 Receiver** | 可能从未打开小程序 | 先看礼笺再决定；隐价；少步骤填址；手机脱敏 |
| **门店导购 / 店员** | 这有店现场 | 代客购赠、自提核销清晰 |
| **店长 / 超管** | 配置与履约 | 开关、超时天数、默认交付、贺卡、显价策略 |

### 3.2 核心场景（MVP 优先）

| ID | 场景 | 路径摘要 | 优先级 |
|----|------|----------|--------|
| **S0** | **先付后填址（主路径）** | 选礼 → 礼笺 → **邀请 TA 填写地址** → 支付 → 分享 → TA 开礼笺 → 接受 → 填址 → **再发货** | **MVP 主路径** |
| S1 | 生日 / 纪念日（走 S0） | 同上；用生日礼笺模板 | MVP |
| S2 | 乔迁 / 感谢（走 S0） | 同上；可加礼盒 | MVP |
| S3 | 已知地址直寄 | 交付「快递给 TA」→ 送礼人填址 → 支付 → 发货（可不分享领取卡） | MVP 并列 |
| S4 | 寄给我再当面转交 | 交付「寄给我」→ 支付 → 物流到己 / 自提 | MVP 并列 |
| S5 | 门店自提代赠 | 选门店 → 支付 → 分享领取码 / 到店核销 | MVP 并列 |
| S6 | 收礼人拒绝 | 领取页「婉拒」→ 通知送礼人 → 自动退或改送 **【二期】** | 二期 |
| S7 | 收礼人转赠第三人 | 填址前转给另一人 **【二期】** | 二期 |
| S8 | 预约开箱日 | 定时解锁礼笺 **【二期】** | 二期 |
| S9 | 企业批量 | 对公 / 批量礼笺 | 二期 |

### 3.3 交付方式关系（必须对齐）

四种交付方式**并列**，其中 **「邀请 TA 填写地址」为默认选中的主路径**：

| `deliveryType` | 名称 | 谁填地址 | 何时可发货 | 典型用途 |
|----------------|------|----------|------------|----------|
| **`invite_address`** | **邀请 TA 填写地址（先付后填址）** | 收礼人 | **地址提交且校验通过后** | 惊喜送礼、不知地址 |
| `ship_to_receiver` | 快递给 TA | 送礼人下单时 | 支付成功后即可履约 | 已知地址、代订 |
| `ship_to_self` | 寄给我（再转交） | 送礼人 | 支付成功后 | 当面送、自己包装 |
| `store_pickup` | 门店自提代赠 | 选门店；领取人可后补 | 备货完成后待核销 | 这有店现场 |

**产品建议（C8）**：编排页交付方式默认勾选 `invite_address`；其余三项折叠为「其他交付方式」。

### 3.4 用户故事与验收要点

| ID | 故事 | 验收要点 |
|----|------|----------|
| G1 | 作为送礼人，我希望支付时**不必填写 TA 的地址** | `invite_address` 下地址表单不出现；可完成支付 |
| G2 | 作为送礼人，我希望写礼笺并可选隐价 | 隐价默认开；确认页仅己方见价 |
| G3 | 作为送礼人，支付后我能立刻分享领取卡 | 成功页主 CTA「交给 TA」 |
| G4 | 作为送礼人，TA 未填址时我能看到「待 TA 填写」并催一催 | 订单详情催填入口；有频控 |

| R4 | 作为收礼人，链接过期或已退时看到体面失效页 | 无技术报错码堆砌 |
| S1 | 作为店员，自提礼赠可核销 | 核销 = 已领取 |

### 4.2 二期

- 收礼人**婉拒**（自动全额退或退回送礼人改地址）
- 收礼人**转赠**第三人（重新生成 token）
- 预约开箱日、企业批量、礼赠专题馆、纸质信签打印、心愿单
- ~~语音礼笺~~（已提前纳入编排 / 领取页：`giftMeta.voiceFileID` + `voiceDuration`）

### 4.3 非目标

- 不做礼金 / 红包 / 分销裂变；
- 不做完全匿名不可追溯送礼；
- 不做默认短信轰炸（催填以站内信 + 订阅消息 + 送礼人手动分享为主）。

## 5. 下单链路与状态机

### 5.1 主链路：先付后填址（MVP 默认）

```
选礼（商详「送 TA」）
  → 礼赠编排（礼盒 · 礼笺 · 隐私）
  → 交付方式：默认「邀请 TA 填写地址」
  → 确认页（仅送礼人见价；无需 TA 地址）
  → 支付
  → 支付成功：强引导分享领取卡 + 订阅消息授权（催填 / 进度）
  → 【待 TA 开启】库存已锁定，不发货
  → 收礼人打开分享卡
       → 礼笺仪式（隐价）
       → 确认「收下这份山海」（需登录）
       → 填写收货地址（姓名 / 手机 / 地区 / 详址）
       → 提交成功 → 订单进入可履约（待发货）
  → 仓发 / 物流
  → 签收 / 开箱回执 → 证书与养护导流
```

对标说明（逻辑对齐，文案自有）：

| 步骤 | 淘宝送礼 / 星礼送常见做法 | 山海造物 |
|------|---------------------------|----------|
| 支付时 | 可不填对方地址 | 同左（`invite_address`） |
| 领取页 | 礼物卡面 → 收下 → 地址 | 标本纸礼笺 → 收下 → 地址 |
| 隐私 | 不展示实付价 | 默认隐价；可配 |
| 催促 | 站内信 / 服务通知催填 | 山海有信 + 订阅消息 + 送礼人「再提醒」 |
| 过期 | 超时自动退 | MVP 必须；天数可配 |
| 拒绝 / 转赠 | 部分支持 | **二期** |

### 5.2 并列链路（摘要）

```
快递给 TA：编排 → 填 TA 地址 → 支付 →（可选分享礼笺）→ 发货 → 签收
寄给我：    编排 → 己方地址/自提 → 支付 → 收货 →（可选标记已转交）
门店自提：  编排 → 选门店 → 支付 → 备货 → 分享领取码 / 到店核销
```

### 5.3 页面级流程（先付后填址）

1. **商详** →「送 TA」进入编排（不进普通结算）。  
2. **编排** → 礼盒 / 礼笺 / 隐私 →「下一步 · 选择交付」。  
3. **交付与确认** → 默认「邀请 TA 填写地址」；展示规则摘要（领取期限、超时退款）→ 支付。  
4. **支付成功** → 主 CTA「把这份心意交给 TA」；进度文案「正等 TA 留下地址」。  
5. **领取 / 开箱页** → 礼笺 → 收下 → **填址页** → 提交成功页（「馆员将为你备妥启程」）。  
6. **送礼人订单** → 进度：已支付 → 待 TA 填写 → 已收下待发货 → 运送中 → 已签收。

### 5.4 状态机简表

**底层订单建议映射**（逻辑名，非实现）：

| 底层 / 履约闸门 | 含义 |
|-----------------|------|
| `pending_pay` | 待支付 |
| `paid_awaiting_address` | 已支付，等待收礼人填址（**不可发货**） |
| `paid` / `awaiting_shipment` | 地址已齐，可拣货发货 |
| `shipped` / `ready_pickup` | 已发货 / 自提备货完成 |
| `received` / `completed` | 签收完成 |
| `expired_refunding` → `refunded` | 填址超时自动退 |
| `cancelled` / `refunded` | 主动取消或售后 |

**展示层状态**（C 端文案）：

| 展示状态 | 条件 | 送礼人 | 收礼人 |
|----------|------|--------|--------|
| 待支付 | 未付 | 待支付的心意 | — |
| 待 TA 开启 | 已付 + `invite_address` + 未接受 | 把卡片交给 TA 吧 | 有一份山海待你开启 |
| 待留下地址 | 已接受 + 未提交地址 | TA 已开启，正等地址 | 请留下收件去处 |
| 催填中 | 已触发催填（子状态） | 已捎去提醒 | 地址尚未写下 |
| 待启程 | 地址已提交未发货 | 馆员正在备妥 | 即将启程 |
| 运送中 | 已发货 | 已交予承运 | 标本正在向你靠近 |
| 待领取（自提） | 备货完成 | 可邀到店 | 出示领取码 |
| 已收下 | 签收 / 核销 | TA 已收下 | 可查看证书 |
| 已过期 | 超时未填址 | 期限已至，款项将退回 | 这份邀约已过期 |
| 已收回 | 退款完成 / 取消 | 心意已收回 | 链接失效 |
| 售后中 | 退货退款流程中 | 按规则处理 | 暂不可操作 |

**闸门规则**：

- 仅当 `deliveryType=invite_address` 时出现「待 TA 开启 / 待留下地址」；**地址未提交不得创建发货任务**。  
- `ship_to_receiver` / `ship_to_self` 支付后直接进入待启程。  
- `store_pickup` 支付后进备货，不走填快递地址（可收集领取人姓名手机，脱敏展示）。

### 5.5 催填、过期与退款（先付后填址专用）

| 规则项 | MVP 建议默认 | 说明 |
|--------|--------------|------|
| 领取 / 填址有效期 | **7 个自然日**（自支付成功起算）**【C9】** | 后台可配 3/7/14 |
| 自动催填 | 第 3 日、第 6 日各 1 次 | 山海有信 → 送礼人「请再提醒 TA」；若收礼人已登录则同时有信 |
| 手动催填 | 送礼人每日最多 **1** 次 | 防骚扰；按钮文案「再提醒一声」 |
| 订阅消息 | 支付后向送礼人申请「进度提醒」；收礼人登录后可申请「待填地址」 | 未授权不影响主路径 |
| 到期未填址 | 自动发起全额退款；`shareToken` 失效 | 有信 `gift_expired_refund` |
| 填址前主动取消 | 送礼人可全额退；链接立即失效 | 同未发货取消 |
| 填址后发货前取消 | 允许全额退（拦截发货） | 与普通未发货一致 |
| 已发货 | 不支持因「不想要了」无理由退；质量问题除外 | 见退换表 |
| 婉拒 / 转赠 | **二期** | MVP 不提供正式「拒绝」按钮，避免误触退款；用户可忽略链接直至过期退款 |

### 5.6 退换规则差异（更新）

| 情形 | 规则 | 【待确认】 |
|------|------|------------|
| 支付后、地址未提交 | 送礼人可取消全额退；超时自动退；链接失效 | 是 |
| 地址已提交、未发货 | 可取消全额退 | 是 |
| 已发货未签收 | 拦截退回；不改派无协作第三方 | 法务 |
| 已签收 | 非质量问题不支持无理由退；质量问题由**送礼人**发起售后 | 是 |
| 隐价订单 | 售后金额仅送礼人可见 | 是 |
| 唯一编号 / 定制 | 沿用定制不退，编排页强提示 | 是 |

## 11. 非目标 / 风险 / 合规

### 11.1 非目标

- MVP 不做婉拒按钮、转赠、预约开箱；语音礼笺已支持（按住说话 / 听 TA 说）；  
- 不做默认短信催填；  
- 不做晒单比价。

### 11.2 风险

| 风险 | 可能 | 影响 | 缓解 |
|------|------|------|------|
| 分享后无人打开 / 不填址 | 高 | 高 | 强引导分享；催填；7 日自动退；库存锁定期与超时对齐 |
| 唯一件库存空挂 | 中 | 高 | 支付即锁库存；超时释放；运营可配超时天数 |
| 链接被多人打开冒领 | 中 | 高 | 首次「收下」绑定 openid（C10）；失效页 |
| 价格 / 手机隐私泄漏 | 中 | 高 | 角色鉴权；脱敏；分享图审核 |
| 催填骚扰 | 中 | 中 | 日频控 + 自动节点上限 |
| 退款时效投诉 | 中 | 中 | 确认页写清期限；到期有信 |

### 11.3 合规

- 隐价不等于虚假宣传；票据在送礼人侧完整。  
- 未成年人：跟微信支付实名；不做诱导充值礼赠营销。  
- 个人信息：地址手机仅履约；保留周期随订单。  
- 填址前退款与超时退款规则须可公示、客服口径一致。

### 13.2 MVP 验收 Checklist（更新）

**主路径（先付后填址）——必须全过**

- [ ] 默认交付为「邀请 TA 填写地址」；支付无需 TA 地址  
- [ ] 支付成功可分享；另一账号可打开礼笺且**无价格**  
- [ ] 收下 → 填址 → 提交后订单才进入可发货；店长端发货按钮此前禁用

- [ ] 超时未填址：自动退款 + 链接失效 + 送礼人有信  
- [ ] 填址前取消：全额退 + 链接失效  

**并列路径**

- [ ] 快递给 TA（预填地址）→ 支付 → 可发货  
- [ ] 寄给我 → 支付 → 收货  
- [ ] 门店自提代赠 → 备货 → 核销  

**隐私**

- [ ] 收礼人链路与分享图无成交价  
- [ ] 手机号展示脱敏（非编辑态）  

**告知 / 埋点 / 后台**

- [ ] §7.3 相关有信节点写入

| **C11** | **送礼人是否看收礼人手机全号** | 产品 / 合规 | 全号可见（履约需要） |
| **C12** | 礼笺字数上限 | 产品 | 200 |
| **C13** | 店员可否代改地址 | 门店 | 发货前可，记审计日志 |
| **C14** | MVP 是否提供「婉拒」 | 产品 | **否，二期**；过期退即可 |
| **C15** | 运费：填址后若偏远补运费？ | 产品 / 运营 | MVP **下单按默认运费模板锁价**，不二次加收；不可达地址提交时报错换址 |

### 14.3 我的礼赠 · 日子类型（人情账本）

集合 `gift_dates`；由 `manageGift` 的 `listDates` / `saveDate` 读写。类型枚举白名单如下（约 10 项，勿随意堆砌）：

| key | 文案 | 默认礼赠场景 `sceneKey` | 是否强制完整年月日 |
|-----|------|-------------------------|--------------------|
| `birthday` | 生日 | `birthday` | 否（年份可选，作年龄参考） |
| `anniversary` | 纪念日 | `anniversary` | **是** |
| `wedding` | 结婚纪念 | `wedding` | **是** |
| `housewarming` | 乔迁 | `housewarming` | 否 |
| `enrollment` | 升学 | `enrollment` | 否 |
| `graduation` | 毕业 | `graduation` | 否 |
| `new_job` | 入职 | `new_job` | 否 |
| `newborn` | 新生儿 | `gratitude` | 否 |
| `festival` | 节日 | `gratitude` | 否（春节/中秋等写在标题备注） |
| `custom` | 自定义 | `gratitude` | 否 |

临近焦点条 / 列表标签均展示 `typeLabel`；「去礼赠」带入对应 `sceneKey`。UI 用芯片选择，禁止 emoji 图标。
