# 首页配置和状态栏重写说明

**重写日期**: 2025-01-XX  
**状态**: ✅ 已完成重写

## 🎯 重写原因

之前的修复方案未能完全解决问题，存在以下问题：
1. **首页配置无限刷新**：加载锁机制不够完善，仍然可能出现重复调用
2. **状态栏右侧拉伸**：CSS布局问题，固定定位元素在某些情况下被拉伸

---

## ✅ 重写方案

### 1. 首页配置加载逻辑重写

#### 核心改进

1. **使用初始化锁替代配置加载锁**
   - 使用 `_initializing` 锁控制整个初始化流程
   - 使用 `_configLoaded` 标记配置是否已加载
   - 避免在初始化过程中重复调用

2. **简化配置加载流程**
   - 移除复杂的 Promise.race 超时逻辑
   - 统一使用 try-catch 错误处理
   - 一次性设置所有状态，避免多次 setData

3. **分离计算和设置**
   - `computeModuleVisibility()` 只计算，不setData
   - 在 `loadHomeConfig()` 中一次性设置所有状态
   - 避免多次 setData 导致的响应式循环

#### 代码对比

**重写前（问题代码）**:
```javascript
async loadHomeConfig() {
  if (this._loadingConfig) return;
  this._loadingConfig = true;
  try {
    const cached = getCache('HOME_CONFIG');
    if (cached) {
      this.setData({ homeConfig: cached, moduleOrder: ... });
      this.updateModuleVisibility(); // ❌ 可能导致循环
      this._loadingConfig = false;
      this.updateHomeConfigCache().catch(() => {});
      return;
    }
    // ...
  } finally {
    this._loadingConfig = false; // ❌ 可能和上面的提前return冲突
  }
}
```

**重写后（稳定代码）**:
```javascript
async loadHomeConfig() {
  if (this._configLoaded) return; // ✅ 简单标记，避免重复加载
  
  try {
    const cached = getCache('HOME_CONFIG');
    if (cached) {
      const moduleOrder = this.getModuleOrder(cached);
      const visibility = this.computeModuleVisibility(cached); // ✅ 只计算，不setData
      
      // ✅ 一次性设置所有状态
      this.setData({ 
        homeConfig: cached,
        moduleOrder: moduleOrder,
        ...visibility,
        loadingConfig: false
      });
      
      this._configLoaded = true;
      this.updateHomeConfigCache().catch(() => {});
      return;
    }
    // ...
  } catch (e) {
    // 错误处理
  }
}
```

### 2. 状态栏和导航栏布局重写

#### 核心改进

1. **添加状态栏占位**
   - 使用独立的 `status-bar-placeholder` 元素
   - 固定定位，限制最大宽度为 `100vw`
   - 防止内容被状态栏遮挡

2. **修复导航栏拉伸**
   - 添加 `max-width: 100vw` 限制最大宽度
   - 使用 `overflow: hidden` 防止内容溢出
   - 明确指定 `box-sizing: border-box`

3. **添加内容占位**
   - 使用 `content-spacer` 为内容区域提供顶部占位
   - 高度 = `navTop + 44px`（状态栏高度 + 导航栏高度）
   - 避免内容被固定定位的导航栏遮挡

#### CSS对比

**重写前（问题代码）**:
```css
.nav-fixed-wrapper {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%; /* ❌ 可能被拉伸 */
  padding-top: {{navTop}}px; /* ❌ 使用padding可能导致问题 */
}

.nav-bar {
  padding-left: 30rpx;
  width: 100%; /* ❌ 可能被拉伸 */
}
```

**重写后（稳定代码）**:
```css
.status-bar-placeholder {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  max-width: 100vw; /* ✅ 限制最大宽度 */
  box-sizing: border-box;
  overflow: hidden; /* ✅ 防止溢出 */
}

.nav-fixed-wrapper {
  position: fixed;
  top: {{navTop}}px; /* ✅ 使用top定位，不用padding */
  left: 0;
  width: 100%;
  max-width: 100vw; /* ✅ 限制最大宽度 */
  box-sizing: border-box;
  overflow: hidden; /* ✅ 防止内容溢出 */
}

.nav-bar {
  padding-left: 30rpx;
  padding-right: 30rpx;
  width: 100%;
  max-width: 100%; /* ✅ 限制最大宽度 */
  box-sizing: border-box;
  position: relative; /* ✅ 使用相对定位 */
}

.content-spacer {
  width: 100%;
  height: {{navTop + 44}}px; /* ✅ 为内容提供占位 */
}
```

## 🔧 关键技术点

### 1. 初始化锁机制
- `_initializing`：控制整个初始化流程
- `_configLoaded`：标记配置是否已加载
- 下拉刷新时重置所有标记

### 2. 一次性状态设置
- 使用展开运算符 `...visibility` 一次性设置多个状态
- 避免多次 setData 导致的响应式循环
- 减少渲染次数，提升性能

### 3. CSS布局最佳实践
- 使用 `max-width: 100vw` 限制最大宽度
- 使用 `overflow: hidden` 防止内容溢出
- 使用 `box-sizing: border-box` 确保宽度计算正确
- 使用固定定位 + 占位元素，避免内容被遮挡

## 📝 注意事项

1. **初始化锁的使用**
   - 确保在所有退出路径都正确设置标记
   - 下拉刷新时需要重置所有标记
   - 避免在异步操作中忘记设置标记

2. **CSS固定定位**
   - 固定定位的元素需要明确限制宽度
   - 使用占位元素避免内容被遮挡
   - 注意z-index层级关系

3. **性能考虑**
   - 一次性设置多个状态，减少setData调用
   - 后台更新配置使用异步，不阻塞主流程
   - 使用缓存减少网络请求
