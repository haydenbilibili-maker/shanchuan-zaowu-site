# 藏品库 · 「分类管理」顶部切换区重构（2026-10-14 · 第二次）

> 产品负责人真机截图 + 一句话：「藏品库-分类管理顶部的分类切换区域进行一次样式和交互的重构，目前看着比较混乱」。
>
> **根因是我 2026-10-13 那次「视觉一致性」返工**：当时把分区页签也做成了「分段控件」，
> 想靠"大一点 / 小一点"区分层级。真机上失败了 —— 详见 §1。

## 0. 一句话

两排**同款**分段控件叠在一起（上排 4 个页面页签、下排 3 个分区页签，圆角/描边/等宽一模一样），
两排里各有一个「分类管理」都亮着，而下排的金色实底还比上排重 —— **层级被倒过来了**。
改法：层级用「**不同种**」控件表达，而不是「不同程度」。分区页签改成**下划线页签**；
顺带修掉一个更严重的问题 —— 分类树**加载中被画成了「暂无分类，可在下方添加」**（谎报）。

## 1. 为什么"只改大小"必然失败

| | 2026-10-13 那一版 | 现在 |
|---|---|---|
| 页面页签（4 个） | 分段控件：`flex:1` 等分 + 卡片描边 + 圆角 | **不变**（它是页面导航，该稳） |
| 分区页签（3 个） | 也是分段控件：`flex:1` 等分 + 卡片描边 + 圆角，只是字号 22→22、金色**实底** | **下划线页签**：左对齐、宽度由文字决定、无边框、无实底，选中项坐一条金色指示条 |
| 层级靠什么区分 | **程度**（大一点 / 小一点、实底 / 浅底） | **种类**（分段控件 ↔ 下划线页签） |
| 标签 | 「分类管理」「属性维护」「选项维护」 | 「**分类**」「**属性**」「**选项**」 |
| 结果 | 两排长得一样；两排各有一个「分类管理」都亮着；分区那排更重 → 混乱 + 层级倒置 | 一眼看出"我在哪个页面 / 我在这个卡片的哪一块" |

**教训（写给以后的自己）**：同一种控件只改尺寸/底色，在真机上**分不出层级** ——
层级要么换控件种类（分段 ↔ 下划线 ↔ 胶囊），要么用间距/分组容器把它推到另一个层级，
不能只靠"缩小一号 + 换个填充色"。我上一版还在注释里把"大小分段"当成解决方案写下来了，
说明当时是**想清楚了一半**（意识到两排 pill 会重复）却选错了手段。

## 2. 标签去重：两处都叫「分类管理」

页面第 4 个 tab 与分区第 1 个 tab 原先**逐字同名**，而且都在"第三个位置"、都亮着。
现在分区标签收敛成 2 字（分类 / 属性 / 选项），与页面 tab 文案**零交集**。
守卫 E7 会取两排的文案做交集，非空即判红 —— 以后谁再加一个同名分区会被拦下。

## 3. 「同步标准分类」不再当主 CTA

原先是**金色实底**（与"真正的主动作"同一套语言），但它其实是**低频且有副作用**的动作
（按种子停用非标准一级分类）。现在三个维护动作**同级描边**，左侧加一个内联「维护」标签，
把它们与下面的"查找与筛选"分成两组。搜索框 / 排序 chips / 只看空分类仍是原来那套（未改）。

## 4. 顺带修掉的真 bug：加载中被画成「暂无分类」

产品负责人那张截图的底部写着「**暂无分类，可在下方添加**」—— 而分类库明明有 63 条。

- `loadCategoriesManage()` 要跑 **2 次云端查询**（分类树 + 每类件数），期间 `categoryManageTree` 还是空；
- 老代码的分类树区只有两支：`wx:if="{{catTreeView.length}}"` / `wx:else` →
  读取期间直接落到空态，屏幕上写「暂无分类，可在下方添加」。**那不是空态，是谎报。**
- 同一次读取还会让「只看空分类 **0**」显示成**假的 0**。

修法：加 `catTreeLoading`，分类树区改成**三态**，顺序不能反：

```
读取中（catTreeLoading）→ 有数据（catTreeView.length）→ 真的空
```

⚠️ `catTreeLoading` 的清位放在 `finally` 里 —— 否则加载失败时页面会永远停在「读取分类中…」。

## 5. 交互改动

| 改动 | 为什么 |
|---|---|
| 重复点当前分区**直接返回** | 改前每次都会 `setData` + `loadCatZoneData`，「选项维护」的字典会被无谓重拉一遍 |
| 分类树区新增「读取分类中…」 | 见 §4 |
| `catTreeLoading` 失败也落地（`finally`） | 否则失败态与加载态分不开 |
| 页面 tab 记住上次分区 | 行为未变（`catZone` 一直保留），本轮补了注释说明这是**有意**的 |
| 非超管只有一个分区时**不渲染**分区页签 | 行为未变（`wx:if="{{canProductFields}}"`），本轮把它写进证据（`r10-lib-category` 场景） |

## 6. 证据

离线渲染 3 张（`node miniprogram/scripts/render-c-stream-preview.mjs --only r10-lib-category-default,r10-lib-category-loading,r10-lib-category`）：

| 场景 | 看什么 |
|---|---|
| `r10-lib-category-default` | **超管（多分区）**：上排实底分段控件 + 下排下划线页签，两种控件一眼可分；维护动作三颗同级描边 |
| `r10-lib-category-loading` | **产品负责人截图那一屏的修复**：同样位置现在写「读取分类中…」，不再谎报「暂无分类」 |
| `r10-lib-category` | **非超管（单分区）**：只有一排页面页签，**不出现**分区页签（不渲染多余的切换器） |

> 上一次跑这套场景时 `canProductFields: false`，所以**分区页签根本没进图** ——
> 这正是"上一版的问题没被自己的出图发现"的原因。默认态现在改成 `true`。

## 7. 守卫

`check:product-lib-risk` 新增 **E7**（8 条判据，9 条注入）：

| 判据 | 注入（都必须被检出） |
|---|---|
| 分区页签**不许** `flex:1`（等分 = 又变回分段控件） | 给 `.cat-zone-tab` 加 `flex: 1` |
| 选中的分区页签**不许**金色实底 / 渐变 | 给 `.cat-zone-tab.on` 加回 `linear-gradient` |
| 必须有下划线指示条 + 容器有基线 | 删掉 `.cat-zone-tab.on::after` |
| 分区标签与页面标签**零交集** | 把分区「分类」改成「分类管理」 |
| `.cat-sync-btn` 不许金色实底 | 把 `background` 改回 `var(--gold)` |
| 分类树必须有「读取中」态且**排在空态之前** | 删掉 `.cat-tree-loading` 块 |
| `loadCategoriesManage` 真的置位 / 清位 `catTreeLoading` | 删掉 `catTreeLoading: true` |
| 清位必须在 `finally` 里 | 把清位移出 `finally` |
| 重复点当前分区不重拉 | 删掉同值早退 |

`--selftest`：**64 项 / 63 条注入全检出**（本轮 E7 之前是 55 项 / 54 条）。

### 7.1 本轮又修掉 3 处**守卫自身**的毛病（都是"看着在跑、其实没查"）

1. **`methodBody()` 写死了 2 空格缩进** → 本文件里有**顶层（0 缩进）方法**（`loadCategoriesManage` 等，
   `managerPageConfig.js` 是多段对象拼起来的）。写死缩进让那种方法取到**空串**，判据静默失效
   （"loadCategoriesManage 没有置位 catTreeLoading"报了假红，实际是我取不到方法体）。
   现在终止锚点按**起始行自己的缩进**推。
2. **注释顶掉判据（第 3 次了）** → 「读取中必须排在空态之前」这条被**我自己解释性注释**里那句
   「…屏幕上写着『暂无分类，可在下方添加』」命中，`indexOf` 拿到的是注释的位置。
   现在 wxml 的存在性 / 文案 / 计数 / 位置判据**一律走去掉注释的正文**（`wxmlCode`）。
   同类错误已在 `/taxonomy\.kingdom/` 那次出现过一次 —— 这次直接做成了机制，不再逐条去打补丁。
3. **取一排页签用非贪婪匹配停在半路** → `class="sub-tab-row product-lib-tabs"([\s\S]*?)</view>`
   停在第一颗页签的收尾标签上，页面文案取到 0 条；且全文件的 `data-tab=` 有 10 处（别的页签也叫 data-tab，
   不限定范围会算进 10）。现在用**定长窗口** + 限定在藏品库那一排。

## 8. 真机核对点

1. 进「藏品库 → 分类管理」（**超管**）：顶上是**两排**，但一眼能分出层级 ——
   上排是**实底分段控件**（4 个：藏品明细 / 风险管理 / 库存概览 / 分类管理），
   下排是**左对齐的下划线页签**（3 个：**分类 / 属性 / 选项**），只有一条金色指示条，没有方框、没有实底。
2. 两排里**不再有同名文案**（上排叫「分类管理」，下排叫「分类」）。
3. 点「属性」→ 指示条滑到「属性」，下面换成属性维护那一块；点「选项」→ 同理。
   **重复点当前那一项**：页面不闪、不重新转圈（不再无谓重拉字典）。
4. 「维护」这三个动作（同步标准分类 / 补齐拉丁名 / 修复藏品关联）**都是描边**，
   没有任何一颗是金色实底（不再像本页主按钮）。
5. **进「分类管理」的瞬间**：分类树位置写的是「**读取分类中…**」，
   **绝不**出现「暂无分类，可在下方添加」；读完之后才显示分类树。
6. 断网后进「分类管理」：应看到「读取分类中…」→ 提示「加载分类失败」→ **不会**永远卡在「读取分类中…」。
7. **非超管**（只有一个分区）进「分类管理」：**没有**下排分区页签，只有一排页面页签。
8. 搜索「蝶」→ 只剩含蝶的分类并显示匹配计数；「按数量」「按名称」「只看空分类」与树一致；
   「新增分类」里选「所属馆」→ 一级下拉仍是**完整**列表（不被筛选影响）。
9. 原生组件（`switch` / `picker` / `radio`）离线不画，真机才能看（本页的「所属馆」下拉与层级单选）。
