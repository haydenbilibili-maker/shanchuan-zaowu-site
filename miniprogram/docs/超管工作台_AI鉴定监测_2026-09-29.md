# 超管工作台 · AI 鉴定监测（蓝图 + 取证，2026-09-29）

> **产品负责人原话**：小程序「超管工作台」新增「AI 鉴定监测」，能看到用户使用 AI 鉴定（馆藏页搜索栏旁「AI 鉴定」入口）拍摄的全量信息：图片、识别结果等。
> **性质**：新增旁路模块。AI 鉴定链路**不在**稳定期清单（电商 / 礼赠 / 注册登录 / 后台），但仍按「只旁路、不改契约」施工：`identifySpecimen` 的入参、出参、`success` 语义与既有集合写入**逐字不变**。
> **点名范围**：新集合 `ai_identify_logs`（含 `admin/src/cloud.js` 的 `COLLECTIONS` 登记）、新云函数 `aiIdentifyMonitor`、`identifySpecimen` 旁路日志、超管 Hub 入口与新页。

## 1. 取证（只读实测，2026-09-29 12:40）

### 1.1 链路

| 环节 | 位置 | 事实 |
|---|---|---|
| 入口 | `pages/category/index.wxml:19`「AI 鉴定」→ `goIdentify` | `navigateTo /subpackages/feature/identify/index?from=gallery_search`；另有门店码 `store_qr`、搜索页、首页球等 9 种 `entry_source` |
| 拍摄/上传 | `subpackages/feature/identify/index.js` | `wx.chooseMedia` → 压到 ≤2MB → **客户端 `wx.cloud.uploadFile` 到 `identify/<毫秒时间戳>-<6 位随机>.jpg`** → 把 `fileID` 交给云函数 |
| 识别 | 云函数 `identifySpecimen`（超时 60 s） | 下载图片 → 内容安全图检 → 同图缓存（`identification_cache`/`content_hash`）→ `qwen-vl-plus` 视觉识别（URL 失败回退 base64）→ 置信度 ≥0.6 时 `qwen-turbo` 生成科普 → 同物种去重 → 关联商品（`species_product_map` + `products` 模糊）/ 百科 → **新建 `identification_records`** |
| 结果 | `identify/result` 页 | 按 `record_id` 走 `get_record`（本人或已分享） |

### 1.2 落库现状

| 集合 | 线上条数 | 说明 |
|---|---|---|
| `identification_records` | **214**（130 名用户，最早 2026-03-22，近 7 日 ≈ 110） | 字段：`_openid`、`image_url`(= fileID)、`species_info`（中/拉/英名、分类、`confidence`、`is_specimen`、`alternatives`）、`ai_content`（12 段科普）、`related_products_snapshot`、`related_wiki_snapshot`、`confidence_level`、`entry_source`、`category_hint`、`created_at` 等 |
| `identification_cache` | 210 | 同图指纹 → record_id |
| `identification_feedback` | 2 | 用户纠错 |
| `user_collection` | 36 | 入图鉴 |

**缺口（这正是「全量」看不到的部分）**：

1. **失败不落库**：图检拒绝、读图失败、模型报错/超时、未配密钥 —— 直接 `return {success:false}`，没有任何记录；
2. **复用不落新记录**：同图缓存与同物种去重命中时只在旧记录上 `reuse_count+1`，**这次拍的新照片 fileID 丢失**（文件仍在云存储，但没有任何指针指向它）；
3. **没有耗时、没有模型名**；
4. 规则 `doc._openid == auth.openid` → 本来就只有本人与云函数可读，超管也看不到他人记录。

### 1.3 图片与云存储

- 图片**本来就由客户端上传到云存储**（`identify/` 前缀，214/214），抽检 3/3 文件仍在 → **不需要新增上传，对鉴定耗时零影响**。
- 云存储全局权限（线上 `getStorageAcl`）= **`READONLY`**（所有用户可读、仅创建者可写）。实测：
  - 桶列举（`tcb.qcloud.la/?prefix=identify/`、COS 源站）→ **403 AccessDenied**，**不可被公开列举** ✅；
  - 已知完整路径的**无签名直链 HEAD → 200**：知道 fileID 的人可以直接看图。路径 = 毫秒时间戳 + 6 位 base36 随机（≈ 21 亿种/毫秒），**实际不可枚举**；fileID 只出现在本人可读的记录与本人主动分享的结果里。
  - 这是**全局设置**（商品图等所有公开图同一开关），本需求**不改**；收紧方案见 §6「需点名」。
- 新集合只存 fileID、规则全拒，**不新增任何图片暴露面**；监测页只拿 10 分钟临时链接。

## 2. 方案

### 2.1 旁路日志（`identifySpecimen`）

- 原 `exports.main` 函数体**一行不改**，只改名为 `identifyMain`；新 `exports.main` 包一层：
  `const res = await identifyMain(event, context)` → 若是**鉴定调用**（无 action 或 action 不在既有 7 个动作里 —— 与原分支判定同口径）则写一条 `ai_identify_logs` → **原样返回 `res`**（同一对象引用）。
- 写日志：`identifyLog.js`（新文件）组装 + `Promise.race` 1.5 s 上限 + `try/catch` 吞错。**写失败 / 超时 / 组装抛错都不影响返回**；`identifyMain` 自身抛错时照样记一条失败日志后**原样重新抛出**。
- 其它 7 个动作（列表、分享、入图鉴、纠错…）**不写日志**。
- **耗时影响**：同区域一次 `db.add` 通常数十毫秒，而鉴定本身 15–60 s；最坏被 1.5 s 上限截断。上线后以「快速失败路径」前后对比实测（§5）。**若实测增加 >300 ms 则不上线**。

### 2.2 `ai_identify_logs` 字段

| 字段 | 说明 |
|---|---|
| `openid` | 调用者（不用 `_openid`，避免与客户端规则语义混淆） |
| `image_file_id` | 本次照片 fileID（复用命中时也是**本次**这张） |
| `status` | `success`（新识别）/ `reused`（同图或同物种复用）/ `failed` |
| `success` | 与原出参 `success` 同值 |
| `error_msg` | 失败原因（原出参 `msg` 或异常 message，≤300 字） |
| `record_id` | 对应鉴定记录（失败为空） |
| `reuse_reason` | `same_image` / `same_species` / `''` |
| `species_name_zh` / `species_name_latin` / `confidence` / `confidence_level` / `is_specimen` | 结论摘要（列表用） |
| `species_info` / `ai_content` | 识别结果全文 |
| `related_products` | 匹配商品 `[{_id,title,price,cover}]`（≤6） |
| `model` / `text_model` | `qwen-vl-plus` / `qwen-turbo`；`use_mock` 时为 `mock` |
| `duration_ms` | 函数内耗时（不含写日志本身） |
| `entry_source` / `category_hint` | 入口来源 / 用户选的类别 |
| `created_at` / `day` | 毫秒时间戳 / 北京时间 `YYYY-MM-DD` |
| `source` | `live`（上线后实时）/ `history`（历史回填） |

规则：`{"read": false, "write": false}`（客户端读写全拒，仅云函数）。登记 `cloudbase/sensitive-collections.json` 的 `serverOnly`（用户照片 = 敏感）。

### 2.3 历史数据

一次性脚本 `miniprogram/scripts/backfill-ai-identify-logs.mjs`（默认 dry-run，`--apply` 才写）：把 `identification_records` 214 条按 `hist_<record_id>` 固定 `_id` 写进新集合（`source:'history'`，无耗时/模型，状态 `success`），**只写新集合、不改任何旧数据**，可重复执行不重复写。历史里的失败与复用调用**无从恢复**，监测页空态与列表底部如实说明「上线前只保留了成功新建的鉴定」。

### 2.4 读取：新云函数 `aiIdentifyMonitor`

- 鉴权：`staffGuard.assertStaff(db, openid, { requireSuperAdmin: true })`（与 `secureDataRead` ERP 动作同一判定；**不收 adminOpsKey**，只认小程序身份）。
- 动作：
  - `overview`：今日 / 近 7 日次数、7 日成功率、今日 / 7 日人数、累计（只聚合数，**不审计**）；
  - `list`：日期区间（北京时间）、状态（全部 / 成功 / 失败）、用户（手机号 / 昵称 / openid）、分页 20 条；返回缩略图临时链接、结论、用户（昵称 + 脱敏手机号）、时间、状态；
  - `detail`：原图临时链接、完整识别结果、匹配商品、耗时、错误、同记录的用户纠错。
- **审计先行**：`list` / `detail` 读数据前先写 `admin_operation_logs`（`module:'privacy'`，`action:'view_identify_logs' | 'view_identify_detail'`，惯例同 `secureDataRead` reveal），**审计写失败即拒绝**。
- 临时链接 `maxAge` 600 s；列表缩略图在临时链接后拼 `imageMogr2/thumbnail/240x>`，加载失败页面回落原图。

### 2.5 页面 `subpackages/manager/identify-monitor/`（超管分包，不进主包）

- 入口：超管 Hub「会员与触达」分区磁贴「AI 鉴定」（`MENU_KEYS.AI_IDENTIFY_MONITOR`，只在超管菜单；店长菜单不含）；页内 `guardStaffPage('super_admin')`；云函数再执法。
- 结构：顶部概览 5 格 → 筛选条（日期 / 状态 / 用户）→ 列表（缩略图、结论、置信度、用户、时间、成功/复用/失败标记）→ 分页「加载更多」→ 详情抽屉（大图可 `previewImage`、完整结果、匹配商品跳商品详情、耗时、错误、纠错）。
- 约束：暗色金调（`ops-museum` / `ops-dashboard`）、反馈走页内提示条（**不新增 `wx.showModal`/`showToast`**）、界面不出现集合名 / 字段名、多列网格用百分比 + `space-between` 留余量（E26）。

## 3. 守卫：`test:ai-identify-monitor`（manager 域，带 `--selftest`）

真跑 `identifySpecimen` / `aiIdentifyMonitor` 真源（内存 mock `wx-server-sdk`），断言：

1. 旁路：日志写入抛错 / 挂起 → 出参与原函数**逐字相同**、且在上限内返回；非鉴定动作不写日志；原函数抛错时照样抛；
2. 日志字段：成功 / 复用 / 失败三态、fileID、模型名与 `index.js` 调用处一致；
3. 鉴权：非超管 `list`/`detail`/`overview` 全拒且**零读取**日志集合；超管放行；审计写失败即拒且不读；
4. 规则：两处（仓库规则 + 敏感清单 `serverOnly`）全拒；客户端（小程序 / ERP）不得直读该集合；
5. 页面：在超管分包、只调 `aiIdentifyMonitor`、无原生弹窗、无集合名文案；菜单键不在店长菜单。

`check:sensitive-rules` 新增判据：`serverOnly` 里的集合规则必须 `read:false` 且所有写字段 `false`，且不得进 ERP 只读网关（+注入）。

## 4. 隐私合规（**只拟稿，不改协议正文**）

现行《隐私政策》（`subpackages/content/utils/legalContent.js`）已覆盖：摄像头/相册用途、照片传至通义千问、「AI 鉴定记录**未分享时仅您本人可见**」、「仅在必需期限内保留」。
**未覆盖**：①平台保存鉴定照片与结果用于服务质量监测 / 识别准确率改进；②经授权的管理员可查看；③明确保留期限。上线后「仅您本人可见」字面上与事实不符，建议补充（由产品负责人决定）：

> **「二、我们收集的信息」— 替换 AI 鉴定可见范围一条：**
> AI 鉴定记录的可见范围：未分享时，其他用户无法查看您的鉴定照片与结果；当您主动分享（转发给好友 / 分享到朋友圈 / 生成海报）后，该条鉴定结果对获得该分享链接或海报二维码的人可见。为保障服务质量，经授权的少数管理人员可在后台查看鉴定照片、识别结果与调用记录，每次查看均留存审计记录。
>
> **「三、信息的使用」— 新增一条：**
> 您在 AI 标本鉴定中拍摄或上传的照片、识别结果及调用记录（时间、耗时、是否成功），会被我们保存并用于排查识别故障、评估与改进识别准确率及服务体验；我们不会将其用于与上述目的无关的用途，也不会公开展示未经您分享的照片。
>
> **「五、存储与安全」— 新增一条：**
> AI 鉴定照片与调用记录自上传之日起保存 **180 天**，到期后删除或匿名化处理；您已保存到山海图鉴或主动分享的鉴定结果，在您删除或申请删除前继续保留。您可通过「联系专员」申请提前删除。

保留期限建议：**调用日志与照片 180 天**（覆盖两个季度的识别质量对比；过长增加泄露面）；到期清理需另做定时任务（本期不做，见 §6）。

## 5. 上线步骤与验收

1. 建集合并应用规则：`cd admin && node scripts/apply-database-rules.mjs --only ai_identify_logs`；
2. 部署（只本流）：`bash miniprogram/scripts/deploy-drifted.sh identifySpecimen aiIdentifyMonitor`；
3. 耗时实测：`identifySpecimen` 快速失败路径（不存在的 fileID）部署前后各 5 次对比；
4. 历史回填：`node miniprogram/scripts/backfill-ai-identify-logs.mjs --apply`；
5. 真实调用 `aiIdentifyMonitor`：非超管身份被拒；
6. 小程序新版上传后真机：超管 Hub → 会员与触达 →「AI 鉴定」。
