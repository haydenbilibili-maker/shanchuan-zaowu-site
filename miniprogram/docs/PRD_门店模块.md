## 2. 背景与问题陈述

### 2.1 业务诉求

山海造物已在**长春这有山**运营线下空间，并规划/已开设**两家门店**。小程序当前存在三类缺口：

| 缺口 | 现状 | 问题 |
|---|---|---|
| **门店存在感弱** | 地址散落在「关于品牌」、联系专员配置中 | 用户不知道有两家店、各自卖什么、如何到达 |
| **预约占 Tab 过重** | 底部 Tab 独立「预约」 | 预约是**到店服务的子集**，却占据一级入口；参观频次低于探索 / 馆藏 |
| **展陈无法线上预览** | 无「门店长什么样、有什么柜区」 | 无法承接商场导流与「先逛再约」的决策路径 |
| **多店未建模** | 代码中两处地址不一致 **【待统一】** | 无法按门店展示活动、预约库存、工坊承接 |

### 2.2 现状诊断（基于代码）

| 维度 | 现状 | 说明 |
|---|---|---|
| 底部 Tab | 探索 / 馆藏 / **预约** / 购物车 / 我的 | `app.json` + `custom-tab-bar` |
| 预约页 | `pages/booking/index` | 入店参观、手作课程、特别活动、预约历史 四 Tab |
| 我的预约 | 资产宫格「我的预约」→ `subpackages/business/my-bookings` | 已有入口，缺「发起预约」主路径 |
| 关于品牌 | `subpackages/business/about` | **单店**硬编码坐标与地址 |
| 专员配置 | `getSupportConfig` 默认地址 | 这有山山坡 X-06-1 |
| 预约数据 | `bookings` 集合 | **无 storeId** 字段 |
| 店长后台 | 活动 `activities`、预约核销 | 未区分门店 |

**结论**：应用 **「门店一级 Tab + 预约并入我的」** 的信息架构；以**门店**为线下服务的聚合页，以**我的**为个人服务（含预约）的聚合页。

## 3. 产品定位

### 3.1 一句话定位

> **门店 Tab = 把「这有山里的山海造物」搬进手机——选一家店，看展陈、查信息、约到店。**

### 3.2 与相邻 Tab 的分工（变更后）

| Tab | 定位 | 与门店关系 |
|---|---|---|
| 探索 | 品牌门面、内容分发 | 可跳转「默认门店 / 活动」 |
| 馆藏 | 内容馆 + 品类导购 | 商品可标注「哪家门店可体验」**【P2】** |
| **门店** | **线下空间前台**（本 PRD） | — |
| 购物车 | 待结算 | 到店自提可关联门店 **【P2】** |
| **我的** | 账户 + **个人服务（含预约）** | 我的预约、票券、到店记录 |

### 3.3 北极星指标（建议）

| 指标 | 说明 |
|---|---|
| 门店 Tab 有效访问率 | 进入门店 Tab 且切换门店 / 点击导航 / 发起预约 UV |
| 预约创建来源分布 | 门店 Tab vs 我的 vs 定制/伴宠跳转 |
| 展陈详情完读率 | 用户浏览展陈介绍的比例 |
| 导航 / 拨号点击率 | 到店转化意图 |
| 多店切换率 | 用户是否主动对比两家门店 |

## 4. 设计原则

1. **Walk-in First** — 门店页首要回答「在哪、几点开、有什么可看」，而非直接推销售。
2. **One Store at a Time** — 任意时刻只强调**一家**门店内容；切换需明确、状态可记忆。
3. **Museum, Not Mall Directory** — 展陈介绍用策展语言（柜区、主题、物种故事），禁止促销横幅堆砌。
4. **Booking as Service** — 预约是到店手段，入口在门店与我的两处可达，不占 Tab。
5. **Same Language Offline-Online** — 门店名称、楼层、柜区命名与线下导视 / 店员话术一致 **【待确认】**。
6. **Graceful Single-Store** — 架构支持 N 店，但 MVP 仅配置 2 店；仅 1 店营业时隐藏切换器。

## 6. 信息架构

### 6.1 导航变更

```
变更前 Tab：  探索 | 馆藏 | 预约 | 购物车 | 我的
变更后 Tab：  探索 | 馆藏 | 这有店 | 购物车 | 我的
```

| 变更项 | 处理方式 |
|---|---|
| `pages/booking/index` | **保留页面**，从 Tab 移除；改为普通页面（`navigateTo`） |
| 预约历史 Tab | 合并至 `my-bookings`；booking 页内 Tab3「预约历史」可弱化或移除 |
| Tab 图标 | 暂用 `exhibition-tab.png` / `exhibition-tab-active.png`；后续可交付专用图标 |
| 旧入口 `switchTab` 至 booking | 已替换为 `store` 或 `navigateTo` booking **【M1 已完成】** |

### 6.2 「我的」预约合并方案

| 区域 | 内容 |
|---|---|
| 资产宫格（已有） | **我的预约** — 数量 + 跳转 `my-bookings` |
| 新增服务行 | **预约参观** — 跳转 `pages/booking/index?tab=0&from=user`（预填记忆门店） |
| 新增服务行 | **手作课程** — 跳转 booking Tab1（预填星宸工坊） |
| 站内信 | 预约提醒类消息不变，链接仍指向票券 / my-bookings |

**booking 页四 Tab 迁移建议**：

| 原 Tab | 迁移后入口 |
|---|---|
| 入店参观 | 门店 Tab 主 CTA + 我的 → 预约参观 |
| 手作课程 | 门店 Tab「本店活动」+ 我的 → 手作课程 |
| 特别活动 | 门店 Tab 活动区 + 探索联动 |
| 预约历史 | **仅** 我的 → 我的预约（booking 内可保留快捷链） |

## 11. 视觉与文案

### 11.1 Museum Mode 要点

- 背景 `#1A1814`，卡片 `#1F1D1A`，强调 `#C4A76C`
- 门店封面：实景暗调 + 暖光，禁止纯白带大量促销字
- 展陈卡片可用品类色作 Overline / 标签（见 Design System §2.4）
- Tab 文案：**门店**（非「店铺」「专卖店」）

### 11.2 文案禁忌

- 禁止「爆款门店」「打卡必去」等直播电商话术
- 用「参观 / 走入 / 展陈 / 柜区」，不用「卖场 / 货架」
