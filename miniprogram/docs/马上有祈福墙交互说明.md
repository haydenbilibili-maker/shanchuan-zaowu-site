# 马上有祈福墙 交互与视觉说明

> 页面：`subpackages/feature/wish-wall/index`（需求 28「马上有 · 弹幕祈福墙」）
> 入口组件：`components/WishWallEntry/index`
> 布局基座：`utils/wishWall.js`（`buildDanmakuRows` / `danmakuClearMs` / `danmakuCycleEndMs`）
> 守卫：`npm run test:wish-wall`（223 项断言 + 26 个回归注入自检）

## 1. 为什么重做：原样是「灾难现场」的四个根因

业务方原话「现在的样式简直是一个灾难现场」。逐项取证后，四个根因**都可证**：

| # | 根因 | 后果 | 取证 |
|---|------|------|------|
| 1 | 点灯卡片命名为 `.lamp`，**与 `app.wxss` 的全局信号灯基类 `.lamp` 同名** | 全局给 `.lamp` 定了 `width/height: 12rpx; border-radius: 50%; flex-shrink: 0`，而页面只写了 `padding/display` → 卡片被压成 **6px 宽竖条**，文案一字一行并被裁切 | 浏览器实测：卡片 **30×28px**，文案列 **0px** |
| 2 | 弹幕同轨间隔写成固定 `LANE_GAP_MS = 900ms`，而单条穿越要 **6–26 秒** | 4 条轨道各叠 4 条，整面墙糊成一坨 | 浏览器实测：同轨**可见重叠 2 对**（16 条） |
| 3 | 标题拼成 `{{productTitle}} · 祈福墙`，而入口传进来的 title 本身就含「马上有」 | 出现「马上有 · 祈福墙」，且 40rpx 长标题折行 | 浏览器实测标题文本 `马上有 · 祈福墙` |
| 4 | 全站只有信号灯的「灯」是圆的，页面却拿「灯」当卡片名 | 与 Museum Mode 的纸质/铜牌语言完全脱节，深色圆角块堆叠 | 目视 |

**守卫为什么没拦住**：原测试的「同轨道不重叠」断言是
`rows[0].delayMs < rows[2].delayMs || rows[0].lane !== rows[2].lane` —— 对 ≤4 条**恒真**（lane 不同就通过）。
本轮已换成真判据（见 §4）。

## 2. 重做的设计：牌匾 → 灯龛 → 纸墙 → 写愿 → 愿签

```
┌ 牌匾（浅纸 + 铜字）  WISH WALL · 马上有愿 ●  ─────────────┐
│   山海造物 / 祈福墙  [马上有]                              │
│   把想成真的心愿挂上墙。轻一点写，短一点说。                 │
├ 灯龛（深卡 + 暖光）  ◉ 今日灯已点 / 愿今日有风，也有归处。   │
├ 纸墙（浅纸 + 深字弹幕）  4 条轨道，左侧刻度，底部「N 条正在流动」│
├ 写愿（深卡）  灵感 chips → 输入框 + 挂上墙 → 0/30            │
└ 愿签（深签卡）  左侧铜线 + 右上铜钉 + 馆方/置顶印章            │
```

设计取舍：

- **浅纸只给「牌匾」和「墙面」两块**。墙面必须是浅底：弹幕是深字浅底才读得清（原设计深底浅字 + text-shadow，
  在 4 轨重叠时必然糊）。其余交互面维持深卡，避免整页发白。
- **牌匾与礼赠页的「标本纸页头」同一语言**：`linear-gradient(165deg,#FAF6ED,#F2EDE4,#EDE6DA)` +
  `#E0CFA3` 描边 + 纸纤维（浅底必须 `mix-blend-mode: multiply`）+ 压印内框 + 右下标本水印 + 铜印。
- **主标题固定「祈福墙」**，入口传来的产品名降级为一枚铜色小签（`ww-scope`），从结构上消灭重复。
- **灯龛把光晕放进固定尺寸的灯座盒**（`ww-lantern-box` 56×56rpx），行内不再出现绝对定位元素；
  文案列 `flex:1 + min-width:0`。这是对根因 1 的结构性防御：即便将来又撞上某个全局类，也不会再把文案挤成竖排。
- **愿签**用衬线正文 + 左侧铜线（签绳）+ 右上铜钉 + 印章，读起来是「签」而不是「列表项」。
- 信号灯沿用全站语义类（`lamp-brass` / `lamp-muted hollow` / `lamp-warn`），
  浅纸上额外加深铜描边（`#C4A76C on #FAF6ED` 几乎看不见）。

## 3. 弹幕排期：同轨「尾部离开右边缘」才准下一条进场

```
时长      danmakuDurationMs(text) = (屏宽 750 + 字数×28) / 90 rpx/s，限 6–26s  （视觉匀速）
进场清空  danmakuClearMs(text)   = 时长 × 文案宽 / (屏宽 + 文案宽)
                                  —— 头部走完「文案宽」时，尾部才离开右边缘
排期      laneNextAt[lane] = delay + clearMs + LANE_GAP_MS(520)
```

- `LANE_GAP_MS` 从「两条的进场间隔」降级为「尾部离开后再留的空白」，真正的间隔由 `clearMs` 承担。
- **只播一轮**（`animation-iteration-count: 1` + `animation-fill-mode: forwards`）：
  每条时长不同，各自 `infinite` 会越走越错位，第二轮起同轨又叠。整批重排放在 JS：
  `scheduleDanmakuCycle()` 在 `danmakuCycleEndMs(rows) + CYCLE_PAUSE_MS(1400)` 后重建 rows，
  轮次进 `rows[].key`（同 key 不会重播动画）。切后台/卸载清定时器。
- 轨道刻度（`.ww-wall-rail`）**挂在 `.ww-wall-inner` 内**：与弹幕同一坐标系。
  挂到 `.ww-wall` 上会因底部页脚（44rpx）逐轨错开，第 4 条差 18px（已实测）。

## 4. 验收方式

1. `npm run test:wish-wall` —— **274 项**断言。第一轮新增：
   - **真·同轨不重叠**：造 16 条压满 4 轨，逐对断言
     `下一条 delay ≥ 上一条 delay + 上一条 clearMs`（旧断言对 ≤4 条恒真，正是它放行了事故）；
   - **全仓撞车守卫**：`app.wxss` 里「裸选择器且带死尺寸」的类（如 `.lamp`），
     不得被任何页面拿**同名裸类**去搭容器（写了 `display:flex`/`padding` 却没写 `width`/`height`）——
     这正是根因 1 的一般化。有意复用 `.btn-primary` / `.signal-light` 等共享工具类不受影响；
   - 结构性断言：本页不得再定义 `.lamp`；标题固定「祈福墙」；弹幕 `iteration-count: 1` + `forwards`；
     光晕必须是灯座盒的子元素；文案列 `flex:1`；轮播已接线（含 `applyItems` 调用点）；刻度四条与 `LANES` 一致。
   - **对标 6 项**：页面底色走 token、下拉样式、骨架（含 shimmer 动画名）、重试入口、
     三段互斥（失败不与空态同屏）、按钮 48% 配方与色阶 token。
   - **第四轮（详情页位置）**：入口唯一且在 `.content-body` 首个子节点/价格卡之前、旧位置已清空、
     间距在宿主包裹层（组件根零外边距）、`ext-class` 口子仍在、首屏位 `compact`、
     灯用三层选择器、`applyDisplayFlags` 重测锚点、三个 `#section-*` 锚点都在。
   - **第三轮**：`--font-hand` 存在且弹幕/愿签都用它、弹幕字号 28rpx；
     `LIST_LIMIT === 云函数 LIST_MAX`、请求上限不硬编码；
     `splitTagColumns` 行为（5 条 → 3+2、不丢项、按下标奇偶、确定性、空/null 安全、列数可覆写）、
     `isTagListCapped` 边界（29/30/31/0/null）、两列 flex 列而非 flex-wrap、收尾条与"仅展示最近 N 条"。
   `--selftest` **41 个注入**必须全部被检出（含 `entry-buried-again`、`slot-margin-dropped`、
   `compact-dropped`、`flags-no-remeasure`、`lamp-specificity-dropped`、
   `lane-overlap`、`danmaku-infinite-loop`、
   `lamp-class-collision`、`title-duplication`、`no-danmaku-cycle`、`page-bg-divergence`、
   `error-shown-as-empty`、`no-retry-entry`、`skeleton-removed`、`global-layer-collision`、
   `handwriting-dropped`、`list-limit-drift`、`tags-single-column`、`no-end-marker`、`cap-lies`）。
2. `npm run lint:wxml`。
3. 浏览器实测（一次性，不在仓内）：真 WXML + 真 WXSS + 真 `applyGate`/`applyItems` 渲进无头 Chrome，
   **把整页动画冻结到同一时刻**再量（否则量不到「同轨是否重叠」），并对 `/tmp` 里的旧版做对照：
   - 旧版：点灯卡片 **30×28px**、文案列 **0px**、同轨可见重叠 **2 对**、标题「马上有 · 祈福墙」；

## 5. 对标全站（第二轮：设计系统与同族页对齐）

方法：先写一个**量化对标脚本**，拿 8 个参考页（礼券夹 / 钱包 / 我的礼赠 / 积分 / 我的 / 首页 / 订单）
统计站点约定，再逐项比祈福墙；同时跑仓内现成的两个规范工具
（`normalize-style.mjs --copy` / `--colors`）。结论是 **6 项真实偏离**：

| # | 偏离（有证据） | 站点基线 | 修法 |
|---|---|---|---|
| 1 | `page { background: #14120F }` —— **全仓唯一**，而本页 `index.json` 自己写的是 `#1A1814`（自相矛盾） | 6/8 参考页用 `#1A1814`；钱包直接用 `var(--color-bg)` | 改用 `var(--color-bg)` |
| 2 | 开了下拉刷新但没给 `backgroundTextStyle` | 同族三页（礼赠/钱包/礼券夹）都有 | 补 `backgroundTextStyle: light` + `backgroundColorTop/Bottom`（否则深底上转圈几乎看不见） |
| 3 | 加载中只有一行字 | 钱包/礼赠/首页都有骨架；全局有 `@keyframes skeleton-shimmer` | 墙面 4 条轨道骨架（纸色微光）+ 愿签 3 张骨架卡（铜色微光，同 `wallet-leather-skel`） |
| 4 | 加载失败无重试入口 | 礼券夹/礼赠/积分/首页/订单五页都有「再试一次」 | 错误块 + `再试一次` → `refresh()` |
| 5 | **失败被显示成空墙**：`loadError` 时同时渲染「墙面还是空的 / 做第一个许愿的人」与「还没有人许愿」 | — | 骨架 → 错误 → 列表/空态三段互斥；墙面在失败时改口径为「墙面未展开 / 网络或权限异常，可在下方重试」 |
| 6 | 黄铜色阶硬编码 7 个色值、主按钮渐变 stop 写成 `52%` | `app.wxss` 有完整 `--brass-50..900`；全站黄铜主按钮配方是 `160deg / 48%` + 描边 + 顶部内高光（3 处一致） | 色值全部换 token；按钮对齐 48% 配方 |

**故意不改的两处**（比对后确认是站点惯例，不是偏离）：

- 空态手写 `.xx-empty` 而不是用全局 `.empty-state` —— 礼券夹/钱包/礼赠**都**是手写（纸质空态标记），
  只有旧页面用全局三件套。跟随同族惯例。
- 计数用弱化文本而不是 `.meta-progress` —— 同族的「礼赠」页计数就是 `.list-count` 弱化文本。
- 另外确认：同族页**都没有** `onShareAppMessage`，所以本页不分享也是惯例（分享在详情页）。

**顺带修掉一个我自己守卫的漏洞**：撞车守卫原先只扫 `app.wxss` 正文，
而 `styles/badges.wxss` 是 `@import` 进来的 —— 整个 badge 家族（`.badge-outline-brass` 等，
`min-width+height` 有死尺寸）都扫不到；且规则解析用了 `(^|})…{…}` 的写法，
`g` 模式下匹配完一条会把游标推到该条的 `}` 之后，**每隔一条规则才被检查**（只覆盖一半）。
现在改成真扫描器（`parseRules` + 去 at-rule），并覆盖 `@import` 层；
新增注入 `global-layer-collision` 证明它确实能看见那一层。

## 6. 手写体与愿签两列瀑布（第三轮）

### 6.1 弹幕与愿签正文改手写体

**做法：设计系统新增 `--font-hand`（`app.wxss`），走系统字体栈，不下载 webfont。**

```css
--font-hand: "HanziPen SC", "Hannotate SC", "Weibei SC", "STKaiti", "Kaiti SC", "KaiTi", "楷体",
  "Source Han Serif SC", "Noto Serif SC", "Songti SC", Georgia, serif;
```

- 为什么不用 `wx.loadFontFace` 拉手写体：全仓**没有任何字体资产与加载先例**，字体一律走系统栈
  （`--font-brand` / `--font-heading` / `--font-body` / `--font-mono` 都是）。下载 webfont 会引入
  CDN 资产、首屏闪烁与失败态，收益只是"Android 也有楷体"。
- **平台差异（必须知道）**：iOS/macOS 命中汉仪手写体与签笔（实测渲染器用的是 `HanziPen SC`）；
  Android 没有楷体系列 → 落到思源宋体再落 `serif`。**手写感在 iOS 最足，Android 是衬线兜底**，两端都可读。
- 弹幕字号 26rpx → **28rpx**：手写体笔画细，移动中要认得出。
- 愿签正文同样用 `--font-hand`（30rpx）—— 弹幕与愿签是**同一批心愿**，都该是"写上去的"；
  昵称/时间等元信息仍用无衬线，保证可读。

### 6.2 愿签：单列无尽滚动 → 两列瀑布 + 明确收尾

先纠正一个前提：**服务端根本没有分页**（`manageWishWall` 的 `LIST_MAX = 30`，`listPublic` 只接受
`limit`，没有 `skip`/`cursor`）。所以「无限下拉」是**观感**——30 张全宽卡片拉出一条看不到头的列表，
不是真的无限加载。据此做三件事：

| 改动 | 理由 |
|---|---|
| **两列瀑布**（`splitTagColumns`，按下标奇偶分列） | 4–6 字的文案占满整行是浪费；两列后滚动长度减半，且更像"一面贴满愿签的墙" |
| **不用 flex-wrap 两列** | 文案长度 2–30 字差异大，按行对齐会出现成片空洞；瀑布列内纵向堆叠才贴得住（实测变长内容下两列底部差 540px） |
| **收尾条 + 诚实口径** | 到底了要看得出来：「已到墙底 · 共 N 条」；打到服务端上限时改说「已到墙底 · **仅展示最近 30 条**」，不装作全量 |
| 签面重排 | 顶部留 48rpx"顶带"放左铜钉与右印章（原 34rpx 时印章压行盒 5rpx，46rpx 仍差 0.5rpx —— Android 字体回退会真的压上，故留 2.8rpx 余量） |

`LIST_LIMIT` 与云函数 `LIST_MAX` **必须相等**（请求上限与"是否只展示了最近 N 条"共用它），
守卫**直接读云函数源码比对**，防两端漂移。

## 7. 商品详情页入口位置（第四轮）

**改动：`<wish-wall-entry>` 从「藏品参数之后 / 图文详情之前」搬到「头部主 SKU 商品图正下方」
（`.content-body` 首个子节点，价格卡之前）。** 原位置在参数区深处，等于没人看得到。

搬完后有三处连带问题，都已在代码里处理并被守卫钉住：

| 问题 | 处理 |
|---|---|
| **首屏最贵的一块地**：三行卡片会把价格卡挤出首屏 | 新增 `compact` 一行版（灯 + 品牌 + 标题 + 箭头，不显示 desc）。实测：一行版入口 **47px**、价格卡顶 **534px** < 667px 折叠线；完整版 66px → 价格卡 553px |
| **间距归属**：组件与宿主都设 margin 时谁生效**不保证** | 间距改由**宿主自己的包裹 view**（`.wish-wall-slot { margin: 24rpx 0 }`）承担，组件根节点 `margin: 0`。切片实测过：用 `ext-class` 传间距时，宿主的 `margin-top` 会被组件样式吃掉（渲染成 0） |
| **三个页签锚点整体位移一个入口的高度** | `applyDisplayFlags` 里开关一翻转就重测 `computeSectionTops()`（原实现只在 onReady / 商品加载后测，开关后到时会错位） |

另外两个踩过的坑（都已修 + 守卫）：

- **灯被全局类压回空心圈**：全局是 `.signal-light.lamp-brass`（两个类），组件里写单类 `.wish-wall-entry-lamp`
  会被按特异性压过 → 必须用三层选择器 `.wish-wall-entry .wish-wall-entry-row .wish-wall-entry-lamp`
  （实测：单类时灯是 `rgb(196,167,108)` 空心描边，三层时才是实心 `rgb(168,144,60)` + 深铜描边）。
- **`ext-class` 仍然保留**（站点惯例同 `components/NavBack`），但只用于宿主"改皮肤"，不用于间距 ——
  API 的优先级不保证，就不该拿它承担布局。

**验收方式**：用**真实组件 WXML/WXSS + 真实详情页 WXSS**做「主图 → 入口 → 价格卡」切片渲染
（只简化主图与价格卡内容），量：主图→入口 **12px**、入口→价格卡 **12px**、入口高 **47px**、
入口两侧 12~363px（与价格卡对齐）、价格卡顶 534px 在首屏内、无横向溢出；
并与完整版对照（66px / 553px）证明"首屏位必须 compact"。

> 这轮还吃了两个"静默失败"的教训：① 一次对详情页 WXSS 的替换因断言写错对象而**没生效**，
> 是切片渲染量到间距为 0 才暴露；② 守卫里新块重复声明了同名变量，靠 lint 报错才发现。
> 结论：改样式后**必须量几何**，`grep` 通过不等于改上了。
