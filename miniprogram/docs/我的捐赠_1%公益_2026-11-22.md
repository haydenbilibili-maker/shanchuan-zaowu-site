# 我的捐赠 · 1% 公益（2026-11-22）

> 产品负责人原话：「在我的钱包页面新增我的捐赠查询入口，将 1% 捐赠的公益逻辑做重点展示，即客户累计总支付金额的 1% 将由山海万物公益基金代为捐赠，详细规划这个栏目，进行重点功能设计与展示。」

## 一、定位

- 把品牌承诺「取自山海，还于自然」从下单页的一行脚注，变成每位顾客**看得见、算得清、可追溯**的个人账本。
- 一句话规则：**您在山海造物小程序的累计实付金额，其 1% 将由山海万物公益基金代为捐赠。**
- 三条原则：
  - **只陈述能兑现的事**：页面金额是按口径算出的应捐额；拨付和凭证以年度捐赠报告为准。不写「已捐」，不编受捐机构，不做「折合几棵树」这类换算。
  - **与店内账本同口径**：B 端 `pledgeDue` 与 C 端「我的捐赠」用同一组状态、同一取整方式，守卫逐项比对。
  - **不另收费**：这 1% 由山海造物从营收中拨出，页面上明说。

## 二、口径（与 `syncFinanceData.reconcileOnlineOrders` 一致）

| 项 | 口径 |
|----|------|
| 计入状态 | `paid` / `paid_awaiting_address` / `shipped` / `received` / `aftersales` / `refunded`（部分退款的留存部分） |
| 暂不计入 | `refunding` / `expired_refunding`：退款结束后自动归位 |
| 金额 | `totalPrice`，即扣券后、含运费的实付；钱包余额支付的订单照常计入 |
| 退款 | 扣回 `refundFee`。`refunded` 但没有 `refundFee` 的老单按**全额退款**处理 |
| 不计 | 钱包充值本身（余额花出去时才计，避免重复）；线下门店收银（按顾客归属不了）；未支付订单 |
| 礼赠 | 计入付款的送礼人 |
| 取整 | 累计净额 × 1%，按分四舍五入，算法与 `onePercentPledge.calcOnePercentYuan` 相同。逐笔明细各自取整，合计以累计额为准 |
| 年度 | 按支付日的北京时间归年。当年为「进行中 · 年末统一拨付」，往年为「年度已截止 · 捐赠报告将经山海有信转呈」 |

> **口径差异（留给产品负责人定夺）**：店内账本遇到「已退款但缺 `refundFee`」的老单，按退款 0 元处理（仍计入应捐）；顾客侧按全额退款处理。顾客侧不能出现「退掉的单还算我捐了」，店内账本是否跟进，需要点名再改（财务读路径不在本轮范围）。

## 三、功能设计

### 1. 钱包入口（钱包 tab，余额卡下第一张卡）
- 铜边卡片，标「GIVING · 1%」和「我的捐赠」，右侧放大号「1%」。
- 卡内一句话：有金额时写「累计 ¥X 将由山海万物公益基金代为捐赠」；没有金额或查询失败时只讲规则，不显示 ¥0.00。
- 金额通过 `getMyDonations({ summaryOnly: true })` 读取，只回合计；进入钱包和下拉刷新时各读一次，失败不影响钱包本身。

### 2. 「我的捐赠」页（`subpackages/business/donations/index`）
1. **公益铭牌（主视觉）**：深色木底嵌一块铜牌，底纹是放大的「1%」。
   - 累计金额从 0 数到最终值，只在云端新数据到达时播放一次。
   - 公式胶囊：「累计实付 ¥X × 1%」。
   - 订单笔数 · 起始日期 · 同行第 N 天。
   - 底部铭文：「由山海万物公益基金代为捐赠」。
2. **规则一句话** + 「不另向您收取任何费用」。
3. **1% 如何流动**：每一笔实付 → 取其 1% → 山海万物公益基金，三站依次点亮。
4. **去向**：四枚方印（生 / 林 / 园 / 境），对应品牌承诺里的四个方向。
5. **年度**：每年一张卡，含应捐额、实付、笔数和年度阶段；当年用铜边高亮。
6. **逐笔明细**：
   - 按年份筛选，每次 20 笔，可继续展开；
   - 部分退款、已退款、退款中分别标注，后两种置灰；
   - 点击进入订单详情。
7. **常见问题**：怎么算、哪些计入、哪些不计、要不要另付钱、怎么知道真的捐了。
8. **页脚**：「页面金额为按上述口径计算的应捐额，实际拨付以年度捐赠报告为准。」

**状态**
- 未登录：展示规则、流向、去向和问答，铭牌显示「去登录」。
- 查询失败：铭牌显示「暂时查不到」和「重试」；规则区照常展示，不会把 ¥0 当成「您还没捐」。
- 没有订单：显示「您的第一笔 1% 还在路上」和「去馆藏看看」。
- 本机快照按 openid 隔离，先画快照、再以云端为准。

**分享**：标题只讲规则，不带个人金额；对方打开看到的是规则和去向。

### 3. 云函数 `getMyDonations`（新增只读旁路）
- 只查调用者本人（OPENID 取自上下文），只读，不写任何集合。
- 每页 100 条，最多 2000 单；明细最多回 300 行，合计始终包含全部订单。
- 纯函数在 `donationLedger.js`，守卫在内存里直接求值。
