# 礼券夹（我的礼券夹）交互与视觉说明

> 页面：`subpackages/business/coupons/index`（`WXML` / `WXSS` / `index.js`）
> 需求来源：业务方 33 条需求 **#7【P2】礼券夹已使用券折叠 + 打孔核销样式**
> 本轮（交互视觉整体优化）落点：三分组口径、卡券券包堆叠折叠件、打眼 + 斜章核销语言、卡片信息层级与临期提醒
> 守卫：`npm run test:coupon-fold`（含 `--selftest`，6 个回归注入）

## 1. 分组口径：可用 / 占用中 / 已失效（三分类，不是两分类）

| 组 | 判定 | 呈现 |
|----|------|------|
| **可用** | `canUse === true`（`status='unused'` 且未过期） | 平铺券卡，金色满血 + 实心金按钮 |
| **使用中** | 其余且状态不是终态（`locked` / 未知状态） | 单独小组，虚线描边券卡 + 灰胶囊「占用中」，**不折叠、不称失效** |
| **已失效** | `status ∈ {used, expired}` | 收进券包折叠件，默认收起 |

**为什么必须拆出「占用中」**：`locked` 是下单占用（未支付/未取消），**是进行时，不是终态**。
早期实现折叠口径写成 `!canUse`，于是「已失效礼券 N 张」里混进了还会回来的券 —— 对顾客是谎报。
「已失效」只收真正结束的券，这条口径由守卫断言钉住（`fold-everything-not-usable` 注入会失败）。

派生字段（页面层，见 `index.js`）：

```
splitCouponGroups(list) -> { usable, locked, dead }     // 三组互斥，总数守恒
couponExpiryHint(item, now) -> '' | '今日到期' | '明日到期' | 'N 天后过期'
decorateCoupon(item, now) -> { expiryHint, expiringSoon, voidLabel, voidKind }
```

- **角标口径**：`usableCouponCount` 只能等于 `groups.usable.length`。它同时喂
  `WalletHubBar` 角标与空态判断，把占用中/失效券算进去会让角标虚高。
- **不改共享比较器**：排序仍走 `utils/couponHelper.js` 的 `compareCouponsForDisplay`
  （选券弹层共用），分组只在本页派生。

## 2. 折叠件：卡券券包堆叠

- 结构：`.pouch` > `.pouch-head`（可点）+ `.pouch-body`（`wx:if` 惰性渲染）。
- 堆叠示意：`.pouch-stack` 内 **3 张错位迷你券**（`t3` 旋转 +7°、`t2` −4°、`t1` 正放），
  `t1` 提亮一档并在券面打 **3 个孔** —— 小尺寸下与前两张同色会糊成一块。
- 文案：标题「已失效礼券」，副文案「N 张 · 展开查看 / 收起」。
- 交互：`bindtap="toggleClosedCoupons"`，`softVibrate('light')` 软震动；
  箭头是 CSS 折角（`border-right/bottom` + `rotate(45deg)` → 展开 `-135deg`），
  比字符箭头转动更可控；`translate(-4rpx,-4rpx)` 把旋转后的视觉中心补偿回垂直居中。
- 动画：`.pouch-body { animation: pouch-in .26s ease both }`（轻微下移淡入）。
- 可访问性：`aria-role="button"` + `aria-expanded="{{closedExpanded}}"` + `aria-label`。

## 3. 打眼 + 斜章：失效券的核销语言

失效券**不再渲染状态胶囊** —— 章就是状态。两者并存会在券面右侧打成一片
（这曾是本页真实存在的缺陷，浏览器实测求交为重叠；守卫 `stamp-and-chip` 注入会失败）。

| 元素 | 实现 |
|------|------|
| 骑缝打眼 | `.punch-line` 沿骑缝均分 **7 个孔**（`.punch-hole`，直径 12rpx，色 `#12100D` = 页面底色，内阴影做出「打穿」的厚度感）；失效券的虚线 `line` 降到 `opacity .35` 让位 |
| 斜章 | `.void-stamp` 绝对定位券面右侧，`rotate(-11deg)`、虚线描边；已核销=金章 `is-used`，已过期=灰章 `is-expired` |
| 避让 | `.coupon-card.is-void .c-right { padding-right: 168rpx }` —— 文字区给章留位，日期/来源不会被章压住 |
| 降调 | 整卡 `opacity .8` + `#1C1A17` 底 + `#262320` 描边；**不用重度灰度**（会把章和打眼孔一起糊掉） |

## 4. 卡片信息层级

```
┌──────────┬──────────────┬──────────────────────────┐
│ ¥50      │ 骑缝          │ 满 300 减 50             │
│ 满300可用 │ 虚线/打眼孔   │ [渠道标签] 至 2026.09.21  │  ← 第 1 行：渠道 + 有效期
│          │              │ [5 天后过期] 官方发放      │  ← 第 2 行：临期标 + 来源
│          │              │                  [去使用] │
└──────────┴──────────────┴──────────────────────────┘
```

- **临期标不许进第 1 行**：券面文字区只有约 150px 宽，塞进去会把日期挤到第二行
  （浏览器实测抓到的真实回归，守卫 `hint-into-meta-row` 注入会失败）。
  临期标与来源同属「状态」层级，放第二行且 `flex-shrink: 0`，来源 `flex: 1` 省略号收尾，
  由此卡片高度稳定在 94–95px，列表节奏不抖。
- 临期窗口 `EXPIRING_SOON_DAYS = 7`，同时驱动券面标与头部提醒
  「N 张礼券 7 天内到期，请尽快使用」。
- 页头副标题给出分组概览：「我的礼券夹 · 可用 N · 已失效 M」。
- 主操作按钮用 `hover-class="c-status-press"`（部分机型 `:active` 不触发，点了没反馈）。
- **一张可用券都没有时**给内联出口 `.inline-cta`「当前没有可用礼券 | 去积分中心兑换」，
  不留「只剩一个券包」的死胡同。

## 5. 验收方式

1. `npm run test:coupon-fold` —— 加载**真源码**跑分组/临期/章文案纯函数，并核对 WXML/WXSS 结构；
   `--selftest` 注入 6 个回归（占用中算失效、占用中算可用、临期恒真、章+胶囊并存、
   临期标进第一行、丢 `aria-expanded`）必须全部被检出。
2. `npm run lint:wxml`。
3. 浏览器实测（一次性，不在仓内）：把真 WXML + 真 WXSS + 真 `loadCoupons` 渲染进无头 Chrome，
   量「章与文字区是否相交」「信息行是否被撑成两行」「券卡高度差」「横向溢出」等静态分析判不出的项。
   本轮实测结论：章零重叠、信息行单行、卡高 94–95px、无横向溢出。
