### 4-3（**已核实完成**）品类色已是令牌，无需再登记

起草本文档时以为「六色未进令牌层」，**实测推翻**：`app.wxss:39,53–56` 已登记
`--color-wood #8B6F47` / `--color-insecta #52B788` / `--color-minerals #7B68AE` /
`--color-plantae #6DA34D` / `--color-marine #5B8FB9`。

注意一处**同名不同义**（不是缺陷，但容易误判）：
`--color-forest: #2D5A3F` 是**信号灯色**（`.lamp-forest` / `.lamp-forest.hollow`），
与规范第 04 页的品类色「山林绿 `#2D6A4F`」**不是同一个东西**。「山林绿」这枚在代码里确实不存在。

遗留：各页仍有硬编码的品类色 hex。**2026-10-14 补了"只报告不改动"的扫描器**（小程序侧原先没有）：
`npm run report:colors:mp`（`--json` / `--ambiguous` / `--selftest`）。实测规模：

| 口径 | 处数 |
|---|---|
| 字面量总计 | **10769** 处（414 个 wxss/wxml · 令牌 99 条） |
| 其中 `var(--token, #hex)` **合规兜底**（不用动） | 1816 处 |
| **需收口** | **8953** 处 |

**扫描器发现的新事实（比"品类色"更根本）**：`app.wxss` 的 99 条令牌里 **38 条是历史短名**
（`--primary` / `--bg-root` / `--text-main` / `--pop-*` …），与 VIS 3.0 命名**同值并存**；
**12 组值挂了多个令牌**，最极端的一个值挂了 **6 个**：
`#C4A76C` = `--primary` / `--gold` / `--primary-light` / `--text-gold` / `--color-primary` / `--brass-400`。

所以"需收口 8953 处"其实是两件不同的事：

| 类别 | 个数 | 处数 | 怎么定 |
|---|---|---|---|
| **语义 ambiguous**（同值既是品类色又是功能色） | 2 | 198 | **必须人工定语义**（`#52B788`=昆虫/成功、`#5B8FB9`=海洋/信息） |
| **命名重复**（同值挂 VIS 3.0 名 + 历史短名） | 10 | **4924** | 机械可定，**但先要一句口径**：「一律往 VIS 3.0 名收」 |
| 其余（有唯一同值令牌 / 只有最近令牌） | 549+ | 3831 | 逐页判断（有 Δ 距离可参考） |

**建议**：先拍「往 VIS 3.0 名收口 + 品类↔功能按语义分别定向」这一条口径，
剩下的就是逐页机械替换 + 逐页跑对比度守卫；**在那之前不要动**（扫出来就是依据，不是补丁）。

**本轮新增一条机制**（第五次校准时发现）：R7 的 **WXSS 侧判据无法被自检证明** ——
`ruleR7` 自己从磁盘读同名 WXSS，而自检喂的是内存合成样本，于是"渐隐写在 WXSS 里"这条路
**从来没有被自检覆盖过**（第五次校准那个 `rgba()` bug 就藏在这里）。
现在把"读同名 WXSS"改成**可注入的依赖**（`ruleR7(..., readSiblingCss)`），自检用 2 个新样本
（带 `rgba()` 的渐变必须放行 / 渐变不收到透明时仍须报红）把它钉住。

**三条通用教训**（已写进判据注释）：

1. **静态判不了的要降级**，别硬判。「一屏一个主按钮」（要先知道哪些 `wx:if` 互斥）、
   「图像融入夜色」（要浏览器量层级）、「金额等宽」（要 computed style）——
   这三条硬判必然骗人，只能作参考项 + 基线棘轮。
2. **代理指标必须收窄到规范的本意**。规范点名的是「主图印章那枚孤品标」「em dash 空值符号」
   「金色发光」，不是字面上那两个字 / 那个字符。
3. **代理指标必须用"真结构"，不能用"字符窗口"**。`slice(i, i+3000)` 这类窗口看着够用，
   实际既会**误报**（把后面无关的图算进来）又会**漏报**（前面的兄弟看不到、窗口太短看不到）——
   R7 第四、五次校准去掉的 14 条全是这么来的。要判「容器里有什么」就老老实实按标签配平取子树。

## 6. 复现命令

```bash
# 盘点（人读）
node miniprogram/scripts/audit-vis3-rules.mjs
node miniprogram/scripts/audit-vis3-rules.mjs --rule R2      # 单条
node miniprogram/scripts/audit-vis3-rules.mjs --json         # 出 JSON

# 守卫（非 0 = 有硬项 / 参考项超基线）
npm run check:vis3-rules

# 自检（证明每条判据都会红；喂合成样本，不写真实文件）
node miniprogram/scripts/audit-vis3-rules.mjs --selftest

# 参考项收紧（改动后、确认变好时）
node miniprogram/scripts/audit-vis3-rules.mjs --print-baseline > miniprogram/scripts/vis3-rules-baseline.json

# 小程序侧色彩残留**只报告不改动**（对标 ERP 的 report:colors；先给分类依据，再谈替换）
npm run report:colors:mp
```

> 收紧基线前先 diff：`--print-baseline` 的输出要跟现有基线逐条比 ——
> **变小**才允许直接接受；**变大**必须能说出理由（写进 §7.1）。
