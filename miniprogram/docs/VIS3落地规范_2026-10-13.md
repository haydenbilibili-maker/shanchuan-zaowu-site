1. **纪律 08**：`app.wxss` 的 `.btn-primary` / `.btn-secondary` / `.btn-text` / `.btn-ghost` / `.mu-cn` 补 `white-space: nowrap`。

## 4. 待办 / 需拍板

### 4-1（**需拍板**）纪律 02「克制的金」：95 处金色发光

规范原文：「金色以**发丝线（1rpx）**出现；印章是**细线描边**，不是金属徽章。」
判定为「发光」= 金色阴影且模糊半径 > 4rpx（纯 `inset 0 1rpx` 发丝线**合规**，不在此列）。

| 文件 | 处数 | 性质 |
|---|---|---|
| `subpackages/business/booking/index.wxss` | 23 | 预约票根 —— **纸品仪式面**，发光可能是刻意的 |
| `subpackages/feature/wish-wall/index.wxss` | 15 | 旧祈福墙（已退役，转向心愿签） |
| `subpackages/business/about/index.wxss` | 12 | 关于页 —— 仪式感版面 |
| `subpackages/extra/user/certificates/index.wxss` | 8 | 收藏证书 —— **证书面** |
| `subpackages/manager/manager/index.wxss` | 6 | 员工端（`.btn` / `.vc-btn` 等） |
| `subpackages/business/certificate/index.wxss` | 5 | 证书 |
| `subpackages/plays/play-zodiac/index.wxss` | 5 | 星座玩法（轮盘） |
| 另 10 个文件 | 各 1–4 | CouponPrintMint ×2 / Calendar / UserVipCard / WishWallEntry / ritual-play / … |

**为什么不一刀切**：规范第 04 页写「宣纸为**纸主场**」——票根 / 证书 / 礼笺属于纸品面，
那里的金色微光（如 `.submit-btn { 0 8rpx 32rpx rgba(196,167,108,.5) }`）与
「克制」的关系需要设计判断，不是纯静态可判。且这批涉及**稳定期模块边界**。

**建议**：分两类处理 ——
① **明确违规**（C 端浏览页的按钮 / 卡片发光）：直接去光，用发丝描边替代；
② **纸品仪式面**（booking 票根 / certificates 证书 / about 仪式版）：**保留发光**，但把「微光」写法收敛成一个令牌；
③ 旧祈福墙（wish-wall）随其退役一并处理，不单独改。

### 4-3（**已核实完成**）品类色已是令牌，无需再登记

起草本文档时以为「六色未进令牌层」，**实测推翻**：`app.wxss:39,53–56` 已登记
`--color-wood #8B6F47` / `--color-insecta #52B788` / `--color-minerals #7B68AE` /
`--color-plantae #6DA34D` / `--color-marine #5B8FB9`。

注意一处**同名不同义**（不是缺陷，但容易误判）：
`--color-forest: #2D5A3F` 是**信号灯色**（`.lamp-forest` / `.lamp-forest.hollow`），
与规范第 04 页的品类色「山林绿 `#2D6A4F`」**不是同一个东西**。「山林绿」这枚在代码里确实不存在。

遗留：各页仍有硬编码的品类色 hex（`#52B788` 命中 26 个 wxss、`#8B6F47` 20 个），
建议逐步换成 `var(--color-*)`；但那是**逐页收口**，非本轮范围。

## 5. 判据校准记录（**改判据前必读**）

首版判据在 5 条上共报出 **74+ 条假红**，全部是判据自己**读错了主语**
（本仓错题本 E3：「读的是镜像、不是真源」）。逐条记下来，避免下次重犯：

| 纪律 | 首版判据的错 | 假红 | 修正 |
|---|---|---|---|
| R1 | 把管理端商品筛选器的「孤品」chip、`isOneOfAKind` 表单开关算成「主图印章标记」 | 6 | 只认详情页主图那枚**营销徽标**（`detail/index.wxml`） |
| R2 | 凡"阴影含黄铜色"就判红 —— 但 `inset 0 1rpx 0 rgba(212,188,133,.08)` 正是规范要的**发丝线** | 22 | 要求 blur > 4rpx，且纯 inset 短长度豁免 |
| R2 | 只认带单位的长度 → `0 0 12rpx` 的前两个 `0` 被漏掉，blur 算成 0 | — | 无单位 `0` 按长度算 |
| R3 | 按页统计 `.btn-primary` —— `gift/receive` 的 6 处其实落在 `wx:if/elif` 的**互斥状态块**里 | 14 | 只判**同一父节点下并列**；页面级降为参考项 |
| R6 | 把普通连字符 `-` 也算空占位 —— 实为价格**区间连接符**（100 — 500）、滑块**最小值标签**、步进器**减号按钮** | 3 | 只判 em dash `—`，且排掉 `dash/sep/minus/lbl/s-btn` 语境的类名 |
| R7 | ① class **子串**匹配（`hero-plate` 无图 / `note-cover` 是缩略图）；② `\bhero` 匹配到 `sk-hero`（骨架屏） | 6 + 68 | 按 class **词元**匹配 + 排骨架 + 要求容器内真有图 |
| R7 | ③ **找错了文件** —— 只在 WXML 片段里找 `gradient`，而渐变写在 **WXSS** 里（`index.wxss:218`、`wiki-detail.wxss:8` 都被误报） | 19 | 跨到同名 WXSS 找，且认**子元素**上的遮罩（首页 `.hero-mask-vignette`） |
| `--json` | 过滤写在 json 分支**之后** → `--rule R2 --json` 吐出全部规则的合集 | — | 过滤前置 |

**两条通用教训**（已写进判据注释）：

1. **静态判不了的要降级**，别硬判。「一屏一个主按钮」（要先知道哪些 `wx:if` 互斥）、
   「图像融入夜色」（要浏览器量层级）、「金额等宽」（要 computed style）——
   这三条硬判必然骗人，只能作参考项 + 基线棘轮。
2. **代理指标必须收窄到规范的本意**。规范点名的是「主图印章那枚孤品标」「em dash 空值符号」
   「金色发光」，不是字面上那两个字 / 那个字符。
