## 3. 设计结论

### 3.1 信息架构
- 头部：`EVENTS · WORKSHOPS / 活动课程` + 右侧「＋ 发布活动」（取代悬浮 ＋）。
- 三个关键数：**报名中场次 / 未开场报名人数 / 已截止场次**。
- **过期仍展示横幅**：`N 场已结束的活动仍在对顾客展示` + 「一键下架」（两步确认，写 `status: closed`）。
- 分组 Tab（按实际数据状态，不造「草稿」）：
  - **报名中** = 日期 ≥ 今天 且 `open`；
  - **已截止** = 日期 ≥ 今天 且 `closed`/`full`；
  - **已结束** = 日期 < 今天（**不看 status**）；
  - **全部**。首次进入若「报名中」为空，自动落到第一个有内容的分组。
  - 排序：未结束按日期近→远；已结束按远→近倒序。「今天」按北京时间。

### 3.2 卡片（关键数据前置）
日期块（`09/28 周一`，今天高亮金底；跨年显示年份）· 标题 · 状态徽标 · 类型 · 「今天 / 明天 / N 天后 / 已过 N 天」· 时间 · 门店 · 地点；
四格数字：**报名 x/名额 · 已核销 · 余位 · 价格（0 → 免费）**＋ 报名进度条；
报名 / 核销来自 `bookings` 计数（口径 = 活动 `title + date`，与预约页写入一致；报名 = confirmed/pending/used，核销 = used），
**读不到时显示「—」，不编 0**。警示条：未绑门店（预约页看不到）、过期仍展示。
操作：编辑 · **再办一场**（复制除日期外的全部字段）· 去核销（当天且有报名，跳店员工作台）· 截止报名 / 重新开放 / 下架 · 删除（两步确认，有报名时写明人数）。

### 3.3 创建 / 编辑
- 字段顺序按「必填在首屏」：标题 → 类型（分段）→ **门店（分段，写 storeId）** → 日期（显示 `10月3日 周六`，新建不能选过去）→ 开始 / 结束时间（time picker，合成 `14:00 - 16:00`，与旧数据同格式）→ 价格 / 名额并排（0 = 免费 / 不限）→ 地点（跟随门店默认，手填过不覆盖）→ 封面（可选，放最后）。
- 校验落到字段：红框 + 字段下方文字，并 `scroll-into-view` 滚到出错字段；保存失败在面板顶部显示；按钮「发布活动 / 保存修改 / 保存中…」。
- 编辑**不回写 status**；名额变了才按差值平移 `remain`，没变不碰。

### 3.4 视觉
工作台深色金色：卡片 `--color-bg-card` + `--color-bg-elevated` 描边，金色只给主按钮、关键数、今天、选中态；
危险操作用红（确认态 `#B8323A` 底白字，对比度 5.9）。样式独立文件 `workspace/activityBoard.wxss`，不改共享 `index.wxss`。

## 9. 待点名项修复（2026-09-28 晚，产品负责人拍板「三项都修复」）

### 9.1 工作台子页提示看不见
- **根因**：`showHubTip` 只 `setData({ hubTipText })`，而 `page-tip` 只画在 Hub（`manager/index.wxml:54`）；工作台子页 `workspace/index.wxml` 只挂了 `<app-toast>`。`managerPageConfig.js` 里 337 处调用在子页全部静默。
- **改法（一处覆盖全部调用点）**：`workspace/index.js` 在 `...managerPageConfig` 之后覆写 `showHubTip` → 转 `showAppToast`（主视觉轻提示，非原生、不计入弹窗棘轮）；`clearHubTip` 置空。Hub 不受影响（仍用自己的 page-tip，不会重复）。
- **长文案**：≤12 字整句做标题；更长时按首个标点拆「标题 + 说明」（如「保存失败，云函数…」）；无标点给短标题（请留意 / 已完成）+ 整句进说明，**不截断丢字**；停留时长随说明长度 2.2s→最多 5s。

### 9.2 C 端展示过期活动
- **根因**：首页 `where({ status })`、预约页 / 门店页 `where({ status: 'open', storeId })` 都不看日期；活动过期但 status 仍 open 就一直展示。
- **改法**：查询层加 `date: _.gte(今天)`（北京时间，`utils/activityExpiry.js` 的 `todayKey`）；当天再按结束时间（无结束取开始，都没写到 24:00）过滤一次（`isActivityExpired`）。首页加 `orderBy('date','asc')` 让 limit 取最近的几场。搜索页的活动结果同口径过滤。HomeReco 未碰。
- 活动数据由客户端直读（非云函数），故过滤在客户端查询层；**没填日期的活动不再出现在 C 端**（`date >= 今天` 不含空串）。

### 9.3 报名不扣名额
- **取证**：预约写入**已走云函数** `createBooking`（`booking/index.js` 两处 `callFunction`），`bookings` 集合规则 `write: false`、`activities` 规则 `write: false` —— **客户端本就写不了，规则无需收紧、无上线顺序约束**。缺口是服务端没关联活动也不扣名额（原注释「暂未做严格的 activityId 库存校验」）。
- **改法**（只加可选入参，回包 `{ success, bookingId, ticketCode }` / `{ success:false, msg }` 不变）：
  - `createBooking` 新增可选 `activityId`：校验活动存在、`status === 'open'`、未过期（北京时间，同 `activityExpiry.js` 副本）；有名额上限时 `where({ _id, status:'open', remain: _.gte(人数) }).update({ remain: _.inc(-人数) })`，`updated !== 1` 即「名额已满」；历史活动没 remain 先按名额补齐（条件更新）。标题 / 日期 / 时间 / 价格以活动文档为准；预约记 `activityId`、`seatHeld`。写预约失败回补名额。
  - `cancelBooking`：状态更新改为条件更新 `where({ _id, status:'confirmed' })`，只有一次生效 → 归还 `seatHeld` 并记 `seatReleased`；重复 / 并发取消不重复归还。
  - 不带 `activityId` 的旧调用（到店参观、定制确认、伴宠交接、旧版小程序）行为完全不变。
  - 预约页：报名传 `activityId`；`remain <= 0` 且有名额上限的卡片显示「已满」、置灰，选中 / 提交都拦下（沿用原有提示位，不新增原生弹窗）；有名额上限时显示「余 N 位」。报名回包后重拉活动。
  - 工作台看板 / ERP `Activities.vue`：报名数按 bookings 计，`activityId` 优先，历史无 `activityId` 回退「标题 + 日期」（读时兼容，不迁移）。工作台编辑名额前先取活动最新文档再平移 remain，避免旧列表值覆盖服务端扣减。
- **未改 / 需知**：`updateBooking`（改期）无任何调用方，未改；若将来启用，活动预约改期需先释放名额再占位。`cancelBooking` / `updateBooking` 里 `wx.cloud.callFunction` 在云函数环境不可用（被 try 吞掉，提醒不发），属既有问题，未改。
- 字段说明已同步 `cloudbase/schema/bookings.md`、`cloudbase/schema/activities.md`。
