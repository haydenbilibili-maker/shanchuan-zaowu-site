# 钱包账单流水交互说明

> 页面：`subpackages/feature/user/stored-value/index`（我的钱包）
> 纯派生模块：`subpackages/feature/user/stored-value/wallet-ledger.js`
> 守卫：`npm run test:wallet-ledger`（含 `--selftest`，9 个回归注入）
> 数据来源：云函数 `manageStoredValue` 的 `getAccount` / `listLedgers`（`createTime` 倒序 + limit/offset）

---

## 1. 这次解决的四件事

| 问题 | 旧实现 | 现在 |
|------|--------|------|
| **看不出结构** | 一列平铺，每行竖排「类型 / 说明 / 完整日期」三行，20 笔 = 60 行文字墙 | 时间轴：**月带 → 日组（日头含当日净额）→ 行**，行内只留「时分」 |
| **时间静默丢失** | `new Date(row.createTime)`；云函数回包若是 `{ $date }` 形态则每行时间变空、页面照常渲染 | `ledgerTimeMs()` 兼容 `Date` / `{ $date }` / 数字 / ISO / 双层 `$date` / `getTime()` |
| **首屏闪空态** | 进页面先渲染「暂无流水」，几百毫秒后才出流水 | `ledgerLoading` 驱动**骨架**，空态只在真正 0 笔时出现 |
| **分页只能点按钮** | 只有「加载更多」按钮 | `scroll-view` 的 `bindscrolltolower` **滚到底自动加载**，按钮保留作兜底 |

## 2. 口径（宁可不给，也不谎报）

这三条是「算错了看不出来」的那类逻辑，都锁在 `wallet-ledger.js` 里并被守卫钉住：

1. **分页边界的那一天不给当日净额**
   `hasMore === true` 说明还有更早的流水没加载，此时**时间最早的那一天**可能还没加载完。
   该天日头显示「未完」，不显示净额；其余天正常显示。加载完后自动补上。
2. **时间未知的行不给净额**
   无 `createTime` 的行落进「时间未知」组 —— 它们可能跨天，算合计就是错的。
3. **口径文案只说实数**
   还有更早的 → 「已加载 N 笔」；已到最早 → 「共 N 笔」。不用「近 N 笔」这种描述估算的字眼。

## 3. 视觉与交互

### 时间轴
- **月带**：`2026 年 9 月`（等宽字 + 一条细铜线），只在跨月时出现。
- **日头**：左 `今天` / `昨天` / `09.14` + 星期；右当日净额（`+¥414.00` 铜色 / `-¥126.00` 次级 / `¥0.00` 弱化）。
- **轨道线**：从圆点下方连到**下一行圆点的上沿**（`bottom: -30rpx`，与 `.sv-ledger-dot` 的 `top` 强绑定）；
  当天最后一笔、以及全表最后一行不画线 —— 轨道线不允许悬在半空。
- **圆点语义**：收入 = 铜色，支出 = 次级灰，退款/回账 = 绿。
- **行**：左「类型 + 时分」，下「说明」，右「金额 + 余额」。时分右对齐成列，金额列定宽（`min-width: 188rpx`）——
  否则金额位数一变（`-¥56.00` vs `-¥1286.00`）列宽就跳，把左边的时分列一起推歪。

### 交互
- **点行开订单**：`refType === 'order'` 且 `refId` 非空的行可点，右侧出箭头，跳到
  `/subpackages/business/order-detail/index?id=<refId>`（`refId` 就是订单 `_id`）。
  其余行（充值单、门店扣款、调账、赠金过期）**不给假箭头**。
- **自动加载 + 去重**：游标按**服务端返回条数**推进，不按去重后的可见条数 ——
  否则期间表头插入新流水就会重复拉同一页、永久卡住。合并时按 `id` 去重。
- **首屏骨架**：复用 `.wallet-leather-skel` 的铜色微光，与正式行同高，避免布局跳动。

## 4. 验收方式

1. `npm run test:wallet-ledger` —— 加载**真源码**跑时间解析 / 分组 / 净额 / 单行派生 / 口径文案纯函数，
   并用真 `onLoadMoreLedgers` + 打桩云函数跑两页分页（含「表头插入导致重复」与「收口」）。
   `--selftest` 注入 9 个回归必须全部被检出：
   `{ $date }` 不认、边界日照算净额、月带重复、轨道线悬空、轨道线永不断、口径说谎、
   游标按可见条数、箭头不受可点性约束、骨架晚于空态。
2. `npm run lint:wxml`。
3. 浏览器实测（一次性，不在仓内）：把真 WXML + 真 WXSS（含 `app.wxss` 与组件样式）+
   真 `bootstrap → refreshAccount → listLedgers` 渲染进无头 Chrome，量静态分析判不出的项。
   本轮实测：轨道线接缝 0px、圆点与轨道同轴、三列（时分/金额/日净额）右缘各自对齐、
   行高 58px 一致、无横向溢出、骨架态不出空态。

## 5. 待办 / 边界

- **不做类型筛选**：`listLedgers` 服务端不支持 `types` 过滤，客户端只能筛「已加载的 20 笔」——
  那会让用户以为筛的是全部。要做必须先加云函数参数并部署，本轮**刻意不做**。
- **不做「本月合计」**：同理，服务端没有按月聚合的口径，客户端算出来的只是「已加载窗口」的合计，
  标成「本月」就是谎报。日头净额只在**该日已加载完**时给，这条口径已由守卫钉住。
- 时间轴按客户端本地时区分日（与服务端 `createTime` 的 UTC 时刻一致）。
