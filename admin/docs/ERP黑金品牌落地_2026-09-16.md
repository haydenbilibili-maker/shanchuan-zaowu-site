# ERP 黑金品牌适配（2026-09-16）

> **决策**：黑金是小程序的品牌色；**ERP 做「适配」而非「复制」**。
> **约束**（产品负责人 2026-09-16）：必须同时兼顾 **效率 / 视觉舒适度 / 品牌调性**。
>
> 关联审计：`ERP系统专项审计_2026-09-16.md` §0 P0-14（品牌漂移）、P1「交互与一致性」。

---

## 1. 为什么不能直接把 ERP 刷成暗色黑金

ERP 是**每天长时间处理密集表格**的工具（113 个 `el-table`、`Orders.vue` 单表最小宽度 1155px）。
把工作台也做成暗色 + 大面积金，会同时伤两件事：

- **效率**：暗底上做数字比对、跨行核对更慢；截图贴进群里、打印对账都变差。
- **舒适度**：深色大面积 + 高饱和金在长时间注视下更易疲劳；且现有 4 份移动端 CSS（2269 行、260 处
  `!important`）都建立在浅色假设上，反色必然引发成片回归。

而「黑金」的**硬边界其实是对比度**，不是明暗：

| 候选 | 在白底 | 结论 |
| --- | --- | --- |
| `#d4af37`（散落硬编码的金） | **2.10:1** | 正文完全不可读，必须弃用于浅色面 |
| `--gold-500` `#a88d42` | **3.20:1** | 只够大字/图形，不够正文 |
| `--gold-700` `#6e5b28` | **6.58:1** | ✅ 浅色面上可用作正文/按钮/链接 |
| `--gold-300` `#d4b86a` 在深色面上 | **7.80 ~ 8.98:1** | ✅ 亮金只在这里用 |

## 2. 落地原则（三准则的对应关系）

| 准则 | 落法 |
| --- | --- |
| **品牌调性** | 品牌放**外壳与点缀**：近黑侧栏/顶栏/登录/命令面板 + 金色发丝线与亮金文字；主色、焦点环、图表主色阶全部转金 |
| **效率** | 工作台**保持浅色高对比**；金色只做**信号**（主按钮、激活态、链接、图表、焦点），不做大面积填充 |
| **视觉舒适度** | 亮金（gold-300/400）**只允许出现在深色面**；浅色面一律 `--erp-gold-on-light`（gold-700，6.58:1）；表头档位做成一行可切 |

## 4. 旋钮：如何换档而不用改组件

改 `design-tokens.css` 里这三行即可在「品牌感」与「密集表格舒适度」之间切换：

```css
/* 档位 A（当前，默认）：黑金表头——品牌感强，对比 7.80:1 */
--erp-table-head-bg: var(--erp-black-soft);
--erp-table-head-fg: var(--erp-gold-on-dark);
--erp-table-head-rule: transparent;

/* 档位 B：暖白表头 + 金下划线——113 个表格更轻，舒适优先 */
--erp-table-head-bg: var(--light-bg-secondary);
--erp-table-head-fg: var(--erp-gold-on-light);
--erp-table-head-rule: var(--gold-300);
```

`npm run check:brand-contrast` 对两个档位都会校验（档位 B 用 gold-700 也达标）。

## 5. Phase 2：令牌翻转**够不到**的残留（必须是语义迁移，不能全局替换）

| 残留 | 处数 | 说明 |
| --- | --- | --- |
| `rgba(45, 106, 79, …)` 等绿色字面量 | **350** | 大量是 hover 阴影/半透明底 |
| `var(--brand-green-*)` 用法 | **274** | 令牌定义本身要保留（它是一套色板），但**用法**要分类 |
| 硬编码绿/蓝 `#2d6a4f`/`#52b788`/`#409eff` | **61** | `#409eff` 是 EP 默认蓝，属主色残留 |
| 硬编码金 `#d4af37` | **340** | **不能在浅色面上直接用**（2.10:1），须换成 `--erp-gold-on-light`；深色面上可保留 |

> ⚠️ **这 1,025 处必须逐个判语义，禁止 find-replace。**
> 同一个 `var(--brand-green-500)`：当「品牌主色」用 → 换金；当「成功/通过」语义用 → **必须保持绿**。
> 反过来 `#d4af37` 也不全该改：它在深色面上是对的。
> 这与本仓已记录的教训一致（见审计 §1.3：机械替换会造出大量假阳性）。

**建议的 Phase 2 做法**：写一个**只报告不改动**的分类脚本，把每处按上下文归入
「品牌主色 / 语义色（成功·警告·错误）/ 中性色」，人工过一遍分类结果后再分批替换，
每批跑 `check:brand-contrast` + 构建。**不要一次性替换 1,025 处。**
