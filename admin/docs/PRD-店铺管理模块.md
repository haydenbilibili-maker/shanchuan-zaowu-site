## 1. 背景与目标

### 1.1 背景

当前中台已覆盖藏品、订单、会员、活动、财务账本等能力，但**线下门店作为经营单元**缺少统一档案：位置与场地信息分散、证照与纸质票据未结构化留存、发票与租金周期难以按店追溯、店内人员与总部「团队与标本师」模块边界不清；**门店侧营收**未与店铺主数据绑定，财务流水难以按店归集与对账。随着多店与加盟推进，需要独立的**店铺管理**能力支撑合规、财税协同与日常运营，并要求**财务核算系统**支持店铺维度关联。

### 1.2 目标

- **G1**：建立「一店一档」主数据，含地理位置、经营属性、场地与联系信息。
- **G2**：证照、资质类文件可上传、版本留痕、列表与预览展示，满足巡检与对外提供材料场景。
- **G3**：房租/租金相关**收据与合同附件**可上传、按周期归档，支持检索与导出清单。
- **G4**：**发票**按店登记（进项/销项或费用类型可配置），关联金额、期间、附件，便于与财务模块对账。
- **G5**：**店铺员工**与门店绑定，支持花名册、岗位、入离店日期；与现有权限/账号体系可对接或预留接口。
- **G6**：**门店营收**可按店、按日/周/月登记或汇总展示，支撑经营看数与财务对账；与订单/POS 自动同步可作为增强路径。
- **G7**：**财务核算系统**中收支、报表、统计均支持 **店铺（门店）关联**，与店铺管理中的门店主数据一致、可筛选、可导出。

### 1.3 成功指标（建议）

| 指标 | 说明 |
|------|------|
| 建档覆盖率 | 在营门店 100% 具备完整主数据与至少一份在效证照记录 |
| 附件可追溯 | 任意租金/发票记录可定位到文件与上传人、上传时间 |
| 操作效率 | 单店信息维护完成时间较「纯线下表格」缩短 50% 以上（可用调研验证） |
| 营收可归集 | 在营门店月度营收在系统内可查，且与财务流水在「店铺」维度可对齐（允许暂以手工对齐为验收标准） |

## 2. 范围说明

### 2.1 本期包含

- 门店主数据与位置信息（地址、地图坐标可选、面积、房东/物业摘要等）。
- 证照类型配置 + 多文件上传 + 列表展示 + 预览（图片/PDF）。
- 租金收据（及可选租赁合同）附件上传、期间、金额、备注。
- 发票登记：发票代码/号码、类型、金额、税额、开票日期、购销方摘要、附件上传。
- 店铺员工：姓名、岗位、手机、入职/离职、状态、附件（如劳动合同可选）。
- **门店营收**：按店登记或导入营业数据（金额、期间、渠道摘要），店铺详情内汇总与简单趋势；与财务模块店铺字段联动展示。
- **财务侧配套**：财务核算中账本记录、筛选与统计支持关联 **门店**（见第 11 章）。

### 2.2 本期不包含（可列二期）

- 与税局系统直连的电子发票自动拉取。
- 自动 OCR 识别发票全字段（可作为增强项单独立项）。
- 排班与考勤深度集成。
- 门店 POS 流水自动入账、与订单系统自动轧账（与财务已有规划可另案衔接；本期可先手工录入或批量导入营收行）。

## 3. 用户与权限

### 3.1 角色假设

| 角色 | 典型诉求 |
|------|----------|
| 总部管理员 | 全部门店可见、可增删改、导出 |
| 区域/运营负责人 | 所辖门店可见、维护证照与租金发票 |
| 单店店长（可选） | 仅本店只读或有限编辑（如仅上传收据） |
| 财务 | 全部门店发票与租金记录只读或审核；维护账本时必选/可选关联门店（规则见第 11 章） |

### 3.2 权限原则

- 数据按 **门店维度** 隔离；总部角色可跨店。
- 所有附件上传/删除/下载写入 **操作日志**（操作者、时间、对象 ID）。
- 敏感字段（如房东个人身份证号）支持 **脱敏展示** 或「仅备注不落结构化」由实施策略决定。

### 4.6 门店营收

用于线下门店**经营数据留痕**与对账参考；本期以「结构化登记 + 汇总展示」为主，自动从订单/POS 拉数可作为后续迭代。

| ID | 需求描述 | 优先级 | 备注 |
|----|----------|--------|------|
| Rev-01 | 营收记录归属 **必选门店**；支持按「营业日」或「自然日」记账（产品默认一种并在界面标明） | P0 | 与财务口径需对齐说明 |
| Rev-02 | 单行字段建议：统计日期、**营业流水（含税/不含税可配置默认）**、退款/调整金额（可选）、净额、币种、渠道类型（线下收银/小程序到店/其他）、备注 | P0 | 净额可由公式计算并允许覆盖 |
| Rev-03 | 支持 **附件上传**（如收银日报截图、店长汇总表 PDF），多条附件 | P1 | 与统一附件组件一致 |
| Rev-04 | 门店详情内 **营收 Tab**：表格列表 + 按日/周/月聚合视图（至少月汇总 + 最近 30 日趋势或表格） | P0 | 趋势图可二期 |
| Rev-05 | 门店列表展示 **快捷指标**：如本月累计营收（可配置是否展示）、无数据时显示「—」 | P1 | 性能注意聚合查询 |
| Rev-06 | 筛选：按门店、按日期区间、按渠道；导出当前结果（元数据 + 可选附件链接列） | P1 | |
| Rev-07 | **与财务关联**：营收行可标记「已计入财务」或关联财务账本记录 ID（二期可做双向）；MVP 至少在店铺详情展示「关联财务笔数」占位或说明文案 | P1 | 见第 11 章 |
| Rev-08 | 批量导入：Excel 模板（门店编码、日期、金额、渠道、备注）校验后写入 | P2 | 错误行回执下载 |

**业务规则（建议）**：

- 同一门店同一营业日允许多条营收记录（早班/晚班分开记）或强制合并一条，**由门店运营规范二选一**，写入配置项。
- 与「全渠道订单」GMV 并存时，需在帮助文案中说明：**订单为成交明细，营收为门店上报或日结汇总**，二者差异在财务对账流程中处理。

**验收要点**：任意营收记录可追溯到门店与日期；列表筛选与门店权限一致；净额与分项金额校验规则一致。

## 5. 数据模型概要

以下为逻辑实体（非最终表结构），供研发估时与评审。

```
门店 Store
  - id, code, name, status, region, address*, geo(optional),
    area_m2, lease_start, lease_end, landlord_name, landlord_contact,
    manager_user_id(optional), created_at, updated_at

证照 StoreLicense
  - id, store_id, license_type_id, cert_no, issuer, valid_from, valid_to,
    is_current, note, created_at

证照附件 StoreLicenseFile
  - id, license_id, file_id/url, file_name, mime, size, uploaded_by, uploaded_at

租金记录 StoreRentPayment
  - id, store_id, period_start, period_end, amount, pay_date, pay_method,
    payee_name, voucher_no, remark, created_at

租金附件 StoreRentPaymentFile
  - id, rent_payment_id, file_id/url, ...

发票 StoreInvoice
  - id, store_id, direction(in/out), invoice_kind, code, number, issue_date,
    amount_excl_tax, tax_amount, total, seller_name, seller_tax_id,
    buyer_name, buyer_tax_id, remark, rent_payment_id(optional), created_at

发票附件 StoreInvoiceFile
  - id, invoice_id, file_id/url, ...

店铺员工 StoreStaff
  - id, store_id, name, phone, gender, position, hire_date, leave_date,
    status(active/left), remark, created_at

门店营收 StoreRevenueEntry（或日汇总表 + 明细表，实施二选一）
  - id, store_id, biz_date, gross_amount, refund_amount(optional), net_amount,
    channel(enum: offline_pos, miniprogram_store, other), tax_included(boolean),
    currency, remark, finance_ledger_id(optional), synced_flag(optional), created_at, created_by

营收附件 StoreRevenueFile
  - id, revenue_entry_id, file_id/url, ...
```

索引建议：`store_id` 在各子表建立；发票 `(code, number)` 唯一约束需结合发票类型规则；营收表建议复合索引 `(store_id, biz_date)`。

## 9. 验收标准（摘要）

1. 可完成「创建门店 → 维护地址与面积 → 上传营业执照 → 新增一条租金并上传收据 → 登记一张进项发票并上传 PDF → **登记一条门店营收**」全流程无断点。
2. 无权限用户无法查看其他门店任意 Tab 数据（含营收）。
3. 证照过期状态与服务器日期一致；将过期门店在列表中有可识别标识（若 M1 实现提醒）。
4. 删除附件/记录符合二次确认与审计要求。
5. 构建与现有工程规范一致，可通过冒烟测试清单（由测试补充）。
6. 财务人员在「财务核算系统」中新增一笔收支时，可 **选择关联门店**（按权限过滤可选列表）；保存后在详情中展示门店名称与编码；列表与导出支持按门店筛选。

## 11. 财务管理模块需求补充（店铺关联）

本章描述对现有 **财务核算系统** 的增量需求，与「店铺管理」共用 **门店主数据**（`Store.id` / 门店编码一致），不在此重复定义门店字段。

### 11.1 目标

- 每一笔（或每一行）**收支账本记录**均可关联 **0 或 1 个门店**；总部费用、集团统收等允许为空并标注「非门店」。
- 列表、筛选、导出、简单统计均支持 **按门店** 维度，便于与店铺管理中的租金、发票、**门店营收** 交叉核对。

### 11.2 功能需求

| ID | 需求描述 | 优先级 | 备注 |
|----|----------|--------|------|
| F-01 | 账本记录模型增加 **`store_id`（可选）**；下拉选项数据来源于店铺管理已启用门店列表 | P0 | 下拉按权限过滤可见门店 |
| F-02 | 新增/编辑收支表单：**关联门店** 表单项（可清空）；展示门店名称 + 编码 | P0 | 与店铺管理编码一致 |
| F-03 | 账本列表：增加「门店」列；支持按门店 **筛选**（含「未关联」筛选项） | P0 | |
| F-04 | 账本详情/抽屉：展示关联门店信息块（名称、编码、城市、状态） | P0 | 只读引用主数据 |
| F-05 | 导出 Excel/CSV：包含 **门店编码、门店名称** 列 | P0 | |
| F-06 | 财务侧 **统计/看板**（若已有）：增加按门店聚合（收入合计、支出合计、净利）；无门店维度保留「未分配」桶 | P1 | 与 Dashboard 是否联动另议 |
| F-07 | 权限：无某店数据权限的用户不可将该店选入账本；仅编辑本人记录时沿用原规则 | P0 | |
| F-08 | 校验：若业务规则要求某类收支 **必须** 关联门店（如门店租金支出），可通过 **收支类型配置** 扩展「是否强制门店」 | P1 | 配置化优先 |

### 11.3 与店铺管理模块的协同

| 场景 | 说明 |
|------|------|
| 租金支出入账 | 财务登记支出时选择对应门店，与店铺管理中「租金收据」记录可通过备注或 `rent_payment_id`（二期）弱关联 |
| 发票 | 店铺发票与财务进项/销项在门店维度一致；对账时可按 `store_id` + 期间过滤 |
| 门店营收 | 店铺侧登记的 Rev 数据与财务流水在门店+日期维度人工或报表对账；后续可用 `finance_ledger_id` 强关联 |

### 11.4 数据与兼容

- 历史数据 `store_id` 为空：**默认合法**；列表筛选「未关联门店」便于财务补录。
- 门店在店铺管理中被 **停用**：已关联记录保留快照或仍显示 ID+「已停用」标签，**禁止**再选入新单据（或仅管理员可选，产品二选一）。

### 11.5 验收要点（财务侧）

1. 新建收支并选择门店后保存，再次打开记录门店信息正确。
2. 列表按门店筛选结果集正确；导出列含门店信息。
3. 无门店权限用户在下拉中不可见不可选对应门店。
