## 0. 问题与原则

工作室日常的**采购、原料/成品库存、出货**目前在飞书多维表里跑；Admin 已有门店订货履约（`purchase_orders` / `fulfillment_shipments` / `stock_movements`）。两边不能各写一套库存，否则必然对不上。

**原则：分域单一真相，禁止无映射双写。**

| 业务域 | 真相源 | Admin | 飞书 |
|--------|--------|-------|------|
| 原材料采购 | **飞书** | 只读镜像 `feishu_purchases` | 继续录入 |
| 原料库存 | **飞书** | 只读看板 | 继续盘点 |
| 门店/渠道订货履约 | **Admin / 店长** | 主写 PO / 出货 / 收货 | 接收出货回写（物流、数量） |
| 总部成品可用量 | **Admin `products.stock`** | 出货扣减、手工盘点 | 可由飞书「成品库存」表 **校准入库**（人工确认后应用） |

飞书继续给工作室当作业台；Admin 给门店订货与 C 端商城当经营账。打通的是 **SKU 映射 + 单向同步**，不是两套系统互相覆盖。

## 1. 架构

```
飞书多维表（app_token=WCs2bnIHsaty7vsjcnaczu0Wnod）
  采购表 ──pull──► feishu_purchases（Admin 只读）
  库存表 ──pull──► feishu_inventory（只读） ──人工「应用为 HQ 库存」──► products.stock + stock_movements
  出货/发货表 ◄──push── fulfillment_shipments（已发货且无 feishuRecordId）

凭证：Cloudflare Pages / 本地 Vite 代理环境变量 FEISHU_APP_ID / FEISHU_APP_SECRET（不进 SPA）
映射：CloudBase configs 文档 feishu_bitable

```

- **线上**：`functions/api/feishu-sync.js`（Cloudflare Pages Function，`/api/feishu-sync`）
- **本地**：Vite 插件 `/admin/api/feishu-sync`（读 `admin/.env`）
- **镜像写入**：Admin SPA 匿名 CloudBase（`feishu_purchases` / `feishu_inventory`）
- 微信云函数 `syncFeishuBitable` 仅作小程序侧备用，**Admin 不再调用**（Web 匿名会 `PERMISSION_DENIED`）

Admin：订货履约 → **飞书对接** Tab。

## 2. 开通步骤（一次）

权限管理 / 分享里搜不到应用是正常的，那里只搜人。必须走「添加文档应用」。

1. [飞书开放平台](https://open.feishu.cn/app) 创建**企业自建应用**。
2. 权限管理勾选 **查看、评论、编辑和管理多维表格**（`bitable:app`）。未开通任一云文档 API 权限时，添加文档应用窗口搜不到该应用。
3. **版本管理与发布** → 创建版本 → 申请发布。可用范围必须包含这张 Base 的所有者（你自己）。权限未发布不会生效。
4. 打开 Base，右上角 **⋯ → ⋯更多 → 添加文档应用**（不要进「权限管理」搜人）。搜应用名，权限选 **可编辑**；若开了高级权限，给 **可管理**。
5. 配置密钥（不要 `VITE_` 前缀）：
   - **本地**：`admin/.env` 写 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`，重启 `npm run dev:admin`
   - **线上**：[Cloudflare Dashboard](https://dash.cloudflare.com/) → Workers 和 Pages → `shanchuan-zaowu-site` → Settings → Environment variables，同样写入；再部署一次（需包含仓库 `functions/`）
6. Admin「飞书对接」点 **探测表结构**，对上采购 / 库存 / 出货三张表后保存，再拉取。

搜不到应用时逐项核对：权限已勾且已发布、可用范围含当前账号、用的是「添加文档应用」不是分享。备选：给应用加**机器人**能力并发布 → 建群把应用加为群机器人（不是自定义机器人）→ Base **分享**该群并给可编辑。

## 3. 字段映射（保存后可改）

探测成功后按飞书列名填写。常见中文列（仅作默认猜测，以探测结果为准）：

| 角色 | 飞书列（示例） | 系统字段 |
|------|----------------|----------|
| 库存 | 品名 / SKU / 数量 / 单位 | `skuName` / `skuId` / `qty` / `unit` |
| 采购 | 单号 / 物料 / 数量 / 供应商 / 状态 / 日期 | `orderNo` / `skuName` / `qty` / `supplier` / `status` / `date` |
| 出货 | 单号 / 门店 / 物流公司 / 物流单号 / 状态 | `orderNo` / `storeName` / `carrier` / `trackingNumber` / `status` |

SKU 对齐：优先 `skuId`；否则按品名匹配 `products.title` / 价目 `skuId`。匹配不上的进「未映射」列表，不改库存。

## 4. 同步策略

- **拉取**：飞书 → 镜像集合，可重复执行（按 `record_id` upsert）。
- **应用库存**：仅把「已映射且数量有差异」写成 `stock_movements.type = feishu_pull`，并更新 `products.stock`。
- **回写出货**：Admin 已发货单若无 `feishuRecordId`，在飞书出货表新建一行并回写 id。
- **不做**：飞书改物流单号自动改 Admin；Admin 改飞书采购单。
