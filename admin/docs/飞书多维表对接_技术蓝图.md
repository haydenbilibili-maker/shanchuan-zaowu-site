## 0. 问题与原则

工作室日常的**采购、原料/成品库存、出货**目前在飞书多维表里跑；Admin 已有门店订货履约（`purchase_orders` / `fulfillment_shipments` / `stock_movements`）与超管采购账目（`ops_purchases`）。两边不能各写一套账，否则必然对不上。

**原则：分域单一真相，禁止无映射双写。**

| 业务域 | 真相源 | Admin | 飞书 |
|--------|--------|-------|------|
| **采购账目（门店+工作室）** | **云库 `ops_purchases`（SSOT）** | ERP 同步管理 + CRUD；小程序超管可写 / 店长·股东只读 | 录入源之一；拉取 upsert（`feishuRecordId`） |
| 原材料采购镜像 | 飞书（过渡镜像） | 只读镜像 `feishu_purchases` | 继续录入 |
| 原料库存 | **飞书** | 只读看板 | 继续盘点 |
| 门店/渠道订货履约 | **Admin / 店长** | 主写 PO / 出货 / 收货 | 接收出货回写（物流、数量） |
| 总部成品可用量 | **Admin `products.stock`** | 出货扣减、手工盘点 | 可由飞书「成品库存」表 **校准入库**（人工确认后应用） |

飞书继续给工作室当作业台；Admin 给门店订货与 C 端商城当经营账；**采购账目以 `ops_purchases` 为多端同一数据库**。打通的是 **SKU/字段映射 + 同步**，不是两套系统互相覆盖。

## 1. 架构

```
飞书多维表（app_token=WCs2bnIHsaty7vsjcnaczu0Wnod）
  采购表 ──pull──► feishu_purchases（镜像）
                 └─► managePurchaseOrder.upsertFromFeishu → ops_purchases（SSOT）
  库存表 ──pull──► feishu_inventory（只读） ──人工「应用为 HQ 库存」──► products.stock + stock_movements
  出货/发货表 ◄──push── fulfillment_shipments（已发货且无 feishuRecordId）
  采购表 ◄──push── ops_purchases（ERP 新建/编辑可选回写）

凭证：Cloudflare Pages / 本地 Vite 代理环境变量 FEISHU_APP_ID / FEISHU_APP_SECRET（不进 SPA / 不进 git）
映射：CloudBase configs 文档 feishu_bitable
审计：feishu_sync_logs + configs/ops_purchase_sync
```

- **线上**：`functions/api/feishu-sync.js`（Cloudflare Pages Function，`/api/feishu-sync`）
- **本地**：Vite 插件 `/admin/api/feishu-sync`（读 `admin/.env`）
- **账目 SSOT**：云函数 `managePurchaseOrder` → `ops_purchases`
- Admin 入口：
  - **飞书同步中心**（模块 78）：统一入口——连接状态、字段映射探测/保存、一键同步采购→`ops_purchases`、库存应用、出货回写、最近日志与失败重试
  - **采购管理**（模块 76）：保留「从飞书同步」快捷按钮（同一套 `runFeishuSync('pullPurchases')`）；「飞书同步中心」跳转模块 78
  - **订货履约**（模块 52）：原「飞书对接」Tab 改为跳转链接，不再内嵌双份 UI
- 小程序：
  - 超管：采购管理（可写，展示来源；同步在 ERP 完成）
  - 店长：同页只读本店
  - 股东：观测台「本店采购摘要」

## 1.1 日常工作流（3 步）

1. 打开 **业务运营 → 交易履约 → 飞书同步中心**（或命令面板搜「飞书」）。顶部确认「连接 = 已配置」。
2. 若采购映射未就绪：点「探测并自动映射」（默认列名可猜中则自动保存）；必要时在「映射设置」微调。
3. 点 **一键同步采购表 → ops_purchases**。失败可在日志行点「重试」，或回采购管理用快捷「从飞书同步」。

库存 / 出货在同一中心分 Tab，无需再跳订货履约。

## 2. 开通步骤（一次）

权限管理 / 分享里搜不到应用是正常的，那里只搜人。必须走「添加文档应用」。

1. [飞书开放平台](https://open.feishu.cn/app) 创建**企业自建应用**。
2. 权限管理勾选 **查看、评论、编辑和管理多维表格**（`bitable:app`）。未开通任一云文档 API 权限时，添加文档应用窗口搜不到该应用。
3. **版本管理与发布** → 创建版本 → 申请发布。可用范围必须包含这张 Base 的所有者（你自己）。权限未发布不会生效。
4. 打开 Base，右上角 **⋯ → ⋯更多 → 添加文档应用**（不要进「权限管理」搜人）。搜应用名，权限选 **可编辑**；若开了高级权限，给 **可管理**。
5. 配置密钥（不要 `VITE_` 前缀，**勿提交 git**）：
   - **本地**：`admin/.env` 写 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`，重启 `npm run dev:admin`
   - **线上**：[Cloudflare Dashboard](https://dash.cloudflare.com/) → Workers 和 Pages → `shanchuan-zaowu-site` → Settings → Environment variables，同样写入；再部署一次（需包含仓库 `functions/`）
6. Admin 打开 **飞书同步中心**，确认连接「已配置」；点 **探测并自动映射**（或「映射设置」），对上采购 / 库存 / 出货三张表后确认已保存。
7. 在同步中心点 **一键同步采购表**（或采购管理「从飞书同步」），确认 `ops_purchases` 出现记录且带来源「飞书」。

搜不到应用时逐项核对：权限已勾且已发布、可用范围含当前账号、用的是「添加文档应用」不是分享。备选：给应用加**机器人**能力并发布 → 建群把应用加为群机器人（不是自定义机器人）→ Base **分享**该群并给可编辑。

## 3. 字段映射（保存后可改）

探测成功后按飞书列名填写。常见中文列（仅作默认猜测，以探测结果为准）：

| 角色 | 飞书列（示例） | 系统字段（ops_purchases） |
|------|----------------|---------------------------|
| 采购 | 单号 / 物料 / 数量 / 单位 / 单价 / 供应商 / 状态 / 日期 / 归属 / 规格 / 备注 | `orderNo` / `itemName` / `qty` / `unit` / `unitPrice` / `supplier` / `status` / `purchaseDate` / `entityId` / `spec` / `note` |
| 库存 | 品名 / SKU / 数量 / 单位 | `skuName` / `skuId` / `qty` / `unit` |
| 出货 | 单号 / 门店 / 物流公司 / 物流单号 / 状态 | `orderNo` / `storeName` / `carrier` / `trackingNumber` / `status` |

去重键：`feishuRecordId`（飞书 `record_id`）。归属缺省猜为 `studio_specimen`；「山川/星宸」文案映射到对应门店 entity。

## 4. 同步策略

- **拉取采购**：飞书 → 镜像 `feishu_purchases` + SSOT `ops_purchases`（按 `feishuRecordId` upsert），可重复执行。
- **回写采购**：ERP 新建/编辑勾选「回写飞书」→ 创建或更新飞书行并 `bindFeishuRecord`。
- **应用库存**：仅把「已映射且数量有差异」写成 `stock_movements.type = feishu_pull`，并更新 `products.stock`。
- **回写出货**：Admin 已发货单若无 `feishuRecordId`，在飞书出货表新建一行并回写 id。
- **不做**：飞书改物流单号自动改 Admin；店长/股东改采购单。
