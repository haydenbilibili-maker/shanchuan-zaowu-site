# 移动端 AI 工作台（小程序内嵌 DSH）· Phase 1 技术蓝图

> 状态：**蓝图（待实现）** · 建立 2026-09-18
> 目标：把已跑通的云端 DeepSeek Harness（`https://agent.shanhaizaowu.com/`）**内嵌进小程序超管工作台**，
> 作为一个界面适配手机、方便移动办公的工作台入口。
> 归属：新流 `mobile-agent`（2026-09-18 经产品负责人授权新建）。

---

## 0. 一句话方案

小程序新增**一个 `web-view` 页面**指向 `agent.shanhaizaowu.com`；**不复制任何实现**（DSH 仍是唯一那套）。
鉴权继续由已有的 `agent-gate` 负责，新增两件网关侧能力：**服务微信业务域名校验文件** + **一次性登录票据**（免二次输密码）。

```
超管工作台 → [入口] → web-view 页面 (?ticket=<一次性票据>)
                            ↓
              https://agent.shanhaizaowu.com/  ← agent-gate（现有）
                 ├ /__gate/wechat-verify.txt      微信业务域名校验文件（免鉴权）
                 ├ ?ticket=… → 校验 → 下发 gate cookie → 302 到 /
                 └ 其余：登录页 + 365 天 cookie（现状不变）
                            ↓
                        DSH (127.0.0.1:3080)
```

## 2. 网关侧改动（`deploy/agent-server/`，可**独立完成并验证**，不碰小程序）

### 2.1 服务微信业务域名校验文件

微信要求把校验文件放到域名根，例如 `https://agent.shanhaizaowu.com/MP_verify_xxxxxxxx.txt`。

- 在 `agent-gate.mjs` 增加**免鉴权**路由：`/MP_verify_*.txt` → 返回该文件内容，`content-type: text/plain`。
- 文件内容由 mp 后台生成；落在 `/etc/agent-gate/wechat-verify.txt`（600），网关启动时读入内存。
- **注意**：该路由**必须放在鉴权判断之前**，否则微信抓不到文件 → 业务域名配置失败。
- 安全：只允许**精确匹配**该文件名（不做通配/目录遍历），内容由运维写入，不接受用户输入。

### 2.2 一次性登录票据（免二次输密码）

**协议**（对称 HMAC，复用网关已有的 `COOKIE_SECRET`，不引入新密钥）：

```
ticket = base64url( exp )  + "." + HMAC_SHA256(secret, "ticket." + exp )
```
- **短时效**：默认 **120 秒**（够小程序跳转，泄露窗口极小）。
- **一次性**：网关内存记录已用过的 `exp`（TTL 到过期为止），重复使用直接 401。
- 校验通过 → 下发与普通登录**完全相同**的 gate cookie（365 天）→ **302 到 `/`**（URL 里不留票据）。
- 失败 → 落到**登录页**（不是 401 白屏），用户仍可手输密码 ⇒ **票据坏了不影响可用性**（这是关键的降级设计）。

**票据从哪来**：三种可选，**先做最简单的第 1 种**，其余按需：
1. **固定共享票据**（Phase 1）：运维在网关生成一个长效票据写进小程序配置 —— 简单，但**泄露=永久后门**，只在"小程序包本身不公开"的前提下可接受。（**不推荐长期用**）
2. **云函数签发**（推荐）：小程序调一个云函数（`getAgentTicket`），由服务端用同一密钥签 120 秒票据 ⇒ 可校验调用者身份、可审计、可撤销。
3. **完全无票据**：退化成"再输一次密码"（方案 a）。

> ⚠ **密钥归属**：第 2 种需要把 `COOKIE_SECRET` 给云函数用。该密钥在服务器 `/etc/agent-gate.env`（600，仅 root）。
> **不要把密钥写进小程序**（小程序包可被解包）。Phase 1 用第 1 种时必须明确接受其风险，或直接上第 2 种。

## 4. 移动适配（**独立一件**，不在本 Phase 强绑）

DSH 的 `CENTER_MIN = 400px` 在 web-view 里**同样存在**（web-view 内容区就是手机宽度）。而手机浏览器里可用的
「请求桌面版网站」开关，**在 web-view 里没有** ⇒ 退路被封。

| 选项 | 做法 | 评价 |
|---|---|---|
| A | **引导横屏**（横屏约 844px，中栏可 >400px） | 零改动、立刻可用；体验一般 |
| B | 网关注入 CSS 放宽 DSH 桌面约束 | **脆弱**（依赖 DSH 压缩类名，升级即失效）—— 必须标注失效风险与自检方式 |
| C | 等 DSH 官方响应式 | DSH 标着预览版/内测，可能较快改善 |
| D | 自建移动端 UI 调 DSH API | **不做**：DSH 的浏览器传输是 RPC，不是公开 API；等于重写一套 |

**决策原则**（错题本 E8）：版式类改动**必须真机截图复核**才算完成，静态断言不算。

## 6. 验收标准（可证伪）

1. 服务器上 `curl -s https://agent.shanhaizaowu.com/MP_verify_*.txt` → 返回校验内容，**无需任何凭据**。
2. 带有效票据访问 → 302 且 `set-cookie: gate=…`；**同一个票据再用一次 → 401**（一次性）。
3. 票据过期（>120s）→ 落在**登录页**（不是 401 白屏）—— 保证降级可用。
4. 小程序真机：超管工作台 → AI 工作台 → **直接进入 DSH**（不出现登录页）。
5. 票据失效时（模拟）→ 出现登录页，**手输密码仍能进**（降级路径可用）。
6. 关掉手机/切后台再回来 → 仍在登录态（gate cookie 365 天 + webview 持久 cookie）。
