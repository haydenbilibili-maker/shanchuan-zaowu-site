# 物业合作测算 · 评估案例说明

> 模块入口：ERP 菜单「物业合作测算」（`admin/src/components/PropertyEval.vue`）
> 模型引擎：`admin/src/utils/propertyEvalModel.js`（物业合作测算 v3，与《水文化园19号楼_收益测算模型_v3.xlsx》对齐）
> 云端：`property_proposals` 集合（匿名读写，组件内直连）

## 定位

用于物业合作提案的量化测算（坪效锚定 → 营收/毛利 → 四种合作结构 → 回本与 IRR），
同时沉淀**评估案例**（含否决/不合作的复盘记录），供后续物业评估对照参考。

## 状态枚举（`STATUS_LABELS`）

| 值 | 文案 | 语义 |
|----|------|------|
| `evaluating` | 🔍 评估中 | 默认 |
| `negotiating` | 🤝 谈判中 | — |
| `signed` | ✅ 已签约 | — |
| `declined` | 🚫 不合作 | **终态**：评估后明确否决（如什刹海案例） |
| `rejected` | 🛑 已搁置 | 暂缓/搁置，可能再议 |

## 评估案例字段（非计算字段，随案例保存展示）

- `decision`：决策结论 `{ result: 'declined', summary: '不合作', date: 'YYYY-MM-DD', reasons: [...] }`
- `risks`：风险清单 `[{ level: 'critical|high|medium|low', point: '...' }]`，UI 以「🚦 风险与决策」区块渲染
- `dealTerms`：合作条件原文记录（数组）

> 以上字段为可选项：普通提案可只填数字参数；评估案例建议三字段齐全，`status` 置 `declined`。

### 什刹海民房评估案例要点

- 条件：北京什刹海民房（非营运场景）约 70㎡；4 个月免租；月营业额超 20000 进入分成（比例未明确）。
- 否决原因（6 条，见 `risks`）：非合法营运 / 时间窗口不足（4 个月无法布展并合法营收）/
  房租虚报（报价 25000、实际 15000，水分约 66%）/ 合作方为个人投资+朋友合伙（非公司主体、无对赌保证金）/
  淡季空置+行为止损 / 地段悖论（地段好只是表面）。
- 测算口径：以这有山锚点坪效 10% 保守估测（非营运民房+胡同游业态），月营收约 2 万、恰好踩在分成门槛上；
  模型四结构（年度固定租金/分成）与实际条款不对应，**数值仅作示意，决策由定性风险驱动**。

## 可复用否决条件（命中任一即不合作）

1. 非合法营运场景（住宅/无证照商用，面临取缔停业风险）；
2. 房租/条件虚报（报价与实价水分过大，合作方信用存疑）；
3. 时间窗口不足以完成布展并形成合法营收；
4. 合作方非公司主体、无担保/对赌/保证金，止损成本可能转嫁山海；
5. 强季节性导致淡季空置、分成模式空转。

## 新增评估案例

1. 在 `PRESET_PROPERTIES`（`propertyEvalModel.js`）追加一条 `status: 'declined'`、含 `decision/risks/dealTerms` 的记录；
2. `PropertyEval.vue` 的 `refresh()` 会按 id 自动补齐预置案例（老用户 localStorage 也能看到）；
3. 保存后同步至云集合 `property_proposals`。
