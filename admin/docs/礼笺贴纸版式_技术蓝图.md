# 礼笺贴纸版式（热敏不干胶 90×110mm）· Phase 1 技术蓝图

> 状态：**蓝图（实现中）** · 建立 2026-09-19 · 归属：新流 `gift-label`（产品负责人 2026-09-19 授权新建）
> 决策：与既有 **A6 并存**（**不替换**）；实物测量稍后进行，**先实现**。

## 1. 目标

让礼笺能打印到即将到货的**热敏不干胶标签贴纸**（1 卷 3 色）的**白色空白处**。

## 2. 贴纸规格与影像测量（**预估，非实测**）

**标定**：图片中大标签约 457px（横）× 560px（纵）。反推比例：457/90 = **5.08 px/mm**、
560/110 = **5.09 px/mm** —— 两者一致，故标称可信 ⇒ 贴纸 **90mm 宽 × 110mm 高（竖版）**。

| 边 | 估测 | mm |
|---|---|---|
| 左 / 右装饰边框 | ~37 / ~40 px | 7.3 / 7.9 |
| 上边框 | ~30 px | 5.9 |
| **底部水彩花带** | ~150 px | **29.5**（最厚，约占下部 27%） |

⇒ 白色区约 380px 见方 ≈ **75 × 75 mm**；
但右下有**预印圆形印章「AS YOU WISH」**（直径 ~120px ≈ **24mm**），上缘侵入白区约 30px
⇒ **干净可打印区 ≈ 75mm 宽 × 69mm 高**。

> ⚠️ **这是影像预估**。按 E8/E10（版式类必须真图验证、字段必须实测），
> **权威值只能来自实物**。计划：贴纸到货后先印**校准网格**（每 5mm 一格）量真实安全区。

## 3. 关键结论：**A6 放不下 —— 这是版式重构，不是缩小**

| | 宽高比 |
|---|---|
| A6（105 × 148 mm） | 1 : **1.41**（瘦高） |
| 可打印区（75 × 69 mm） | 1 : **0.92**（近方形） |

105mm → 75mm 时，高为 **105.7mm > 69mm** ⇒ **A6 无论怎么缩都放不进**。

## 4. 现状（**实测**）

- **印刷版渲染器**：`miniprogram/utils/giftShareCard.js`（A6 规格 `1240 × 1748` 定义在此）
- **守卫**：`miniprogram/scripts/test-gift-note-variants.mjs`，列在 `guards/80-cross.txt`（域 `cross`）
- **已钉住的硬约束**（每一条都是真图 bug 换来的，新版式必须继续满足）：
  满幅无黑边（印刷用）／正文在题记与署名之间**垂直居中**／**页脚带独立**且正文让位／
  页脚带内**两枚 15mm 码**从 `footerTop` 起／**正文自适应、永不截断**／署名下划线不越过右侧两码

## 5. 目标规格（待实物确认）

- **@300dpi**：75 × 69 mm = **886 × 815 px**
- 额外 **2mm 安全内缩**（防裁切/印刷偏移）⇒ 实际内容区 ≈ **71 × 65 mm**
- **不印自带边框**（贴纸已有装饰边）；内容**避开右下 24mm 印章区**

## 6. 实现方案

1. 渲染器支持**两种规格**（`a6` 与 `sticker`），由调用方选择；**A6 行为零改动**（守卫继续钉 A6）
2. 新增 sticker 版式：近方形下的纵向分配（题记 / 正文 / 署名 / 页脚两码）
3. **重点风险**：近方形下**署名与两枚码争位** —— 历史真图 bug（两枚码压住署名）会重演，
   必须在版式里重解并加断言，而不是靠调参试出来
4. **守卫**：在**本流域文件**新增 sticker 断言（按新守卫基础设施：`guards/_meta.json` + `guards/<NN>-<域>.txt`，
   **不写 `package.json`**、不改 `80-cross.txt`）；延续「永不截断」

## 7. 验收

| 层 | 内容 |
|---|---|
| 静态 | 新守卫断言：规格 / 永不截断 / 码不与署名重叠 |
| **实物（唯一算数）** | 贴纸到货 → 印**校准网格**量真实安全区 → 定稿 → 印真实礼笺**真图复核**（E8） |

## 8. 诚实边界

- **可打印区是影像预估**，未经实物验证；第 5 节的数值可能被实测推翻
- 当前分支是 **`guard-registration`**（非 `main`）→ 提交落在此分支
- 自检类守卫（`check:admin:selftest`）会对源码注入→还原，**必须在隔离 worktree 跑**（AGENTS.md 明示）

## 8bis. 交互升级：导出必须「先生成、后动作」（2026-09-19）

> 触发：产品负责人「继续优化导出礼笺贴纸卡的交互设计」。
> 版式（§2–§6）解决"印出来好不好看"；本节解决"**会不会印错**"。

### 现状问题（实测代码，非推测）

`subpackages/manager/gift-ops/index.js` 的导出原本是**一点即存相册并上传云端**：

| 问题 | 证据 |
|---|---|
| **没有回看机会** | 生成后直接 `saveImageToPhotosAlbum` + `cloud.uploadFile`；受礼人姓名/正文/规格印错了也照印 |
| **两个 toast 抢屏** | 「已存相册」之后紧接着「已上传…」，第二条会盖掉第一条；都还是裸 `wx.showToast`（与主视觉不一致、阻塞） |
| **权限被拒没有出口** | 只提示「未存相册（可检查相册权限）」，不给 `wx.openSetting`，运营卡死在这一步 |
| **文件无处可寻** | 只 `console.log` 一个 fileID，页面上没有任何"刚导出了什么"的痕迹 |
| **两个入口看不出差别** | 「导出礼笺图」/「导出贴纸图」没有尺寸或用途说明 |

### 升级后的交互（六条硬要求）

| # | 要求 | 实现 |
|---|---|---|
| ① | **先生成、后动作** | 导出只把结果放进 `printPreview`（预览层）；**存相册/上传都由预览层里的显式动作触发** |
| ② | 权限被拒给**可执行出口** | 样式化弹窗（`utils/appModal` 的 `withAppModal`）→「去设置」→ 授权后**自动重试一次** |
| ③ | 反馈统一 **AppToast** | 本页零裸 `wx.showToast`；提示非阻塞、与主视觉一致 |
| ④ | 不新增原生弹窗 | 走 `appModal`（`check:dialog-ratchet` 盯着原生调用数） |
| ⑤ | 导出中**禁用**两个入口 | `exporting` 状态 → `is-off`；失败/完成都必须复位 |
| ⑥ | **可追溯、可重试** | 文件名 = `orderId-规格-时间戳.png`，云路径 = `gift-print/<该文件名>`；长按复制；「最近导出」留最近 5 条；上传失败可单独重试（相册原图始终在） |

### 守卫与验收

| 层 | 内容 | 结果 |
|---|---|---|
| 新守卫 | `guards/85-gift-print.txt` → **`check:gift-export-flow`**：驱动**真实页面 JS** 断言「导出后进预览且**没有**写相册/上传」、权限被拒→弹窗→`openSetting`→自动重试、上传失败不说谎且可重试、文件名可追溯、结构上零裸 toast/原生弹窗、按钮禁用与副标题齐备 | **39/39** |
| 注入 | `no-preview`（退回一点即存）、`bare-toast`、`no-permission-exit`、`untraceable-filename`、`native-modal` | **5/5 全检出** |
| 版式守卫（既有，判据收紧） | 两条判据原先按"API 出现次数 == 1 / 内联模板"判，被合法改动（授权后重试、文件名抽成一处）误报 → 改为**按方法归属**（每个 API 只许出现在一个方法里）与**可追溯文件名**判定，**不是放宽** | **87/87 + 16 注入** |
| 真 WXML 渲染 | `/tmp/gift-preview`（真 WXML 片段 + 真 WXSS + app 令牌）：预览面板贴底（bottom=821=真实视口）、规格/文件名/两个动作可见且可点、最近导出 2 条、无横向溢出 | **10/10** |

> 验收台两处**自身缺陷**已记录（E7：先判"源码错还是判据错"）：① 未设 viewport meta → 移动端模拟下 `position: fixed` 的包含块退化成内容高度（2123px）；② 用请求高度 812 当基准，而模拟视口 `innerHeight` 实为 821 → 改成以 `window.innerHeight` 为准。

### 诚实边界

- 预览**核对的是图**，不能替运营判断"文案对不对"；提示语已写「建议先核对受礼人姓名与正文」。
- 上传仍是**手工动作**（不再自动）：多一步点击换来"不再印错"，这是刻意的取舍。
- 「最近导出」是**页内状态**（刷新即失），不是持久台账；要长期可查需落库（未做）。

## 8ter. 版式第二轮：右下重心 + 字号（2026-09-19 产品负责人指示）

> 「署名和两个二维码都放在右下角；继续优化文字字号」→ 经确认走 **A 方案：右下重心但不压预印印章**。

### 约束（为什么不能直接放右下角）

贴纸**右下有预印圆章「AS YOU WISH」**（≈24mm，距右缘 1.5mm，上缘距页脚带顶 1.5mm ⇒ 占右下 24×15mm，蓝图 §2）。
`STICKER` 表为此有 `stampSize / stampRightPad / stampTopPad`；直接把内容放进去 = **印在印章上**。

### 落墨变化（A 方案）

| 元素 | 原 | 现 |
|---|---|---|
| 署名 | 左对齐（`axisX`），下划线受"印章左缘"限制 | **右对齐到内容右缘**（`axisRight`）；下划线同轴右对齐并**独立限宽**（`sigMaxW`） |
| 署名纵向 | `sigOffset = 14mm`（带顶上方 14mm） | **`sigOffset = 5mm`** → 落在**印章正上方**（右下角）；副产品：正文竖向余量**多出 9mm** |
| 日期 | 左对齐，`dateOffset = 10.2mm` | **右对齐**（与署名同轴在下方），`dateOffset = 1.5mm` |
| 两枚码 | 从左往右铺（左下） | **整体右对齐到印章左缘内缩 2mm**（`qrRight = min(stampLeft - 2mm, 页脚右内缩)`） |

判据随之**收紧**（不是放宽）：新增「署名/日期/下划线**都在印章上缘之上**」的 y 不变量（原来靠"不越印章左缘"这条左对齐时代的判据），
以及「下划线右端对齐内容右缘且不出纸」；版式断言从 87 → **99 条**。

### 字号（印刷可读性 + 层级）

| 元素 | 原 | 现 | 依据 |
|---|---|---|---|
| 码下小字 | 18px = **1.52mm** | **21px = 1.78mm** | 热敏 1.5mm 级小字易糊 |
| 日期 | 20px | **22px** | 与署名成层级但仍清楚 |
| 「写给 · TA」 | 26px | **28px** | 收礼人姓名第一眼信息 |
| 题记说明 | 24px / 行高 27 | **25px / 行高 28** | 与 32px 主题名成 0.78 |
| 正文（手写体） | 34px 起（下限 24） | 不变 | 保"永不截断"余量 |

**调大字号挤掉正文余量 → 守卫当场抓出「长笺被压到 22px < 24px 下限」**（真回归，非判据问题）；
从三处找回空间：题记行高 27→28、带底留白 3.5→3.0mm、带间距 2→1.7mm。

### 校验台自身的两处缺陷（E7：先判"源码错还是判据错"）

1. **mock canvas 只折算 `center`，不认 `right`** → 右对齐文本被按 `x→x+w` 计范围 → 合法排版被判"越界/进印章区"。
   已修为按 `align` 折算（left / center / right）——**这条修完，居中类的历史判据也更准了**。
2. 新增的「下划线限宽」注入一度检不出：右对齐后 `sw` 已被缩字链约束，外层 clamp 变冗余。
   处置：**补回源码形状断言**（下划线必须有独立 `Math.min(..., sigMaxW)` 限宽），而不是删掉那条注入。

### 验收

真 2D canvas 渲染（`/tmp/sticker-render`，浏览器真 context 跑仓库 painter，886×815）+ `check:gift-sticker-layout` **99/99**、自检 **16/16 注入**（在隔离 worktree 跑）+ A6 守卫 **95/95 未受影响**。
