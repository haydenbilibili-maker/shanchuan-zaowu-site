## 1. 背景与目标

### 1.1 背景

财务系统已具备经营日报、账本流水、股东分红模型等能力，但**员工层面的固定薪酬、提成与考勤**仍依赖线下表格；且**门店店员**与**标本师/总部及其它职能**的计薪逻辑不同——店员应与**门店营收**挂钩，其它岗位应**单独核算**（以基本工资为主、提成规则独立或暂无）。需要在财务域内增加**员工薪酬管理**模块，实现双轨制算薪、发薪日与导出图表。

### 1.2 目标

- **G1**：维护在职/离职员工薪酬主数据，并区分**员工类型**（门店店员 / 标本师 / 其它职能等）。
- **G2**：支持**考勤**录入或导入，参与扣款或全勤奖（可选规则）。
- **G3（店员）**：**基本工资** + **提成**：提成基数为**该员工归属门店在「店铺管理」中登记的当月门店营收（净额）之和**，默认提点比例 **1%**（比例可配置）；多店员时提成池分摊规则见 §5.2。
- **G4（标本师与其它职能）**：**单独算薪酬**：以**基本工资**为主，可配置**固定绩效/项目奖金**或**与全店财务营收无关**的手工津贴项；**不参与**门店营收 1% 规则（除非未来单独立项「职能绩效方案」）。
- **G5**：在**每月发薪日**触发或一键生成**当月薪酬明细**（应发、提成/奖金、扣款、实发）。
- **G6**：支持 **Excel/CSV 导出**、**可视化图表**（门店提成 vs 职能薪酬结构、趋势等）。

## 2. 范围说明

### 2.1 本期包含

- 员工信息：姓名、工号、**员工类型**（门店店员 / 标本师 / 其它职能）、部门/岗位、入职日期、状态；**门店店员须绑定 `storeId`**（与店铺管理一致）。
- 考勤：按月汇总出勤天数、迟到早退次数、请假天数；支持手工录入与 CSV 导入。
- **门店店员薪酬结构**：基本工资 + **门店营收提点（默认该店当月门店营收净额 × 1%）** + 可选津贴/扣款；提点在池内或按人规则见 §5.2。
- **标本师与其它职能薪酬结构**：基本工资 + **单独维护的绩效/奖金字段**（可默认 0）+ 津贴/扣款；**不使用门店营收 1% 公式**。
- **门店营收数据来源**：「店铺管理」模块中 `revenueEntries` 按 `storeId` + `bizDate` 归属自然月汇总（`netAmount` 或产品约定字段）；无数据时提示并允许财务录入「当月计提成门店营收」覆盖值并留痕。
- 发薪日：全局配置「每月发薪日」；生成全员薪酬表（分类型走不同计算分支）。
- 导出、可视化：分类型展示（如店员提成 vs 职能固定成本）。

### 2.2 本期不包含（可列二期）

- 与税局个税申报系统对接。
- 生物识别/排班机直连考勤。
- 多币种、海外发薪。
- 店员阶梯提点、跨店支援拆营收等复杂规则。
- 标本师产量计件与标本等级挂钩（可另立 PRD）。

## 3. 用户与权限

| 角色 | 权限 |
|------|------|
| 财务 / 总部管理员 | 全量查看、编辑、算薪、导出、配置发薪日与提成比例 |
| 店长（可选） | 仅本店员工考勤录入与只读薪酬汇总（按数据范围控制） |
| 普通员工 | 不在本模块开放个人明细（若开放需独立「员工自助」立项） |

敏感信息（完整银行卡号、身份证）默认**不落库或脱敏**；导出文件需水印或权限审计。

## 4. 员工类型与薪酬路径

| 类型代码 | 说明 | 提成/绩效来源 | 必填字段 |
|----------|------|----------------|----------|
| `store_clerk` | **门店店员** | **归属门店**当月「店铺管理-门店营收」汇总 × **提点比例（默认 1%）** | `storeId` |
| `specimen` | **标本师** | **单独算薪**：基本工资 + 手工/配置的绩效奖金字段（不与门店营收 1% 挂钩） | 无门店强制要求 |
| `function` | **其它职能**（仓管、行政、总部运营等） | 同标本师路径：基本工资为主 + 可选奖金项 | 视岗位可选 `storeId` |

算薪引擎在生成 `PayrollSlip` 时根据 `employeeType` 分支：**仅 `store_clerk` 写入 `commissionPortion`（来自门店营收规则）**；`specimen` / `function` 可将「绩效奖金」写入 `allowance` 或独立字段 `performanceBonus`（模型见 §7）。

## 5. 名词与计算规则

### 5.1 门店月营收（仅用于店员提成基数）

- **定义**：自然月 `YYYY-MM` 内，**某门店**在「店铺管理」中登记的**门店营收**记录，对 `netAmount`（若无则用 `grossAmount - refundAmount`）按 `bizDate` 落在该月求和，记为 \(R_{\text{store},m}\)。
- **来源优先级**：① 店铺管理 `revenueEntries` 自动汇总 ② 无记录时由财务在该门店下录入「当月计提成营收覆盖值」并留痕。
- **与财务账本关系**：财务账本侧重公司/门店流水对账；**店员提成以店铺管理门店营收为准**（若两源不一致，以薪酬模块配置选择「优先门店登记」为 MVP 默认）。

### 5.2 门店店员提成计算（默认 1%）

**全店提成池（推荐 MVP 默认，避免多人重复放大基数）：**

\[
\text{池}_m = \max(0,\ R_{\text{store},m}) \times R_{\text{rate}},\quad R_{\text{rate}}=1\%\ (\text{可配置})
\]

\[
\text{店员 }i\text{ 当月提成} = \text{池}_m \times w_i \Big/ \sum_j w_j
\]

- 默认权重 \(w_i = 1\)（**人均平分**全店 1% 池）。权重表（职级系数）可二期。
- **备选方案（需配置开关）**：每人提成 \(= R_{\text{store},m} \times R_{\text{rate}}\)（即**每人**全额 1%，多名店员则总人力成本为 \(N \times 1\% \times R\)）；上线前须财务确认。

支持**按门店**配置 `storeCommissionRate` 覆盖全局 1%；支持**店员个人** `commissionRateOverride` 覆盖（在池内再乘系数或按比例缩小份额）。

### 5.3 标本师与其它职能（单独薪酬）

\[
\text{应发}_{\text{职能}} = \text{基本工资} + \text{绩效/奖金} + \text{津贴} - \text{考勤扣款}
\]

- **绩效/奖金**：MVP 为**按月手工录入或固定月薪内已含**；不做自动营收比例。
- 预留与「计件产量」「项目奖」对接的扩展字段，本期可不实现自动逻辑。

### 5.4 应发与实发（统一）

\[
\text{应发} = \text{基本工资} + \text{提成或绩效项} + \text{津贴} - \text{考勤扣款}
\]

- **基本工资**：月薪计入（是否按出勤折算见 §12）。
- **考勤扣款**：简化规则，写入配置表。
- **实发**：MVP 可与应发一致；预留社保公积金二期。

### 5.5 发薪日自动计算

- 配置项：`payDayOfMonth`（1～28）。
- **触发方式**：定时任务（云函数）或手动「生成当月薪酬表」。
- **锁定机制**：草稿 → 已锁定 → 归档；锁定后仅管理员可解锁。

## 7. 数据模型概要

```
员工 PayrollEmployee（本地 localStorage `sc_payroll_bundle_v1`，非 CloudBase）
  - id, employeeNo, name, employeeType(store_clerk|specimen|function),
    phone, gender,
    idCardNumber, bankCardNumber, bankName,   // 敏感：列表脱敏，编辑可看完整值
    department, position, status, hireDate, leaveDate(optional),
    storeId(optional, 店员必填), teamMemberId(optional),
    baseSalaryMonthly,
    commissionParticipate(boolean, 店员默认 true),
    commissionRateOverride(optional, decimal),
    monthlyPerformanceBonus(optional, 职能/标本师默认可空),
    feishuRecordId(optional), syncedFromFeishuAt(optional),
    createdAt, updatedAt

考勤汇总 PayrollAttendanceMonth
  - id, employeeId, yearMonth, expectedDays, actualDays, lateCount, leaveDays,
    deductionAmount(optional), remark, updatedAt

薪酬明细 PayrollSlip
  - id, employeeId, yearMonth, employeeType(快照),
    basePortion, commissionPortion(店员; 职能可为0),
    performanceBonus(职能/标本师), allowance, deduction,
    grossPay, netPay,
    revenueBaseUsed(店员: 门店月营收; 职能: 可空),
    commissionRateUsed, storeId(快照),
    status(draft|locked), lockedAt(optional), createdAt

全局配置 PayrollSettings
  - payDayOfMonth, clerkCommissionRate(0.01), clerkCommissionMode(pool|per_head),
    defaultExpectedWorkDays(22), ...
```

索引：`PayrollSlip(employeeId, yearMonth)` 唯一；`PayrollAttendanceMonth(employeeId, yearMonth)` 唯一。

## 11. 验收标准

1. 同一门店两名店员、一条已知门店月营收：在**提成池**模式下，两人提成之和等于 \(R_{\text{store},m} \times 1\%\)（允许四舍五入误差在规则内）。
2. 标本师与职能员工生成薪酬时 **commissionPortion 恒为 0**；若有绩效则写入 **performanceBonus**，**不与门店营收公式联动**。
3. 店员未绑定 `storeId` 时禁止生成薪酬并给出明确校验提示。
4. 导出含员工类型、门店编码、提成基数等列且与界面一致。
5. 锁定后非授权用户不可改关键金额字段。

## 12. 待定事项

- [ ] 店员提成模式最终采用 **pool（全店 1% 池平分）** 还是 **per_head（每人 1%×店营收）**；PRD 默认 **pool**。
- [ ] 基本工资是否按出勤比例折算。
- [ ] 与现有财务设置里「员工人数、人均月薪」字段的迁移或弃用策略。
- [ ] 自动发薪：云函数 Cron 与站内提醒方案。
- [ ] 跨店支援店员当月 `storeId` 归属规则（按编制店还是按考勤店）。
