## 1. 信息架构

```
超管工作台 · 工作室 ─ 磁贴「供应商管理」(原「供应商预览」)
  └─ /subpackages/b2bdesk/center/index   供应商管理中心（新分包 b2bdesk）
       ├─ 大盘   时间范围（今日/近7天/近30天/本月/全部）× 伙伴筛选 → 订单 / 货款 / 账龄 / 伙伴排行 / 价目概况
       ├─ 订单   状态·货款·方向·伙伴·日期筛选 → 列表 → /b2bdesk/order/index 详情时间线（只读）
       ├─ 价目   搜索 / 状态 / 题材 → 上下架 · 上移下移 · 编辑 · 删除(被引用→停用) → /b2bdesk/price-edit/index
       └─ 伙伴   B2B 伙伴列表（角色 / 状态 / 功能项 / 订单概况）→ /b2bdesk/partner/index 权限编辑
                 └─ 「以伙伴视角预览」→ 原采购商工作台 Hub（保留原「预览」能力）
伙伴端（采购商 / 供货方）
  └─ 采购商工作台 Hub 新增模块「对账与物流」→ /subpackages/b2bdesk/statement/index（按功能项 statement 服务端放行）
```

- 新分包而非塞进 manager / extra：manager ≈1972KiB、extra ≈2059KiB（源码口径）已贴 2048 线；新分包独立计量，不设预下载（仅超管与伙伴使用）。
- 伙伴端页面也放 b2bdesk：`statement` 需复用同一套格式化工具，放 extra 会跨包 require。

## 2. 权限模型

三级，**由外到内，每一级都在服务端判定**：

| 级 | 载体 | 谁改 | 在哪校验 |
|---|---|---|---|
| L1 账号启停 | `staff_members.status`（`active`/`disabled`） | 本中心 `adminSetPartnerStatus`（**仅限纯 B2B 伙伴**；含门店角色的人仍走花名册） | `staffGuard.resolveActor` 只认 `active` → **所有云函数**（含 `payB2bPurchase`）自动拒绝 |
| L2 角色 | `staff_members.roles`（buyer/franchisee/channel/supplier） | 花名册 `manageStaff.upsert`（不变） | `payB2bPurchase.requireBuyer` / `handleSupplierList` 的 `hasRole` |
| L3 功能项（新） | `staff_members.b2bDesk.features`（可选字段，缺省 = 默认值） | 本中心 `adminSavePartnerAccess` | 见下表「服务端校验点」 |

**功能项目录**（`deskCore.DESK_FEATURES`，默认值写死在代码里；字段缺省即默认，存量伙伴行为不变）：

| key | 适用 | 名称 | 默认 | 服务端校验点 | 本期状态 |
|---|---|---|---|---|---|
| `catalog` | 采购商 | 价目选购 | 开 | Hub 隐藏入口；**价目集合当前对任意登录用户可读**（规则 `read: auth != null`） | ⚠️ 界面级；集合读规则收紧需点名（N-3） |
| `order` | 采购商 | 下单 / 支付 / 我的采购单 | 开 | `payB2bPurchase.create/pay/markOfflinePending/list` | ⚠️ 已交付判定函数 `deskAccess.js`，**接入属 B2B 支付流**（变更请求 CR-1） |
| `demand` | 供货方 | 采购需求 | 开 | `payB2bPurchase.supplierList` | ⚠️ 同上 CR-1 |
| `ship` | 供货方 | 发货回传 | **关** | 目前**不存在**任何写回路径（Phase1「写回待下版」），开关先占位；将来写回动作必须先过 `hasDeskFeature(actor,'ship')` | ✅（无路径即无越权） |
| `statement` | 两者 | 对账与物流 | 开 | 本中心 `myStatement` | ✅ 服务端拒绝 |

- 超管：全部功能项恒为开（`deskKind=preview`）。
- **不改 staffGuard**（59 份副本 + `payB2bPurchase` 副本属 B2B 流在写文件）；功能项判定放在本中心自带的 `deskAccess.js`（纯函数，读同一个 actor + staff 行），供 B2B 流原样复制接入。

## 3. 大盘指标与口径

- **时间**：北京时间（UTC+8）自然日，与 `manager/utils/reportDay.js` / `getAnalyticsDashboard.toBizDate` 同构（云函数不能跨包 require，`deskCore.bizDateKey/dayBounds` 为同式副本，守卫钉住 00:30 边界）。
- **范围字段**：订单按 `submittedAt || createdAt` 落入范围；范围 = 今日 / 近 7 天（含今日）/ 近 30 天 / 本月（1 日起）/ 全部。
- **单据口径**：`scope=desk`（默认）= `source=buyer_workbench` ∪ `party=supplier_fulfillment`；`scope=all` 另含店长订货 / 意向转单 / ERP 建单（这些单无 B2B 支付字段，货款记「不适用」）。
- **金额单位**：内部一律**分**（`*Fen`）。订单金额 `amountFen = round(totalAmount×100)`，缺省回落 `payFen`；实收 `receivedFen = paidFen ?? amountFen`（E18：名字自带单位，不混用元/分）。

| 指标 | 定义 |
|---|---|
| 订单数 / 金额 | 范围内、`status ∉ {draft, cancelled}` |
| 待确认 | `status = submitted`（供货方另含 `pending_supplier_confirm`） |
| 待发货 | `status ∈ {confirmed, shipping}` |
| 在途 | `status = shipped` 且无 `receivedAt` |
| 已签收 | `status ∈ {received, closed}` 或有 `receivedAt` |
| 已收款 | 采购商单 `paymentStatus = paid`（金额取 `paidFen`） |
| 验收标记 | `marked_paid`（**非真实收款**，单列不计入已收） |
| 待收款 | 采购商单 `paymentStatus ∈ {unpaid, pending, awaiting_config, 缺省}` |
| 对公待确认 | `offline_pending` |
| 金额待核对 | `pay_review`（B2B 流：回调金额不符） |
| 已退款 | `paymentStatus = refunded` 或 `refund.status = refunded` |
| 超期未收 | 待收 / 对公待确认 / 金额待核对 且账龄 > **7 天**（`PAY_TERM_DAYS`，账期待点名 N-4） |
| 账龄分档 | 北京时间营业日差：0–7 / 8–30 / 30+ |
| 应付供货方 | `party=supplier_fulfillment` 已发货/签收单金额；**付款字段未建模** → 只报应付，不编「已付」 |
| 伙伴排行 | 按伙伴（采购商 = `buyerOpenid ‖ _openid`；供货方 = `supplierId`）聚合 单数 / 金额 / 待收 |

## 4. 价目单 CRUD

| 动作 | 云函数 action | 规则 |
|---|---|---|
| 查 | `adminListPriceItems` | 关键词（品名 / skuId / 物种）· 状态 · 题材；按 `sort` 升序；每条附**被引用单数** |
| 增 / 改 | `adminSavePriceItem` | 必填 skuId / 品名 / 物种 / 包装文案（与 ERP 同）；skuId 唯一；**已被引用的 SKU 不许改 skuId**；价格 = 单一价（>0）/ 区间价（0<min≤max）/ 议价（null）；枚举与 ERP `priceListHelpers` 一致 |
| 上下架 | `adminSetPriceStatus` | 只写 `status` + `updatedAt` |
| 排序 | `adminMovePriceItem` | 与相邻项交换 `sort`；`sort` 缺失时先按当前顺序补齐 |
| 删 | `adminRemovePriceItem` | 统计 `purchase_orders.items.skuId` 与 `fulfillment_shipments.items.skuId` 引用：**有引用 → 改为停用**（`status=inactive, retiredAt`），**无引用才硬删**（同出货中心 `priceBook.removeIfUnused`） |

- 写操作全部 **仅超管**（`requireSuperAdmin`）；店长 / 伙伴调用一律 `FORBIDDEN` 且零写入（守卫运行时断言）。
- 提示：改价 / 下架会影响官网 `/price-list/` 与**未支付采购单**（B2B 流在支付时按当前上架价重算）。

## 5. 订单 / 物流 / 货款追踪（**只读**）

- 列表 `adminListOrders`：状态（待确认/待发货/在途/已签收/已取消）· 货款（待收/已收/对公/待核对/已退款/超期）· 方向（采购商→总部 / 总部→供货方）· 伙伴 · 起止日期 · 关键词；分页 20。
- 详情 `adminGetOrder`：头部（单号 / 伙伴 / 金额 / 货款标签 / 账龄）+ **时间线**：
  `下单 → 付款（微信 / 对公 / 验收标记 / 待核对）→ 确认 → 发货（承运商 + 单号）→ 签收 → 结算`；
  退款、取消为终态节点；供货方单的「结算」节点标「未建模」。付款节点展示 `payTrades` 次数、`transactionId` 尾号（只读，B2B 流修复后的字段；缺省不显示）。
- 物流：优先 `fulfillment_shipments.logistics`（`purchaseOrderId` 关联），其次采购单 `logisticsCarrier/logisticsTracking`；**只展示 + 复制单号**（§6.3）。
- 页面与云函数对 `purchase_orders` / `fulfillment_shipments` **零写入**：守卫对全部读 action 做运行时断言（假库记录写操作 = 0）+ 页面静态断言（不调 `payB2bPurchase` / `manageStoreContent` / 不直写集合）。

### 6.3 物流轨迹为何只展示单号

`logisticsPlugin` 同一 provider 不能在多个分包重复声明（已在 business 分包），且 `openWaybillTracking` 需要服务端先用「物流查询组件」按**收件人 openid + 商品**换 `waybillToken` —— 那是 C 端订单链路（稳定期）。B2B 收货人多半没有小程序 openid。接快递 100 等外部接口需商务开通 + 密钥 → 本期**只展示承运商 + 单号 + 一键复制**，列为需点名 N-5。
