## 1. 背景与目标

### 1.1 背景

品牌处于「直营样板 + 加盟扩张」阶段，招商线索、意向城市、铺位与商业资源信息分散在表格、微信与邮件中，难以统一跟进、分配负责人与复盘转化。总部需要在中台内建立**加盟商拓展域**：从**加盟意向**建档，经**城市与选址**评估，沉淀**商业资源**（人脉、渠道、物业线索），并与后续「筹备中门店」在店铺管理中衔接，形成可追溯的招商漏斗。

### 1.2 目标

- **G1**：建立**加盟意向库**，结构化采集意向人**姓名**、**联系方式**及来源、意向强度等，支持检索、导出与跟进记录。
- **G2**：建立**城市选址**子域，按城市/商圈维度登记拓展优先级、实地考察结论、竞品与客群摘要，并可关联到具体意向或门店筹备单。
- **G3**：建立**商业资源**子域，登记可触达的渠道方、业主/招商、政府或园区关系等（脱敏与权限控制），支持关联意向与城市。
- **G4**：提供清晰的**线索阶段**（如：新线索 → 已联系 → 深度沟通 → 选址中 → 已通过评审 → 签约 / 流失），便于管理与报表。
- **G5**：与**店铺管理**打通：评审通过的意向可一键或向导式生成「筹备中」门店草稿（主数据预填），减少重复录入。

### 1.3 成功指标（建议）

| 指标 | 说明 |
|------|------|
| 线索结构化率 | 有效招商线索 100% 在系统内有建档（或从导入批次可追溯） |
| 跟进时效 | 新线索在 N 小时/工作日内完成首次跟进记录的比例（N 由运营配置） |
| 转化可追溯 | 从意向到签约门店，可在系统内串联「意向 → 选址/资源 → 门店筹备」ID |
| 敏感信息合规 | 联系方式与资源方信息访问与导出均受角色约束，操作留痕 |

## 2. 范围说明

### 2.1 本期包含（MVP）

- **加盟意向库**：列表、新建/编辑、详情、跟进日志、阶段流转、基础筛选与导出（CSV/Excel）。
- **城市选址**：城市/商圈档案、优先级与拓展状态、考察记录（文本 + 可选附件）、与意向的多对多或主从关联（产品选型见 §11）。
- **商业资源**：资源方类型、名称、对接摘要、联系方式（权限控制）、关联城市与关联意向（可选）。
- **简单看板**：按阶段漏斗数量、按城市意向数、近 30 天新增/流失（可先列表统计，图表为 P1）。

### 2.2 本期不包含（可列二期）

- 对外公开加盟申请表单自动入库（需官网/小程序表单项 + 接口，另案）。
- 与税局、工商、地图 POI 的自动核验。
- 电子签约（加盟合同）与中台直连。
- 加盟商正式运营后的进销存/对账（属店铺与财务域）。
- 复杂商机评分模型与 AI 预测（可后续与 AI 中心结合）。

## 3. 用户与权限

### 3.1 角色假设

| 角色 | 典型诉求 |
|------|----------|
| 总部招商 / 拓展负责人 | 全量线索与资源维护、阶段推进、分配跟进人、导出 |
| 区域负责人 | 所辖城市与关联线索可见、维护选址与考察记录 |
| 高管 / 只读审计 | 漏斗与敏感字段脱敏视图（可配置） |
| 其它模块用户 | 默认无权限；不开放给门店店长查看全库（避免信息外泄） |

### 3.2 权限原则

- **联系方式与商业资源中的电话/微信**等：默认仅招商与管理员可见；列表页可脱敏展示（如手机中间四位掩码）。
- 所有新建、编辑、阶段变更、导出写入**操作日志**（操作者、时间、对象 ID、摘要）。
- 导出需**二次确认**或单独「导出权限」角色，降低批量泄露风险。

## 4. 业务流程与状态机

### 4.1 意向主状态（建议枚举）

| 状态代码 | 展示名 | 说明 |
|----------|--------|------|
| `new` | 新线索 | 刚录入或导入，未实质跟进 |
| `contacted` | 已联系 | 已完成至少一次有效沟通 |
| `qualifying` | 评估中 | 资质、资金、意向城市评估 |
| `site_selection` | 选址中 | 与城市选址记录强关联阶段 |
| `approved` | 已通过评审 | 内部评审通过，可进入签约或建店流程 |
| `contracting` | 签约中 | 法务/商务条款推进（可与外部签约系统并行） |
| `won` | 已签约 | 成功；建议关联「店铺管理」筹备门店或合同编号 |
| `lost` | 已流失 | 需填写流失原因（枚举 + 备注） |

状态只能按业务规则**单向或有限跳转**（如 `lost` 可允许「复活」为 `contacted` 并留痕）。

### 4.2 与城市、资源的关系

- 一条意向可关联 **1 个主意向城市** + **多个候选城市**（MVP 可简化为多选城市标签）。
- 商业资源可关联 **城市** 与 **0～N 条意向**（介绍人、业主推荐等场景）。

## 5. 功能需求

### 5.1 加盟意向库

| ID | 需求描述 | 优先级 | 备注 |
|----|----------|--------|------|
| F-01 | 列表：姓名、手机（脱敏）、主意向城市、阶段、来源、跟进人、最近跟进时间、创建时间 | P0 | 支持按阶段、城市、来源、时间筛选 |
| F-02 | 新建/编辑：**姓名**（必填）、**手机**（必填，格式校验）、备用联系方式（微信/邮箱选填） | P0 | 手机唯一性：同号合并或提示冲突由 §11 定 |
| F-03 | 扩展字段：性别（可选）、意向投资区间、从业背景、获知渠道、备注 | P1 | 渠道字典可配置 |
| F-04 | 详情页：**跟进时间线**（文本 + 下次跟进提醒日期可选） | P0 | 时间线倒序 |
| F-05 | 阶段手动变更 + 必填校验（如转 `lost` 必选原因） | P0 | |
| F-06 | 分配跟进人（从系统用户或「拓展成员」名单选择） | P1 | MVP 可仅文本字段「负责人姓名」 |
| F-07 | 导出当前筛选结果为 CSV/Excel | P1 | 受导出权限控制 |
| F-08 | 批量导入：模板列与校验错误报告 | P2 | |

**验收要点**：新建后列表立即可见；必填与手机号校验明确；详情时间线可追溯。

### 5.2 城市选址

| ID | 需求描述 | 优先级 | 备注 |
|----|----------|--------|------|
| C-01 | 城市档案列表：省/市、拓展优先级（高/中/低）、状态（未启动/调研中/已开放加盟/暂缓） | P0 | |
| C-02 | 城市详情：**商圈/备选点位**子表或富文本（地址摘要、租金带、客流判断、竞品品牌） | P0 | |
| C-03 | **考察记录**：日期、参与人、结论摘要、附件（照片/PDF） | P1 | 多条记录时间线 |
| C-04 | 关联意向：从城市详情跳转关联意向列表或勾选绑定 | P1 | 与 F 模块双向入口 |
| C-05 | 地图坐标（手填经纬度或后续接地图 SDK） | P2 | 与店铺管理地图能力对齐 |

**验收要点**：城市维度信息可独立维护；考察记录可追加且带时间序。

### 5.3 商业资源

| ID | 需求描述 | 优先级 | 备注 |

## 6. 数据模型概要

> 以下为逻辑实体，实际字段名以实现阶段与前端存储方案为准（可与现有 `localStorage`/云同步模式对齐）。

### 6.1 `FranchiseLead`（加盟意向）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string (UUID) | 主键 |
| `name` | string | 姓名 |
| `phone` | string | 手机，索引 |
| `phoneAlt` / `wechat` / `email` | string, optional | 备用联系 |
| `source` | string | 获知渠道 |
| `stage` | enum | 见 §4.1 |
| `primaryCityId` | string?, optional | 主意向城市 |
| `cityIds` | string[] | 候选城市 |
| `ownerUserId` or `ownerName` | string | 跟进人 |
| `lostReason` | string?, optional | 流失原因 |
| `notes` | string | 备注 |
| `linkedStoreId` | string?, optional | 关联筹备/在营门店 |
| `createdAt` / `updatedAt` | ISO8601 | |

### 6.2 `CityExpansion`（城市选址）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 主键 |
| `province` / `city` | string | 行政区划 |
| `priority` | enum | 高/中/低 |
| `status` | enum | 未启动/调研中/已开放/暂缓 |
| `summary` | string | 市场与商圈摘要 |
| `siteNotes` | text/json | 备选点位与结构化扩展 |
| `inspections[]` | array | `{ date, attendees, conclusion, attachmentIds[] }` |
| `relatedLeadIds` | string[] | 关联意向 |

### 6.3 `BusinessResource`（商业资源）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 主键 |
| `type` | enum | 资源类型 |
| `orgName` | string | 机构/资源方名称 |
| `contactName` | string | 对接人 |
| `contactPhone` | string | 加密或明文+权限（实现选型） |
| `description` | string | 关系与可协助事项 |
| `cityIds` | string[] | 适用城市 |
| `relatedLeadIds` | string[] | 关联意向 |
| `cooperationStatus` | enum | 接触中/已合作/休眠 |

### 6.4 `FranchiseFollowUp`（跟进记录，可选独立表或嵌入 Lead）

| 字段 | 类型 | 说明 |
|------|------|------|
| `leadId` | string | 外键 |
| `content` | string | 跟进内容 |
| `nextFollowUpAt` | datetime?, optional | 下次提醒 |
| `createdBy` / `createdAt` | string / ISO8601 | |

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 列表默认分页，单页 ≤50 条；筛选响应在常规数据量下无明显卡顿 |
| 安全 | 联系方式与资源敏感字段按角色展示；导出审计 |
| 可用性 | 与现有 ERP 导航、表格、表单交互风格一致（参考店铺管理、薪酬模块） |
| 备份 | 若数据仅存浏览器本地，需在用户文档中说明风险；中长期建议与统一云同步策略一致 |

## 8. 与现有系统的关系

| 模块 | 关系 |
|------|------|
| **店铺管理** | 意向转「筹备中门店」主数据；`linkedStoreId` 回写 |
| **公司治理中心** | 加盟政策 DOC 分发与**本模块业务数据**分离，界面可提供「资料链接」入口 |
| **CRM**（若已建设） | 线索可单向同步或定期导入，避免双录；若暂无 CRM，本模块承担 MVP 线索主库 |
| **权限管理** | 新增菜单与 `franchise.*` 粒度权限点（示例：`franchise.lead.read`、`franchise.resource.read_sensitive`） |
| **三期规划** | 与多门店、加盟商看板规划对齐，本模块为上游数据源 |

## 10. 验收标准（摘要）

1. 具备加盟意向的增删改查与阶段流转，**姓名、手机**为必填且校验正确。
2. 跟进时间线在详情页连续可读，阶段变更在日志中可追溯。
3. 城市选址可独立建档，考察记录可多条追加。
4. 商业资源在受限角色下**不可见完整手机号**（或不可导出明文）。
5. 「创建筹备门店」在联调环境下能生成店铺草稿并回写关联 ID（若 R-1 纳入本期范围）。

## 11. 待定事项

| 编号 | 议题 | 备选方向 |
|------|------|----------|
| D-01 | 手机号是否全局唯一 | 唯一则冲突拦截；不唯一则依赖「合并」功能 |
| D-02 | 城市主数据是否与国标行政区划表对齐 | 对齐利于报表；MVP 可手填省市区文本 |
| D-03 | 数据存储 | 延续本地 JSON  vs  接入现有 BaaS，与 PRD《数据库连接》一致 |
| D-04 | 意向与城市多对多 UI | 主城市 + 标签 vs 独立关联表 |
| D-05 | 是否对接外部表单线索 API | 排期与鉴权方案 |
