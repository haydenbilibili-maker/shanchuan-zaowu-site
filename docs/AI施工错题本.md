# AI 施工错题本（底层规律版）

> **用途**：本仓库 AI 施工者（含 Cursor / Codex / DSH 等）**开工前必读**。
> 这里记的不是个案，而是**反复犯错的底层模式**——每条都写清：症状 → 根因 → 规矩 → 现有防复发机制。
> 维护约定：**同类错误第二次发生 → 必须补一条守卫或自检**，并把机制写进「防复发」列。

最后更新：2026-09-19（依据 2026-09-17~19 施工期实际事故整理）

---

## 一、编辑与锚点类（最高频，占事故约一半）

### E1 · 从「渲染后的输出」里复制锚点
- **症状**：锚点找不到 / 缩进多两层 / 匹配到错误位置。本会话复现 **10+ 次**。
- **根因**：我用 `sed 's/^/  /'`、`cat -n`、`awk` 加了前缀后再从终端**回抄**文本；也用被
  **截断打印**的标识符（`_id` 只显示 26 字符）当数据用。
- **规矩**：
  1. 改文件**只用行号定位**（`next(i for i,l in enumerate(lines) …)`）；
  2. 必须看原文时用 `repr()` 或直接读文件，**绝不用加过前缀的终端输出**；
  3. 要复制的标识符（`_id` / 路径 / 长串）先确认**完整长度**再使用。
- **防复发**：改完立刻 `node --check` / `npm run lint:wxml`。

### E2 · 多行标签当成单行匹配
- **症状**：把新片段插进 `<view ...>` 标签**内部**，标记结构被破坏，`lint:wxml` 报错。
- **根因**：WXML 标签经常跨行（`<view\n  wx:if=…\n  class=…\n>`），我却按"一行一个标签"假设。
- **规矩**：插入点选**唯一属性行**或**注释行**；结构复杂时**整块重写**（给出行区间，而不是插在中间）。
- **防复发**：`npm run lint:wxml`（仓库既有）。

### E3 · 删除「成对结构」时找错闭合符 → 残留孤儿片段
- **症状**：礼赠编排页**整页打不开**（WXSS 编译失败）；根因是删 `@keyframes` 时只吃掉了
  `from {…}`，把 `to {…}` 和收尾 `}` 留成孤儿 → 花括号 163 vs 164。
- **根因**：删除脚本用「找下一个 `}`」而非**配平扫描**；删完没校验文件结构。
- **规矩**：删除成对结构必须**括号配平扫描**；删完立刻 lint；批量删除前先 `git status` 确认干净。
- **防复发**：**`npm run check:wxss-syntax`**（2026-09-19 新增，74 条清单内）——括号配平 +
  `@keyframes` 外的 from/to/N% 孤儿片段；自检两条注入。

## 二、批量改动类

### E4 · 跨文件盲目 find-replace
- **症状**：改守卫路径时用统一替换，把**注释**和**本来正确的路径**一起改了 → `check:admin`
  红条从 4 涨到 8；最终**整批回退**（包体第二批第一次尝试）。
- **根因**：把「同一字符串在多处出现」当成「同一处需要改」；没先列清单。
- **规矩**：
  1. **禁止**跨文件盲目 find-replace（AGENTS.md 对配色早有此禁令，**路径同样适用**）；
  2. 先 `grep -rln` **列出**将受影响文件 → 逐个判断 → 只改该改的 → 每条改完**立刻跑**对应守卫；
  3. 引用路径替换前先判断**引用形式**（`miniprogram/…` 全路径 vs 纯相对），**只补缺失部分**。
- **防复发**：`npm run check:require-paths` / `check:subpackage-refs`（改完必跑）。

### E5 · 相对路径被二次前缀
- **症状**：`subpackages/manager/subpackages/manager/utils/memberScan.js`；`sync-refund-policy.sh`
  与 `test-wish-wall.mjs` 均中招（运行时报 ENOENT）。
- **根因**：同 E4 第 3 条；且**改完没实跑**那两个脚本。
- **规矩**：改路径后**立刻实跑该脚本/守卫**（不是只看 diff）。
- **防复发**：同上；脚本类改动一律实跑一次。

### E6 · 一次做太多
- **症状**：包体第二批原计划一次下沉 8 个文件 → 出错后**整批回退**，收益归零。
- **规矩**：**一件一验** —— 搬一个文件 → 跑它对应的守卫 → 提交 → 再做下一个。
  （此为用户明确偏好，写入此处以固定。）

## 三、守卫与验证类

### E7 · 守卫自身的语义错 → 假失败
- **症状**：守卫报错但源码是对的。本会话 **5 次以上**：CSS「后写覆盖先写」只读第一条；
  品牌金令牌除 `--brass-400` 还有 `--gold`；固定 9000 字符切片**越界到下一个函数**；
  断言引用了**别的块**里的变量（ReferenceError）。
- **根因**：把「文本里出现过」当成「生效了」；用位置窗口代替语法边界；忽视块级作用域。
- **规矩**：
  1. 判定「生效值」要用**最后一条**同名规则 / 真实解析，不是"出现过"；
  2. 切片按**语法边界**（下一个 `\nfunction `），不用固定长度；
  3. 每个断言块**自包含**（需要的数据在块内读或内联计算）；
  4. 遇到**假失败要改判据**，**不得放宽断言**（放宽 = 守卫失效）。
- **防复发**：每条守卫必须 `--selftest`；`npm run check:admin:selftest`。

### E8 · 只凭静态分析就认为"对了"
- **症状**：守卫全绿但真机/真图是错的：印刷卡上**署名被二维码压住**、正文**丢了一整行**、
  两枚码**白底方块**、题记带被图盖住 —— 全都是用户发真图才暴露的。
- **根因**：canvas 绘制、版式重叠、原生组件行为**无法被文本断言覆盖**。
- **规矩**：视觉 / canvas / 样式 / 原生组件类改动，**必须真机或真图验证**后才算完成；
  用户发来的真图就是最高优先级证据。
- **防复发**：AGENTS.md 既有「静态分析 ≠ 事实」；本条补充：**版式类必须留真图复核**。

### E9 · 不跑全量就交付
- **规矩**：每个批次结束跑 **`npm run check:admin`**（逐条独立执行、全部跑完再汇总）。
  常态红只有 2 条（`check:miniprogram-sync` 待同步、`verify:site-dist` 官网缺图），其余必须绿。

### E14 · 画布/资源「加载失败只重试、不报错」→ 界面静默空白
- **症状**（2026-09-18 真机截图）：礼券夹「到店亮码」弹层里**二维码一片空白**，
  而编号与 58s 倒计时都在，**零报错、无重试入口**。用户只能看到一块空白色块。
- **根因（三层叠加，缺一层都不会这么难查）**：
  1. `require.async('../utils/qrCanvas.js')` —— **少退一层**，解析到不存在的
     `components/utils/qrCanvas.js`（正确是 `../../utils/qrCanvas`，同目录兄弟组件就写对了）；
     而旧 `check:require-paths` 的正则**既不认 `.async` 也不认跨行**，这类路径从未被检查过；
  2. 失败后的 `.catch()` **只重试、不置失败态** → 重试 4 次后彻底静默；
  3. `qrCanvas.js` 用 `new Promise(async (resolve) => …)`：异步 executor 抛错被吞，
     **Promise 永不 settle** → 上层「重试 + 失败提示」永远不触发。
- **规矩**：
  - **异步加载失败必须落到可见状态**（错误文案 + 重试入口），只重试不报错 = 静默空白；
  - **同分包用同步 `require`**，`require.async` 只用于跨包；
  - 画布类函数**必须始终 settle**（兜底超时 + 失败 `resolve(false)`），
    并且**回读像素**确认真的落墨（防「画到已分离节点却返回成功」）；
  - 禁止 `new Promise(async …)`（swallow 异常的经典形态）。
- **防复发**：`check:qr-draw`（新增，含 4 条注入自检）+ `check:require-paths` 扩面（`.async`/跨行/回调形态）。

### E15 · shell 里 `$var` 紧跟多字节字符 → 变量静默变空 + 吞字（2026-09-18 补记）
- **症状**：写 P0-4 自检时输出成 `✓ ★ 被检出：副本内容漂移（��` —— **路径没了，半个「）」也没了**。
  第一反应是"终端显示问题"，差点放过。
- **根因**：`"…（$target）"` 里，`）` 是多字节字符，bash 把它的字节当成**变量名的一部分**，
  于是 `$target）` 被解析成未定义变量 → 展开为空，且该字符的起始字节被吃掉。
  **不报错、不失败，只是少东西** —— 属于 E1（锚点/转义）家族，但更隐蔽。
- **规矩**：
  1. 变量后面紧跟非 ASCII 字符时**一律写 `${var}`**；
  2. 中文提示语里嵌变量，都用 `${}`，不要靠"看起来没事"；
  3. 自检/守卫的**输出本身也要核对**：用 `od -c` 看字节，不要只看滚屏（本轮就是这么抓出来的）。
- **防复发**：全仓扫描 `grep -rnP '\$[A-Za-z_][A-Za-z0-9_]*[^\x00-\x7F]' --include=*.sh --include=*.mjs --include=*.cjs --include=*.js scripts/ miniprogram/scripts/ admin/scripts/ miniprogram/cloudfunctions/*/`
  （2026-09-18 实测 **0 处**）。**若第二次发生 → 必须补一条守卫**（脚本放 `scripts/`，照 `check:wxss-syntax` 范式，含 `--selftest`）。
- **连带教训**：`bash -c "node -e \"…\""` 这种多层引号 + `$`/正则的写法会让**报错指向错误的位置**
  （本轮实测：同一个 `node -e` 报 `p['check:admin:guards']` 为 undefined，而键其实存在）。
  **复杂 JS 一律先落地成 `.mjs` 文件再跑**，不要塞进 `-e`。

### E16 · 「无法验证」被当成「通过」（2026-09-18 补记；**同类本轮出现 4 次，故已配守卫**）
- **症状**：守卫**得不出一判定**时仍然**成功退出**（或输出里写「跳过/未验证」却 `exit 0`），
  于是 `check:admin` 的汇总表里它就是一行 `✓` —— **看起来全绿，其实那件事根本没被检查**。
  它比"守卫报错"危险得多：报错会有人看，假绿不会。
- **同类 4 例（本轮实测，且都是"已存在一段时间"的）**

  | # | 形态 | 后果 |
  |---|---|---|
  | 1 | `check:dedupe-index-coverage` 只把每个云函数的 `index.js` 喂给写入扫描 | 报 `✓ 覆盖齐全（10 个函数）`，真值 **29 函数 / 47 文件** |
  | 2 | `check:species-dedup` 的"副本一致"是 `cmp -s "$SRC" "$dst"`，而 `dst` 就是真源自己 | **恒真**，等于没查 |
  | 3 | `check:source-origin:selftest` 用 BSD 专有的 `sed -i ''` | CI(GNU) 上 `set -e` 直接 exit 2 → **守卫从未被真正测到**（本机却"绿"） |
  | 4 | `check-dedupe-index-live` 无凭据时打印「⏭ 不是通过」但 `exit 0` | 一旦接进链，汇总里就是 `✓` |

- **根因**：把「没报错」等同于「检查过了」；**跳过/降级路径的退出码没有专门设计**。
- **规矩**
  1. **无法判定 → 必须非 0 退出**（本仓约定 `exit 2`），并**留在守卫链外**按需手动跑
     （同 `check:fn-sync` / `audit:collections`）；见 `后续工作基座` §2.5「不要把它们当作通过」。
  2. 「跳过」与 `✓` 必须在**退出码与视觉上都可区分**；禁止只写一句提示就给 0。
  3. 判据只覆盖**部分**输入时（例如只扫 `index.js`），必须在输出里写明覆盖面 ——
     否则那句 `✓` 就是空头承诺。
- **防复发**：`check:guards-coverage` 新增判据 —— **依赖 TCB 凭据的守卫不得进守卫链**
  （静态判定：脚本里出现 `TCB_SECRET_ID`/`TCB_SECRET_KEY`），配**判据专属**的注入断言
  + 一条"留在链外不报"的反例。基线实测 0（当前所有凭据守卫都在链外）。

### E17 · 编辑时把「注释」与下一行**接在一起** → `//` 吞掉代码（2026-09-20 补记）

- **症状**：文件里出现 `// 说明文字'lamp-sound-dropped': {` 这种一行 —— 注释把**下一行的键名
  整行吞掉**，报错点是别处（或直接语法错）。本次发生在 `test-wish-wall.mjs` 的注入表里。
- **怎么发生的（值得记住的机制）**：我用「替换」去掉一处**尾随空格**，`old_string` 以
  `\n  `（换行 + 两空格）结尾、`new_string` 以 `\n` 之外的字符结尾 → 替换后**换行也被吃掉**，
  于是下一行被接到注释末尾。
- **为什么危险**：它不是"少了个空格"这种外观问题，而是**把代码变成注释的一部分** ——
  那条注入就此消失（或整个守卫文件语法错）。若没人在意，就是一次**静默的覆盖损失**。
- **规矩**
  1. 用「替换」修**空白/格式**时，`old_string` 与 `new_string` 的**首尾换行必须对齐**；
     拿不准就**把整行（含换行）作为锚点**，不要只替换片段。
  2. 改完 `.mjs`/`.js` **立刻 `node --check`**（本次正是它在 1 秒内抓到）。
  3. 守卫文件的语法错**不会**悄悄溜过闸：`run-guards` 会执行每条守卫，语法错 = 该条非 0 = 闸红。
     所以**别因为"只是守卫文件"就跳过自检**。
- **防复发的现成机制**：`node --check`（手工那一秒）+ 守卫链本身（最终兜底）。
  本条**不需要新守卫** —— 需要的是"改空白也当成改代码"的习惯。

## 四、事实核查类

- **症状**：

  - `products[0]._id` 我加的 `productId` 在真实订单里是**空串**。

  能取多来源时**写优先级链**并说明依据，而不是赌一个字段。
- **防复发**：只读查询脚本（`scripts/audit-*.mjs` 范式）+ 结论写进注释。

### E11 · 占位/占位符当内容

## 六、开工前自检 5 问 & 收工前自检 5 问

**动手前**
1. 我要改的字段/素材，**实测确认**过了吗？（E10）
2. 这是**一件**而不是一批吗？（E6）
3. 锚点用**行号**吗？会不会落在多行标签内部？（E1/E2）
4. 引用形式是**全路径还是相对**？只补缺失部分了吗？（E4/E5）
5. 有没有**先跑 `git status`** 确认工作区干净？（E12）

**收工前**
1. `node --check` / `lint:wxml` / **`check:wxss-syntax`** 过了吗？（E3）
2. 对应守卫**实跑**了吗（脚本类要真跑）？（E5）
3. 守卫若报错——是**源码错**还是**守卫判据错**？假失败要改判据，不许放宽断言。（E7）
4. 视觉/版式类改动有**真机或真图**验证吗？（E8）
5. `npm run check:admin` 跑了吗？只有 2 条常态红吗？（E9）
