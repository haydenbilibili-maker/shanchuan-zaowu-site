# AI 鉴定「分享给他人也能看」· 链路开发说明（2026-09-15）

> 目标：把鉴定结果分享给好友 / 朋友圈 / 海报扫码后，**对方能打开并看到这条鉴定**。

## 1. 原有链路缺在哪

| 环节 | 原状 |
|------|------|
| 结果页「分享海报」 | ✅ 走 `generateSharePoster`，服务端会把记录标记 `is_shared=true` |
| 结果页「微信转发 / 朋友圈」 | ❌ **只生成了带 record_id 的链接，从未标记记录可被他人查看** |
| 好友打开链接 / 扫码 | ❌ 云端 `get_record` 判定「非本人且未公开分享」→ 直接拒绝；线上 `is_shared=true` 的记录数为 **0**，即这条链路从来没通 |
| 好友侧界面 | ✅ 已经准备好（显示「他人分享的鉴定 · 去拍一件自己的」，并隐藏「保存到我的山海图鉴」） |
| 图片可读性 | ✅ 云存储为公开读，好友端可直接取临时链接 |

## 2. 本次开发内容

| 文件 | 改动 |
|------|------|
| `cloudfunctions/identifySpecimen/index.js` | 新增 `mark_shared` action：**仅本人**可标记，`shared:false` 可撤回为仅本人可见（幂等） |
| `subpackages/feature/identify/result/index.js` | ① `onShareAppMessage`（转发）与 ② 新增 `onShareTimeline`（朋友圈）时提交「分享即公开」标记，失败不阻塞分享；③ 好友打开未分享记录时，报错文案改为可执行提示 |
| `subpackages/feature/identify/share/index.js` | 生成海报时带上当前环境（`envVersion`），开发/体验版扫码能进对应版本，便于真机验证 |
| `cloudfunctions/generateSharePoster/index.js` | 小程序码 `envVersion` 支持 release / trial / develop（默认 release） |
| `subpackages/feature/utils/legalContent.js` | 隐私政策补一条可见范围说明：**未分享仅本人可见；主动分享后，持有链接或二维码的人可见** |

设计口径：**分享即公开**（与 PRD「分享海报 → 扫码可看」一致）。撤回能力已在云端就绪（`mark_shared` + `shared:false`），暂未挂 UI。

## 4. 上线清单（须按顺序）

1. **云函数**：✅ 已部署（本次）。
2. **小程序**：需上传新版本并发布 —— 好友侧必须用带 `get_record` 读取逻辑的新客户端；旧版客户端是「仅本人可读」的直读，仍然打不开分享链接。
3. **验证顺序**（真机）：
   - 自己鉴定一条 → 结果页点「转发」给好友（或生成海报）；
   - 好友打开卡片 / 扫码 → 应能看到该鉴定的物种卡与图片，并显示「他人分享的鉴定」；
   - 未分享过的记录，用他人身份打开应提示「还没有公开分享」。
4. 海报二维码默认指向**正式版**；开发/体验阶段可在开发者工具里生成后自行扫码验证（`env_version` 已按运行时环境自动带上）。
