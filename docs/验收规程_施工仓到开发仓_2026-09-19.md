# 验收规程：施工仓 → 开发仓（本地 agent 拉回验收）

> **这份文档解决什么**：施工代理在云服务器上干活并推 git，本地 agent 把成果拉回本机、
> 在微信开发者工具里验收，通过后才提交体验版与微信审核。
> 2026-09-19 实测暴露的坑是：**两边测的不是同一份代码**（本地在开发仓的旧快照上验构造仓的改动），
> 结果「弹窗没有新样式」被误判成改动失败。本文把边界与步骤写死，避免重复踩。

---

## 0. 两个仓库、两个角色（先把边界说清）

| | 位置 | 谁在用 | 说明 |
|---|---|---|---|
| **施工仓** | 云服务器 `/home/admin/shanchuanzaowu` | **施工代理** | 唯一代码主库；编译/运行都从这里产出 |
| **开发仓** | 本地 `Business_Projects/WeChatProjects/shanchuanspecimens-只上传` | **本地 agent + 产品负责人** | **微信开发者工具打开的是它**；按流程它是「已验收」的镜像 |

**关键事实（踩过）**：施工代理**不能**直接改你本地的开发仓，你本地的 DevTools **也不会**自动看到施工仓的改动。
两者之间**只有 git 一条通路**。

## 1. 拉取协议（本地 agent 执行）

### 1.1 拉哪个提交：**认提交哈希，不认分支名**

```bash
git fetch origin --prune
git log --oneline -1 origin/guard-registration      # 记下这个哈希
```

> ⚠️ **施工代理会持续往这个分支推**（文档、守卫、修复）。所以**验收必须钉住一个确定哈希**，
> 不要用「分支最新」——否则你验到一半，代码已经变了。
> 本文每轮验收会明确给出**建议钉住的哈希**。

### 1.2 拿到代码的两种方式

**A. 本地仓是 git clone（推荐）**

```bash
git fetch origin --prune
git worktree add ../sczw-verify <哈希>      # 或 git checkout <哈希>
```

**B. 本地仓不是 clone（只是一份目录）**

施工代理侧导出精确树（不含 git 元数据），你解开覆盖：

```bash
# 在云服务器上
git -C /home/admin/shanchuanzaowu archive --format=tar <哈希> | gzip > /tmp/sczw-<哈希>.tar.gz
# 你本地
tar -xzf sczw-<哈希>.tar.gz -C <你的目录>
```

### 1.3 DevTools 打开哪个目录 ⚠️

```
<仓根>/miniprogram        ← 这里有 project.config.json（DevTools 认它）
```

**不要打开仓根**（没有 `project.config.json`）。**不要**打开开发仓的旧快照还指望看到新改动。

## 2. 验收清单（当前这轮）

**钉住的提交**：见施工代理每轮的交付说明（本文不写死哈希 —— 写死必然过期，这是本仓已多次踩的坑）。

| # | 动作 | 期望看到 | 不通过的样子 |
|---|---|---|---|
| 1 | 店长端 → 藏品库 → 编辑藏品 → **标识** tab | 祈运标签区块渲染出 6 个 chip；提示为「最多 **3** 个；写入 blessTags…」 | 区块不出现 / 数字不是 3 |
| 2 | 点满 3 个标签后，**再点一个暗着的** | **博物黑面板**：铜金细描边 + 四角折角 + 上方一行小字 **`BLESS TAG LIMIT`** + 主文案「最多选 3 个祈运标签」 | 只有深灰方块、无 overline → 还是原生 toast（说明测的不是新代码） |
| 3 | 等它自行消失（约 2.2 秒），**再点第 4 个**一次 | **还能再弹一次** | 第二次不弹 → `AppToast` 的 `close` 事件没接上 |
| 4 | 祈福墙 C 端 | 与既有截图一致（灵感词 / 4 个玩法瓦片 / 6 轨弹幕 / 30 条 / `3/30` + 「今日还可写 5 条」） | — |

> **第 2 项的坑**：条件是「点**未选中**的 + 已选满 3 个」。点已点亮的标签只是**取消**，不会触发提示。

**为什么第 2、3 项是真机必做**：施工代理只能证明「接线齐全」（组件登记、宿主挂载、`observer` 存在、`close` 复位），
**证不了它真的弹出来**。把原生 toast 换成自绘组件时，最危险的失败是**棘轮数字降了（守卫变绿）、但用户再也看不到提示** ——
这属于 `docs/AI施工错题本.md` 的 E16「无法验证被当成通过」。

## 5. 已知的、会被误判成「改动失败」的三件事

| 现象 | 真因 | 怎么排除 |
|---|---|---|
| 新样式/新文案看不到 | 测的是开发仓旧快照，不是施工仓 | 核对 DevTools 项目目录是不是从施工仓拉来的那份 |
| `main` 上验不到功能 | `main` **还没有**该功能（如祈运标签：`main` 上 `blessTags.js` 都不存在） | 用 `guard-registration` 分支，别用 `main` |
| 守卫在 `/tmp` 检出里红 4 条（`check:sfc-dev` / `check:nav-sources` / `test:module-search` / `check:astro`） | 那 4 条要解析 `vite`/`astro`，Node 模块解析**走不出仓库根** | 必须在**仓内**目录跑，且先 `npm ci --include=dev` |
