# 验收规程：施工仓 → 开发仓（本地 agent 拉回验收）

> **这份文档解决什么**：施工代理在云服务器上干活并推 git，本地 agent 把成果拉回本机、
> 在微信开发者工具里验收，通过后才提交体验版与微信审核。
> 2026-09-19 实测暴露的坑是：**两边测的不是同一份代码**（本地在开发仓的旧快照上验构造仓的改动），
> 结果「弹窗没有新样式」被误判成改动失败。本文把边界与步骤写死，避免重复踩。

---

## 0. 两个仓库、两个角色（先把边界说清）

| | 位置 | 谁在用 | 说明 |
|---|---|---|---|
| **施工仓** | 云服务器 `/home/admin/shanchuanzaowu` | **施工代理** | 唯一代码主库；编译/运行都从这里产出 |
| **开发仓** | 本地 `Business_Projects/WeChatProjects/shanchuanspecimens-只上传` | **本地 agent + 产品负责人** | **微信开发者工具打开的是它**；按流程它是「已验收」的镜像 |

**关键事实（踩过）**：施工代理**不能**直接改你本地的开发仓，你本地的 DevTools **也不会**自动看到施工仓的改动。
两者之间**只有 git 一条通路**。

## 1. 拉取协议（本地 agent 执行）

### 1.1 拉哪个提交：**认提交哈希，不认分支名**

```bash
git fetch origin --prune
git log --oneline -1 origin/guard-registration      # 记下这个哈希
```

> ⚠️ **施工代理会持续往这个分支推**（文档、守卫、修复）。所以**验收必须钉住一个确定哈希**，
> 不要用「分支最新」——否则你验到一半，代码已经变了。
> 本文每轮验收会明确给出**建议钉住的哈希**。

### 1.2 拿到代码的两种方式

**A. 本地仓是 git clone（推荐）**

```bash
git fetch origin --prune
git worktree add ../sczw-verify <哈希>      # 或 git checkout <哈希>
```

**B. 本地仓不是 clone（只是一份目录）**

施工代理侧导出精确树（不含 git 元数据），你解开覆盖：

```bash
# 在云服务器上
git -C /home/admin/shanchuanzaowu archive --format=tar <哈希> | gzip > /tmp/sczw-<哈希>.tar.gz
# 你本地
tar -xzf sczw-<哈希>.tar.gz -C <你的目录>
```

### 1.3 DevTools 打开哪个目录 ⚠️

```
<仓根>/miniprogram        ← 这里有 project.config.json（DevTools 认它）
```

**不要打开仓根**（没有 `project.config.json`）。**不要**打开开发仓的旧快照还指望看到新改动。

> **⚠️ 2026-09-19 实测：施工仓作为 DevTools 目标会编译失败（原因待定位，别再用它当验收入口）**
>
> 产品负责人把 DevTools 指向 `施工仓/miniprogram` 后，Console 报
> `Error: module "pages/index/index" is not defined` + `module "components/…"`，模拟器黑屏。
> **仓侧已逐项排除**（全部有实测数字，不是"看着没问题"）：
> ① DevTools 本地存储里登记的路径**正确**（就是 `施工仓/miniprogram`）；
> ② `app.json` 的 6 主包 + 118 分包页**全部存在**；③ 87 条 `usingComponents`**全部解析得到**；
> ④ 381 个 JS **零语法错误**；⑤ `lint:wxml` **154 个通过**；⑥ WXSS 语法守卫在绿名单内；
> ⑦ 全部 **876 处** require 的相对依赖**全部解析得到**（曾扫出 2 条"坏 require"，
> 读行后确认**都在 JSDoc 注释里**——一个是写给页面的用法示例、一个的 `...` 是占位符；
> 教训：**正则扫原文有"注释盲区"，要做成守卫必须走 AST**）；
> ⑧ 分包根与 `packOptions.ignore` 无冲突；⑨ `miniprogram_npm` 两仓都缺且小程序**无** `package.json`
> → 不需要构建 npm；⑩ 施工仓与开发仓内容**等价**（顶层只差 `.DS_Store` 与开发仓自己的 `.git`）。
>
> **两个首选怀疑对象（都在 DevTools 侧，不在仓里）**：
> 1. `project.private.config.json` 的 **`ignoreDevUnusedFiles: true`**（本地设置→"过滤未使用文件"）——
>    DevTools 静态判"未使用"就把模块排除出编译，症状**正是** `module "xxx" is not defined`。
>    → 取消勾选后重新编译可一分钟证伪；
> 2. **工程编译缓存/模块图过期**（施工仓是**首次**作为 DevTools 目标）→ 工具→清除缓存→全部清除。
>
> **操作结论（当时采用，现已推翻）**：曾**改回用开发仓验收**——把集成分支同步进开发仓
> （`npm run sync:miniprogram`），在**已验证能编译**的工程里验。这同时是一刀切开病因的实验：
> 开发仓能跑 → 是施工仓的 DevTools 状态；开发仓也报同样错 → 是代码，须拿**编译面板第一条**报错继续查。

> **施工代理的三条禁止（验收通过前）**，出自 `施工与发布流程.md` §二：
> ① 不部署云函数；② 不执行 `sync:miniprogram`；③ 不执行 `cli preview` / `cli upload`。

> **⚠️ 第 3 步为什么必须本地执行**（2026-09-19 产品负责人验收时修正）：
> `sync:miniprogram` 把 `施工仓/miniprogram` 写到**开发仓的绝对路径**，而开发仓在
> **本机** `Business_Projects/WeChatProjects/shanchuanspecimens-只上传`。云服务器的施工仓里没有这个路径，
> 该命令的预检 `sync:miniprogram:check` 在开发仓不存在时会**安全跳过**（这是 CI / 他人机器上的正常行为）。
> 于是云端执行第 3 步的结果是**什么都没发生、但没有报错** —— 极易被回报成「已同步」。
> 这正是 `docs/AI施工错题本.md` E16「无法验证被当成通过」的形态：**必须核对 31 处差异归零，而不是看命令退码 0**。

## 5. 已知的、会被误判成「改动失败」的事

> **本轮（出货结算）新增两条 —— 遇到这几种现象，先查环境，别当成代码坏了：**
>
> | 现象 | 真实原因 | 怎么确认 |
> |---|---|---|
> | 进「核对出货单」页一片空白 / 提示"算价失败" | **云函数 `manageStudioSettlement` 还没部署**（新函数） | 部署后再试；Console 里会报 function not found / -501000 之类 |
> | 算价页面点「选原材料」搜不到任何条目 | **两张价目表集合没建、或规则没贴、或里面还没录条目** | 先按 §11.4 第 1–3 步录价目 |
> | 算价明明开了却仍显示"算价未启用" | `configs/studio_settlement` 的 `enabled` **缺字段默认关** | 到 ERP「价目表配置 → 费率与规则」显式打开 |
> | 出货单存进去了但金额是"—"/待核价 | 这是**设计如此**：没写包装的行按裁决 3 报红，必须人工选 | 见 §11.4 第 6 步 |
>
> 另外：施工仓工作树里有一份**并行 `gift-label` 流尚未提交**的
> `miniprogram/utils/giftShareCard.js`（`PRINT_SPECS`，礼笺贴纸版式，与本轮无关）。
> 它会被 DevTools 一起编译 —— 若礼笺打印相关有异常，**不是本轮改动造成的**，请找那条流。

| 现象 | 真因 | 怎么排除 |
|---|---|---|
| 新样式/新文案看不到 | 测的是开发仓旧快照，不是施工仓 | 核对 DevTools 项目目录是不是从施工仓拉来的那份 |
| `main` 上验不到功能 | `main` **还没有**该功能（如祈运标签：`main` 上 `blessTags.js` 都不存在） | 用 `guard-registration` 分支，别用 `main` |
| 守卫在 `/tmp` 检出里红 4 条（`check:sfc-dev` / `check:nav-sources` / `test:module-search` / `check:astro`） | 那 4 条要解析 `vite`/`astro`，Node 模块解析**走不出仓库根** | 必须在**仓内**目录跑，且先 `npm ci --include=dev` |
