# 小程序订阅通知模板配置教程（逐参数版）

> 适用范围：山海造物小程序（AppID `wxf2550373b010b447`）的**一次性订阅消息**（微信「服务通知」）。
> 本文与代码**逐字段对齐**，字段 ID 与限制均来自仓库实现，不是通用模板。
> 平台字段规则来源：[微信官方订阅消息开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)、
> [参数值限制说明](https://www.cnblogs.com/blackcatah/p/17712622.html)。

---

## 0. 先理解三件事（否则会白建模板）

**① 「服务号」= 小程序的「服务通知」**，不是公众号。
本项目已确认（2026-09-16 业务口径）：需求里的「微信服务号通知」指的就是订阅消息下发后落在微信
**「服务通知」**会话。**不需要公众号主体，也不需要公众号模板审核。**

**② 一次性订阅 = 每授权一次只能发一条。**
用户在弹窗点「允许」→ 攒 **1 次** 下发额度；发出后即耗尽，需用户再次允许。
所以**客户端必须提供授权入口**（本项目已在工作台与工单入口接了），否则服务端会收到 `43101`。

**③ 模板 ID 要填两处，否则不生效。**
微信**不允许**客户端动态获取模板 ID，所以：

| 位置 | 用途 |
|---|---|
| 云函数环境变量 | 服务端 `subscribeMessage.send` 用 |
| `miniprogram/utils/staffOrderSubscribe.js` 常量 | 客户端 `requestSubscribeMessage` 用 |

**少填任何一处 = 该模板完全不工作。**

## 2. 微信平台字段类型规则（选关键词时对照）

**这是最容易出错的地方**：你在公众平台「详细内容」里选的**每个关键词**都带一个类型，
类型的字数上限**不能改**。代码里的 `clip(v, 20)` / `clipCharacterString(v, 32)` 就是按这张表定的。

| 参数类别 | 参数说明 | 参数值限制 | 备注 |
|---|---|---|---|
| `thing.DATA` | 事物 | **20 个以内字符** | 可汉字、数字、字母或符号组合 |
| `character_string.DATA` | 字符串 | **32 位以内**数字、字母或符号 | **不能含汉字** |
| `time.DATA` | 时间 | 24 小时制，支持 +年月日 | 如 `2026年9月14日 11:15` |
| `date.DATA` | 日期 | 年月日，支持 +24 小时制 | |
| `amount.DATA` | 金额 | 1 个币种符号 + **10 位以内**纯数字，可带小数 | 结尾可带「元」 |
| `phrase.DATA` | 汉字 | **5 个以内汉字** | 如「货物配送中」 |
| `number.DATA` | 数字 | 32 位以内数字 | 只能数字，可带小数 |
| `letter.DATA` | 字母 | 32 位以内字母 | 只能字母 |
| `symbol.DATA` | 符号 | 5 位以内符号 | 只能符号 |
| `phone_number.DATA` | 电话 | 17 位以内 | 数字、符号 |
| `name.DATA` | 姓名 | 中文 **10 个**汉字内；纯英文 **20 个**字母内 | 中西混合按中文算（10 字） |
| `car_number.DATA` | 车牌 | 8 位以内 | |

**选关键词时的硬约束**（违反会报 `47003`）：

- 关键词的**类型必须与你要填的值匹配**。例如订单号含字母 → 只能选 `character_string`，
  选 `number` 会失败；申请人姓名建议 `name` 或 `thing`。
- **类型后的数字是「顺序位」，不是字数**。`thing1`/`thing2` 里的 `1`/`2` 只是该模板内第几个 `thing` 类关键词。
- 一次下发的 `data` **必须包含该模板全部关键词**，不能少发（代码里对缺失值统一填 `—`）。

## 3. 平台操作步骤（在微信公众平台）

1. 登录 [微信公众平台](https://mp.weixin.qq.com) → 用**小程序**账号（不是公众号）
2. 左侧菜单：**功能 → 订阅消息**
3. 点「**公共模板库**」→ 按用途搜索（如「审批」「开票」「补货」）
4. 选中模板 → 点「**选用**」
5. 在「**详细内容**」编辑区**逐个勾选关键词**（顺序即 `1/2/3…` 编号来源）
6. 保存后回到「**我的模板**」，复制该模板的 **模板 ID**（形如 `MLNyj-...`）
7. 把模板 ID 填入 §1 表里对应的**环境变量**与**客户端常量**

> ⚠️ 关键词**一旦选定不能增减**（改了等于换模板，模板 ID 会变）。
> 所以**先读下面对应模板的字段表，再动手选关键词**。

## 7. 验收与排错

### 7.1 下发成功长什么样

微信「服务通知」会话里收到一条卡片，点开跳转到模板配置的 `page`（已自动去掉前导 `/`）。

### 7.2 常见错误码

| 错误 | 含义 | 排查 |
|---|---|---|
| `43101` | 用户未授权 / 额度已用尽 / 已勾选「总是保持以上选择」并拒绝 | 让用户在**工作台点「工作微信通知」**再允许一次；已拒绝的需到「小程序设置」里改回 |
| `47003` | 参数不符（最关键） | 逐字段核对：① 关键词类型与值是否匹配 ② `thing` 是否超 20 字 ③ `phrase` 是否超 5 汉字 ④ `amount` 是否含非法字符 ⑤ 是否漏发模板里的某个关键词 |
| `40003` | openid 无效 | 确认 `touser` 是店员真实 openid（`staff_members.openid`） |
| `41030` | page 路径不存在 | 检查跳转路径是否拼错、是否在对应分包内 |

### 7.3 自查命令（仓库内）

```bash
# 模板一致性 + 行为断言（防止字段映射被改坏）
npm run check:species-dedup        # 同物种去重键（示例：同类守卫）

# 云函数 openapi 权限与入口完整性
npm run check:fn-integrity

# 全量守卫（含上面两项）
npm run check:admin
```

### 7.4 定位下发的日志

云函数日志里搜 `workOrderSubscribe send` / `staffOrderSubscribe`，会看到：

```

```

`skipReason`），可按 `templateCode` 统计投递成功率。

## 8. 最容易踩的 6 个坑（汇总）

1. **只填了环境变量、没填客户端常量** → 服务端能发但用户从没授权 → 全部 `43101`。
2. **把 `thing` 当长文本用** → 超 20 字直接 `47003`。要长文本请改用多个 `thing` 或缩短文案。
3. **`character_string` 里放了汉字** → 只允许数字/字母/符号。
4. **`phrase` 写了超过 5 个汉字** → 如「等待店长审批处理」必失败。
5. **漏发某个关键词** → `data` 必须包含模板全部关键词（本项目对缺失值填 `—`，但字段不能整个缺失）。
6. **改了模板关键词后没换 ID** → 平台改关键词会生成**新模板 ID**，旧 ID 失效，两处都要更新。

## 9. 一次性订阅的授权规则（照做，否则白配）

来自[官方指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)：

1. `requestSubscribeMessage` **必须由用户点击同步触发**（不能在 `onShow` 或 `await` 之后调用）
   —— 本项目所有调用点都放在 `bindtap` 处理函数内，符合要求。
2. 每次点「允许」只攒 **1 次**下发额度，**发完即尽**，需再次允许。
3. 若用户勾选「总是保持以上选择」并**拒绝**，之后不再弹窗 → 需引导其到「小程序设置」里改回。
4. 一次 `requestSubscribeMessage` 可带**多个**模板 ID（本项目一次带全部已配置模板，用户允许一次即可）。
