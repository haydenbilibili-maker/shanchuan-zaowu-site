## 2. #20 信封卡实现

### 2.1 状态判定（谁能看到信封）

`pages/user/index.js`

| 场景 | 判定 | 结果 |
|---|---|---|
| 本机退出登录 | `isLocalLoggedOut()` | `applyLoggedOutState()` → `guestMemberCardFields()`（`cardGuest: true`）+ `guestLoggedOut: true` |
| 未注册（会话成功但未绑手机 / 无有效代号） | `cardGuest = !user.phone \|\| resolveAuthState(user) === 'guest'` | `cardGuest: true`，`guestLoggedOut: false` |
| 骨架态（有 openid、快照未回填） | `pendingMemberCardFields()` | `cardGuest: false` → 画金铜骨架，**避免「先信封再等级卡」闪动** |
| 已注册 / 有快照 | 会话或快照字段 | `cardGuest: false` → 原等级卡（六档 + Lv99） |

> 「未绑手机」即未注册：注册完成标志就是手机号绑定（`onboarding` 文案「授权手机号即可完成注册」；
> 档案页 `phoneBound: !!u.phone`）。只用 `resolveAuthState` 会漏掉「有代号但没手机」这一类。

### 2.2 卡片结构（`components/UserVipCard/`）—— 与礼赠启封同构

```
<view class="vip-card-container guest-card-wrap" wx:if="{{cardGuest}}">   ← 信封卡（不翻转）
  .guest-envelope.phase-{idle|seal|lid|done}    场景（perspective:1400rpx，overflow:hidden 不出卡位）
    .ge-glow        暖光呼吸（对齐礼赠 .box-glow）
    .ge-shadow      袋内落影
    .ge-pocket      深墨袋身 + 亚麻纸纹 + 底部两片折角 + 启封后露出的铜边(.ge-flap-lip)
    .ge-face        封缄态文案（启封后淡出）
    .ge-letter      信纸（启封后自袋中升起：手写线 + 小铜印 + 说明 + CTA + 注脚）
    .ge-flap        封盖（斜切两片成 V + 折痕），掀盖 rotateX(-118deg)
    .ge-seal        红色封蜡 + 蜡滴 + 阴刻「山海」，压在封盖尖端
    .ge-butterfly   停驻蝴蝶：与蜡印同一中轴、翼尖搭在蜡面上（漂浮 + 振翅 + 暖光）
    .ge-hint        轻触开启 · 长按可直接进入
</view>
<view class="vip-card-container ..." wx:else>                            ← 原等级卡，一字未动
```

**与 Lv1「原木·见习者」的三重区分**（可静态核对）：

| 维度 | Lv1 等级卡 | 信封卡 |
|---|---|---|
| 材质 | **浅色**卡纸 / 木卡（深色文字系统） | **深墨**袋身 `#2C2822 → #191612`（信纸为米白，只在启封瞬间出现） |
| 结构 | 等级章、成长里程碑、标本水印、翻转字形、头像 | 全部**没有**（守卫断言：信封段内不得出现 `badge-pill` / `growth-panel` / `card-flip-glyph` / `card-specimen` / `avatar-wrap`） |
| 交互 | 翻转看背板 | **启封仪式**（见 2.4），单次 1.46s，不可翻转 |

### 2.3 交互：轻触启封（对齐礼赠启封的节拍与手势）

| 手势 | 行为 |
|---|---|
| **轻触信封** | `idle → seal(320ms 裂蜡) → lid(720ms 掀盖) → done(展信) → 进入`（注册引导 / 重新进入） |
| **长按** | 跳过仪式直接进入（**仪式进行中也能跳**，与礼赠 `skipCeremony` 同一语义） |
| **手指按住** | 蝴蝶当场加速振翅（620ms 后回到常态），不需要额外手势 |
| 连点 / 长按叠加 | `fireGuestCta()` 只发一次：不会二次跳转 |

**节拍不是「看起来差不多」，而是与礼赠启封同源**：`RITE_SEAL_MS/LID/DONE = 320/720/420`
与 `subpackages/feature/gift/receive/index.js` 的 `PHASE_SEAL_MS/PHASE_LID_MS/PHASE_DONE_MS` 逐值相等，
封盖掀起角度也与礼盒盖同为 `rotateX(-118deg)` —— 守卫**跨模块对账**（改一处忘改另一处 → 直接失败）。
`detached` 生命周期清定时器 + 回调前 `_cleared` 双重保险，避免卸载后 `setData`。

### 2.3.1 信封真实感（第二轮肉眼反馈后的返工）

第一版真机截图暴露两个问题，均已按「对齐礼赠启封」返工，并**逐项做成量化断言**：

| 反馈 | 病根（实测） | 返工 |
|---|---|---|
| **信封不像信封** | 封盖底色 `#3A342B` 与袋身 `#2C2822` 只差 ~12 感知亮度 → 真机上封盖**几乎看不见**，只剩两条折线，看着像「帐篷」 | 封盖提到 `#4A4236`（与袋身差 **~25**，有上下限断言：≥15 可辨识、≤28 不至变浅色帐篷）；补齐**同一套纸纹**、内侧**黄铜细线**（对齐礼赠 `.lid-brass-line`）、折口亮线 + 紧随暗线 + 随 skew 倾斜的投影 |
| **折痕抢戏** | 底部折痕 0.34 亮度横贯卡面，与封盖边线组成 X → 卡面像几何图 | 折痕压到 0.16 且**两端淡出**、下移到 `top:366rpx`；封盖中线不再用 1px 亮线（信封背面本就没有这道折痕，真机会读成裂缝） |
| **封蜡不逼真** | 高光 38%×30% 且 0.66 亮度 → 上半块被冲成粉色；两个正圆「蜡滴」挂在下缘 → 像**两颗红珠子** | 高光收到 24%×18%/0.5；蜡体加深（`#BE3038→#47070D`）；**冷蜡硬边三层**（暗红描边 + 外圈柔影）；压印圈改成**凹槽**（暗线 + 亮边）；「山海」改成**双色阴影阴刻**；溢蜡改成**与主体大面积重叠的不规则蜡块**（宽度 ≥ 蜡体 45%、嵌入 ≥ 25rpx，两道断言） |
| （自查发现）蝴蝶像贴纸 | 蝴蝶与蜡面之间没有接触关系 | `.ge-butterfly-glow` 里加**落在蜡面上的接触影**（与暖光同层、在蝴蝶图之下） |

### 2.3.2 信封「上半部分」返工（第三轮肉眼反馈）

反馈原文：「信封还是不像，特别是上半部分」。用预览器截图后定位到**几何画法错了**，不是配色问题：

| 坑 | 现象 | 病根（算出来的，不是猜的） |
|---|---|---|
| **封盖画成了「屋顶」** | 顶部中心有一道深色楔形缺口，两片浅色板像帐篷 | 两片斜切矩形按「**上边贴顶、斜边当底**」画，于是**斜掉的是上边**：左片上边 `y = 0.158x`，在 x=350 处比左端低 **55rpx** → 顶部中心 (x≈343, y<54) 变成**未被覆盖的袋身**。信封盖应只有一条斜边（折口），不能有第二条斜边 |
| 修法 | 现在是正三角形封盖 | 把斜边做成**下沿（折口）**，矩形主体伸到卡面之上、交给 `overflow:hidden` 裁掉：`top:-240rpx; height:240rpx; transform-origin: left/right bottom; skewY(±atan(224/343)=±33.1°)` —— 可见部分正好是「顶边 + 折口」围成的三角。**右侧必须用负角**（原点在右边，左侧点 local x 为负，正角会往上翻） |
| **渐变映射错位** | 渲染出的封盖比断言预期的暗（断言绿、画面弱） | 元素盒伸到卡面上方后，可见部分只占 local `11..240`：亮端被裁掉、可见段落在渐变暗端。**断言算的是 CSS 首停靠点，渲染看的是可见段** —— 这正是「静态分析 ≠ 事实」。已把亮端压到前 60%（`#4E4638 0% → #4A4236 60% → #2C271F 100%`），并给亮度差加了上下限（≥15 可辨识 / ≤34 不至变浅色帐篷） |

### 2.4 红蜡封印 + 蝴蝶落位

- **封蜡**：`.ge-seal` 是**红色封蜡**（非金印）：三层径向渐变（左上高光 / 右下暗角 / 深红主体
  `#C2383F → #9C1F2A → #74151E → #54090F`）+ 椭圆半径拼出的不规则边 + `::before/::after` 两坨**溢出的蜡滴**；
  「山海」为蜡面**阴刻**（浅色 `rgba(255,226,216,.9)` + 微阴影），压印圈 `.ge-seal-ring` 做成浅凹环。
  刻意避开 `--color-error (#D64045)`，不让封蜡与「错误态」串味（守卫断言）。
- **蝴蝶落位**：与蜡印**同一中轴**（两者都是 `left:50%` + `margin-left:-宽/2`，守卫做几何对账），
  竖直方向**翼尖搭在蜡面上**（盒体与蜡印重叠 64rpx ≥ 40rpx 下限），且停在上半部 ——
  「山海」二字完整露在蜡面下方，不被翅膀压住。启封时与蜡印一同飞离 / 裂开。

### 2.5 蝴蝶（静态素材，动效与飞离都走 CSS）

- 给定素材实测为 **静态 WebP**（无 `ANIM` / `ANMF` chunk），因此不做 GIF，改三层 CSS 动效：
  - 外层 `.ge-butterfly` → `ge-butterfly-float`（5.2s：位移 + 微旋）
  - 内层 `.ge-butterfly-img` → `ge-butterfly-wing`（1.7s：`scaleX` 振翅；按住时降到 0.42s）
  - 下层 `.ge-butterfly-glow` → `ge-butterfly-glow`（暖光呼吸）
- **启封即飞离**：`.phase-seal/.phase-lid/.phase-done` 下 `opacity:0` + 上移放大旋转（与礼赠 `brass-butterfly` 的相位规则同构）。
- 两层 transform 分离，避免「漂浮与振翅互相覆盖」这一常见坑（守卫断言两者都挂在各自元素上）。
- 素材：`miniprogram/assets/envelope/butterfly_pink.png`（320×320 **PNG RGBA**，34KB，主包；
  源 WebP 已转 PNG 以保证 iOS/安卓 `<image>` 一致渲染）。

### 3.1 清单与完成度**同源**

`NEXT_STEP_DEFS` 的 `gain` 与 `profileHelper.calcProfileScore` 的加分项**逐项对应**：
`25(手机) + 15(头像) + 15(生日) + 15(兴趣) + 10(代号) + 8(MBTI) + 7(星座) + 5(性别) = 100`。
守卫直接断言 **`Σgain === calcProfileScore(满档)` = 100**，防止出现「完成度 100% 但还列着待补项」。
清单在 `syncProfileHeader()` 内刷新 —— 与顶部完成度同一次 setData 周期，不会脱节。

### 3.2 可达性（本轮最容易静默失效的点）

清单项的 `anchor` 必须在档案页 WXML 上真实存在，否则点「去补全」**什么都不发生**。
已为 8 个 anchor 补 `id`（`field-avatar` / `field-nick` / `field-phone` / `field-birthday` / `field-interests` / `field-gender` / `field-mbti` / `field-zodiac`），
并做成守卫断言（anchor ↔ `id` 对账）—— 改 anchor 忘改 WXML 会直接失败。

## 3.5 离线预览渲染（肉眼证据，不进 check:admin）

真机之外，「信封像不像」没有任何静态办法能证明。新增开发工具：

```bash
node miniprogram/scripts/render-vip-card-preview.mjs --state loggedOut --phase idle
```
