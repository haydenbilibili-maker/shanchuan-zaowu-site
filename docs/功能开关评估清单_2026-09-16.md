# 功能开关评估清单（需求 24 交付物）

> 需求 24 原文：「评估还有哪些功能需要开关，为其在超管工作台提供功能开关」。
> **本文交付的是评估结论与落点清单**（不是代码）—— 按需求原文，这一条的交付物就是「清单 + 归属」。
> 目的：让「哪些模块该有开关、为什么、装在哪、怎么验」有据可查，避免开关散落或重复。
>
> 现状基线：`content_display_flags` 集合 + 云函数 `getContentDisplayFlags` + ERP
> `admin/src/components/ContentDisplayFlags.vue`（超管工作台）。
>
> 关联：33 条需求逐条现状见 `docs/33条需求现状核查_2026-09-16.md`。

## 0. 判定标准：什么该有开关

不是所有模块都该加开关 —— 过多开关本身就是维护负担，也会让「默认值」变成事实上的产品决策。
本清单用 **4 条标准**筛选：

| # | 标准 | 说明 |
|---|---|---|
| **A** | **上线就绪度不确定** | 内容/数据未齐（如百科知识库为空、社区无帖子）、功能在灰度或待提审 → 必须能一键下架，避免用户看到空壳 |
| **B** | **有运营/合规风险面** | 涉 UGC（社区、评论、祈福弹幕）、涉未成年人/隐私、涉平台规则 → 需要可即时关闭的闸门 |
| **C** | **成本敏感** | 消耗模型 token / 短信 / 云资源（如 AI 生成、语音）→ 异常时能止血 |
| **D** | **分阶段发布** | 按门店/客群/时间分批开放 → 需要开关而非发版 |

**不该加开关**：基础闭环能力（下单/支付/登录/订单查看）。这些若挂了也不是靠开关救，
加了反而给「关掉它」留下误操作空间。

### 2.3 评估认为**不需要**新增的（并说明原因）

| 模块 | 为什么不加 |
|---|---|
| 预约参观（`booking`） | 已有 `showBookingEntry`，且是业务闭环（付费预约），符合「不该加」判据 |
| 积分中心（`points`） | 积分是会员体系核心，非可选模块；异常应修不应关 |
| 票根（`ticket`）/ 收藏证书（`certificate`） | 交易后凭证，关掉会破坏用户权益 |
| 知识文章（`articles`） | 已由 `encyclopedia` 内容体系与 `ContentManager` 的发布状态（`enabled`/草稿）控制，**再加开关是重复** |
| 专题展览 / 近期活动 | 已有 `getHomeConfig` 的 per-item `enabled`（更细粒度，优于全局开关） |
| 商品/订单/支付/登录 | 基础闭环，见 §0 判据 |
| 积分获得动作（分享/评论/签到…） | 已有 `store_point_rules.modules` + `isModuleEnabled()`（发放侧开关），**语义不同不应混入展示开关** |

## 3. 分工：两类开关不要混

本仓库实际有**两套语义不同**的开关，评估时必须区分，否则会做出「看起来能关其实没关」的假开关：

| 体系 | 位置 | 语义 | 举例 |
|---|---|---|---|
| **展示开关** | `content_display_flags` | 「**给不给用户看**」 | `showGift`、`showAtlas` |
| **发放开关** | `store_point_rules.modules` + `isModuleEnabled()` | 「**发不发积分**」 | 分享奖励、浏览奖励 |
| **内容开关** | `getHomeConfig` 每项 `enabled`、`ContentManager` 发布状态 | 「**这条内容是否上线**」 | 单条轮播/展览 |

> 若某需求想「关闭积分分享」——应改**发放开关**，不是展示开关。
> 反之「关闭社区」——`showUserCommunity` 控入口，`showCommunityPost` 控写入，两者独立。

## 5. 实施方式（新增开关的标准三处改）

按现有 `imageThumbEnabled` 的落地路径，新增一个开关只需**三处**：

| # | 文件 | 改什么 |
|---|---|---|
| 1 | `cloudfunctions/getContentDisplayFlags/index.js` | `getDefaultFlags()` + `normalizeFlags()` + save 白名单，共 **3 处**（2026-09-16 实测：两个新开关各 3 处，共 6 处） |
| 2 | `utils/contentDisplayFlags.js` | `normalizeContentDisplayFlags()` 加归一（缺字段默认值要与云函数**一致**） |
| 3 | `admin/src/components/ContentDisplayFlags.vue` | 模板开关 + `DEFAULT_FLAGS` + `applyFlags` + `buildPayload` + `resetDefaults`，共 **5 处** |

消费侧按模块性质选择：入口显隐（`wx:if`）或云函数拒绝（写操作建议**双端都拦**，
参考 #13「交接方式置灰」的三层做法：UI + 前端拦截 + 云端白名单）。

**验收**：`npm run check:admin`（含 `check:sfc-dev` 编译、`lint:wxml`）。
