## 5. 冻结方案（核心交付）

### 5.1 判据形状：**白名单 + 处数棘轮 + 分带**（三条一起才成立）

真判据（交接页 §11-⑦ 的原话是「冻结字阶令牌集合 + 非令牌取值 0 处」）落到可执行层，需要补三件事，
否则会重演 §11-⑦ 的假绿：

| 编号 | 判据 | 为什么必须这样 |
|---|---|---|
| **D1** | `font-size` 的字面量取值 ∈ **白名单**（= `app.wxss` 里 14 条 `--fs-*` 的值）**或** ∈ **装饰带豁免清单** | 按**白名单**判，不按出现次数判 —— 次数口径 3–9 次会静默逃逸（§2.2 的 14 种 / 61 处） |
| **D2** | 非令牌**处数** ≤ 棘轮基线，且 **单调不增** | 数**处数**不是**种类数** —— 种类口径下「+8 处 `23rpx`」反而 19→18 更绿（§6.1 实测复现） |
| **D3** | 棘轮基线是**按文件的白名单**（file → 允许处数 + 允许值），**新增/超额的任何文件即失败** | 只盯全仓总数会被"A 文件减 10、B 文件加 10"互相抵消；按文件才能按页推进、且 diff 可评审 |
| **D4** | 令牌**定义**必须与白名单**双射**：14 档全在、命名即尺寸、无幻影令牌 | 已有先例：`check-toast-style` 的 A1/A2（防 `--fs-27` 这类幻影令牌绕过） |
| **D5** | 装饰带每条豁免必须**显式登记**（选择器 + 理由 + 几何语义），**不允许**"因为 ≥56 就当装饰" | 现判据正是凭 `num>48` 一刀切，把 `.h-title 88rpx` / `.tm-amount 76rpx` 正常文字算成"问题"（§6.4） |

**D2/D3 的棘轮文件形状草案**【推断】（不落盘，供集成官评估）：

```json
{
  "_doc": "字阶非令牌棘轮。数值只许减不许加；新增文件必须显式登记（哪怕为 0）。",
  "baselineTotal": 99,
  "allowed": {
    "miniprogram/components/UserVipCard/index.wxss": { "count": 17, "values": [144,148,152,160,164,168,172,176,188,196,198,204,210] },
    "miniprogram/subpackages/feature/wish-wall/index.wxss": { "count": 8, "values": [19,21,25,42] }
  }
}
```

判据必须**同时**校验：① 每个文件的实测处数 ≤ 登记值；② 全仓实测处数 ≤ `baselineTotal`；
③ 出现未登记的文件 → 失败。这三条缺一都会留后门（例：只查 ①，新建一个文件放 500 处字面量不会被发现）。

理由（数据而非偏好）：
1. 它们是**仅在册档位之间**的取值（19 = 18/20 之间，21 = 20/22 之间）。凡"改值 1rpx"落在**两档正中间**的，
   视觉效果等价于"换个档"，没有"就近"可言 —— 改值不是收敛，是**在没有产品口径的情况下替产品做选择**；
2. 它们**离现有档位全是 1rpx**，说明用户（页面作者）本来就在找一档"比 20 小一点 / 比 20 大一点"；
   补档比改值**改动量更小**（补档 = `app.wxss` +2 行 + 18 处 `var()` 替换；改值 = 18 处取值改动 + 视觉回归）；
3. `21rpx` 散布在 **10 个文件**（最长尾的一个值），"改值"要动 10 个页面的视觉，风险面远大于 2 行令牌。

**但补档有代价，必须写明**【推断】：补 `--fs-19/21` 会把字阶从 14 档变成 **16 档**，
直接改契约 C7 §1.1 的"14 档"数字，**需要 visual 流发契约变更单**；
且 `report:type` 现在把 `21rpx×12` 当成"事实字阶"报出来（≥10 次口径），补档后它才真正在册。

**对照方案（同样给数据）**：若不补档、全按就近改值：
- `21rpx` → `20rpx`（或 22）要动 **10 个文件 12 处**：`wish-wall:386/1901`、`detail:1900/1904`、  `cart:851`、`confirm-order:903`、`member-crm:1525`、`articles/detail:435`、`messages/detail:427`、
  `onboarding/done:204`、`UserVipCard:2995`、`RegisterAuthDialog:123`；
- `19rpx` → `18rpx`（或 20）要动 **2 个文件 6 处**：`wish-wall:1155/1662/1850/1881`、`cart:920/982`。
两条路的**改动面差 5 倍**（补档：2 行定义 + 18 处 `var()` 机械替换、0 处取值变化；
改值：**12 个文件**（10 个装 `21rpx` + 2 个装 `19rpx`）共 18 处取值变化，每处都可能改变视觉）。
这正是"该补档"的量化依据，不是偏好。

**展示/几何带（不该补令牌的那一半）**：

| 事实 | 数据 |
|---|---|
| `≥56rpx` 非令牌取值 | 26 种 / 46 处 |
| 集中在 | `UserVipCard` **17 处 / 12 种不同值**（`168rpx` 出现 3 次、`160rpx` 2 次、`176rpx` 2 次，故 17 处 ≠ 17 种）；`manager/manager` 8 处 / 5 种；`app.wxss` 3 处 / 3 种 |
| 最大档位 | `--fs-48`（48rpx）；`56–260rpx` 全部**不在**字阶内 |
| **能否靠改值收敛？** | **不能**：C7 §1.4 已明示这是 **E8 陷阱**（无真机压缩装饰几何 → "圆章超出卡片"这类只有肉眼能发现的问题） |

**【推断】结论二：这 46 处**不该**变成令牌，也不该被"字阶 0 处"计入。**
正确动作是把它们**移出 `font-size` 语义**（改用 `width/height` + 组件私有几何变量，如 `--seal-*`），
并进 §5.1 的 D5 豁免清单（选择器 + 理由）。**这条要产品/视觉 owner 逐条确认**，
不是判据能自动完成的。**在没有真机验收窗口前，本提案建议这批保持现状 + 白名单登记**（与 C7 §1.4 同口径）。

### 5.3 分批路线（每批的判据 + 怎么证明会失败）

> **每批的"证明会失败"= 通过注入回归让该批的闸门变红**（错题本 E7/E16 的纪律：

|---|---|---|---|
| **P0 · 新代码棘轮** | 不改存量。只建"新代码不许用非令牌值"的闸门 | ① `git diff --name-status <base>...HEAD` 里**新增文件**（`A`）的 `.wxss`：非令牌 `font-size` 处数 = 0；② 已登记文件**实测处数 ≤ 登记值**；③ 未登记文件出现非令牌值 → 失败 | 新建 `miniprogram/components/__probe/index.wxss` 写 `font-size: 19rpx;` → 闸门必须红（exit 1）；删掉 → 必须绿。**在隔离副本里跑**（见 §7 口径②） |

## 6. `report:type` 本体的判据缺陷（实测复现，**本次不改它**）

> 纪律要求：发现即记录，不顺手改。以下 5 条全部是**本次实跑复现**，不是读代码推测。

### 6.1 棘轮数「种类数」而非「处数」—— +8 处同一离群值反而更绿（**已复现**）

在 `/tmp` 的全量副本上（`/tmp/sczw-probe`，`miniprogram/` 完整拷贝）：

| 步骤 | total | distinct | orphans（种类数） | `23rpx` 是否在离群清单 |
|---|---:|---:|---:|---|
| 基线（= 今天的真实仓） | 4495 | 48 | **19** | 在（×2） |
| 注入 +8 处 `23rpx` | 4503 | 48 | **18** | **不在**（涨到 10 次，掉出"≤2 次"） |

→ 加 8 处硬编码字号，**判据从 19 绿到 18**。`--strict` 的 `exit code` 在这两种状态下**都是 0**。
**根因**：`if (d.orphans.length > max)` 数的是**种数**（L88）。

### 6.2 阈值 `TYPE_ORPHAN_MAX=22` 与实测值不成比例，留了 3 种余量

实测离群 **19 种**，默认阈值 **22** —— 要变红需凑到**第 23 种**（全新取值）。
即：今天往仓里塞 22 种新取值、每处都硬编码，`--strict` **仍然绿**。

### 6.3 3–9 次区间是无主地带（**看不见的比看得见的还多**）

**14 种 / 61 处**既不是"离群"（>2）也不是"事实字阶"（<10），在 `--json` 里**零命中**（§2.2）。
而它列出的"离群 19 种"里，**文本类可改的只有 `23rpx×2`（2 处）**。
→ 今天按下这个清单收敛，改 2 处就"清干净了"。

### 6.4 `num>48 → 图标/装饰` 只看数值，把正常文字算成"问题"

报告 L143–L148 按 `num>48` 二分。实测被误判为"图标/装饰"的**正常排版文字**：
`.h-title 88rpx`（`business/about:104`）、`.tm-amount 76rpx`（`CouponPrintMint:236`）、
`.rich-dropcap 80rpx`（`app.wxss:232`，首字下沉）、`.card-value-lg 80rpx`（`manager:117`）、
`.empty-icon 120rpx` / `.error-icon 100rpx`（**这两个反而是真图标**）。
→ 二分线与"是不是装饰"**没有相关性**；正确判据只能是 §5.1 的 D5（逐条登记）。

### 6.5 它把非令牌值当成"事实字阶"报出来（判据自相矛盾）

报告 L136 打印「事实字阶（15 档）」，其中**包含 `21rpx`** —— 一个**不在契约 C7 任何档位里**的值。
同时 L138 又把 `23rpx` 叫"离群"。**同一个东西（非令牌取值）在两个标题下有两种身份**：
`21rpx` 因为出现 12 次就成了"字阶"，`23rpx` 因为出现 2 次就成了"离群"。这正是"按出现次数判"的必然结果。
