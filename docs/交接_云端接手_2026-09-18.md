## 9. 本轮自查发现的偏差（**含集成官自己的三处错，记录在案**）

> 这一节存在的意义：**接手者不该继承我的错误结论**。三条都是我在过程中做过、随后被自己推翻的判断。

### ① ❌ 我误判过"两条线分叉、`d5decb8` 必须抢救"

我曾用 `git merge-base --is-ancestor c373922 HEAD` 在服务器上得到 `Not a valid object name`，
就断言"服务器那条线与主干无关、必须抢救"。**错。** 真实原因是**服务器从没 fetch 过 `c373922`**，
所以那个对象在它本地不存在 —— 缺对象 ≠ 历史无关。

**事实**：`d5decb8` 是 `origin/main`（`c373922`）的**祖先**，也是我本地 `main`（`f0f22df`）的祖先；
`git rev-list --count origin/main..d5decb8` = **0** → **没有任何独有提交，无需抢救，只需快进**。

> 教训：**"对象不存在"与"历史无关"是两件事**。判分叉要先 `fetch`，再用 `rev-list --count <base>..<head>` 看"有没有独有提交"。
