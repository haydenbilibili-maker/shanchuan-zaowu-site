## 6. 坑

**云端环境特有**
- `deploy/agent-server/README.md` 实测：**服务器连 GitHub 被限速**（20MB/300s 后断开）→ **别在服务器上跑重构建或大克隆**。
  后果：云端很可能**跑不了完整 `check:admin`**（`check:sfc-dev` 要 vite、`check:astro` 要 astro）。
  → 云端的正确分工是**改 + 提交 + 推分支**，**闸门交给 GitHub Actions**。
- 服务器仓库是普通 clone（`/home/admin/shanchuanzaowu`），**没有 worktree** → 要自己 `node scripts/worktree.mjs add <流id>`。
- **不要把本机的 8 个 worktree 搬过去**（在 `/tmp`，一次性副本，路径不同）。rsync 后跑 `git worktree prune`。
- 服务器**已有自己的模型 key**（与本地隔离，刻意设计）——**不要用本地的 `~/.dsh/.credentials.yaml` 覆盖**。
- `admin/.env`（`TCB_SECRET_*`）不在 git 里；要跑只读索引预检需单独 `scp`。

**本项目特有**
- `check:admin` 与 `check:admin:selftest` 是**两条独立链**：前者不跑自检 → **本地全绿也能把自检改坏**（本轮真实发生过）。
- 自检会**注入→还原源文件**：**绝不要在共享工作区跑**（会覆盖别人正在写的内容）。
- 登录门禁的 launch token 只在浏览器有效；取法见 `deploy/agent-server/README.md`（**别用宽松 grep，会抓到假值**）。
- `orders.field-level.desired.json` 是**死愿望稿**（平台无法落库含 `request.data` 的规则）→ **别以为它生效而放行 ERP 直写**。
