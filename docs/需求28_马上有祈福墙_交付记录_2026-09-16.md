## 2. 没有审核，就必须有别的兜底

「不接审核」是业务决定。**没有审核不等于没有防线** —— 本实现补了三层：

| 层 | 做法 | 防的是什么 |
|---|---|---|
| 写入闸口唯一化 | 集合规则 `write:false`，全部写入经 `manageWishWall` | 客户端直写可绕过长度/频控，还能自己把弹幕设成 `status:'visible'` + `pinned:true` |
| 人工兜底可见 | 超管端内容开关面板**默认「全部」**，含 `hidden`；可隐藏/恢复/置顶/删除 | 若管理端只看 visible，被隐藏的内容将无人可见、无从复核 |
| 一行开关 | 环境变量 `WISH_WALL_SECURITY=on` → 走微信 `security.msgSecCheck`，risky 直接拒发 | 平台复核或客诉要求补审核时，**改环境变量即可**，无需改代码发版（`config.json` 已声明权限） |

真正的热键在**开关**：`showMaShangYou` 缺配置默认**关**。关闭时 C 端入口消失，
且祈福墙页面**不发起任何网络请求**（关闭后还去拉列表 = 等于没关，守卫有断言）。

## 3. 服务端做对的四件事

| 项 | 做法 | 为什么 |
|---|---|---|
| 展示名 | 从 `users` 读 `nickName` / `avatarUrl`，缺省「匿名藏家」 | 信客户端入参 = 任何人可冒充他人发弹幕（守卫 `trust-client-nickname` 注入可证） |
| 频控 | 每人每日 5 条 + 两条间隔 ≥10 秒，按 **Asia/Shanghai 自然日** 计算 | 弹幕墙最大的滥用形态是刷屏；容器时区不保证，故手工换算 |
| 文案 | 2–30 字；折叠全部空白（弹幕是单行，换行会撑破轨道）；剔除零宽/控制字符 | 零宽字符能让同一条文案在审核视图里「看起来不一样」 |
| 频控查询失败 | **放行**（记 warn） | 宁多一条弹幕，也不要因索引缺失导致完全发不出去 |

公开列表只回 `visible`，且**不返回 openid / status**（最小暴露）；管理列表才带 `status` / `openid`。

## 4. 弹幕为什么不用随机数

`buildDanmakuRows()` 是纯函数、确定性：

- **轨道分配**用 `i % lanes`：同一份数据两次渲染得到**同一布局**。用随机数的话每次 `setData` 都会跳位置，
  且测试无法断言「同轨道不重叠」。
- **时长按字数换算**（`(屏宽 + 字数×字宽) / 固定速度`，钳在 6–26 秒）：
  固定时长会让长文案跑得比短文案快，观感是「忽快忽慢」。
- 同轨道内用 `LANE_GAP_MS` 错开，首屏再按 `i*400ms` 逐条入场，避免一屏同时涌入。
- 轨道垂直位置预留顶部 6% / 底部 10% 安全区，避免贴边裁切。

同时保留**静态列表**与弹幕同源：弹幕看得快，列表看得清（可复制、可无障碍阅读）。

## 5. 商品命中：为什么先看字段再看标题

```js
isWishWallProduct({ title: '马上有', wishWallEnabled: false }) === false   // ★
```

「马上有」当前是真实 SKU，但代码里没有任何硬引用（只有文档示例字符串）。
若只按标题子串判定，将来任何标题含「马上有」的藏品都会长出祈福墙，且**改名即失效**。
因此优先读显式字段 `wishWallEnabled`（ERP 侧后续可在藏品档案上补），标题子串只作过渡兜底。

## 10. 增量（本轮）：仪式感 · 彩蛋 · AI 第一批基础内容

需求原文要求三件上一版没有的东西：**用 AI 创作第一批「马上有XX」基础内容**、
**进入页面时的彩蛋机制**、**为全站拓展与彩蛋机制做好长线预留**。本节是这三件的交付说明。

### 10.1 AI 第一批基础内容 —— 空墙悖论

祈福墙最致命的不是没人发，而是**第一个进来的人看到空白就不会发**。
所以内容必须在用户到达前就存在，且不能依赖外部 API 的可用性：

| 层 | 做法 | 为什么 |
|---|---|---|
| 基线 | `wishSeeds.js` 的 24 条人工审校文案（生计/相遇/心境/身体/行事/念想 六个主题） | AI 没配 key、超时、返回垃圾时，"第一批内容"依然存在 |
| AI | `staffSeedAi` → DashScope `qwen-plus`，提示词带**风格样本 + 已存在清单 + 禁止项** | 只说"有仪式感"模型会写成语录体或"马上暴富" |
| 四道闸 | 句式（必须「马上有X」）/ 长度（2–30）/ 与墙上**全部状态**比对 / 批内去重 | 第三道含 `hidden`：只比 visible 的话，被人工隐藏的内容会被重新种一遍，等于绕过治理 |
| 兜底 | AI 条数不足 → 用基线补齐；两者皆空 → `NO_NEW_SEED` 明确拒绝 | **宁可拒绝，也不重复铺墙**；重复铺墙是最难被发现的内容事故 |
| 灵感 | `list` 附带按上海自然日轮换的 4 条 chip | 空墙时用户仍有"可以点一下"的起兴物 |

落库与用户弹幕**同表同字段**（`source: 'ai' | 'seed'`、`seedBatch`、`aiGenerated`），
`_openid` 留空 → 不属于任何用户、不参与用户频控与「我的」。
好处是**治理只有一处**：超管端内容开关面板照常可以隐藏/删除 AI 内容，不存在"免治理通道"。

### 10.2 进页彩蛋 —— 「吉量」，以及为什么它只弹一次

选择「吉量」（《山海经·海内北经》「乘之寿千岁」的文马）而不是随便一个神兽：
它与藏品（黑马标本）同科，且语义本身就是"祈福"，进页面的人第一眼能把彩蛋和藏品连起来。

实现上给彩蛋框架补了**自动触发类型**：

- 新增 `tryPageEnter()` / `tryWishPosted()`，页面只报事件，`pages` 由注册表持有
  → 全站拓展时新页面不必回到 `easterEgg.js` 改匹配逻辑；
- 自动类型带 `skipIfDiscovered`：**已拾得不再弹出**。这是本轮最关键的一处行为修正 ——
  `pageEnter` 每次进页都会命中，若沿用"可重看"语义，彩蛋会从惊喜变成骚扰；
- 用户主动触发（长按/关键词/连点）语义不变，仍然可以重看。

「驳」挂在 `wishPosted` 上，与「吉量」组成**进门—落愿**两段式仪式。

### 10.3 全站拓展的预留能力

落实为三处**可验证**的预留（不是注释里的"以后再说"）：

| 预留 | 实现 | 断言 |
|---|---|---|
| 作用域参数化 | `resolveWishWallKey(product)`：显式 `wishWallKey` 优先，否则回落 `mashangyou` | `entry-key-hardcoded` 注入可证 |
| 入口组件化 | `components/WishWallEntry`（判定 + 跳转唯一实现），详情页旧副本已删除 | 「详情页不再自持入口实现」断言 |
| 彩蛋注册表驱动 | `triggers[].pages` 由注册表持有，页面只报事件 | `triggerMatches` 三态断言 |

### 10.4 点灯仪式 —— 给"不想写"的人一个动作

输入框是全站转化门槛最高的控件。点灯是**零门槛**的入场动作：点一下 → 亮出当天那一句 →
本地记住"今天来过"。每日灯语用 FNV-1a 由日期键确定性选出（同一天两次进同一句），
连续天数**含今日**（今日没点就是 0，不靠昨天充数）。
纯逻辑在 `utils/wishWall.js`，读写与词表在 `utils/wishRitual.js`，
`wx` 不可用时降级为"未点灯"—— 彩蛋/仪式永远不能挡住发弹幕。

详细接入契约见 `docs/仪式感与彩蛋机制_长线框架_2026-09-16.md`。

### 11.1 入口口径写错了（已修，见 §8.1）

记录与需求台账都把入口写成「超管工作台 → **内容模块**」，而实际落点是磁贴「**开关**」(tab 16，页面标题「内容开关」)。
「内容管理」(tab 9) 里是专题/文章/评价/养护，按原口径找必然落空。
修复：「内容管理」顶部加直达条 + 全套文档口径更正（磁贴名一度改成全称，已按产品口径改回「开关」，见 §8.1）。

### 11.2 内容开关存在跨端互抹（已修）

翻这个面板的保存链路时发现一个真缺陷，**与入口无关但同属这条控制路径**：

`getContentDisplayFlags.saveFlags` 是**按固定 16 个字段整体写入**的（缺字段 → 落默认值）。
而小程序端面板只携带其中 12 个：

| 端 | 跑的是哪条写路径 | 结果 |
|---|---|---|
| 小程序超管工作台 | 云函数 `saveFlags`（整体写入 16 字段） | 未携带的 4 个字段被**重置为默认值** |
| ERP `ContentDisplayFlags.vue` | `cdnUpdate` → `doc(id).update(payload)`（**字段级**局部更新） | 只写自己带的字段，不会抹掉别的字段 |

缺的 4 个是 `allowIosStoredValue` / `imageThumbEnabled` / `showAtlas` / `showAchievements`
（编辑入口在 ERP，小程序面板没渲染它们的开关）。默认值都是"开"，所以实际后果是：
**ERP 关掉的图鉴 / 我的成就 / 列表缩略图 / iOS 储值，会被小程序里任意一次「保存开关」静默重新打开。**

修复选的是**原值回传**而不是改云函数语义：在小程序端 `data.contentFlags` 默认值与
`loadContentDisplayFlags` 归一化里补齐这 4 个字段（面板不渲染它们，保存时按读到的原值写回）。
这样 `saveFlags` 的「显式透传」契约不变（既有断言继续有效），也只动一个端。

守卫新增**结构一致性断言**：把云函数 `saveFlags` 读取的字段名逐个抽出，
要求小程序端归一化必须全部覆盖 —— 以后谁再漏字段会当场失败（注入 `flags-field-dropped` 可证）。

### 11.3 两个记录在案、本轮未改的点

1. **ERP 没有 `showMaShangYou` 开关**：ERP `ContentDisplayFlags.vue` 的字段表里没有它，
   所以在 ERP 里开不了祈福墙（只能在小程序工作台开）。原因见 §7（该页当时有并发重构）。
   ERP 保存不会关掉它 —— 那条写路径是字段级 update。
2. **店长有治理权限却没有入口**：`MENU_KEYS.CONTENT_FLAGS` 只在 `SUPER_ADMIN_MENUS` 内，
   而 `manageWishWall` 的 `staffList/staffSetStatus/staffRemove` 允许 `ROLE_MANAGER`。
   若要让店长也能复核弹幕，把 `CONTENT_FLAGS` 加进 `STORE_MANAGER_MENUS` 即可（一行）。
   本轮按"超管口径"未改，避免在未确认前扩大 UGC 治理面。

## 12. 第二次实测反馈核查（「点了没反应」「开了开关没入口」）

反馈两条：① 点「AI 生成一批心愿」毫无反应；② 开关打开后「马上有」详情页没有任何入口。
**两条都是真 bug，都属于「静默失败」**——不报错、不失败，所以既有的 175 项断言全绿也照样漏掉。
根因与修法如下，两条都补了断言 + 注入。

### 12.1 点「AI 生成一批心愿」没反应 —— `showModal` 按钮文案 5 个字

微信 `wx.showModal` 的 `confirmText` / `cancelText` **最多 4 个字符**（官方硬限制）。
超长时 `showModal` 直接失败；**不传 `fail` 回调时既没有弹窗也没有任何报错** ——
这正是「点了没反应」。

原代码写的是 `confirmText: '生成并上墙'`（**5 个字**），必中：

| 项 | 修法 |
|---|---|
| 文案 | `'生成并上墙'` → `'生成'`（≤4 字） |
| 失败可见 | 补 `fail` 回调 + toast：**弹窗失败不能再静默** |

> 断言只搜裸词会被注释里的同名函数骗过（§6 已踩过一次），所以注入用的是
> 「把文案改回 5 个字」（`modal-text-too-long`），断言校验**实际字面量长度**。

**这是全仓性问题，不止这一处**：扫描全仓 `confirmText`/`cancelText`，
另有 **5 处超长**，即 5 个**永远弹不出来的弹窗**，且都在低频但关键的路径上：

| 位置 | 文案 | 字数 | 所在路径 |
|---|---|---|---|
| `subpackages/business/order-detail/index.js` | 先复制单号 | 5 | 物流轨迹组件未加载的降级提示 |
| `subpackages/business/utils/refundPolicy.js` | 去上传举证 | 5 | 退款举证 |
| `subpackages/feature/utils/refundPolicy.js` | 去上传举证 | 5 | 退款举证 |
| `subpackages/manager/utils/refundPolicy.js` | 去上传举证 | 5 | 退款举证 |
| `subpackages/manager/manager/managerPageConfig.js` | 确认补履约 | 5 | 补履约 |

这 5 处**本轮未改**（属退款/履约链路，且 refundPolicy 有 3 份同步副本，需一起改并复核），
改为新增守卫 **`npm run check:modal-text`**（棘轮）把它们登记为基线：**只许减少，不许新增**。
`--selftest` 用 6 个用例证明它能抓到超长、也不误报 ≤4 字（含真实事故形态 5 字文案）。

### 12.2 开关开了、详情页没有入口 —— SWR 把新鲜值丢了

`fetchContentDisplayFlags` 走 SWR：**缓存命中时立刻返回缓存值**，新鲜值只在后台回填；
缓存 TTL 10 分钟，陈旧窗口 **24 小时**，且缓存落 `wx.setStorageSync`（重启也还在）。

而详情页原来只读一次返回值就完事：

```js
const { flags } = await fetchContentDisplayFlags();   // ← 拿到的是旧值
this.setData({ wishWallEnabled: flags.showMaShangYou === true });
```

后台那次刷新拿回来的新值**没有任何人接**。于是「超管刚把开关打开」→
C 端最长 ~24 小时看不到入口；若缓存还在 10 分钟"新鲜期"内，连后台刷新都不会触发，
表现就是**反复重进详情页也一直没入口**。工作台看到的「展示中」是直连云函数读的（不走缓存），
所以**开关显示已开、C 端却是关的**——现象完全对得上。

三处修法：

| 位置 | 修法 |
|---|---|
| `subpackages/feature/detail/index.js` | 抽出 `applyDisplayFlags(flags)`（带签名去重），并作为 `onUpdate` 传入 —— 缓存值先上屏，新鲜值到达自动重放（**不额外发请求**） |
| `subpackages/feature/wish-wall/index.js` | 门禁收敛成 `applyGate(flags)`，同样接 `onUpdate`；下拉刷新改为 `bootstrap({ force: true })`，给用户一个**自救动作** |
| `managerPageConfig.saveContentDisplayFlags` | 保存成功后 `invalidateContentDisplayFlags()` —— 本机缓存立刻失效，同机验证即时生效 |

顺带补了第三条易踩的坑：**开关是"先改本地、点保存才写云端"**，
原来拨动开关后界面照样显示「展示中」，很容易以为已经生效。现在拨动即标脏，
面板显示「有未保存的改动 —— 点下方『保存开关』后 C 端才会生效」。

## 18. 升级 · 第四期：多面墙的**内容正确性**（句式前缀跟着墙走）

第三期让第二面墙"可治"，但还有一处更隐蔽的问题：**生成的内容本身是错的**。

### 18.1 洞在哪：AI 播种的句式被写死成「马上有XX」

`wishSeeds.js` 把句式前缀写死成一个常量，并且：

- 句式闸按它筛（`text.indexOf(SEED_PREFIX) !== 0` → 丢弃）；
- 提示词写「必须是『马上有 + 2–6 个字』」并给 12 条「马上有XX」风格样本；
- 人工基线 24 条全是「马上有XX」。

多面墙之后，给第二面墙播种的结果是：**墙上长满「马上有XX」——那是别的墙的话**。
更糟的是句式闸会**把 AI 写对的「月兔XX」全部丢掉**，于是可能一条都不剩（空墙）。

### 18.2 改了什么

| 层 | 改动 | 关键点 |
|---|---|---|
| `wishSeeds.js` | 前缀变成**参数**：`normalizePrefix`（去空白、截 6 字、空则回落「马上有」）；`isSeedPhrase(text, prefix)`、`selectNewSeeds({ prefix })`、`buildSeedPrompt({ prefix })` | 默认值仍是「马上有」，**旧调用不改也照旧**；前缀过长会吃掉正文，故上限 6 字 |
| 提示词 | 自定义前缀下**不给「马上有」样本**，句式要求与输出示例都换成该前缀 | 样本本身就是「马上有XX」写的 —— 套到别的墙上正是把句式带偏的原因 |
| 人工基线 | **只在默认前缀下兜底**（`isDefaultPrefix`）；自定义前缀不补 | 24 条基线是「马上有XX」写的，**铺错内容比不铺更糟**。没内容时返回可辨识的 `NO_NEW_SEED` + 说明 |
| 治理页 | 新增「句式前缀」输入（留空 = 马上有），随请求上传；结果行回报**这批用的前缀** | 切墙时一并清空前缀（上一个墙的句式在新墙上不适用）；输入边打边去空白 |

## 19. 升级 · 第五期：**注册转化**（祈福墙被定为注册转化路径，对齐 AI 识别）

2026-09-18 产品口径：**祈福墙接下来是一条重要的注册转化路径**，上一个这样的入口是 **AI 识别**。
并行流程已完成视觉与仪式侧（木鱼、额度预告、分段控件、落愿高亮等），本期接手做转化。

### 19.1 先对齐既有范式，不另造一套

仓库里已经有这条路径的成品：**`components/RegisterAuthDialog`**（原地一键注册弹窗），
已被 `identify/result`（上一个转化入口）与 `detail/wiki-detail` 使用。它自带的约定我全部照用：

| 约定 | 内容 |
|---|---|
| 为什么是自定义组件 | 微信 `getPhoneNumber` **只能由 `<button open-type="getPhoneNumber">` 的用户点击触发**，系统弹窗里放不了 → 必须自带按钮 |
| 事件 | `bind:success` / `bind:fail` / `bind:close` |
| 新老用户文案 | 组件自己 `ensureSession` 一次，已注册则换「确认手机号继续」文案，**不再承诺新客礼包** |
| 合规 | 「同意」写在 CTA 上（`同意并一键注册`）+ 底部协议入口 |
| 漏斗埋点 | 事件 `<moment>_gate`，`step = show / go_register / dismiss / resume_success`，并在 ERP 报表侧登记漏斗 |

### 19.2 门禁挂在哪：**落愿**，不在进页

产品判断：**浏览与仪式免费（价值先行），落愿这一步才要身份** ——
心愿挂在谁名下、以后回来"我的心愿"里看谁的心愿，都需要账号。
进页就弹注册会把还没看到价值的人挡在门外；而点「挂上墙」的那一刻，用户的意图最明确，转化也最自然。

| 环节 | 设计 | 理由 |
|---|---|---|
| 弹窗时机 | `submitWish` 校验通过与额度检查之后 | 别让"字都没写对"的人也吃一个注册弹窗 |
| 弹窗可关 | `closable={{true}}` + `close-text="先不挂"` | 与 AI 识别结果页（内容门禁、不可关）不同：这里关掉**不损失任何已渲染内容**，把用户困住只会换来卸载。收紧成硬门禁是一处 prop 的改动，留给产品定 |
| 关闭后的草稿 | **保留**（只丢"待发"） | 「先不挂」之后回来还能接着挂，不制造"白写了"的挫败 |
| 注册成功后 | **自动续发那条心愿**（`_resumeAfterRegister` 跳过门禁） | 转化动作必须闭环；用户刚授权完，不该还要自己再点一次 |
| 会话刷新 | **不阻塞续发**（fire-and-forget） | 注册已经成功，不该因为一次会话往返把心愿吞掉；跳过门禁也避免了"会话未刷新 → 又弹一次"的死循环 |
| 会话读取失败 | **fail-open**（按已注册处理） | 注册引导是**转化动作**，不能因为会话读不到就把「挂上墙」这个核心功能挡下来 —— 宁少一次曝光，不废一个功能 |

## 21. 灯芯图标换成「灯泡」（2026-09-18 产品指定：附件 SVG）

### 21.1 做法

| 决策 | 理由 |
|---|---|
| **不新增 `.svg` 资源、不用 `<image src="*.svg">`** | 微信 `<image>` 不渲染 svg 文件，且本仓 svg 文件图标**零先例**（全仓 0 处）；改用 WXSS `background-image` 的 **data URI**，本文件本来就有先例（噪音纹理），也不牵扯双仓同步 |

| 点亮态**不用 box-shadow** | 方形盒子的阴影会在灯泡四角露出来，光晕继续交给 `.ww-lantern-halo` |

### 23.2 音效素材：自己合成（可复现、无版权风险）

木鱼声要挂在**每次敲击**上（高频、可连点），网上素材授权状态说不清。这个声音本质是"几个非谐波模态 + 3ms 槌击噪声 + 指数衰减"，用几行数学就能写出来：

- 生成脚本：`miniprogram/scripts/make-ritual-audio.mjs`（`node miniprogram/scripts/make-ritual-audio.mjs` 可重跑，参数在文件顶部）
- 模态：770Hz / 818Hz（**两个靠近的低频模态，拍频 ≈48Hz**，这是"木头是空心的"那种共鸣；单个正弦听起来像电子音）+ 1540Hz + 2320Hz，各自不同衰减
- 产物：`subpackages/feature/wish-wall/assets/muyu.mp3`，**2.5KB / 260ms / 44.1kHz 单声道**

**实测（不是"听起来差不多"）**：峰值 0.656（无削波）、直流 ≈0（-0.00008）、包络衰减到 -20dB 用时 **72ms**（木质敲击的干脆感）、频点能量集中在 770/818/1540/2320Hz、3kHz 以上几乎无能量（不刺耳）。频谱图（`ffmpeg showspectrumpic`）显示一条低频主带 + 快速衰减的模态谐波 + 3ms 宽频槌击瞬态，与设计一致。

> 我听不了声音，只能证到"波形/频谱/包络是木鱼该有的样子"。**听感请你验收**：不满意给我素材，换文件即可（代码零改动）。

### 23.3 `utils/ritualFeedback.js`：一个口子管住所有玩法的反馈

| 决策 | 理由 |
|---|---|
| 只在**存在素材**的动作上发声（`SOUND_SOURCES` 是唯一事实源） | 登记了但文件不在 = "看起来接了音效、其实永远不响"，守卫核对磁盘 |
| 默认**开**、可关、**跟随系统静音** | 产品口径默认开；`obeyMuteSwitch` 保持默认 true —— 与礼赠语音**刻意相反**：语音是"内容"要压过静音键，仪式音效是"装饰"，必须让静音键说了算 |
| 同一动作最小发声间隔 **120ms**（只节流声音，不节流视觉与震动） | 木鱼可连点；不节流会叠成噪音、低端机上频繁重启音频实例掉帧 |
| 回声文案**第一人称 + ≤14 字 + 按 seq 确定性轮换** | 墙上其余弹幕是别人的心愿，回声一旦没有主语就会被读成"别人发的"（守卫逐条断言）；不用随机数是本仓铁律 |
| **不写云、不进愿签集合** | 木鱼可连点，写服务端就是写放大；回声只是本地瞬时反馈 |
| 失败一律静默降级 | 素材缺失 / 基础库不支持 / 播放失败 / 存储不可用 → 都只是"没响"，不影响动作本身 |

### 23.4 自检抓到我自己的两个 bug（都记下来）

1. **频率闸门拿时间戳 `0` 当"没响过"的哨兵** → `t=0` 响过一声之后闸门失效（连点会叠音）。
   修法：「没响过」只能用 `null/undefined` 表示，0 是合法时间戳。守卫 `sound-gate-zero-sentinel` 钉住。
2. **`pushEcho` 里 seq 先加后用** → 第一次敲木鱼说的是文案池**第二句**，首句永远轮不到。
   修法：先取后加（seq 从 0 起算）。断言「第一次回声 = 第一句」时暴露的。

## 26. 商品祈运标签（2026-09-18 需求 6）

口径：每个商品可以挂**祈运标签**（受控枚举），作为「玩法推荐 / 墙面文案 / 后续排序」的匹配依据之一。

### 26.1 字段与枚举

```js
blessTags: ['fortune', 'peace', 'study', 'bond', 'journey', 'success']  // 最多 3 个
//            求财      求安     求学     求缘     求行       求成
```

| 决策 | 理由 |
|---|---|
| **英文 key 入库、中文 label 展示** | 与 `giftScenes` 同一约定；中文入库会被文案改动牵着走 |
| **受控枚举 + 最多 3 个** | 自由文本没法做匹配、也没法守卫；标签一多就等于没标签 |
| 与「兴趣 tags」「礼赠 giftScenes」**分离** | 那两者回答"喜欢什么 / 送什么人"，祈运标签回答"求什么"；混在一起三处推荐会互相打架 |

## 29. 场景兜底：让存量商品当天就能用上祈运（2026-09-18 需求 6 的"不空转"补丁）

### 29.1 问题：功能在真机上是空的

§28.4 的真机截图证明了一件事：祈运提示不显示、推荐卡不出现 —— 因为「孔雀标本」没有 `blessTags`，
而全仓商品里**绝大多数都没有**（新字段刚加，没人回填）。原计划是做一个"候选建议 + 人工确认"的回填工具，
但本机**没有 `@cloudbase/node-sdk`**（`apply-gift-scenes.mjs` 那套脚本靠它读写库），工具既跑不起来也验证不了。

### 29.2 更好的解法：不做数据迁移，做**兜底推导**

`giftScenes` 本身就是**人工策展**的字段（8 个场景），语义上与"求什么"很近。于是加一张**写死的映射表**
（在唯一事实源 `config/blessTags.js` 里，逐条可评审），并统一入口：

```js
resolveBlessTags(product) = 显式 blessTags（有就用） ?? 由 giftScenes 推导（兜底）
```

| 礼赠场景 | 推导标签 | 理由 |
|---|---|---|
| 乔迁 housewarming / 生日 birthday / 感恩 gratitude | 求安 | 安顿、愿平安 |
| 新婚 wedding / 纪念日 anniversary | 求缘 | 关系 |
| 升学 enrollment | 求学 | 学业 |

而系统里**根本没有任何"同好/共同浏览"数据**。这是最不该有的一类文案（看起来像真的）。

修法（不改推荐逻辑，只改"怎么说"）：

| 位置 | 改法 |
|---|---|
| 云函数 | `matchSource` **逐行判定**：该商品显式打了这个标签 → `tag`；靠场景兜底命中 → `scene` |
| C 端纯函数 | 新增 `recoLabel(matchSource)`：`tag` → 「同好也在看」；`scene` → **「这类心愿常配这件」**；其它 → 「也许你也喜欢」 |
| 模板 | 标签改成 `{{reco.label}}`（文案随依据走，页面不拼词） |

**线上复核**：重新部署后 `tag=study` 返回 `matchSource: ['scene','scene']` ✓ —— 卡片会说「这类心愿常配这件」。

## 37. 真机反馈：吸底发送条与愿签列表「互相遮挡」（2026-09-18）

### 37.1 根因（不是"遮挡"，是**层叠上下文**）

真机截图里：分段控件「墙上的愿签」画在发送条**上面**，愿签卡也从条子底下透出来。核查发现两层原因：

| 层 | 原因 |
|---|---|
| **画在条子上面** | 条子当时放在 `.ww-write` 里，而 `.ww-write` 是 `position: relative; z-index: 1` 的**层叠上下文** —— 条子自己的 `z-index: 20` 只在这个上下文**内部**有效。页面其余 `z-index ≥ 1` 的块（分段控件、愿签卡）因此在它之上 |
| **从条子底下透出来** | 条子背景是 `rgba(20,18,15,0.94)`（94% 不透明）—— 与 §28 回声条同一个坑：**盖在别的东西上的条带，背景就得是实的** |

### 37.2 改法

1. **把条子移出 `.ww-write`**，作为 `.ww-page` 的**直接子节点**（DOM 里排在最后）→ 不再被任何层叠上下文罩住；
2. `z-index: 30`（页面级）＋ 背景改 `var(--color-bg)`（**不透明**，且不写死 hex —— 本页有一条"页面底色必须用 token"的既有判据，第一版我写了 `var(--color-bg, #14120F)` 就被它抓了）；
3. 底部预留 180rpx（≥ 条高 108rpx）保持不变，最后一张愿签不会被压住。

### 37.3 判据（把根因钉住，而不只是钉现象）

| 判据 | 防的是什么 |
|---|---|
| 条子必须挂在 `.ww-page` 下、且**在 `.ww-write` 闭合之后**（用标签配平实算） | 又把它塞回某个层叠上下文里 |
| 条子背景必须是 `var(--color-bg)`（不透明），`z-index: 30` | 半透明 / z-index 不足 |
| 底部预留 ≥ 条高（84 + 12×2） | 最后一张被压住 |

注入 `composer-back-inside-write` / `composer-translucent-again` 证明这两条判据会红；自检 **120 个注入全检出无假阳性**，`test:wish-wall` **645/645**；`preview:wall:check` ✓（条子 750×111、预留 180px）；`check:admin` 86 条（仅剩并行流程的 `dialog-ratchet`）；双仓一致 ✓ 2061。

> 记一笔：**这是"固定条带与层叠上下文"在本期第二次咬人**（第一次是回声条半透明叠字，§28）。
> 两次的教训合成一条：**凡是"盖在内容之上"的条带，必须同时满足①背景不透明 ②不受祖先层叠上下文限制**。

## 38. 细节雕刻：玩法结果层重做 + 产品链路收口（2026-09-18 产品口径）

产品反馈两条：**「玩法弹窗整体仍然与页面非常割裂」**、**「产品推荐的链路也不明确」**。

### 38.1 割裂的根因：它既不像卡，也不像弹窗

旧实现是"在玩法瓦片下面**就地展开**一张浅纸卡"。它在深色瓦片下方突然出现一大块亮色，
又没有任何"弹层"的身份（没有遮罩、没有把手、没有关闭手势），于是读起来像**渲染异常**而不是一个有意的层。

**改法：把它做成一张"签"，从底部递上来**（保持本页的纸张语言，但明确弹层身份）：

| 元素 | 做法 |
|---|---|
| 遮罩 | 暖黑 `rgba(10,9,7,0.78)`，点击关闭（实测 62% 在博物黑上"根本看不出被压暗"，调到 78%） |
| 弹层 | 浅纸渐变 + `28rpx` 顶部圆角 + 铜色把手 + 四角铭牌 + 从底部 `cubic-bezier(.22,.9,.24,1)` 升起 300ms |
| 印章字标 | 用玩法的 `mark`（签/饼/座/我）做成铜色圆章 —— **与瓦片上的铜圈同形**，视觉上把"抽签那一按"和这张签连起来 |
| 签文 | 书法体 44rpx + 加宽字距（本页最大的一行字），正文 25rpx/1.72；正文行**依次淡入**（60ms 阶梯） |
| 关闭 | 遮罩点击 / 「收起」 / **把手下拉**（阈值 88px，纯函数 `sheetDragShouldClose` 可单测） |

### 38.2 链路不明确：三条产品动作 → 一条主路

旧实现的结果卡里同时有「推荐卡」和「看这件藏品」两行，**谁主谁次看不出来**；而"抽之前"根本没有任何产品入口。

现在：**主 CTA 只有一个**（写成心愿）+ **产品只有一条路**（有祈运推荐用推荐，没有就用这面墙的藏品），
并且**页头那颗产品 chip 本身就是常驻入口**（第一屏就能到详情，不必先抽一签）。

### 38.3 文案：把最后一点"编出来的社会证明"删掉

`recoLabel` 原来按匹配来源分两句，其中「**同好也在看**」是编的 —— 系统里没有共同浏览数据（§33 只改掉了场景那一半）。
现在统一为 **`偏「{祈运标签}」· 为你配一件`**：前半句是这面墙的真实标签，后半句是这次推荐的真实动作。
判据里加了一条"用户可见文案里不许出现『同好』"（剥注释后判断，注释里写历史不算违规）。

### 38.4 渲染实测又抓到两个真问题

| 问题 | 根因 | 处置 |
|---|---|---|
| **吸底发送条画在弹层之上**（产品行被压住） | 弹层当时挂在 `.ww-plays` 里，而 `.ww-plays` 是 `z-index:1` 的层叠上下文 → 弹层的 `z-index:41` 只在其中有效 | 弹层与遮罩移到 `.ww-page` 直接子节点；**并把这条规则做成通用判据**：fixed 覆盖层必须是 `.ww-page` 的直接子节点（用**祖先栈**实算，两个覆盖层共用） |
| **遮罩压不动页面**（深色页上看不出被压暗） | 62% 不透明度在博物黑上几乎不可见 | 提到 78%，并在判据里钉住"浓度 ≥ 0.72" |

> 判据自身被自检修了三次（都是"锚点/判据写错"）：① 把元素自己的开标签算成祖先（差一）；

## 39. 补齐「点灯」的音效（2026-09-18，① 的另一半）

复核目标 ① 「玩法动作（点灯/木鱼及后续玩法）的音效」时发现：**只有木鱼有声音，点灯一直是静音的**
（素材表里只有 `muyu`）。本轮补齐。

| 项 | 做法 |
|---|---|
| 铜磬的物理模型 | 按**钟/磬的经典非谐分音比** `1 : 2.76 : 5.40 : 8.93`（基频 480Hz）铺模态，高次分音衰减更快、基频留余韵 —— 与木鱼（两个靠近的低频模态 + 槌击噪声、衰减 ~70ms）**是两套参数**，所以是两个文件、两种性格 |
| 生成方式 | `make-ritual-audio.mjs` 扩展为 `--kind muyu\|lamp`（同一套可复现合成流程，无第三方素材） |
| 产物 | `assets/lamp.mp3` **9.6KB / 1150ms**；实测：峰值 0.59（无削波）、频点能量 480/1325/2592/4286Hz = 1.00/0.45/0.19/0.08（正是设计的分音结构）、3kHz 以上几乎无能量（不刺耳） |
| 接线 | `SOUND_SOURCES` 增加 `lamp` —— 反馈层自动生效，**页面一行没改**（这正是当初把音效做成"动作→素材表"的好处） |

**一处音质自检抓到的缺陷**：第一版基频 `tau=0.6` + 15ms 淡出 → 实测 -20dB 要到 **1092ms**，
等于"还在响的时候被硬切"。改成 `tau=0.42` + **150ms 淡出** → -20dB @ 890ms、时长 1150ms，
尾巴是**自己消散**而不是被切断。

判据（都带注入）：素材表里**每个动作**都要有真文件且 1KB–32KB；点灯与木鱼**不能是同一个文件**（防复制粘贴）；
生成脚本必须真的有两套不同参数（用模态参数体比对，不看注释）。注入 `lamp-sound-dropped` / `sounds-share-one-file` 可证。
