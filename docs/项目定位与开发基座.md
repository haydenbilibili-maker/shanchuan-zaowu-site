> 版本 v1.0 · 2026-08-13 · 全仓盘点产物
> 用途：为后续开发提供**统一的项目定位、现状地图与开发基座规范**；是 `docs/项目总览与后续工作框架.md` 的工程侧补充（业务排期见该文档，本文侧重"代码长什么样、往哪改、怎么改"）。
> 依据：`docs/monorepo.md`、`docs/cloudbase-collections.md`、`admin/docs/PLATFORM_CAPABILITIES.md`、内容工厂/订货履约/飞书三份蓝图、`admin/src` 与 `miniprogram` 实盘盘点、git 状态（截至 2026-08-13）。

## 1. 一句话定位

> **山海造物 =「线上内容 + 线下门店 + 标本藏品」的业务线；本仓库是其唯一代码主库，用「官网(对外叙事) + ERP(对内运营中枢) + 小程序(消费者/店长双端)」三端应用共享一个 CloudBase 数据底座，先跑通单店模型，再按「店铺管理 → 员工薪酬 → 加盟商管理」的顺序做连锁化扩张。**

## 2. 项目定位声明（决策锚点）

| 维度 | 定位 | 含义 |
|------|------|------|
| 商业模式 | 标本藏品零售 + 线下门店 + 内容 IP（双 IP：GRAVITY 沉静 / LIGHTNESS 明亮） | 内容不是营销附属，是与门店并列的业务主线 |
| 数字化形态 | **三端一底座**（Astro 官网 / Vue ERP / 微信小程序 + CloudBase） | 不做独立后端服务；业务逻辑落在前端 + 云函数 + 云库 |
| 开发形态 | **monorepo 单主库** | `shanchuanzaowu` 唯一代码主库；`shanchuan-admin` 只读归档 |
| 阶段目标 | 单店模型跑通 → 连锁化（店铺/薪酬/加盟 PRD 已备） | 先"加法不重构"，后按排期上模块 |
| 内容线 | 内容工厂 Phase 1 落地（选题→终审→发布登记→复盘，人工闸口） | 自动发布/剪辑/数字人明确不做 |

### 3.1 官网（`src/`，Astro 5 + Tailwind v3 + TS）
- **定位**：对外叙事 + 客户转化线索。v0.4 双主题（系统偏好 → localStorage → 手动覆写，博物馆日/夜双主题）。
- **路由**：`/` `/what` `/who` `/why` `/how`(含 senses/space/operations/tech) `/foundation`(含 conservation/strategy/[view]) `/for-properties` `/for-franchise` `/for-investors` `/talent` `/notes` `/benchmarks` `/digital-ops` `/hardcore-tech` `/sound-manual` `/price-list` `/partner/brand`。
- **与业务打通点**：`/price-list` 报价页 → `src/lib/purchaseIntent.ts` → 云集合 `purchase_intents`（本地 localStorage 回退）→ ERP「采购意向」→ 一键转正式订货单。
- **数据驱动**：内容集中在 `src/data/*.ts`（priceList / foundationSixViews / operationsPage 等），页面做渲染。

### 3.2 ERP 后台（`admin/`，Vue 3 + Element Plus + rolldown-vite）
- **定位**：对内运营中枢。**SPA 无路由文件**：`App.vue`（2733 行）以 `currentTab` 条件渲染 60+ 业务组件；导航单一数据源 `config/sidebarNav.js`，命令面板 `utils/modulesRegistry.js` 登记 65 条（id 0–53）。
- **模块地图**（`SIDEBAR_NAV` 六组）：总览决策 / 业务运营（交易履约·商品资产·体验营销·门店场域·定制工坊）/ 客户经营（会员洞察·互动服务·内容营销）/ 小程序配置（内容首页·会员营销·系统权限）/ 组织治理（财务资本·人才组织·治理合规）/ 战略与知识。
- **进行中的新模块**（已注册）：`51` 内容工厂（5 Tab + 4 Agent + 5 张 `content_*` 集合）、`52` 订货履约（purchase_orders / fulfillment_shipments / stock_movements）、`53` 品牌 VIS（Logo 五版规范，资产在 `admin/public/brand/`）。
- **AI 层**：`utils/aiHelper.js` 统一模型网关（bailian/gemini/deepseek/openai/本地 ollama 多路故障转移）；`components/ai/` 22 个场景子模块；全局浮层 `CompanionRobot.vue`（经营助理「马上有」）。
- **数据层**：`cloud.js` 统一初始化 + `utils/cloudbaseCdnDb.js` CDN 式读写封装（get/add/update/remove/upsert/分页）；云函数入口 `callCloudFunction()`。

### 3.3 微信小程序（`miniprogram/`，原生 + 云函数）
- **定位**：消费者端（商城/百科/鉴定/定制/社区/收藏/会员）+ 店长后台（账本/订货/门店管理）双端，与 ERP 同云环境。
- **规模**：AppID `wxf2550373b010b447`；主包 `pages/`（index/category/community/store/cart/user/custom/care/detail/search/identify/collection/articles/videos 等）+ 分包 `subpackages/`（business 店长业务 14 个 / detail / user）；**82 个云函数**（`cloudfunctions/`，各目录独立 package.json）。
- **与 Web 数据同步**：店长账本 `store_ledger`；`syncFinanceData` 云函数双向同步 `finance_records`（**注意：该函数仍需在微信开发者工具上传部署**）；订货履约直连 `purchase_orders` 等集合（店长 `utils/b2bPurchaseOrder.js`，Admin `b2bFulfillment.js`）；飞书对接走站点 `/api/feishu-sync`（密钥放 Cloudflare / `admin/.env`）。

### 3.4 数据底座（CloudBase）
- 环境：`cloud1-8gnkty5bfff9f0bf`（ap-shanghai）；Web 匿名登录 + 安全域名（localhost:5173/5178/4321 + shanhaizaowu.com）。

## 5. 开发基座（协作与改动规范）

### 5.1 命令速查
```bash
npm install          # 安装（含 admin workspace）
npm run dev          # 官网 → http://localhost:4321
npm run dev:admin    # ERP → http://localhost:5178
npm run build        # 完整生产构建：ERP → public/admin/ → dist/admin/ + 官网 → dist/
# 小程序：微信开发者工具打开 miniprogram/ 目录（非仓库根目录），云函数先 cd 函数目录 npm install 再「上传并部署」
```

### 5.2 改动落点
| 改什么 | 去哪改 |
|--------|--------|
| 官网 | `src/`（页面 `src/pages/`、组件 `src/components/`、内容数据 `src/data/*.ts`） |
| ERP 新菜单 | `App.vue`（`el-menu` + 主区 `component :is`）+ `config/sidebarNav.js` + `utils/modulesRegistry.js` 三处 |
| 新云集合 | `admin/src/cloud.js` `COLLECTIONS` ↔ `cloudbase/rules/<name>.json` ↔ `cloudbase/schema/<name>.md` 三处同步 |
| 小程序 | `miniprogram/`（页面/云函数/配置）；云函数改后须在开发者工具重新上传部署 |
| 文档 | 新模块先落蓝图（`admin/docs/`），上线后登记文档索引 |

### 5.3 硬性规范
1. **代码一律进 monorepo**；`shanchuan-admin` 只读归档，确需回灌单向复制并留记录。
2. **文档先行**：新模块先 PRD/蓝图 → 再动代码；蓝图即验收标准。
3. **三处同步**：集合名、权限规则、结构说明任何一处变更，另外两处必须跟上。
4. **加法不重构**：复用 `aiHelper.js` 模型网关、`cloudbaseCdnDb.js` 读写封装、`modulesRegistry.js` 注册机制；不另起炉灶。
5. **密钥不进代码**：AI Key 走 `VITE_*` 环境变量 / 云函数环境变量（`FEISHU_APP_SECRET` 等）；生产构建由 CI 注入。
6. **部署**：官网/ERP 合并 `main` → GitHub Actions（`deploy-pages.yml`）→ Cloudflare Pages；小程序手动上传，不走 Pages。

## 7. 后续开发路线图

1. **收敛当前线**：订货履约 Phase 1 收尾（PO 状态机三端一致、飞书 SKU 映射、`products.stock` 扣减流水）→ 提交部署。
2. **按 PRD 上连锁模块**：店铺管理（数据根节点）→ 员工薪酬（关系发钱）→ 加盟商管理（依赖店铺数据成型）；每模块复用「蓝图 → 注册三处 → 集合三件套 → 验收」流程。
3. **数据与安全升级（A2+）**：匿名登录 → 自定义登录；配置类模板 B + 管理员 UID 白名单；用户/订单类模板 C（openid 隔离）+ 云函数代理写；敏感 `admin_*` 仅云函数写。
4. **内容线**：内容工厂按需深化（复盘飞轮、指标回填），但自动发布/剪辑/数字人保持不做。

## 8. 风险与边界（开发时须遵守）

1. **演示 ≠ 生产**：ERP 前端口令是演示门禁，不是企业 IAM；真实权限以 CloudBase 安全规则为准。
2. **数据真实性**：业务数字可能来自 Mock/本地生成/云库；回答"营收/库存"类问题须先确认数据来源组件与集合。
3. **密钥安全**：`aiHelper.js` 等不得新增明文 Key；生产用环境变量注入，勿提交公开仓库。
4. **双写禁区**：飞书（原材料）与 Admin（成品/门店货）分域单一真相，**禁止无映射双写**。
5. **AI 边界**：AI 生成内容须人工终审（内容工厂闸口强制）；AI 输出不构成财务/法律意见。
