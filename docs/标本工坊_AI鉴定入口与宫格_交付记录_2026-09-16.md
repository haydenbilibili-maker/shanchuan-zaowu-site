## 2. 顺手修掉的一个真实缺陷：编号会漂

原实现把宫格序号写成嵌套三元：

```xml
<view class="fork-icon">{{showGift ? '02' : '01'}}</view>
<view class="fork-icon">{{showGift && showSpecimenCustom ? '03' : (showGift || showSpecimenCustom ? '02' : '01')}}</view>
```

后果：**任何一格开关变化，后面所有编号都会跟着变** —— 用户昨天看到的「03」是伴宠，今天变成鉴定。
现在编号按**固定顺序**分配，某格关闭只是不渲染，其余编号不动。守卫用「五组开关组合」断言这一点。

## 3. 三项设计决定（都有理由）

### 3.1 鉴定入口复用 `showAiIdentify`，不新造开关

工坊四格与内容开关**一一对应**，没有第二套口径：

| 宫格 | 开关字段 | 缺配置默认 |
|---|---|---|
| 01 礼赠 | `showGift` | 关 |
| 02 定制 | `showSpecimenCustom` | 关 |
| **03 鉴定** | **`showAiIdentify`** | **开**（现网已开放，写反会「上线即消失」） |
| 04 伴宠 | `showPetMemorial` | 开 |

超管工作台的开关行**已存在**（`workspace/_subviews.wxml` 的「AI 鉴定」行，`data-field="showAiIdentify"`），
所以运营闭环无需新增界面。鉴定页自身也有第二道门（`identify/index.js` 读同一开关），
即使有人深链进入，关闭时也会被拦下 —— **入口可见性与页面可达性同源**。

### 3.2 鉴定**不在宫格补埋点**

鉴定页自己会发 `identify_entry_click`，`source` 取自 URL 的 `from` —— 所以宫格传
`?from=atelier` 就已经拿到了「从工坊进入」的归因。若宫格再发一条同名事件，
同一次点击会被计**两次**（漏斗虚高）。守卫里有专门注入证明这条锁是活的。

礼赠/定制/伴宠保持原有埋点与 URL **一字不改**（避免顺带改动埋点口径）。

### 3.3 宫格只改静态 WXML，不改 WXSS 的既有约定

四格数据由模块级 `FEATURES` + `buildTiles(flags)` 派生，**一份数据同时驱动渲染与守卫**：
点击统一走 `onFeatureTap`（`data-key` 分发），守卫与提示集中在一处，
不再有「四份重复逻辑各自漂移」的失效面。

```
$ npm run test:atelier-grid

$ npm run test:atelier-grid:selftest

  ✓ 注入 identify-default-off 被检出      （鉴定默认值写反 → 缺配置即消失）
  ✓ 注入 drop-flag-gate 被检出            （去掉守卫 → 开关关闭仍能进）
  ✓ 注入 double-count-identify 被检出     （宫格补埋点 → 同一次点击计两次）
  ✓ 未注入时通过（无假阳性）

$ npm run check:admin            exit=0（27 项守卫）
$ npm run check:admin:selftest   exit=0
$ npm run sync:miniprogram:check ✓ 双仓一致（主库 1889 个文件）
$ node scripts/check-cloud-functions-sync.cjs  ✓ 线上与仓库完全一致（130/130，本轮未动云函数）
```

守卫覆盖的关键断言：

| 断言 | 为什么值得钉住 |
|---|---|
| 五组开关组合下编号恒定 | 用户看到的编号必须指向同一个功能 |
| 鉴定 `defaultOn === true` | 写反 = 上线后入口直接消失 |
| 鉴定 `track === null` | 写反 = 埋点重复计数（报表虚高且没人会发现） |
| 关闭时**不跳转**且给出提示 | 只有提示不拦跳转 = 开关形同虚设 |
| WXML/WXSS 无 `fork-card`/`.fork-*` 残留 | 半改状态会让样式与结构对不上 |
