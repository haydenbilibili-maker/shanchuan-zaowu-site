# ERP × 小程序：总功能对齐（2026-09-14）

> **对齐对象**：小程序店长台/超管台今天新增的能力 ↔ ERP（`admin/`）现有模块与数据口径。
> **对齐方式**：能力清单逐项比对（小程序 41 个店长端页面 + ERP 77 个注册模块 / 119 个组件）+ 数据口径核对（集合与字段）+ 代码级修复。
> **结论**：功能面基本一一对应，**本轮补齐了 6 处数据口径与展示对齐**；仍缺 3–4 个后台模块（定金、直播、装裱师佣金台账、生日礼运营），需要立项。

---

## 1. 本轮已补齐的对齐（代码已改，构建通过）

### 1.1 兑换单不再混进 ERP 的订单口径

小程序侧今天已把代金券/积分兑换单（`orders.source='exchange'`）从藏品订单中隔离；ERP 侧有 6 处订单口径仍在无过滤拉取 `orders`，会把 0 元兑换单当成订单。已统一：

| 位置 | 处理 |
|------|------|
| 新增 `admin/src/utils/orderFilters.js` | 统一口径工具：`isExchangeOrder` / `excludeExchangeOrders` / `isProductOrder` |
| `components/Orders.vue` 订单管理 | 「全部订单」不再显示兑换单 |
| `components/Dashboard.vue` 今日订单兜底 | 兑换单不计入今日订单数与营收 |
| `components/CustomReportBuilder.vue` | 订单类指标排除兑换单 |
| `components/AIStrategicBrain.vue` | AI 战略分析的订单样本排除兑换单 |
| `utils/portraitDataLoad.js`（两处） | 会员画像 / CRM 的订单样本排除兑换单 |
| `utils/storeData.js` | AI 模块（财务/销售/门店/数据报告）与实时监控的订单口径排除兑换单 |
| `utils/miniprogramSandboxBridge.js` | 已自带 `PAID_STATUSES` 不含 `exchanged`，**无需改动** |

### 1.2 ERP 订单管理可见并可编辑「店长备注」

小程序今天新增了店长订单备注（`orders.managerNote`，随发货私信「馆员留言」发给买家）。ERP 此前完全不认识该字段，已补齐：

- 订单表格新增「店长备注」列（超长省略 + 悬浮显示全文）。
- 操作列新增「备注」按钮 → 弹窗编辑 → 调 `managerShipOrder { action: 'saveNote' }`（今天新增的动作，服务端仍以 `staffGuard` / `ADMIN_OPS_KEY` 校验身份）。
- 与小程序同一字段、同一接口、同一 100 字上限——两端改一处，另一处立刻可见。

> 注意：ERP 走 `/api/cloud-fn` 代理（`managerShipOrder` 在代理白名单内），因此**需确认 `managerShipOrder` 已重新部署**，否则备注保存会返回「未知 action」。

## 3. 四个缺口已补齐（Phase 1 已落地）

> 蓝图：`admin/docs/定金管理_Phase1.md`、`admin/docs/直播管理_Phase1.md`、`admin/docs/装裱师佣金_Phase1.md`、`admin/docs/生日礼配置_Phase1.md`
> 数据规则与结构：`cloudbase/rules/{deposit_rules,deposit_intents,live_sessions,live_messages,live_reminders,artisan_commission_config,artisan_commission_ledger,member_birthday_gift}.json` 与对应 `cloudbase/schema/*.md`

| 模块 | 菜单位置 | 组件 | 能力 |
|------|----------|------|------|
| **定金管理** | 业务运营 → 交易履约 | `DepositOps.vue` | 规则编辑（比例/窗口/上下限/逾期不退）＋ 意向列表（状态筛选、逾期标红）＋ 逾期开放 ＋ 清扫逾期尾款 |
| **直播管理** | 业务运营 → 体验营销 | `LiveSessions.vue` | 最近 20 场（状态/主播/挂车/在线/点赞）＋ 详情抽屉（公告、流名、拉流）＋ 强制结束 |
| **装裱师佣金** | 组织治理 → 人才组织 | `ArtisanCommission.vue` | 提成规则（比例/适用工艺/计费说明）＋ 汇总 KPI（净佣金/已入账/已冲销/计佣销售额）＋ 台账分页与类型筛选 |
| **生日礼配置** | 客户经营 → 会员洞察 | `BirthdayGiftConfig.vue` | 启停、文案、积分、礼券档位（面额/门槛/有效天数/张数）、有效期模式、叠加策略；保存 / 恢复默认 |

实现要点：

- 四个云函数（`manageDeposit` / `manageLiveSession` / `manageArtisanCommission` / `manageBirthdayGift`）已加入 ERP `/api/cloud-fn` **代理白名单**，运维密钥由服务端注入，前端不持有。
- 新增的 8 个集合权限按"服务端专用"收口：7 个 `read/write = false`；`deposit_intents` 因小程序「想要」页需要读自己的记录，保留 `read: doc._openid == auth.openid`、`write: false`。
- 与小程序**同源同函数**：ERP 改的是同一份规则/台账，小程序端刷新即见，不存在双写。
