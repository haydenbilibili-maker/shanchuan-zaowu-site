## 2. 根因

线上 `member_welcome_gift`（`_id = 2feda4ef6aa1415a02005646353f37e0`）当时的状态：

```
couponsEnabled: true          ← 礼券总开关：开
coupons: [ {id:c5,   enabled:false, value:5,   minSpend:49 },
           {id:c30,  enabled:false, value:30,  minSpend:299},
           {id:c50,  enabled:false, value:50,  minSpend:499},
           {id:c100, enabled:false, value:100, minSpend:999} ]   ← 4 条券行：全部停用
```

用**发券侧那一份代码**回放该配置（`upsertUserProfile/welcomeGiftDefaults.js`）：

```

describeConfig-> 新会员礼包：100 积分；不可叠加（一单一券）；折扣不低于7.5折
（代码兜底档位则是 4 张券；即配置一旦读不到，反而正常）
```

**三条静默链叠在一起，才让一次误保存变成「用户投诉才发现」**：

| # | 断链 | 表现 |
|---|------|------|
| 1 | 保存侧无校验 | `validateConfigCoupons` 会 `continue` 跳过停用行 → 「总开关开 + 全部券行停用」被当成合法配置写入 |

### 6.3 「唯一权威入口」收口（2026-09-16 晚）

**老板确认的产品口径**：新用户礼券配置以**小程序「我的 → 超管工作台 → 新会员礼包配置」为唯一权威入口**；

**核查结论（改前）**：口径在代码意图上成立、在系统约束上不成立 —— 权威读取确实只有一处

**② ERP 有一条可达的直写路径**、**③ 两处 normalize/选文档算法存在实测差异**。
