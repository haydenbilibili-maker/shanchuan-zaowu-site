# 鉴定记录加载失败 · 排查与修复（2026-09-15）

> 现象：AI 鉴定能出物种名（记录确实写入了云库），但打开鉴定结果页显示「鉴定记录加载失败」。

## 1. 逐层核查结论（都是只读验证，附证据）

| 环节 | 结论 |
|------|------|
| 记录是否写入 | ✅ `identification_records` 共 62 条，最新一条为当天 15:29（尾号 `8jaYy46M` 的账号），字段齐全、`_openid` 无缺失 |
| 记录是否属于本人 | ✅ 最新记录 `_openid` = `oa22s5…8jaYy46M`，与反馈账号一致 |
| 云函数 `get_record` | ✅ 已部署且与仓库代码完全一致（`tcb fn code download` 比对差异 0 行）；用真实记录 id 调用返回 `success:true`、`is_owner:true`，返回体 ~9 KB |
| 集合安全规则 | ✅ 线上为 `read: doc._openid == auth.openid, write: false`，本人可读 |
| 页面数据解析 | ✅ 用云库真实记录 + 客户端同一套模块（`normalizeProfile` / `inferCategory`）本地重放，无异常；档案 blocks=10、图鉴大类可判 |
| 引用完整性 | ✅ `user_collection` 30 条、`atlas_logs` 100 条里的 `record_id` 无悬空、无归属错位 |
| 数据体积 | ✅ 单条记录约 9 KB，远低于 `setData` 上限 |

即：**服务端、数据、权限、解析全部正常**，问题出在结果页的读取流程。

## 2. 根因

当天 15:14 有一版改动把结果页的读取改成「**先调云函数 `get_record`**，只有在云函数明确返回「无权限 / 未分享 / 记录不存在」时才不回退」。这条策略有漏洞：

1. 云函数这条链路一旦返回 `FORBIDDEN`（例如本人在分享/缓存场景下被误判为「非本人」，或线上云函数版本与前端预期不一致），页面**不再回退**客户端直读；
2. 而客户端直读本来是**能读到自己记录**的（安全规则 `doc._openid == auth.openid` 放行），于是「本来能打开」的记录被卡死在报错页。

## 3. 修复

`subpackages/feature/identify/result/index.js` → `fetchRecordDoc()`：

- 云函数这条路**任何**失败（未部署该 action / 超时 / 服务端异常 / 返回失败）都回退客户端直读；
- 直读成功 → 正常渲染；
- 只有**直读也被拒**时，才把「无权 / 未公开分享」的结论抛给用户（保持原有权限语义，不会把「无权」伪装成网络错误）。

顺带修掉一处由术语批量替换造成的文案回退：物种卡片提示「未检测到生物藏品，请拍摄藏品或动植物照片」→ **「未检测到生物标本，请拍摄标本或动植物照片」**（`生物标本` 已加入批量脚本的保留词）。

## 4. 复核方式

- `node --check` + acorn 解析通过；
- 结果页与组件已同步到微信开发者工具目录（两份一致）；
- 若仍复现，请把报错页第二行灰字（`loadErrorMsg`，例如 `该鉴定未公开分享` / `document.get:fail …` / `缺少 record_id`）发我，可秒级定位是权限还是取数。

## 5. 遗留建议（可选）

- **云函数 `get_record` 的分享判定**：目前只有 `is_shared === true` 才允许非本人读，而线上 `is_shared` 为 true 的记录为 0 条（海报分享走 `generateSharePoster` 写入）。若后续要做「分享给朋友也能看」，需要确认海报生成是否成功写入 `is_shared`。
- 结果页可增加「本地最近一次鉴定结果」兜底：刚识别完就打开结果页时，即使读库失败也能先渲染（本次未做，避免掩盖真实故障）。
