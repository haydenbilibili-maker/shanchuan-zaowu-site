## 三️、⚠️ 只改代码兜底**不足以生效**（必须做的一步）

`normalizeConfig(raw)` 是「**云库记录覆盖代码兜底**」：

```js
const merged = { ...base, ...(raw || {}) }   // raw = member_welcome_gift 里那条记录
merged.pointsEnabled = merged.pointsEnabled !== false
```

集合 `member_welcome_gift` 里**已有记录**时，`points: 100 / pointsEnabled: true` 来自云记录，
代码兜底只在「集合为空 / 字段缺失」时兜住。因此：

> **本次改动要在线上生效，必须在「超管工作台 → 新会员礼包」里按新口径保存一次**
> （保存走云函数 `manageWelcomeGift`，`save` 时会自动执行一次 `alignCoupons`）。
> AI 未改任何线上数据（未写库、未调云函数写入、未部署）。

关于「老数据不处理」与保存时的 `alignCoupons`：它只对齐**未使用**券的**条款**（门槛/标题/渠道），
**绝不改面额**，`used / expired / locked` 一律跳过；由于既有 4 档的门槛与标题本次逐字未变，
实际不会有任何旧券被改写（新增的 c10 只会影响此后新发的券）。
