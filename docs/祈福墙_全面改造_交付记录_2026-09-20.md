## 0. 先修工具，再改页面（否则改的是盲盒）

改造前做了一件容易被跳过的事：**`render-wall-preview.mjs` 的结构是手抄的**，而且已经**静默漂移**：

| 漂移 | 后果 |
|---|---|
| 预览里渲染 `.ww-play-mark`（瓦片上的「签/饼/座/我」字标） | 真 `index.wxml` 里**根本没有**这个元素 —— 预览"看着没问题"、真机是四个纯文本框 |
| 预览把发送条摆在**玩法区之后** | 真源码在**弹幕墙正下方**（2026-09-20 `026d758` 改的）→ 工具报出两条「发送条没有吸底」的**假失败** |
| 预览缺整块愿签列表 / 分段控件 / 博物笔记 | 页面下半部分从来没被量过 |

**处理**：新增 `miniprogram/scripts/lib/wxml-preview.mjs`（一个约 230 行的 WXML → HTML 渲染器），
预览结构改为**直接解析真 `index.wxml`**（支持 `{{ }}` / `wx:if|elif|else` / `wx:for` / `<block>` / 自定义组件跳过）。
另外新增两条防漂移：
- `assertSampleCovers()`：样例数据必须覆盖 WXML 里引用到的**每一个根标识符**，缺字段直接报错退出（防"预览少画一块"）；
- 否定判据（`mode: 'absent'`）：例「次瓦片**不许**有字标」。

**顺带修掉的三类解析坑**（都留了注释，避免下一个人重踩）：
`<image …></image>` 的闭合标签会把父节点弹掉（报错点离真因很远）；
`wx:if` 与 `wx:elif` 之间的换行文本节点会让 `wx:elif` 变成"孤儿"；
`{{a}}{{b}}` 这种相邻插值用贪心/非贪心正则都会被当成一个表达式。

## 2. 页面改造（逐条：改前 → 改后 → 为什么）

### 2.1 写愿条：把「输入 / 灵感 / 额度 / 字数」收进同一视线（对应 D1）
- **改前**：`.ww-composer`（输入框 + 挂上墙）在弹幕墙正下方；**灵感词 + 额度 + 字数**在灯 / 木鱼 / 玩法**之后**的 `.ww-write` 卡里。
- **改后**：新增 `.ww-wishassist` 紧贴发送条下方，装下**灵感 chips + 今日额度 + 字数**；`.ww-write` 整块下线；
  「越权提示」（我有 N 条被馆方收起）上移成独立一行。
- **量到的效果**：`灵感行距发送条` **586px → 16px**；`首屏可见` 里多了 `.ww-inspo-row`。
- **为什么不做成一张卡**：它与发送条本来就该读成一组（发送条自己是透明的，见 `.ww-composer` 的说明）。

### 2.2 「我的」章 → 卡片左侧一道铜色细边（对应 D2）
- 理由与 2026-09-18 下线「馆方」章**完全相同**：重复 5 次的信息不再是信息。
- 信号改挂在卡片**已有的左侧铜绳** `.ww-tag::before` 上（粗一档 + 铜色实心 + 一圈微光）：
  `::before` 本来就画在左边缘，**加粗加亮不改任何盒尺寸**，不会把正文挤动一行。
- `official` / `isMine` 字段**都保留在数据与行模型里**，以后要挂回任何印记都不必做数据迁移。
- 守卫同步：断言从"三枚印章都在"改成"**去徽章不许把『哪条是我的』弄丢**"（左边线必须存在），
  注入锚点改锚到下一行「置顶」章。

### 2.3 玩法瓦片分两级（对应 D4）
- **改前**：四枚等大等重、无字标（2026-09-20 极简时把字标当"标题的重复"删掉了）。
- **改后**：前两枚（= `applyBlessScope` 按祈运标签排出来的那两支）为**主瓦片**：
  更高、铜边 + 铜底、名字大一档、带**铜色字标**（取自注册表 `mark`）；
  后两枚为**次瓦片**：更矮、弱边框、无字标。
- 区头副文案随标签走：`偏「求成」先推这两支` —— 把"为什么前两枚更大"写出来，避免读成排版偏心。
- **字标只给主瓦片**：四枚都加等于没加（这正是上一轮删它的理由，在这一层仍然成立）。

### 2.4 「今天的仪式」归位（对应 D6 / D7）
- 新增 `.ww-sec-head`（`今天的仪式` + 音效开关），与「今天的玩法」形成节奏；
  **音效开关从说明行尾巴移到区头右侧**（它是仪式音效，此前是全页最抢镜的次要元素）。
- 说明文案删除：卡片自己写着「点一下，替今天留个记号 / 敲一下，静一分」，
  而「心愿在墙上流动」正是紧邻上方墙页脚的原文。
- **点亮态灯卡不再折行**（对应 D5）：连续天数盒改为**绝对定位在卡片右上角**
  （DOM 顺序 `copy → streak → tail` 不变，故顺序判据与 `min-width: 48rpx` 判据照旧成立）。
  实测：`点灯卡标题 129×78 两行` → `221×39 一行`，灯卡高度 294 → 222，与木鱼卡重新等高。

### 2.5 牌匾真的有一块铜牌（对应线下原件）
- 线下黑马底座嵌着**黄铜三字「马上有」**（PRD §2.1 的原件），而页头此前**通篇没有一个器物** ——
  三行字直接浮在纸面上，牌匾没有重心，撑不起目标 2「一眼认出这是黑马那面墙」。
- 新增 `.ww-plate`：铜底渐变 + 内高光 + 两颗 CSS 铆钉 + 衬线铜字，与「祈福墙」标题并排（`aria-hidden`，纯装饰）。
- ⚠️ 没有动 `.ww-hero.is-joined` 的"页头与墙面合并为一张卡"设计 —— 那是产品负责人 2026-09-20
  明确要求过两次的口径（见 `index.wxss` 里那段注释）。本轮只在**合并态内部**加器物。

### 2.6 段条数与弹幕数据源（对应 D3）
- 新增 `data.wallCount`，**只由 `applyItems`（墙列表回包）写**；「墙上的愿签 N」与墙页脚都用它。
- 顺带修掉同一族的一处：弹幕轮播重排原来读 `this.data.items`（切到「我的心愿」后会被换成我的心愿）
  → 改读 `this._wallItems`。
- 守卫：断言升级为"条数挂在所属段内 **且与当前视图无关**"，并钉住"只有 applyItems 写 wallCount"。

## 3. 交互 / 功能修复（含一个 P0）

| # | 问题 | 处理 |
|---|---|---|
| **P0** | `syncRitualToCloud()` 判一个对象是否 `=== true` → **恒为 false**。后果：① 用户同步成功也被告知「记录仍在本机」（说假话）；② `resume_success` 漏斗恒为 0；③ `_certSyncedCount` 永不写入 → 每次 onHide/onUnload 重复写云 | 按真形态取 `res.ok === true`（保留布尔兼容）。**并补了一条守卫 + 一条自检注入** —— 这个 P0 此前躲过了 851 条断言，因为所有单测都把 `page.syncRitualToCloud` 整个桩掉了、源码级断言只查"调用了 syncToCloud" |
| P1 | 下拉刷新在墙已开放时**不重拉列表**（`force` 在 `applyGate` 的早退分支被丢掉），与注释相反 | `force` 一路传到 `applyGate`，开关没变时也补一次 `refresh()` |
| P1 | 门禁**读失败**被渲染成「祈福墙暂未开放 / 馆方正在准备这块墙面」—— 把网络故障说成馆方的状态，且没有出路 | 新增 `gateError`：说「墙面没能打开」并给「再试一次」（`onGateRetry` → `bootstrap({force:true})`） |
| P1 | 灵感 chip 点了像没反应（不聚焦） | 新增 `focusWishInput(delayMs)`，灵感词（60ms）与「抄一句」（300ms）都聚焦 |
| P2 | `loadMine` 失败时**额度一个字都不动** → 停在默认「今日还可写 5 条」（可能是假的） | 标记 `quota.unknown`，UI 改说「额度暂时读不到，能否再写以提交结果为准」 |
| P2 | `onPlayTap` 的非 `need_profile` 失败**静默 return** → 点瓦片毫无反应 | 走 `showAppToast` 说明「没摇出来」并上报 `wish_wall_play/fail` |
| P2 | `usePlayWish` 的 300ms 聚焦定时器是**匿名 setTimeout**，卸页后仍会 setData（本页唯一漏清的定时器） | 句柄化到 `this._focusTimer`，`onUnload` 清；同时置 `_unloaded` 兜底 |
| P2 | `onShow` 不重算灯态：跨天从后台回来，`lamp.lit` 还是昨天 → 新的一天点不亮 | `onShow` 比对 `dayKey`，跨天则 `initRitual()` |
| — | 「抄一句」只弹 toast「已填进输入框」而输入框在视口上方 | 改为滚到 `#wishInput` + 聚焦 |

  警示色 `#E9A23B` → `var(--color-warning)`（同值）。

  （`check:test-wish-wall` 有一条"与 `--space-*` 同值的间距必须写令牌"的同值判据）。

  待真机确认再动"。本轮不碰它们（动它要同步下调 `FS_NON_TOKEN_OK`，属于"真机之后再收"的一步）。

## 7. 未做 / 已知残留（如实留痕，不粉饰）

1. **离群字号未收**（19/21/25/42rpx 共 8 处）—— 见 §4，等真机确认。
2. **`.ww-hero` 的 base 视觉声明仍是"死代码"**：`.ww-hero { background/border/border-radius/box-shadow }`
   被 `.ww-hero.is-joined` 逐条覆盖，而 WXML 硬编码 `is-joined`。这是 2026-09-20「页头与墙面合并」的
   **有意结果**（注释里写着理由），本轮**没有**借机复活它 —— 那会推翻产品负责人口头要求过两次的合并。
   若要清理，应作为独立一件事（连带删掉 `.ww-fiber/.ww-emboss/.ww-wm` 三个装饰层）。
3. **点亮态的玩法瓦片落在折叠线下**（实测 top 1303）：点灯后灯卡更长、还多一条「功德证」入口。
   已按"参考项（不红）"处理，是否压灯卡由产品定。
4. **emoji 计数仍按 UTF-16 码元**（`draft.length` / `.slice(0,30)`）：emoji 算 2、ZWJ 家庭 emoji 算 8，
   30 字上限对纯中文准确、对 emoji 会少算，极端情况下 `.slice` 会截出半个代理对。
   修它要**同时改客户端与云函数校验口径并重新部署云函数**，超出本轮范围 → 单独一件事。
5. **木鱼连点不节流**（计数与本地存档每一下都写）：唯一节流是音效（120ms 闸门）。
   这是刻意设计（"视觉回声每次都响应"），本轮未动。
6. **`_certShownKey` 只记 claim 曝光**、`view` 模式（回看入口）曝光不进漏斗 —— 已知，未动。
7. **音效素材缺三处**（`wish` / `play` / `lampAgain` 未登记素材 → 不响）：属已知取舍，未动。

3. 若哪一条不符合预期，**只回「哪一条 + 实际现象」**即可（口径见 `docs/施工与发布流程.md`）。
