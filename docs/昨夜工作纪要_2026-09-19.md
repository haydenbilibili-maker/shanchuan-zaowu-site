### 阶段 D · 集成中发现并修掉的两条既存自检红

合并后跑 `npm run check:admin:selftest`（**隔离 worktree**），发现 **2 条失败**。
**先证明与本批合入无关**：同一条注入在两棵树上（合入前 `281ccb3` / 合入后）跑出的输出
**逐字节相同**。然后逐条修：

| 守卫 | 性质 | 根因 | 修法与反证 |
|---|---|---|---|
| `test:register-gate` | 🔴 **真危险的假绿** | 判据 `/closable="\{\{true\}\}"/.test(整页 wxml)` **与对象脱钩**：只要求"整页某处有"。而祈福墙这页有 **3 个** `<register-auth-dialog>`（注册 / 连灯 / 功德证门禁），原注入只改**第一处**，另两处照样满足断言 | 断言改绑到**弹窗自己的标签**，并补「三个弹窗**全部**必须是软钩子」。**反证**：同一份被注入源码（把功德证门禁改成闭不掉的硬门禁）→ **旧判据 `exit 0`（假绿）→ 新判据 `exit 1` 并点名** |
| `check:sfc-dev` | ⚪ 注入样本过时 | `<keep-alive>` 有两个子节点在当前工具链下**已不是编译错误**（最小复现实测：`transformRequest` 正常返回）→ 自检打印「(无失败项)」 | 换成确实会被编译期拒绝的「元素未闭合」（报错原文 `Element is missing end tag.`），判据同步盯该报错。**反证**：把样本补成能编译 → 自检 `exit 1`（`【漏检】`） |

> **为什么第 1 条重要**：它意味着"守卫会红"这句话对一个**真实可发生的缺陷**是假的 ——
> 有人把一个注册门禁改成**困住用户、关不掉**的硬门禁，守卫会放行。
> 这类「判据与对象脱钩」是错题本 E7 的形态，**同类错误第二次发生必须补守卫或自检**。

## 4. 我自己犯的错 / 纠正过的不实陈述（诚实登记）

1. **cwd 泄漏导致我误判「H2 已合入」**：一条复合命令里 `cd /tmp/sczw-merit` 之后**没切回来**，
   于是后面 `git show HEAD:…` 读的是 **H2 worktree 的 HEAD**，不是集成分支。
   我据此以为已合入并去跑"交叉验证"，**实际那 15 个开关里根本没有 `showMuyuCertificate`**。
   → 真相：H2 **从未推送过**（`origin` 上没有那条分支），所以 `git merge origin/feat/muyu-certificate`
   报 `not something we can merge`，我却把这条报错误读成了别的意思。**已用本地分支合入。**
   → 教训：复合命令里 `cd` 之后必须显式切回，或用绝对路径 / `git -C`。
2. **我修的归属守卫自己引入过第二个 bug**：把 `--no-renames` 放在 **git 顶层**（它是 `diff` 的子命令选项）
   → `unknown option` → 三个 diff 全部失败、**恒返回空数组** → 冻结判定与分支范围判定长期「比对 0 个改动文件」。
   而原自检 19 项**全部绕过 git**（直接注入 `branchChanged: [...]`），所以抓不到。
   修法：参数移到子命令后 **+ 补两条走真实命令行的自检**。实测：修前报「比对 0 个」，修后报「比对 191 个」。
3. **我转述失准过一条**：曾对子代理说「开关在后台没法勾」—— **不准确**。
   核实后的开关地图是：**14 个开关每个都有 ≥1 个后台入口**，ERP 表单少的那 4 个是**店长面功能、放在店长端**，
   属**分工**不是缺口。已在交付索引 §2.9 更正。
4. **我一度把「有据的刻意排除」当成漂移**：`wiki_register_gate` 不变量表卡，
   我起初以为"逮到一个漂移"，实际它是 `check:wall-monitor` 里 `REPORT_EXCLUDED_GATES` 的**文档化刻意排除**。
   → 没有去"修"它，而是补了一条 B4「两份排除清单必须同源」的**一致性断言**，并修了守卫的措辞。
