## 10. 已知坑（含本次新踩，按"会让人白干"排序）

1. **合并/大改后必须跑完整构建链**，不能只看守卫。今天两处问题（重复 import、JS 落在 style 里）
   都只在生产构建暴露，而 dev 管线 + 106 条守卫全绿。
2. **规则类配置是双真源**（§6）：改代码不迁云端 = 零生效；`check:shipping-rules` 会拦。
3. **小程序有两个目录**（§7）：不同步 = 真机跑旧代码。
4. **git 会转义非 ASCII 路径**：`git diff --name-only` 输出 `"docs/\345\..."`，
   直接拿去 `git cat-file` 会全部查不到（我据此误判过"23 个文件缺失"）。
   查这类路径一律加 `-c core.quotepath=false`。
5. **不要相信回执**（部署/写库/配置更新都要独立读回，§6）。
6. **不要按渲染输出回抄锚点**：补丁前先 `sed -n` 打印真实区域；`str.replace` 静默不命中是最常见的事故
   （本次又中招一次：`return state.freeShippingThreshold` vs 实际的 `return free`）。
7. **沙箱里 `npm run` 可能因写 `~/.npm/_logs` 被拒** → 直接 `node scripts/…`。
8. **`check:admin:selftest` 必须在隔离 worktree 跑**（会注入源文件）。
9. **不要用静态分析当事实**：CSS 生效取决于 `!important`/特异性/teleport，必须在浏览器实测。
