## 1. 已建好的替代品（本轮交付）

| 文件 | 作用 |
|---|---|
| `components/AppModal/`（js/wxml/wxss/json） | 样式化弹窗：**博物黑 + 铜金铭牌**，与 `RegisterAuthDialog` / `sensitive-blur-gate` 同一套视觉语言；支持确认/仅提示两态、**危险色分级**（删除类走朱红渐变）、`white-space:pre-wrap` 保留 `\n` 语义 |
| `utils/appModal.js` | `withAppModal(config)` 包装 Page，注入 `this.modal(options)` → 返回与 `wx.showModal` success **同形**的 `{confirm, cancel}`；**页面漏挂宿主时自动退回系统弹窗**（绝不静默不弹） |
| `scripts/check-modal-style.mjs` | **棘轮守卫**：原生弹窗数量只许降不许升；已迁移页不得回退；兜底不得被删 |

## 2. 迁移配方（一页三处改动，行为等价）

以 `subpackages/business/address/index.js` 为参考实现：

```js
// ① js 顶部
const { withAppModal } = require('../../../../utils/appModal')
Page(withAppModal({ /* 原配置原样 */ }))      // ← 注意结尾是 }))

// ② js 内：success 回调 → then（语义完全一致，不改业务逻辑）
this.modal({
  title: '删除地址', overline: 'REMOVE ADDRESS',
  content: '确定删除该收货地址？删除后不可恢复。',
  confirmText: '删除', danger: true
}).then(async (res) => { if (!res.confirm) return; /* 原逻辑 */ })
```

```xml
<!-- ③ wxml 末尾（放最外层容器之外，避免被任何 filter/transform 影响） -->
<app-modal id="appModal" />
```
```json
// ④ json：注册宿主
"usingComponents": { "app-modal": "/components/AppModal/index" }
```

**迁移纪律**：一次一页、只改弹窗不改业务；`pre-wrap` 保证多行文案与原 `\n` 一致。

## 3. 建议批次（按「顾客可见性 × 处数」排序）

1. **批 1 · C 端高频**（约 25 处）：`feature/detail`(9)、`business/order-detail`(6)、`business/order-claim`(5)、`pages/cart`(2)、`pages/user`(4)…
   —— 顾客直接看到，视觉收益最大。
2. **批 2 · 交易链路**（约 20 处）：`business/confirm-order`(4)、`business/orders`(2)、`business/booking`(2)、`business/ticket`、`business/store`、`business/points`、`business/store-zone`
3. **批 3 · 后台工作台**（约 85 处）：`manager/managerPageConfig`(30) 等。内部工具，收益低、改动面大，**建议最后做**。
4. **批 4 · 其它**：`feature/gift/*`(6)、`feature/custom`(3)、`extra/user/*`(4)…

每迁一页请**把 `check-modal-style.mjs` 的 `BASELINE` 改小对应处数**并把页面加进 `MIGRATED`
—— 棘轮就是靠这个数字防止回退。

## 4. 本轮没做的（明确留白，不是遗漏）

- **`wx.showActionSheet`（7 处）**：也是原生样式。它常与「点击某项 → 立刻执行」绑定，
  改成自定义需要同样的宿主机制但交互差异更大（底部弹出、可滚动列表），
  建议**单独一批**做，不要和 `showModal` 混在一起改。
- **`wx.showToast` / `wx.showLoading`**：瞬时轻提示，不属于「弹窗」；且 1823 处规模，
  要改应作为独立专项（自定义 toast 需要全局宿主，方案不同）。
