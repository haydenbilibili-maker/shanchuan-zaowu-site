## 2. 迁移配方（一页三处改动，行为等价）

以 `subpackages/business/address/index.js` 为参考实现：

```js
// ① js 顶部
const { withAppModal } = require('../../../../utils/appModal')
Page(withAppModal({ /* 原配置原样 */ }))      // ← 注意结尾是 }))

// ② js 内：success 回调 → then（语义完全一致，不改业务逻辑）
this.modal({
  title: '删除地址', overline: 'REMOVE ADDRESS',
  content: '确定删除该收货地址？删除后不可恢复。',
  confirmText: '删除', danger: true
}).then(async (res) => { if (!res.confirm) return; /* 原逻辑 */ })
```

```xml
<!-- ③ wxml 末尾（放最外层容器之外，避免被任何 filter/transform 影响） -->
<app-modal id="appModal" />
```
```json
// ④ json：注册宿主
"usingComponents": { "app-modal": "/components/AppModal/index" }
```

**迁移纪律**：一次一页、只改弹窗不改业务；`pre-wrap` 保证多行文案与原 `\n` 一致。

## 4. 本轮没做的（明确留白，不是遗漏）

- **`wx.showActionSheet`（7 处）**：也是原生样式。它常与「点击某项 → 立刻执行」绑定，
  改成自定义需要同样的宿主机制但交互差异更大（底部弹出、可滚动列表），
  建议**单独一批**做，不要和 `showModal` 混在一起改。
- **`wx.showToast` / `wx.showLoading`**：瞬时轻提示，不属于「弹窗」；且 1823 处规模，
  要改应作为独立专项（自定义 toast 需要全局宿主，方案不同）。
