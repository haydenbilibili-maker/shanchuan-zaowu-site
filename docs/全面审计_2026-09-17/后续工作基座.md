### 1.3 三个环境坑（会浪费每个人半天）

| # | 坑 | 现象 | 解法 |
|---|----|------|------|
| 1 | **本机预设 `NODE_ENV=production`** | `npm ci` 静默省略**全部 devDependencies** → `vite`/`@vitejs/plugin-vue`/`wrangler` 全缺；`npm run build`、`dev:admin`、`check:sfc-dev` 全报「找不到 vite」 | `npm ci --include=dev`（或先 `unset NODE_ENV`） |
| 2 | npm 默认缓存 `~/.npm` 可能不可写 | `npm error code EACCES ... mkdir /home/<user>/.npm` | `npm ci --cache <可写目录>` |
| 3 | `astro build` 需要可写 `$HOME` | `EACCES: mkdir '/home/<user>/.config/astro'` | `ASTRO_TELEMETRY_DISABLED=1`，或设 `XDG_CONFIG_HOME=<可写目录>` |

> 建议把这三条写进 `AGENTS.md` 的「环境」小节（当前没有）。`docs/monorepo.md` 也只写了 `npm install`，同样会踩坑 1。

## 5. 完成定义（DoD）与验收纪律

一条改动要算「做完」，必须同时满足：

1. **有命令 + 有输出**：不接受「应该没问题」。粘贴实际命令与输出摘要。
2. **过了闸门**：`npm run check:admin` 全绿；涉及小程序加 `lint:wxml`；涉及界面加 `check:nav-dom`。
3. **界面级改动必须有浏览器证据**：`check:sfc-dev` 只覆盖编译层，**编译通过不代表页面画得出来**
   （本项目已被坑过：`<keep-alive>` 两个子节点导致 dev 管线 500、整页白屏，而 `build` 依然 exit 0）。
4. **涉及权限/写路径必须服务端实测**：CSS/规则「哪条生效」受 `!important`/特异性/teleport/线上规则影响，
   脚本判出的结论**必须在浏览器或云函数实测后**才写进文档。
5. **文档同步**：新模块先落蓝图（`admin/docs/`），上线后登记到对应 `README.md` 索引（见 §8）；改了集合加四处。
6. **部署纪律**：产品负责人 2026-09-16 的指令是「后续更改暂不部署，改好统一部署」。
   云函数与线上安全规则类改动**未执行**——不要把「代码已改」写成「已修复」。
