## 4. 未验证与存疑

**未验证（明确不知道）**

1. **线上云函数代码 ↔ 仓库是否一致**：`npm run check:fn-sync` 因缺 `TCB_SECRET_ID/TCB_SECRET_KEY`（`admin/.env`、`admin/.env.local` 均不存在）exit 2，**本轮完全未比对**。所有「现状」结论都只对**仓库代码**成立。
2. **`point_records.dedupeKey` / `store_purchases.dedupeKey` 唯一索引是否已在线上创建**：无任何仓库内手段可查（P0-2）。若未建，则 §2.5(d) 列出的所有幂等**全部**退化为 read-then-write。
3. **`config.json` 声明的 `permissions.openapi` 与线上实际授权是否一致**：P0-4 只证明「代码调用 ⊄ 仓库声明」；存在两种可能——(a) 线上控制台已补勾权限（只是仓库 `config.json` 没同步，属配置漂移）；(b) 线上确实缺失（内容安全真失效）。**无法在只读静态审计中区分**。
4. **经 `/api/cloud-fn`（SCF `Invoke`）调用时 `cloud.getWXContext().SOURCE` 的真实取值**：本报告据 `sourceOrigin.js:56-57`「空串 → 定时触发 → 可信」与 `classifySource` 实现**推断**为「空串 → `isNonClientSource()===true`」，但**未在真实环境实测**。这一步推断是 P0-1 与 §3-14 的影响面判断前提。
5. **`mediaCheckAsync` 失败时的线上用户可见行为**：代码把它设计为「不阻断」（`upsertUserProfile/index.js:638-670`），但「不阻断 + 打标待复核」的复核队列是否有消费方，本轮未追。
6. **各函数 `timeout`（82 份声明）与线上实际超时是否一致**、`wx-server-sdk ~3.0.1` 与线上运行版本是否一致。

**存疑（可能是假阳性，需人工确认）**

1. **P0-4 的严重度**：若线上权限已在控制台勾选，则只是「仓库 `config.json` 落后」，应从 P0 降为 P2（配置漂移）。判据：在云开发控制台核对 `identifySpecimen` / `grantStorePoints` / `submitComment` / `upsertUserProfile` 的 openapi 权限勾选状态。
2. **P0-1 的严重度**：`managerShipOrder:1211` 之后紧跟 `assertStaff`-系校验（`assertShipAccess`），被指定的 openid **仍须是真实员工**，所以它是「审计归属伪造 + 守卫不一致」，不是「任意人越权」。若产品认为「持 ERP 口令者已等同超管」，则可降级为 P1/P2；若审计归属被认为必须可信，则应保持 P0。
3. **`receiveCoupon` 的竞态可利用性**：`coupons` 集合三平台无模板创建入口（§3-6），若线上无活跃模板，则该竞态当前无实际资损面；一旦运营在控制台建模板并放量，立即变为可刷券。
4. **`defaults.js` 11 份 / 6 哈希**：经逐份读文件头，6 个不同哈希**主要是同名不同物**（`store_point_rules` vs `stored_value_config` vs `shipping_rules` vs 早晚班清单 vs 养护内容），**不是漂移**。仅 `earnPoints/defaults.js` 的 `modules.share` 差异是已知并有意为之（`check-store-point-rules-sync.cjs:43` 白名单）。
5. **`getStoreConfig/ensureSeed.js` 的写路径**：需 `stores`/`store_zones` 集合缺失才触发，正常线上环境不会走到；列为 P2 而非 P1。
6. **`catch (e) {}` 计数**：`storeCheckIn/index.js:23` 是唯一真空块，包的是单条门店名查询的降级路径，影响面小。

**建议的下一步（需人工复核的两条，见最终回复）**

- 在云开发控制台核对 4 个函数的 openapi 权限勾选状态（决定 P0-4 生死）。
- 用真实 ERP 会话向 `managerShipOrder` 发 `{_fromApproval:true,_callerOpenid:'<某真实店员>',action:'...'}`，观察 `staff_audit_logs.openid` 是否被写成该店员（决定 P0-1 是否可复现）。
