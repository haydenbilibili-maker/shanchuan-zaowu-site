### 1.5 敏感集合分组（`read:true` / `"auth != null"` 全列）

前置事实：Web ERP 使用 `signInAnonymously()`（`docs/admin-a1-cloudbase.md:52-56`），envId 明文硬编码在公开前端包（`admin/src/cloud.js:11`）→ **`auth != null` 等价于「任何能联网的人」**，不是「受信任用户」。

| 敏感度 | 集合（read 取值） | 可写？ |

### 2.1 P0-1：匿名登录 + `admin_users`/`admin_roles` 全开写 = 提权链

### 2.6 P1-5/P1-6：会话与口令的加固缺口

**证据**
```
functions/_lib/proxySession.mjs:38-40   sessionSecret = ADMIN_PROXY_SECRET || ADMIN_PROXY_PASSWORD || ADMIN_OPS_KEY
functions/_lib/proxySession.mjs:62-68   token = `${exp}.${HMAC(secret,'admin-session:'+exp)}`  ← 无 uid / 无 nonce
functions/_lib/proxySession.mjs:70-82   仅校验签名与 exp；无吊销名单
functions/_lib/proxySession.mjs:97-110  Cookie: HttpOnly + Secure + SameSite=Strict + Max-Age ✅（属性齐全）
functions/api/admin-session.js:52-57    DELETE/GET 直接清 Cookie，不使旧 token 失效
functions/api/admin-session.js:69-77    口令比较为定长循环（好），但无失败计数/锁定/延迟
```
**正面**：Cookie 属性齐全（`HttpOnly; Secure; SameSite=Strict`）、比较为恒定时间、缺 `ADMIN_PROXY_PASSWORD` 时 fail-closed（`admin-session.js:40-50`、`cloud-fn.js:64-74`）、`corsHeaders` 不回显 `*` 且带 `Allow-Credentials`（`proxySession.mjs:139-150`）——这些都做对了。

**缺口**：(a) 令牌无主体绑定 → 任一泄露的 Cookie 可被任意客户端重放 12h；(b) 无吊销 → 「退出登录」只清浏览器侧；(c) 签名密钥可回退到 `ADMIN_OPS_KEY`（同一把密钥同时是「云函数超管凭据」与「会话签名密钥」，一旦泄露可离线批量伪造会话）；(d) 全仓无速率限制。

**建议**：令牌改为 `uid.nonce.exp.sig` 并引入短期 nonce 表；强制 `ADMIN_PROXY_SECRET` 独立（缺失 fail-closed）；为 `/api/admin-session` 加失败计数与指数退避。
