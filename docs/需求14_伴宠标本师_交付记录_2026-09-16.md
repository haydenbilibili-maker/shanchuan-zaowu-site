## 2. 三条门槛：为什么这个人选必须被过滤

`getPetMemorialConfig` 只把**同时满足**下列三条的档案列进可选名单：

1. `petOrderQualified === true` —— 标本师本人显式声明接单（不预设默认，历史档案一律视为不接）；
2. `active !== false` —— 对外展示中；
3. `staffOpenid` 非空 —— 定向通知与工单归属都靠它。

第 3 条是本条需求**最大的静默失效点**：
审计已确认 `staffOpenid` 只由小程序「个人页面维护」保存时写入（`manageStaff.saveArtisanProfile` 的 `data.staffOpenid = openid`），
**ERP 全仓没有任何 `staffOpenid` 写入入口**。若名单不排除「有资质但未绑定 openid」的档案，
客户会看到并选中一个永远收不到通知的标本师 —— 单能下、通知不发、没人知道。

处理方式：**把它们挡在名单之外**，同时云函数日志输出该类档案的条数便于运维发现配置缺口。
即使有人绕过 UI 直接构造 `framerId`，`petMemorialOrder.submit` 也会拒绝并提示改选（不静默降级为平台指派）。

## 3. 安全边界（防越权投放）

| 风险 | 处理 |
|---|---|
| 客户端伪造 `artisan.framerName` 冒充他人 | 落库姓名一律取自 `framers.name`；客户端入参被丢弃（守卫 `trust-client-name` 注入可证） |
| 客户端伪造 `artisan.openid` 把工单派给别人 | 落库 `artisanOpenid` 一律取自 `framers.staffOpenid` |
| 标本师查别人的工单 | `listArtisan` 的 `framerId` 由服务端按调用者 openid 反查，**客户端传的 framerId 不采纳** |
| 标本师替别人接单 | `acceptAssignment` 校验 `doc.artisanFramerId === 我的 framerId`，否则拒绝 |
| 挂名接单后再点 | 已 `acceptedAt` 则拒绝重复确认 |
| 标本师越权报价/改状态 | **不开放**：本函数只给标本师 `listArtisan` + `acceptAssignment` 两个动作，报价与状态流转仍归店长/超管工作台 |
| 旧版客户端保存档案时清掉资质 | `saveArtisanProfile` 改为**「字段出现才写」**（`hasOwnProperty` 判定）。若按 `=== true` 兜底成 false，未升级的客户端每次保存档案都会把已声明的伴宠资质静默清掉 —— 守卫 `wipe-artisan-qualify` 注入可证 |

## 4. 通知链路

```
客户提交（指定 f-ok）
  └─ petMemorialOrder.submit
       ├─ resolveQualifiedArtisan(framerId)      # 三门槛复核
       ├─ add pet_memorial_orders {artisan, artisanFramerId, artisanOpenid}
       ├─ dispatchMessage dispatch  pet_memorial_received  → 客户（既有）
       └─ dispatchMessage notifyWorkOrder  pet_memorial_assigned → 标本师本人（新增）
            └─ workOrderSubscribe.sendWorkOrderSubscribe
                 templateId = env.STAFF_PET_MEMORIAL_TMPL_ID   # 未配置 → skipped: TMPL_PENDING
                 page = subpackages/manager/artisan/pet/index
                 data = { character_string1, thing2, thing3, time4 }
                 → notification_logs 留痕（type=staff_pet_memorial_assigned）
```

字段与平台限制（已按微信「详细内容」规则核过）：

| 字段 | 取值 | 限制 | 裁剪函数 |
|---|---|---|---|
| `character_string1` | 工单号 | ≤32，**不得含汉字** | `clipCharacterString`（剔除非 `[\w\-./#:]`） |
| `thing2` | 宠物名 | ≤20 字符 | `clip` |
| `thing3` | 工艺名 | ≤20 字符 | `clip` |
| `time4` | 提交时间 | 年月日 + 24 小时制 | `formatTimeValue` |

> ⚠️ `logType` 必须是 `staff_` 前缀。审计已指出：现有伴宠模板**全部落在 customer 队列**，
> 标本师在「工作通知」里看不到 —— 这是本条需求最容易做错的一处。

6. 真机验收：C 端可选名单是否只出现已开启资质的人 → 下单 → 标本师端是否收到服务通知 → 工作台是否能确认接单。
