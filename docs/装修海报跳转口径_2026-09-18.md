## 1. SSOT 与两份副本（**这是最容易踩的地方**）

候选列表 `SCHEME_PRESETS` 有两份，服务的却是**同一个 `banners` 集合**（小程序首页轮播）：

| 副本 | 文件 | 谁在用 |
|---|---|---|
| **SSOT（改这里）** | `miniprogram/utils/bannerNav.js` | 店长工作台「店铺装修 → 编辑海报」（`managerPageConfig.js` 的 `schemePresets`，WXML 是原生 `<picker>`） |
| **逐字副本** | `admin/src/utils/bannerNav.js` | ERP「首页运营 → 首页轮播」（`components/BannerManager.vue` 的 `el-select`） |

- 副本里**只有候选数组**要求逐字一致；其余函数（`validateSchemePath` / `buildBannerLinkForSave` / `matchSchemePresetId`）是 ERP **有意精简**的（它不需要运行时跳转）。
- **改完 SSOT 必须同步副本**，否则运营在两个入口看到的候选不一样 —— 历史上就是这样漂了 13 项没人发现。守卫会比对（含顺序与名称）。

### 祈福墙是多面墙，怎么指到某一面？

- **不带参数 = 默认墙**（页面 `onLoad` 对缺失/非法 `productKey` 一律回落默认墙，海报不会跳进空白页 —— 守卫有断言）。
- 要指向某一面墙：把路径写成 `/subpackages/feature/wish-wall/index?productKey=<藏品键>`（路径字段支持 query，`validateSchemePath` 放行）。
- 与 C 端入口组件同源：详情页那个入口是用 `utils/wishWall.buildWishWallUrl()` 生成 URL 的，守卫断言两者**前缀一致**。

## 4. 怎么加一个新功能页（三步）

1. 改 SSOT：`miniprogram/utils/bannerNav.js` 的 `SCHEME_PRESETS` 加一条（`id` 唯一、`label` 是运营看得懂的中文、`path` 必须已登记在 `app.json`）；
2. **同步** `admin/src/utils/bannerNav.js` 的同名数组（逐字，含顺序）；
3. 跑 `npm run test:banner-presets`（它会告诉你路径是否可达、两副本是否一致）。
   —— 若这是**核心功能**，同时在守卫的 `REQUIRED_TARGETS` 里补一行，否则以后有人删掉它不会被发现。
