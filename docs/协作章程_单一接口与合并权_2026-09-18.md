## 0. 模型（一句话）

```
产品负责人  ←──单点交互──→  马斯克（总负责人）  ←──单点交互──→  七条工作流
```

- **产品负责人只与马斯克交互**，不再与各工作流直接对话。
- **工作流只与马斯克交互**，彼此之间**不直接协商**。
- **冲突由马斯克裁决，合并由马斯克执行，质量与目标的后果由马斯克承担。**

## 2. 我（马斯克）对你负责的五条

1. **一个接口**：你只跟我说。任何工作流的诉求由我收敛成一件事再找你。
2. **一本台账**：七条流的波次 / 状态 / 每条红的归因 / 待你拍板的项，随时可查（落在本文 §7 与治理文档 §6）。
3. **不放空炮**：每条结论带可复验的命令与输出；不接受"应该没问题"。**没实测的数字不写进文档。**
4. **验收卡**：每次交付给你六项（改了什么 / 在哪看 / 期望看到什么 / 怎么证明 / 真机真图 / 已知不确定项）。
5. **诚实归因**：每条红都要说清"是我的 / 不是我的 / 是谁的"。**不把我的红说成别人的，也不把别人的红算成常态。**

## 5. 我做不到的（诚实边界，先讲清免得你误判）

| # | 做不到 | 后果 | 替代办法 |
|---|---|---|---|
| 1 | **给"已经在跑的独立进程"发消息** —— 它们不是我的子代理（`list_agents` 里只有我自己 spawn 的），我没有 steer/interrupt 通道 | 我只能**通过仓库产物 + 门禁**治理它们：它们读 `AGENTS.md`/章程/注册表，被守卫拦，被我的合并权挡。**异步、无对话** | 见 §6 第 5 项：把工作流改成**我 spawn 的子代理**，我就能真正对话与叫停 |
| 2 | **阻止任何人直接 `git push main`** | 归属与门禁都能被绕过 | 需要你在 GitHub 上开**分支保护**（我不能从代码里设） |
| 3 | **代替你验收** | 我会把"我觉得行"当成"行" | 我只提供证据与验收卡，判断权在你 |
| 4 | 撤销已推送的历史 | 只能 `revert`，不能算没发生 | 所以"合并权"必须前置，而不是事后补救 |
| 5 | 读别的 agent 的私有状态（它在想什么、做到哪） | 我只能看**盘上的事实** | 要求它们把状态写进盘（台账/交付记录） |

#### ⚠️ 一个必须先告诉你的技术真相

本仓所有 agent **共用同一个 git/GitHub 身份**（实测 `git config user.name` = `Hadyen`）。
因此 **"只有马斯克能合并"在 GitHub 上无法强制** —— 分支保护能挡住**直接 push**，
但挡不住"自己开 PR、自己点合并"（同一个人就是 reviewer）。

> 这跟 ERP 权限模型是**同一个病根**：**没有按人账号，就没有真权限**
> （`后续工作基座` §6 第 1 项、ERP 台账 §7.5 都记着这条）。

能强制的是下面这个**降级版——它比"只有我合并"更硬，因为它可审计**：

| 措施 | 效果 | 谁做 |
|---|---|---|
| ① `main` 分支保护：**Require a pull request before merging** + 禁止 force push + 禁止删除 + **Do not allow bypassing the above settings** | **直接 push main 被技术阻断**（这是最大的收益，拿到它就已经把最容易出事的路径封了） | 你 |
| ② `CODEOWNERS` 把**契约面 + 钱路径 + 发布目录**指到**你的账号**，并开 **Require review from Code Owners** | **这三类改动必须你本人批准**才可能合并 —— 技术强制、可审计。这是"契约冻结权"真正落地的地方 | ✅ **已写好** `.github/CODEOWNERS`（35 条 pattern，owner = `@haydenbilibili-maker`）——**在勾 ② 之前它是惰性的** |
| ③ 本地 `.githooks/pre-push` 拦 `main` 直推（配 `git config core.hooksPath .githooks`） | 防误推。可 `--no-verify` 绕过 → 属"防事故"，不属"防蓄意" | 我加；各流各跑一次 config |
| ④ 我作为集成官做唯一合并执行者 | **约定层**，靠 ①②③ 兜底 | 我 |

**我不建议把 Code Owners 开到全仓** —— 那会把你变成每一条改动的瓶颈。只开**高风险路径**。

#### 分支保护清单（GitHub UI 逐步）

`Settings → Rules → Rulesets → New branch ruleset`（新界面）或 `Settings → Branches → Add rule`（旧界面）：

1. **Target branches** → Add target → **Include default branch**（即 `main`）
2. ✅ **Require a pull request before merging**
   - Required approvals：`0`（因为没有可区分的第二人，填 1 只会把自己卡死）
   - ✅ Dismiss stale pull request approvals
   - ✅ **Require review from Code Owners**（配合 ②，这才是真闸门）
3. ✅ **Block force pushes**
4. ✅ **Restrict deletions**
5. **Bypass list 留空** —— 或至少 ✅ 勾上 **"Do not allow bypassing the above settings"**
6. （可选）✅ Require status checks to pass：`verify`、`guards-can-fail`
   —— 这两个 job 名来自 `.github/workflows/deploy-pages.yml`，勾上后**门禁红就物理上合不了**

> 第 6 条是把"本地守卫全绿"从**纪律**变成**门禁**的那一步。当前它是靠人记着跑的。

## 8. 节奏与仪式

- **成本口径**：只在空闲时段推进（工作日 00:00–09:00 / 12:00–14:00 / 18:00–24:00、周末全天）。高峰不开新工作项。
- **变更请求通道**：工作流把"我要改 X（属 Y 流）"写成一行，落 `docs/`，由我裁决并在注册表留痕。
- **每波收口**：一波结束我出一张汇总（完成/未完成/红因/下一波），**你只需要看这一张**。
- **我不替你做产品决策**：涉及"做不做、优先级、钱的边界、权限模型"的，我永远给选项 + 建议，等你一句话。
