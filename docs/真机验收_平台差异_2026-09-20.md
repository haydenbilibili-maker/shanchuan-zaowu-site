# 真机验收 · **平台差异**必验清单（2026-09-20）

> 触发：产品负责人「今天出现的一个 bug 是在 iOS 上可以使用的功能，但是在安卓上不行，
> 验收需要加强这个环节」。
>
> 这份清单的目的很具体：**平台差异在开发者工具和单一机型上永远看不出来**。
> 今天的三个二维码问题里有两个就是"iOS 正常、安卓不行"，如果验收只在一台机器上走一遍，
> 它们会**照样带到商店审核**。

---

## 1. 今天这一类问题的清单（同一根因族，全部已修）

**共同根因**：安卓热启动时 `onShow(options)` 里的 `options` 可能是**上一次进入的旧值**
（iOS 不受影响）。凡是"靠 `options.scene` 决定跳哪一页"的逻辑，在安卓上就会丢 scene。
微信官方的解法是 `wx.getEnterOptionsSync()`（基础库 2.20.1+，每次进入都会更新）。

| # | 现象 | 平台 | 根因 | 修法 | 证据（可复跑） |
|---|---|---|---|---|---|
| 1 | 扫**门店 AI 识别码**落首页 | 安卓 | 热启动 options 是旧的；`onPageNotFound` 一律 `goHome()` | `app.js#maybeOpenIdentifyEntry`（带 `getEnterOptionsSync` 兜底）+ `onPageNotFound` 对识别类路径**回识别页** | `npm run test:legacy-remap`（122 项） |
| 2 | 扫**收银台「新用户注册」立牌**落首页 | 两端 | 码里的 `page` 是 09-15 那一代（`feature/user/onboarding`），页面 09-17 搬到 `extra/user/…`；**印刷品改不了** | `utils/messageHelper.js` 第二代别名表 `MOVED_SUBPACKAGE_ALIASES`（按 `from` 长度倒序、**query 原样带过去**）+ `app.js#maybeOpenRegisterEntry` | 同上 |
| 3 | 扫**祈福墙立牌**进了 AI 识别页 | 两端（含冷启动） | 立牌与识别码**共用** `from=store_qr` 令牌，识别路由只判 `from` 不看 `k` | 识别路由**让路**：`k=mashangyou` 转给祈福墙；其它未知 `k=` 一律不抢 | `npm run test:legacy-remap` + `npm run check:wall-qr` |
| 4 | 扫**图鉴立牌**在安卓上不跳页 | 安卓 | `maybeOpenAtlasSpot` **没有**热启动兜底（今天核查时新发现） | 补上同样的兜底 | `npm run check:wall-qr`（新判据） |

## 2. 代码层面的护栏（已加，不靠人记）

`check:wall-qr` 现在**从 `app.js` 派生**"所有读入口 scene 的 App 方法"（排除 `onLaunch/onShow/onPageNotFound` 这类只转发 options 的生命周期钩子），
**逐个**要求它自带热启动兜底 —— 直接调 `wx.getEnterOptionsSync()`，或委托 `getEnterSceneText()`
（委托的话，那条 helper 自己也得真的调，否则判据不放行）。

> 为什么必须派生、不能写死名单：**写死名单的话，下次新加一个入口路由忘了兜底，判据不会说话。**
> 这正是这类 bug 复发的方式 —— 图鉴那条就是漏网的（它自己内联解析 scene，不走 `sceneOf(`）。
> 自检里"去掉热启动 scene 兜底"必红（`npm run check:wall-qr --selftest`）。

## 3. 验收清单：**必须双端各走一遍**（iOS + 安卓）

### 3.1 关键前提：每种码都要在**三种进入状态**下各扫一次

安卓的差异几乎只在状态 ②③ 暴露；iOS 三种都容易过 —— **不能只测状态 ①**。

| 状态 | 怎么造 |
|---|---|
| ① 冷启动 | 微信「发现 → 小程序 → 最近使用」里**删除**该小程序 → 扫码 |
| ② 后台热启动 | 打开小程序后按 home 退到后台（**不要**划掉）→ 回到微信聊天窗口扫码 |
| ③ 杀进程后扫码 | 从小程序后台列表**划掉** → 扫码 |

### 3.2 扫码进入（今天的 P0 区）

对每张码 × 每个平台 × 每种状态，期望如下：

| 码 | 期望落点 | 备注 |
|---|---|---|
| 门店 AI 识别码（立牌/桌牌） | `subpackages/feature/identify/index` | 状态②③是安卓的暴露点 |
| 收银台「新用户注册」立牌 | `subpackages/extra/user/onboarding/index`，**且页面是「注册领新客礼」形态**（不是"欢迎回来"） | 码是老路径，全靠客户端别名接住；**旧码不用重印** |
| 祈福墙立牌 | `subpackages/feature/wish-wall/index` | **绝不能**进 AI 识别页 |
| 礼笺贴纸上的养护码 | `subpackages/feature/care/guide/index`，顶部标「来自礼笺」 | 新码（2026-09-20 生成，纯黑） |
| 图鉴立牌（spot） | `subpackages/feature/collection/index?spot=…` | 状态②③是安卓的暴露点 |

⚠️ **注册立牌那一条要特别看**：必须确认落到的是"注册"形态。
`from=counter_qr` 是**独立注册入口**（不继承历史回流的 `returnUrl`）；scene 丢了就会变成普通登录页。

### 3.3 平台差异功能

| 项 | iOS | 安卓 | 怎么验 |
|---|---|---|---|
| 礼笺书写音效 | 应出声 | 应出声 | 编排页写完一段应听到**连续书写床**，不是"只响三声"、也不是卡顿；机型不吃 `stop()+play()` 时看门狗会自动切路径（`check:gift-sfx-perf`） |
| canvas 手写体 | **iOS 专属坑**：WebView 不暴露中文手写族 | 通常正常 | 导出「礼笺图 / 贴纸图」，正文必须是**手写体**（若变宋体 = 没等 `ensureHandFont()`） |
| 储值充值（虚拟支付） | 受 `content_display_flags.allowIosStoredValue` 开关控制 | 不受限 | 按当前开关口径核对 |
| 包体/分包加载 | —— | **低端安卓**易 `navigateTo:fail timeout` | 从首页进 AI 识别、进祈福墙，各连点 3 次不应报错 |

### 3.4 常规动线（双端各走一遍即可）

- 下单 → 支付 → 礼赠履约「导出礼笺图 / 导出贴纸图」→ 预览 → 保存到相册
- 祈福墙：写愿 → 点灯 → 摇签 → 上墙（**含注册后的数据是否真的存上云**）
- 超管：藏品库 → 分类管理 → 字段维护**标记后保存**（今天修的 P0）→ 重新进入页面确认**还在**
- 运费说明（`玻璃罩/标本框` 短标签）在详情页与结账页都不溢出

## 4. 判定口径（写死，避免"iOS 过了就发"）

1. **任一平台、任一进入状态不过 = 不过**；
2. 平台差异类问题**必须报"机型 + 系统版本 + 进入状态"**（只写"安卓不行"没法定位）；
3. 报障时**不要**说"和 iOS 一样"——那是结论，不是现象。
