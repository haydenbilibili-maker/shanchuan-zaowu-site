# 钱包枢纽合并方案（三页 → 一页三面板）· 2026-09-17

> 目标：**顶部交互完全一致 + 切 tab 丝滑无感**。
> 已定：宿主页放 `subpackages/business`；钱包 / 礼券夹 / 积分**三面板全部合并**。

## 一、为什么必须合并（现状的结构性缺陷）

`WalletHubBar.onTap` 现在是 **`wx.redirectTo` 跳另一个页面**：

```js
wx.redirectTo({ url: '/subpackages/business/coupons/index' })   // 整页跳转 → 必有转场动画
```

- **有页面转场** → 视觉上不可能"无感"
- 更糟：三页分属**两个分包**（钱包在 `extra`，礼券夹/积分在 `business`）→ 跨分包跳转首次要**加载分包**，既慢又无法丝滑
- 三页各自维护一套页头/容器对齐（`stretch` vs `center`），所以每加一页就要手调一次位置 —— 前几轮反复漂移的根因

## 二、目标结构

```
subpackages/business/wallet-hub/index.*        ← 宿主页（唯一入口）
  ├─ <wallet-hub-bar>（page 内切 tab，不跳转）
  └─ 三个面板组件（wx:if 切换）
      ├─ components/WalletPanelWallet/    储值余额 + 流水（原 extra/user/stored-value）
      ├─ components/WalletPanelCoupons/   礼券夹（原 business/coupons）
      └─ components/WalletPanelPoints/    积分（原 business/points）

旧三页保留为**薄跳转壳**：onLoad 把查询参数转给宿主页对应 tab
  （保证站内信 / 分享 / 收藏 / 历史链接的落点不失效）
```

**为什么用「面板组件」而不是把三段代码塞进一个 Page**：
- 三份 WXSS 彼此隔离，避免类名撞车（三页都有 `.container` / `.header` / `.title`）
- 三份 data 与方法互不污染，后续单独改一块不影响另两块
- 组件可按需 `attached`（懒加载），首屏不必等三块都就绪

## 三、关键设计决策（避免下一轮再试错）

1. **`WalletHubBar` 改为派发事件**：`bind:tabchange` → 宿主页 `setData({ curTab })`；
   组件自身**不再 `redirectTo`**。旧页面（壳页）不需要 tab 条。
2. **控件级能力上移到宿主页**：`onPullDownRefresh` / `onReachBottom` / `onShow` 是页面级 API，
   组件里没有。宿主页按 `curTab` 转发给当前面板：
   ```js
   onPullDownRefresh() { const p = this.selectComponent('#panel-' + this.data.curTab); p && p.onPullDownRefresh && p.onPullDownRefresh() }
   onReachBottom()     { /* 同上，转发 onReachBottom */ }
   ```
   面板里原来的 `onPullDownRefresh` / `onReachBottom` 原样保留为普通方法。

   **`onShow` 必须分两段（批 1 实测踩到，已固化）**：页生命周期是 `onLoad → onShow → onReady`，
   首屏那次 `onShow` **早于组件 ready** —— 此时 `selectComponent` 还是 `null`。于是：
   - **首次取数由面板自己的 `lifetimes.ready` 负责**（等价于原页面的首次 `onShow`）；
   - **之后每次「页面重新显示」由宿主 `onShow` 转发**，且宿主**跳过首屏那一次**（`this._skipFirstShow`）；
   - 面板里**不得**再挂 `pageLifetimes.show` —— 它与宿主转发是两条独立的路，同时存在会让
     `refreshAll` 每次回页面跑两遍（重复请求，后到的响应还可能覆盖先到的）。
   - 两种时序（`onShow→ready` 与 `ready→onShow`）下都恰好取一次数，由
     `test:wallet-hub-lifecycle` 守住（23 项断言 + 7 条注入回归 + 1 条中性负对照）。
   - **切 tab 不能靠 `pageLifetimes.show`**：宿主 wxml 用 `wx:if`，实例是新建的，而页面并没有重新
     show —— 新面板只能靠自己的 `ready` 取数。这也是必须用 `ready` 而不是 `pageLifetimes.show` 的原因。
3. **钱包面板要"降级简化"**：原页用「固定头部 + 固定滚动区」（`headerBlockPx` / `scrollHeightPx` /
   `measureFixedScroll`）——那套是**因为它自己拥有整个页面**。进了枢纽页之后页头与 tab 由宿主页负责，
   面板只需**普通内容流** → 直接**删掉那套滚动数学**（也顺带消掉我上一轮为它做的 `headerBlockPx` 适配）。
   分页改由宿主页 `onReachBottom` 转发触发。
4. **`onLoad(options)` → `attached()` + properties**：面板不再自己读路由参数；
   需要初始筛选的面板由宿主页通过 property 传入（如券夹的 `filter`）。
5. **样式基线**：宿主页 `.hub-page` 统一 `padding: 0`，页头与 tab 条由组件负责；
   面板自带内边距（积分面板仍是自己的 `.container{padding:0 30rpx}`，一行没改）。
   三页原来各自的 `.hub-bar-bleed` / 负边距 / `align-items` 差异**全部删除** ——
   这正是位置漂移的来源，合并后不再需要。
   **但 `sticky` 要保留**：旧页靠 `.hub-bar-bleed` 的 `position:sticky;top:0;z-index:30` 吸顶，
   宿主用 `.hub-bar-sticky` 承接同样的口径；负边距之所以能删，是因为宿主没有横向内缩
   （负边距原本只是用来抵消各页 `.container` 的内边距）。

**组件化会静默吃掉的两条「页面级」样式**（都已补回，不是猜测）：
1. `page { color: #D5D1C8 }` —— 组件里的 `page` 选择器**无效**，而 app.wxss 全局给的是 `#FFFFFF`
   → 券面文字会整体变亮。→ 补在面板 `.container` 上（继承链位置等价）。
2. `page { height: 100% }` —— 空态 `.empty{flex:1}` 的**垂直居中**依赖它；组件里同样无效，

   → 补一条确定高度链：`.hub-page(min-height:100%) → .hub-panel(flex:1) → 面板 :host(flex:1) → .container(flex:1)`。
   少任何一段都会静默退化（失败模式是「和原来一样贴顶」，不会更糟）。

**顺带补掉的守卫盲区**：`test:gift-mygifts` 把所有 `components/` 路径排除在模板扫描外，
