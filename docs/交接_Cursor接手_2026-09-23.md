## 2. 铁律（每条都对应一次真实事故）

| # | 铁律 | 真实事故（都发生过） |
|---|---|---|
| 1 | **静态分析 ≠ 事实** | CSS 里哪条生效受 `!important`/特异性/teleport 影响；脚本判出的"问题"必须在**浏览器/真渲染**复核后才算数 |
| 2 | **本地验过 ≠ 线上能跑** | 日报用 `.aggregate().append()` —— 那是 manager-node 的 API，`wx-server-sdk` 没有 ⇒ 线上 7 个订单指标全灭，而本地用 `tcb db nosql` 是绿的 |
| 3 | **先证明量具可信，再动手改** | 渲染台的「7 条版式基线红」**7 条全是工具自己的 bug**；出图里弹幕"叠成一团"是**冻结动画 + 伪造摆位**造成的假象。我差点据此去改没好样式 |
| 4 | **负向/形态判据必须看"去注释"的源码** | 判据匹配到我自己写的说明注释 ⇒ 恒红（发生 3 次） |
| 5 | **注入必须与判据同层、且真的越过阈值** | 给文本级判据注入"函数早退"抓不到；`hint-wraps` 用 60rpx/160rpx 都没越过"2 行"上限 ⇒ 自检给的是**假绿** |
| 6 | **预览/守卫不许读"过期镜像"** | 渲染台硬编码了 4 条玩法入口文案 + 手写弹幕样例 ⇒ 我改了注册表**出图一字未变**（错题本 E3） |
| 7 | **不手改"由脚本产出的副本"** | `orderSummary.js` 有 1 份真源 + 12 份副本，由 `sync-order-summary.sh` 同步；手改副本必然漂移 |
| 8 | **动生产数据前先备份、先证伪自己的假设** | 我一度把 `user_messages` 里 9 组重复 `dedupeKey` 判成"重复发送 bug"，**幸好先备份 + 查清语义**才发现是"24 小时窗去重"的设计行为 —— 删了就抹掉顾客真实记录 |
| 9 | **不要在提交信息里用反引号 + `-m`** | shell 会执行反引号、把提交信息吃掉（本会话第 6 次）。**一律用引号 heredoc（`<<'MSG'`）** |
| 10 | **改"用模板串拼页面脚本"的工具后，立刻 `node --check`** | 注释里写反引号会截断模板（本会话第 8 次，`test:wish-wall` 的 `node --check` 判据兜住了） |
| 11 | **子代理/并行会话不要共用同一个工作树** | 一路子代理 `git checkout -b` 把主负责人的分支一起切走了，三条流的未提交改动混在一棵树里 |

## 6. 云端服务器（`agent.shanhaizaowu.com`）

- 架构：浏览器 → Cloudflare（DNS+TLS+**Access 登录**）→ cloudflared 隧道 → 服务器 `127.0.0.1:3080` 的 `dsh web`。
- **2026-09-22 真事故（自伤，不是被攻击）**：agent 在服务器上执行的命令是 `dsh-web.service` 的**子进程**、与 web **同一个 cgroup（上限 2.22 GB）**。整夜反复跑全量守卫 + `astro check` + `vite`，把 cgroup 顶到 94%、load 9.0，**12 个进程挂住 9.8 小时** ⇒ web 答不动 ⇒ Cloudflare **524**。
- **三条纪律**（照做就不会再发生）：
  1. **内循环只用 `npm run check:quick -- <域>`**；全套 `check:admin` 在服务器上要先想一下要不要跑；
  2. **重活必须走包装器**：`dsh-heavy-task <命令>`（独立 cgroup + 默认 25 分钟硬超时 + 1.2 GB 上限）；
  3. **别在服务器上开常驻 dev server / 跑重构建**（`vite` / `astro check` / 大克隆会一直挂着占内存）；需要浏览器验证的活回本地做。
- 兜底：`dsh-heavy-watchdog.timer` 每 2 分钟扫一次，跑超过 10 分钟（或 load > 2.5×核 / cgroup > 75% / **web 无响应**）的重活会被 TERM→KILL 并记 `/var/log/dsh-heavy-watchdog.log`。
- 脚本源码在 `deploy/agent-server/`（`heavy-task.sh` / `heavy-task-watchdog.sh`，改完 scp 到 `/usr/local/bin/dsh-heavy-task`、`/usr/local/bin/dsh-heavy-watchdog`，权限 755）。
