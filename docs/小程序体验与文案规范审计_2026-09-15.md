# 小程序专项审计：排版 / 交互 / 文案一致性 / 标点规范

> **审计对象**：小程序全量界面代码（`pages/` + `subpackages/` + `components/` + `custom-tab-bar/`）。
> **方法**：先从 WXML 文本节点与 JS 字符串字面量中抽取**面向用户的文案**（排除注释与 `console` 日志），得到 **12,061 条**语料；再对样式表、事件绑定、导航调用做可量化扫描，疑点逐条人工核实。
> **一句话结论**：**骨架规范度不错**（字号刻度、圆角/间距 token、Toast 约定、导航降级都做得对），问题集中在三处：**标点/术语的历史遗留不统一**、**近半数样式绕过设计 token**、**三分之二的点击元素没有按压反馈**。

## 1. 排版（Typography / Layout）

### 做得对的部分

- **字号刻度集中**：22rpx（903 次）、24（689）、20（606）、26（434）、28（431）五档占绝大多数，属于有节制的字号体系。
- **设计 token 齐备**：`app.wxss` 已定义 `--primary` / `--gold` / `--color-bg` / `--color-text-*` / `--radius-sm|md|lg|xl` / `--space-*`。
- **异常字号极少**：全仓仅 4 处不在常规刻度（15rpx ×3、25rpx ×1），另有少量 12/14rpx 微字用于角标。

### 问题：近半数样式绕过设计 token

| 指标 | 数量 |
|------|------|
| `var(--*)` 用法 | **6,287** |
| 硬编码 `#hex` 用法 | **5,410（占 46%）** |

更值得注意的是：**硬编码排名前列的颜色就是 token 值本身**。

| 硬编码值 | 次数 | 对应 token |
|----------|------|------------|
| `#C4A76C` | 1,242 | `--primary` / `--gold` / `--color-primary` |
| `#1A1814` | 677 | `--color-bg` |
| `#A09A90` | 500 | `--color-text-secondary` |
| `#6B6560` | 459 | `--color-text-muted` |
| `#262320` | 328 | `--color-bg-elevated` |
| `#1F1D1A` | 304 | `--color-bg-card` |
| `#D5D1C8` | 232 | `--color-text-body` |

即约 **3,400 处**是"用字面量重复写了 token"。后果：改主题色或做深浅色切换时不得不全仓替换，容易出现漏改的"花斑"。

**建议**：按值到 token 的映射脚本化替换，分批提交（按目录），并在 CI 加一条"新增样式不得硬编码品牌色"的检查。

### 本轮未覆盖（建议后续专项）

- 图片 `mode`（`aspectFill` / `widthFix`）一致性；长文本截断（`-webkit-line-clamp`）覆盖；
- 刘海屏安全区（`safe-area-inset-*`）底部留白一致性；
- 卡片圆角与间距的视觉层级是否贴合品牌手册（需真机或设计稿比对，静态扫描不足以判定）。

## 2. 交互（Interaction）

### 导航降级写法正确（值得肯定）

扫出 5 处"疑似 `navigateTo` 跳 tabBar 页"（这类写法会**静默失败**，是常见坑），逐条人工核实后**全部为误报**：跳转目标是子包页面，`wx.switchTab` 都正确写在 `fail` 降级分支里（`utils/userSession.js`、`gift/receive/index.js`、`articles/index.js`）。

### 点击反馈覆盖不足：33%

| 指标 | 数量 |
|------|------|
| `<view bindtap>` 元素 | 1,362 |
| 带 `hover-class`（有按压反馈） | 443（**33%**） |
| 缺反馈 | 919 |

集中在：店长台 `manager/workspace/_subviews.wxml`（227）、`manager/index.wxml`（44）、`live/broadcast`（34），以及用户端 `feature/detail`（27）、`business/booking`（25）。

**建议**：先补用户端（浏览到下单路径优先级最高），店长台作为第二批；统一一个 `.press` 工具类，避免每处自定义。

### 22 个列表页没有空态文案

113 个含列表渲染的页面中，22 个没写空态（无"暂无/去逛逛"之类的引导），例如 `feature/comment`、`feature/articles/detail`、`feature/user/feedback`、`business/store-zone`、`business/framer-recruit`。用户遇到空列表会看到一片空白，分不清是没数据还是加载失败。

其中 `business/confirm-order` 属正常（结算页商品列表不会为空），其余建议逐页确认。

### 提示反馈约定统一

`showToast` 的 icon 分布：`none` 1,506 次、`success` 141 次、未指定 20 次——信息与错误用 `none`、成功用 `success`，约定一致，没有混用造成样式碎裂。`showModal` 73 处用于需要用户决断的场景，分工合理。

## 附录 · 审计口径

- **文案抽取**：WXML 取文本节点与含中文的属性值（`placeholder`/`label`/`title`/`content`/`confirmText` 等）；JS 取含中文的字符串字面量，并剔除注释与 `console.*`，避免把调试日志计入文案。
- **样式扫描**：统计 `font-size` 分布、`var(--*)` 与 `#hex` 出现次数、硬编码色频次。
- **交互扫描**：`<view ... bindtap>` 标签内是否含 `hover-class`；`navigateTo` 目标是否命中 tabBar 五个页面，并逐条人工核实降级分支。
