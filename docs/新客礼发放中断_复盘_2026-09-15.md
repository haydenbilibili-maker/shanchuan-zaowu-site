# 新客礼发放中断 · 复盘（2026-09-15）

> 现象：新用户注册只到账积分、**一张礼券都没有**。
> 结论：**不是代码 bug，是云库配置被改坏**——新会员礼包的 4 条券行全部被存成了「关闭」。

## 1. 现象与定位过程

| 步骤 | 证据 |
|------|------|
| 代码兜底是正常的 | `cloudfunctions/upsertUserProfile/welcomeGiftDefaults.js`：默认 100 积分 + 5 张券（首单友好档 满49减10） |
| 线上实际配置（`member_welcome_gift`） | `points=100`、`pointsEnabled=true`、`couponsEnabled=true`，但 **4 条券行 `enabled` 全为 `false`**（c10 满49减10 / c30 满299减30 / c50 满499减50 / c100 满999减100） |
| 运行时代码如何取舍 | `activeCoupons()` 只返回 `enabled` 的券行 → 实际发券数为 0，积分照发 100 |
| 影响面（查库统计） | 历史 49 条注册礼流水里，**只有 2 条没有券**：openid 尾号 `8hP8h_dw`（现 300 积分）与 `Xa9gfaJ0`（100 积分） |

用户反馈的「300 积分」= 该账号 100（注册礼）+ 200（其它来源），与注册礼无关；券为 0 才是真问题。

## 2. 修复（已执行）

| 动作 | 内容 |
|------|------|
| 打开券行 | `member_welcome_gift`（`_id=2feda4ef6aa1415a02005646353f37e0`）的 4 条券行 `enabled: true`；`couponsEnabled/enabled/status` 复位为开、`active`；积分仍为 100、有效期 90 天 |
| 受影响用户 | 2 个账号标记 `registerGiftIncomplete: true`，生产代码会在其打开「我的」页看到**补领横幅**，点一下即自动补齐 4 张券（走云函数原逻辑，幂等、不重复发积分） |
| 备份 | 现场配置原文：`backups/member_welcome_gift-before-fix-20260915.json`（校验值 `backups/SHA256SUMS-welcomegift-20260915-1530.txt`） |

**复核（用云函数自身代码解析修复后的配置）**：

```
新会员礼包：100 积分 + 礼券 满49减10 / 满299减30 / 满499减50 / 满999减100（90 天）；
不可叠加（一单一券）；折扣不低于 7.5 折
→ activeCoupons = 4
```

## 3. 防复发建议（待排期）

1. **ERP 摘要加显式告警**：现在 `couponsEnabled=true` 但所有券行都关时，摘要只显示「100 积分」，看不出异常。建议显示「⚠️ 礼券已全部关闭，新用户不会收到券」。
2. **云函数保存校验**：`manageWelcomeGift` 保存时，若「券开关开 + 无启用券行」应返回二次确认。
3. **注册完成页提示**：无券但有积分时，页面应提示「礼券待补领」，而不是静默显示积分。

## 4. 相关口径

- 券统一叫**礼券**；商品名词统一叫**藏品**；对客称**馆长**（专名如「标本工坊 / 标本定制 / 标本养护」保持标本，见《小程序体验与文案规范审计_2026-09-15》第 7 节）。
- 该礼包发的是**线上礼券**（`user_coupons`，`source=register_gift`），与门店核销的代金券不是同一物。
