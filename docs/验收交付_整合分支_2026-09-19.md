## 4. 怎么证明（**可独立复验的「它会红」证据**）

这一节是本次交付的重点：**每条新判据都被证明过「能失败」**（AGENTS.md 硬性要求）。

### 4.1 order 双向对账（**不是恒真判据**）

把 `refundOrder/index.js` 唯一一处 `status: 'refunded'` 注入成 `'refund_rejected'`：

```
守卫真实 exit=1，三条判据同时命中：
  B.  幽灵「refund_rejected」被服务端写入 → refundOrder/index.js:239
  A2. in_use 声称「在用」但服务端**零写入方** → refunded（它其实是幽灵）
  F.  幽灵出现次数 == 1 > 基线 0
还原后 exit=0，git diff 为空（逐字还原）
```

**A2 是这条守卫的价值所在**：碰掉 `refunded` 的写入方后，它反过来指出「这其实是幽灵」——
「幽灵删对了且没删漏」由此可证明，而不是靠文档自述。

### 4.2 `blessTags.plays` 必须命中玩法注册表

合法 id 集合**从 `miniprogram/config/ritualPlays.js` 现读**（守卫内零硬编码）：
新增玩法自动合法；玩法改名/删除立即报红。
`--selftest` 3 轮注入（副本漂移 / SSOT 非法 id / **ERP 副本非法 id**）全部检出且逐字节还原；
其中 ERP 那轮是隔离证明（ERP 不参与逐字比对，改前只有新判据能抓到）。

### 4.3 `plays` 里的非法 id 已修（数据）

```
合法玩法 id（ritualPlays.js）：qian, cookie, zodiac, mbti
求安 (peace)：['muyu','qian'] → ['qian']   ← 5 个副本同步
```

理由（已实测）：「木鱼」是 `index.wxml:196` 的常驻 `ww-ritual-card`，**不是玩法瓦片**；
`plays` 的真正消费者是 `index.js:213 blessPlayIds(tags)` 用它排序 `RITUAL_PLAYS`，
而 `'muyu'` 永远匹配不到 → `rank('muyu')` 恒为「未命中」，「求安优先木鱼」的意图**从未生效**。

### 4.4 `write-verify`：「删基线即可变绿」的洞

```
移走 admin/scripts/write-verify-baseline.json 后跑 --strict：
  修复前 → exit 0（静默通过）
  修复后 → exit 2（无法判定，不得当通过 —— 错题本 E16）
还原后 md5 一致、exit 0
```
